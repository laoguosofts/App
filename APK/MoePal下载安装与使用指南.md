## ✨ MoePal 是什么

MoePal 是一款把网盘链接解析和多协议下载引擎打通为一体的下载工具。它的核心思路很直接：用户把网盘分享链接、磁力链接、BT 种子甚至 ED2K 链接丢进来，MoePal 自动完成解析，然后交给内置的 Gopeed 多线程引擎去下载，整个过程不需要在网盘客户端、浏览器插件、命令行下载器之间来回切换。

市面上不乏单独的网盘解析工具，也有不少优秀的下载加速引擎，Gopeed 本身也是开源自有名片。但把这两样真正整合到一个界面里、让用户只做一次"粘贴 → 下载"的动作，MoePal 做的就是这件事。

它的适用场景其实很广：经常从各种网盘收集资料的学生或研究者、需要下载大体积游戏安装包和影视资源的普通用户、手头积累了不少老派 ED2K 链接但找不到还能跑的客户端的怀旧党——这几类人都会觉得 MoePal 顺手。

Gopeed 引擎的引入是关键加分项。传统网盘官方客户端的下载速度往往跟会员等级绑定，多线程下载在 MoePal 里是默认行为，不需要额外配置浏览器扩展或外部工具。对已经在用 IDM、Aria2、迅雷等独立下载器的人来说，MoePal 提供了一个更省事的选择——至少在网盘资源这条线上，它确实帮你省掉了手动抓取直链的步骤。

> [!TIP]
> MoePal 支持的协议范围很广：HTTP/HTTPS、磁力链接、BT 种子、ED2K，加上百度网盘、阿里云盘、夸克网盘、UC 网盘等主流平台的分享链接解析。如果你的下载来源经常横跨这几类，它的价值会比单一用途的工具更明显。

## 🔧 安装步骤

MoePal 同时有桌面端和移动端，不同平台的安装细节略有差异。下面按常见平台分别说明。

### 桌面端安装

1. 从下载页获取最新版本安装包，**务必核对文件大小和版本号**——如果下载页标注的版本号跟安装包内显示的不一致，大概率是过期链接，换一个源试试。
2. Windows 用户运行 `.exe` 安装程序，安装过程中注意两点：
   - 安装路径建议默认系统盘，但如果系统盘空间紧张可以改到其他盘符
   - 杀毒软件可能对下载类工具有误报，属于常见现象——确认来源可信后添加信任即可
3. 安装完成后首次启动，软件会提示是否关联浏览器、是否开启剪贴板监听。剪贴板监听建议开启，后续粘贴链接时 MoePal 能自动识别并弹框确认，省去手动复制的步骤。

> [!WARNING]
> 安装后如果启动崩溃或白屏，最常见的原因是显卡驱动或缺失的运行库。优先更新显卡驱动，其次检查系统是否安装了常见的运行库集合（如 VC++ Redistributable）。

### 移动端安装

Android 端需要允许"未知来源应用"安装权限：进入系统设置 → 安全 → 允许安装未知来源应用，然后直接打开 APK 即可。部分国产 ROM 的设置位置略有不同，但搜索"未知来源"通常能找到。

iOS 端需要通过 TestFlight 或企业证书安装，后者的证书可能会被苹果吊销，遇到无法打开时需要重新获取最新签名版本。

## 📖 使用入门

MoePal 的日常使用逻辑很简单：粘贴链接 → 确认解析结果 → 开始下载。但在实际操作中，有不少细节会影响下载体验。

### 链接解析：哪些场景能自动搞定

绝大多数公开分享链接可以直接粘贴解析——把网盘分享链接、磁力链接、BT 种子、ED2K 链接复制到剪贴板，MoePal 如果开了剪贴板监听会自动弹出确认对话框，点击确认后进入解析流程。

加密分享和私有分享是需要额外处理的场景：

- **带提取码的分享**：MoePal 会弹框让你输入提取码，输入正确后正常解析。阿里云盘、UC 网盘的加密分享都属此类。
- **需要登录账号才能访问的永久分享**：典型代表是百度网盘的"永久分享"。MoePal 支持在设置中通过 OAuth 授权关联网盘账号，授权后解析成功率显著提升。关联过程不会索要账号密码，而是跳转浏览器完成官方授权流程，安全性相对有保障。
- **有效期已过的分享**：如果 MoePal 提示"链接已失效"，先别急着怀疑工具——在浏览器里打开同一个链接验证一下，很可能是分享者取消了分享或者过了有效期。百度网盘常见的有效期有永久、7 天、1 天三种。

> [!NOTE]
> 也有一些场景 MoePal 确实处理不了：白名单 IP 限制的链接、只分享给特定好友账号的专属分享、必须购买会员才能访问的付费资源。遇到这些情况只能用网盘官方客户端配合合法账号来访问。

### Gopeed 引擎：多线程下载怎么用

解析成功后，下载的事就交给 Gopeed 引擎了。这个引擎的分层架构可以简单理解为五层：UI 层（MoePal 界面）接收指令，任务调度层管理下载队列，协议解析层识别链接类型，传输层负责分片和重试，存储层负责本地文件写入。

多线程下载的核心原理是**分片 + 并发 + 合并**：

1. 根据文件大小和可用带宽，把大文件切分成若干固定大小的分片
2. 每个分片分配给一个独立线程去下载
3. 多个线程同时从不同偏移量向服务器请求数据
4. 所有分片下载完成后，按顺序合并写入目标文件

这比单线程顺序下载快得多，尤其是当服务器对单个连接有限速的时候。

#### 线程数调优建议

默认设置下 Gopeed 会根据网络状况动态调整线程数，对大多数用户来说够用了。但手动调优可以进一步榨干带宽：

| 场景 | 推荐线程数 |
|------|-----------|
| 100M 宽带 | 8~12 |
| 300M 宽带 | 12~16 |
| 500M+ 宽带 | 16~32 |
| 移动数据（手机） | 4~8（避免流量消耗过快） |
| 网络不稳定 | 4~8（减少连接开销） |

> [!TIP]
> 线程数不是越多越好。每个线程都要建立 TCP 连接和协商，过多的连接建立开销反而会抵消并发收益。实测表明 100M~500M 宽带设置 8~16 线程是甜区。

#### 速度不理想的排查清单

多线程下载速度上不去的时候，按这个顺序排查最省时间：

1. **先确认本地带宽上限**：打开网速测试工具测一下实际带宽。如果物理带宽只有 50Mbps（约 6.25MB/s），无论多线程还是单线程都不可能突破这个天花板。
2. **检查源服务器是否全局限速**：某些网盘特别是百度网盘有服务端限速策略，多线程也绕不过去。换用夸克网盘、123 云盘等限速较松的平台试试，或者错峰下载避开晚高峰。
3. **确认线程数没有过多**：上面说过的连接开销问题，适当调低线程数可能反而更快。
4. **看 Gopeed 引擎版本**：Gopeed 在不断优化并发调度算法，保持 MoePal 更新到最新版本能获得更好的下载性能。

#### 进度卡了怎么办

多线程下载时进度条在某个百分比停留较久是正常现象——通常是因为某个分片下载特别慢（服务器对该段限速），或者最后几个大分片还在下载。Gopeed 会自动处理，不要因为进度卡了就强制暂停重下，反而会浪费已经下载的分片。

### ED2K：老资源的最后希望

ED2K 是 eDonkey 2000 网络使用的链接格式，虽然年代久远，但直到今天仍有一些资源网站、论坛在用它。典型格式长这样：

```
ed2k://|file|文件名.mp4|文件大小|MD4哈希值|/
```

MoePal 的剪贴板监听可以自动识别 `ed2k://` 开头的链接，粘贴后 Gopeed 引擎解析文件名、大小、哈希值，然后连接 eDonkey / Overnet 网络查找拥有该文件的节点，从多个节点并发拉取数据。下载过程中会持续校验 MD4 哈希确保文件完整性。

ED2K 的特点鲜明：**速度慢但完整性好**。速度慢是因为 eDonkey 网络节点数量比 BT 少得多，大文件可能需要数小时甚至数天。但好处是文件完整性有保障——链接自带 MD4 哈希校验值，下载完成后可以自行校验。

ED2K 的典型使用场景：

- **老资源的最后希望**：很多 2005~2015 年间分享的资源，网盘链接早就被取消了，BT 种子也可能没人做种了，但 ED2K 节点上还能找到。尤其是老番剧、老游戏、老软件。
- **来源明确的可靠下载**：某些资源论坛会在 ED2K 链接旁边标注"下载后请校验 MD4"，就是因为它自带哈希校验。

> [!NOTE]
> ED2K 下载的实用建议：耐心等待（Gopeed 正在尝试连接足够的节点）、后台下载（保持电脑不关机不休眠）、如果长期无进展可以查找 eMule 相关社区的活跃 Server List 导入 Gopeed 配置。

ED2K 下载完成后会进入 MoePal 的历史记录，来源平台标注为"ED2K"，和网盘、BT 的下载文件统一管理。
