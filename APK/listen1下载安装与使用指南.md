## ✨ Listen 1 是什么

Listen 1 是一款开源的音乐聚合播放器，它的核心理念很简单——**一个应用，聚合全网音乐**。不管你平时用网易云、QQ 音乐、酷狗还是酷我，Listen 1 把这些平台的搜索、播放、歌单管理功能整合到了一个界面里，让你不用在多个 App 之间来回切换。

它支持的平台相当广泛，国内主流的音乐服务基本都覆盖了，甚至还能接 Bilibili 视频音频源。除了桌面端（Windows / macOS / Linux），还有 Chrome 和 Firefox 浏览器扩展版，以及移动端 App——基本上你常用的设备都能装一份。

Listen 1 本身不存储音乐文件，它是一个「播放器壳」：登录你自己的各平台账号，调用各平台的官方接口来搜索、播放、收藏。这种设计的好处是完全合法合规，同时也意味着你在每个平台的个人数据（付费会员、已购歌曲）都能继续使用。

适合哪些人用？如果你同时订阅了多个音乐平台，或者想把分散在不同平台的歌单集中管理起来，Listen 1 就是为你设计的。它没有广告、不开会员、不做付费墙，纯靠社区维护，对音乐爱好者来说是一款非常实用的工具。

## 🔧 安装步骤

Listen 1 有四个产品线，每个产品线的安装方式略有不同，这里分别说明。

### 桌面版（Windows / macOS / Linux）

桌面版是使用最广泛的版本，安装过程跟一般软件类似。

**Windows 用户**：下载 ZIP 压缩包后解压到任意目录（建议 `D:\Programs\Listen1\` 这类非系统盘路径，避免权限问题），双击 `Listen1.exe` 即可运行。如果杀毒软件误报，可以将解压目录加入白名单——Listen 1 是开源软件，源码公开在 GitHub 上，可以自行核对。

> [!NOTE]
> Listen 1 是绿色软件，不需要传统的安装向导，解压即用。升级时关闭旧版本、覆盖解压新版本即可，用户数据不会丢失。

**macOS 用户**：下载 DMG 镜像文件，双击打开后把 Listen 1 图标拖到 Applications 文件夹。首次运行可能会被 Gatekeeper 拦截，右键点击应用图标选择「打开」即可绕过。

**Linux 用户**：提供 AppImage、Flatpak 和 deb 包三种方式。AppImage 下载后赋予执行权限直接运行；Flatpak 用户可以通过包管理器一键安装。

### 浏览器扩展版（Chrome / Firefox）

扩展版的好处是不用安装独立应用，直接在浏览器里用。

1. 打开 Chrome 或 Firefox 的扩展管理页面
2. 开启「开发者模式」
3. 下载 Listen 1 扩展的压缩包并解压
4. 点击「加载已解压的扩展程序」，选择解压目录
5. 浏览器工具栏出现 Listen 1 图标，点击即可使用

### 移动端

移动端 App 可以在各平台官方应用商店搜索「Listen 1」下载。Android 用户如果应用商店搜不到，也可以从官方渠道获取 APK 安装包。

## 📖 使用入门

Listen 1 的功能很多，这里挑几个最常用、最能体现它价值的功能来详细说说。

### 登录平台账号

第一次打开 Listen 1，你需要先登录你想用的音乐平台账号。在设置里找到「账号管理」区域，选择对应平台，用你的账号授权登录。登录成功后，Listen 1 就能调用该平台的接口帮你搜索和播放音乐了。

> [!TIP]
> 登录账号时建议用各平台的官方授权页面，不要在第三方页面输入账号密码。Listen 1 的登录流程会跳转到对应平台的官方网站，授权后再回到 Listen 1——注意确认这个跳转路径。

### 导入外部歌单

这是 Listen 1 最受欢迎的功能之一。你在网易云收藏了一个歌单、在 QQ 音乐创建了一个播放列表，现在想把它们搬到 Listen 1 里？不需要手动一首首搜，只要复制歌单链接就行。

操作很简单：进入「我的音乐」→「创建的歌单」区域，点击「导入歌单」按钮，把其他平台的歌单分享链接粘贴进去。等待 3 到 10 秒，Listen 1 会自动解析歌单里的全部歌曲并创建一个同名副本。

支持的平台包括网易云音乐、QQ 音乐、酷狗音乐、酷我音乐、Bilibili、咪咕音乐等。各平台获取歌单链接的方式大同小异：打开歌单页面，点击分享，选择「复制链接」。

导入后的歌单有几个特点：它不会和原歌单保持同步（原歌单删了歌，副本不会自动删），但你可以自由编辑——添加、删除、重命名都没问题。如果遇到部分歌曲导入后无法播放，这是正常现象，可能是原歌曲在当前平台下架了或有版权限制，可以试试「自动切换播放源」功能。

### 搜索与播放

Listen 1 的搜索框默认会同时在你已登录的所有平台上搜索。输入歌曲名、歌手或专辑名，结果会按平台分类展示，你可以直接点击想听的版本。

播放时会自动选择你已登录的平台作为播放源。如果某个平台的链接失效或音质不好，可以手动切换到另一个平台的播放源——V2.9.0 及以上版本还支持自动切换播放源，一个源不行自动换下一个，体验更流畅。

### 快捷键与全局控制

Listen 1 提供了丰富的快捷键来提升操作效率。默认快捷键包括：

| 快捷键 | 功能 | 容易冲突的场景 |
|---|---|---|
| 空格 | 播放 / 暂停 | 被输入法占用 |
| `Ctrl+Alt+Space` | 全局播放暂停 | 极少冲突 |
| `Ctrl+S` | 收藏 | 被浏览器保存网页占用（插件版） |
| `Ctrl+↑/↓` | 音量 | 被系统音量占用 |

如果遇到快捷键不响应，按优先级排查：首先确认 Listen 1 窗口是否在前台（全局快捷键除外）；然后检查是否被输入法占用（比如 `Ctrl+Space` 是 Windows 中英文切换）；接着关闭后台的全局快捷键工具（如 AutoHotkey、Snipaste），逐个测试；Chrome 插件版用户可以在 `chrome://extensions/shortcuts` 查看是否有其他扩展注册了冲突的快捷键。

### GitHub Gist 歌单备份

Listen 1 有一个很巧妙的同步方案——把歌单数据备份到 GitHub Gist。Gist 是 GitHub 提供的轻量级代码片段托管服务，每个 Gist 有唯一 ID，可以通过 API 读写。

为什么选 Gist？因为它免费、可靠、跨设备、可回滚。GitHub 账户自带 Gist 权限，全球 CDN 保证数据安全，任何设备登录同一 GitHub 账户就能同步，而且 Gist 自带版本历史，你可以恢复任意时间点的歌单。

设置过程也不复杂：在 Listen 1 设置 → 账号同步区域，找到「GitHub 授权」按钮，点击后浏览器跳转 GitHub 授权页面，用你的 GitHub 账号登录并确认授权。回调地址会回到 Listen 1，点击「已经完成授权」就搞定了。

授权完成后，Listen 1 会在你的 GitHub 账户下自动创建一个专用 Gist，里面包含歌单列表、收藏列表等 JSON 文件，Gist 会设为私密，只有你和 Listen 1 能访问。之后你可以手动一键备份，也可以开启自动备份。换设备或重装 Listen 1 后，同样用 GitHub 账号授权，Listen 1 检测到云端备份会提示是否恢复，歌单和收藏就能自动拉回来了。

> [!WARNING]
> Gist 备份不会包含各平台的登录 token（出于安全考虑），也不会备份播放历史和搜索历史。升级或换机前除了 Gist 同步，建议再手动导出一次 JSON 做双重保险。

### 版本更新

Listen 1 是社区驱动的开源项目，不会自动弹出更新提示，需要手动关注新版本。四个产品线（桌面版、Chrome 插件、移动端、Python 网页版）分别在各自 GitHub 仓库的 Releases 页面发布更新。

更新频率不固定：大版本更新（功能新增、架构调整）大约 3 到 6 个月一次；小版本更新（bug 修复、适配平台接口变动）1 到 2 个月一次；如果某个平台的播放接口突然失效，社区会紧急发布修复版本。

桌面版更新比较简单：下载新版本 ZIP，关闭 Listen 1，把旧版本目录重命名做个备份，然后把新版本解压到原位置（或新位置）就行。Listen 1 的用户数据存在独立目录里（Windows 是 `%APPDATA%\Listen1\`，macOS 是 `~/Library/Application Support/Listen1/`），只要不删这个目录，升级后歌单和登录状态都会保留。

浏览器扩展版需要在扩展管理页点击「更新」按钮刷新，或者下载新版本后重新加载。插件版的数据和浏览器绑定，升级扩展本身不会清除数据，但如果换浏览器或浏览器配置文件，数据可能丢失，建议升级前手动导出 JSON。
