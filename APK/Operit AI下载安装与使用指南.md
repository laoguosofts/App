## ✨ Operit AI：Android 上能干活的本地 AI Agent

Operit AI 是一款面向 Android 平台的 AI Agent 应用——和普通的聊天机器人不同，它不仅能对话，还能真的替你操作手机：打开应用、点击屏幕、读写文件、跑命令行、调用模型做推理。核心思路是把大模型的理解能力和 Android 系统的无障碍接口打通，让 AI 变成你的手机代理人。

它的架构分三层：**模型引擎**（内置 llama.cpp 跑 GGUF 本地模型，也支持云端 API）、**能力层**（内置工具箱 + MCP Server + Skill 组合）、**产出层**（Artifact 模板市场，把 Agent 的输出变成可复用的脚手架或文档）。三层配合起来，Operit 能覆盖从「日常对话」到「自动化操作 App」再到「生成整个项目」的完整链条。

适合什么人用？首先是喜欢折腾本地 AI 的用户——不想把数据发给云端、想在手机上跑自己的模型；其次是有自动化需求的人——定时读邮件生成摘要、批量整理文件、截图分析界面；还有开发者可以用 Artifact 模板一键生成项目结构、自动生成文档。

> [!TIP]
> Operit 对硬件有一定要求：建议 6GB 以上内存、骁龙 8 系或同级处理器，才能流畅跑 7B 级别的本地模型。低配设备也能用，但建议从 1.5B 小模型起步。

## 🔧 安装与初始配置

Operit 是 Android 应用，安装过程和普通 APK 类似，但有几个关键配置不能跳过。

### APK 安装流程

1. **下载 APK 文件**：从上面的下载入口获取最新版本，建议核对文件大小和 MD5（防止下载损坏）
2. **允许未知来源**：如果是首次安装非应用商店的 APK，需要在系统设置里开启「允许安装未知来源」或对当前浏览器/文件管理器授权
3. **安装 APK**：双击文件按提示完成安装
4. **首次启动**：打开应用，授予基础权限（存储访问、通知权限）

### 必开的系统权限

> [!WARNING]
> 权限没开全 = Operit 只能聊天不能动手。以下权限缺失任意一项，对应的功能就用不了。

| 权限 | 用途 | 不开的后果 |
|---|---|---|
| **无障碍服务** | UI 自动化的核心通道 | 点不动任何 App，只能对话 |
| **存储访问** | 读写模型文件、Artifact 产物、工具箱文件 | 本地模型加载失败，文件管理工具箱不可用 |
| **通知权限** | 读/发系统通知 | 通知工具箱不可用 |
| **后台运行** | Android 11+ 后台启动限制 | 屏幕熄灭后自动化任务中断 |

无障碍服务的开启路径：**系统设置 → 无障碍 → 找到 Operit 对应的服务 → 打开开关**。别只看 Operit 内部的状态提示，务必进系统设置确认开关真的是 ON。

### 模型配置（本地路线）

Operit 内置了 llama.cpp 引擎，直接支持 GGUF 格式模型文件，生态最丰富、选择最多。

**获取 GGUF 模型**：
- HuggingFace 搜索模型名 + GGUF，下载 `.gguf` 文件
- 国内用户推荐 ModelScope 镜像，速度更快
- 入门推荐 Qwen2.5-1.5B-Q4_K_M（约 1GB），够用且轻量

**在 Operit 里配置**：
1. 把 `.gguf` 文件放到 `Operit/models/` 目录
2. 侧栏 → 模型配置 → 新建配置 → 本地模型
3. 引擎选 llama.cpp → 选择刚才放好的 GGUF 文件
4. 测试连接，返回正常回复就通了

> [!NOTE]
> 内存紧张的设备优先选 Q4 量化档位（比 Q8 省约 75% 内存）。4GB 内存的手机建议只用 1.5B 以下的模型，6GB 内存的最多尝试 7B Q4 档。

## 📖 日常使用深度指南

Operit 的能力覆盖面很广，下面从几个高频场景切入，带你上手核心玩法。

### Artifact 市场：一键生成项目与文档

Artifact 是 Operit v1.11 引入的核心概念，和 Skill/MCP 的「能力」不同——Artifact 是**能力的产出物模板**或**预设工作流**。打个比方：MCP 是螺丝刀（原子工具），Skill 是家具组装流程（多步组合），Artifact 就是一套家具图纸（可复用的成品模板）。

**市场里有什么**：
- **项目脚手架**：FastAPI + SQLAlchemy 的 Python API 项目、Express + TypeScript 的 Node REST API、Cobra + Viper 的 Go CLI 工具，一键生成目录结构和基础代码
- **文档模板**：技术博客标准章节、PRD 产品需求模板、读 Git 仓库自动生成 README、OpenAPI/Swagger 格式自动生成
- **代码片段库**：pandas/numpy 常用数据处理、SQL 多表 JOIN 和窗口函数模板、正则表达式集合、Shell 运维脚本
- **预设工作流**：搜索 → 整理 → 绘图 → TTS → 归档的内容流水线、Git diff → 自动审查 → 生成 commit message 的代码提交流程

**使用方式**：对话里直接提需求就行，Agent 会自动匹配对应 Artifact。或者手动打开统一市场浏览分类、点选模板、指定输出目录一键生成。Artifact 还能被 Skill 引用——比如「深度检索」Skill 执行完检索后，会自动用「技术博客」Artifact 模板输出，一步到位生成规范的报告文档结构。

### 内置工具箱：不依赖外部服务的原生能力

Operit 主界面侧栏有个工具箱入口，里面的工具**不需要装任何外部 MCP 或 Skill**，装好即用，稳定性最好。

常用的工具有：
- **命令终端**：内置 chroot Ubuntu 环境，可以在对话里直接跑 `apt update`、写 Python 脚本、装 git/curl
- **文件管理**：直接读写 Android 存储和 chroot 文件系统，批量扫描大文件、跨目录复制
- **格式转换**：PNG 压缩、WebP 转 JPG、Markdown 转 HTML，不依赖 ffmpeg 或 ImageMagick
- **应用权限管理**：列出不用的 App 建议卸载、调试档配合 Shizuku 锁应用防止刷短视频
- **截图与屏幕操作**：触发无障碍服务截图、返回键/Home 键模拟、读取屏幕分辨率和旋转方向
- **剪贴板与通知**：读写剪贴板内容、读取系统通知列表、发送自定义通知

> [!TIP]
> 能用内置工具箱解决的问题就别上 MCP——不依赖外部 Server，稳定且零配置。只有需要访问外部服务（搜索引擎、代码仓库 API、云存储）时才考虑加 MCP Server。

### UI 自动化：让 AI 替你操作手机

这是 Operit 最吸引人也最容易出问题的功能。理想状态下你说「回到桌面，打开设置 App」它就能替你做，但实际使用中经常遇到「点不动」的情况。

**排查步骤**：

1. **确认无障碍服务真的开了**——别信 Operit 内部的状态提示，直接进系统设置 → 无障碍，找到 Operit 对应的服务开关，确认是 ON 状态
2. **先测试最简单的操作**——让它「回到手机桌面，然后打开设置 App」，如果这都不行说明无障碍通道本身有问题
3. **看目标 App 的 UI 特性**——微信聊天界面是 Canvas + 原生控件混合渲染、浏览器几乎全是 WebView、游戏界面完全是 SurfaceView 绘制，这些场景 UI Tree 拿不到完整元素，需要靠 AutoGLM 视觉路径辅助定位
4. **让 Operit 截图诊断**——说「先截一张当前屏幕图，然后告诉我界面上都有哪些元素」，它会截图 + dump UI Tree + 做视觉分析，能直接告诉你界面上到底暴露了哪些节点
5. **检查 Hook Runner**——默认会拦截危险操作，但也可能误伤正常 UI 自动化，临时关掉再试
6. **注意系统级限制**——Android 11+ 后台启动限制、MIUI/EMUI 的后台策略、屏幕锁定状态、省电模式，都可能导致 UI 自动化失效

一个实用技巧：失败时让 Operit 自己截图分析，而不是你去猜它为什么点不动——它的视觉识别比你想象的靠谱。

### 本地模型 vs 云端 API 怎么选

| 维度 | 本地模型（llama.cpp + GGUF） | 云端 API |
|---|---|---|
| 隐私 | 数据不出设备 | 发送到第三方服务器 |
| 成本 | 免费（电费除外） | 按 token 计费 |
| 速度 | 取决于硬件（骁龙 8 Gen 2 跑 7B Q4 约 5-12 tok/s） | 稳定快速 |
| 质量 | 7B Q4 够用但比 70B 差 | 旗舰级模型质量最高 |
| 离线 | 完全支持 | 需要网络 |

实操建议：先用本地 Qwen2.5-1.5B-Q4 跑通整个流程，够用再升级到 7B 级别。需要高质量推理时临时切云端 API。
