## ✨ WebTools 是什么

WebTools 是一款面向移动设备的网络运维工具箱，把平时在电脑上才能用的远程文件管理、SSH 终端、网络测速、端口检测等功能全部搬上了手机。对运维人员、站长、开发者来说，这意味着出差在外、地铁通勤时，掏出手机就能 SSH 登服务器、改 Nginx 配置、测一下当前网络能不能通 22 端口——不用背着电脑跑。

它的核心能力可以归为四大类：远程文件传输（FTP/SFTP 管理器）、服务器交互（SSH 终端、Telnet 终端）、网络诊断（测速、Ping、Telnet 端口检测、HTTP 请求测试）、代码与配置编辑（内置代码编辑器直接修改服务器上的配置文件）。所有功能围绕「移动端运维」这个场景设计——操作界面是触屏友好的，反馈是即时的，不需要外接键盘鼠标也能完成绝大多数日常运维任务。

如果你是一个经常需要远程管理服务器的人，WebTools 能显著降低你的响应门槛：网站挂了、SSH 连不上、想临时改个配置 reload 一下，这些紧急场景不需要等回到电脑前才能处理。

## 🔧 安装与初始化

WebTools 是 Android 平台应用，安装过程和一般的 Android App 没什么区别。下面说几个需要注意的点，避免第一次装完就踩坑。

### 安装包获取与校验

从下载页拿到 APK 文件后，安装前建议核对两件事：**版本号**和**文件大小**。下载页通常会标注最新版本号，拿到的 APK 文件名如果带版本号，对照一下是否一致。文件大小方面，不同版本差异不大，如果明显偏小或偏大，很可能下载不完整或拿到了非官方修改版。

> [!WARNING]
> 不要随意安装来源不明的 APK。非官方修改版可能植入广告或恶意代码，运维类应用涉及服务器登录凭证，安全性优先。

### 未知来源授权

如果是从 APK 直接安装（不是通过应用商店），Android 会提示「未知来源」。不同系统版本的授权路径略有差异，通常在「设置 → 安全 → 安装未知应用」里找到你用的文件管理器，打开允许安装的开关即可。装完后建议关掉这个开关，保持系统安全。

### 首次启动：给足必要权限

第一次打开 WebTools 时，系统会请求存储权限等基础授权，全部允许即可。这些权限用于：访问本地存储里的密钥文件、保存连接配置、导出诊断日志。不给权限的话，SFTP 连接保存密钥、文件上传下载这些核心功能都会受限。

## 📖 核心功能与使用入门

这部分把四个高频场景串起来讲：远程文件管理、网络诊断测速、Telnet 端口检测、手机上改服务器配置。每个场景都从「遇到什么问题 → 怎么在 WebTools 里操作」来展开。

### 远程目录浏览与文件操作（FTP / SFTP）

连好 FTP 或 SFTP 服务器后，WebTools 会直接进入远程目录视图。每一行显示文件名、大小、修改时间，点文件夹进去、左上角返回上一级。日常操作都能在触屏上完成：

**目录导航**：路径栏可以直接点，跳到根目录或中间任意一级，不用一层层返回。默认按名称排序，点排序按钮可以切换到按大小或按时间排序。以 `.` 开头的隐藏文件默认不显示——运维场景经常需要看到 `.htaccess`、`.gitignore` 这类文件，可以在设置里打开隐藏文件显示。

**创建与重命名**：在目标文件夹点「+」按钮就能新建子目录，输入名字确认即可。重命名需要先长按文件或文件夹，弹出菜单后选择「重命名」。注意 WebTools 的重命名不能跨越文件系统边界——就是说不能同时改名字又挪到另一个目录，那得分两步：先重命名，再移动。

**移动、复制、删除**：长按选中文件后，菜单里有「剪切」「复制」「删除」。剪切或复制后导航到目标目录，执行粘贴就完成了。删除会弹二次确认，而且不可恢复——SFTP 连接下删的文件不会进回收站，删之前一定要想清楚。

**文件权限**：SFTP 连接时，部分服务器会显示文件权限（比如 `-rw-r--r--`）。WebTools 能看到权限信息，但**不能在移动端直接改**——改权限得进 SSH 终端执行 `chmod` 命令。

### 网络测速：运维前先摸清楚链路质量

测速功能不只是个「测网速」的玩具，对远程运维来说，它是每次登服务器前的预检步骤。

操作很简单：确保手机连到你要测的网络（Wi-Fi 或移动数据），打开测速功能，点「开始测试」。大约 30 秒后给出三个核心指标：

| 指标 | 含义 | 运维参考 |
| --- | --- | --- |
| 下载速率 | 服务器到手机的传输速度 | 100 Mbps 以上流畅，30 Mbps 以下文件传体会慢 |
| 上传速率 | 手机到服务器的传输速度 | 一般是下载的 1/4 ~ 1/10，上传大文件时心里有数 |
| 延迟（Ping） | 网络往返时间 | <50ms 优秀，50~150ms 一般，>200ms 不适合跑 SSH |

测速能帮你做两件事。第一，**远程运维前先测一下延迟**——如果当前网络延迟超过 200ms，SSH 终端的输入会明显卡顿，长命令输起来会想砸手机。第二，**对比不同网络**——同一个服务器，Wi-Fi 和移动数据哪个连上去更顺畅，测一次就有底了。SSH 连不上但 HTTP 还能通？测速看看是不是带宽耗尽导致丢包严重。

> [!TIP]
> 测速过程中别同时跑视频下载、在线视频这类吃带宽的应用，不然结果不准。移动数据下测一次大概消耗 50MB 左右，注意套餐余量。

### Telnet 端口检测：Ping 能通不代表服务在线

这是运维排查里最被低估的一个小功能。Ping 只能告诉你「服务器还活着」，但服务器活着不代表 SSH 服务没挂、不代表 22 端口没被防火墙封。Telnet 测的是**具体端口**，比 Ping 精确得多。

在 WebTools 的网络诊断里选 Telnet 测试，输入 IP 和端口，瞬间返回三种结果之一：

| 结果 | 排查方向 |
| --- | --- |
| 连接成功 | 端口开放、服务在监听，可以直接用 SSH 连 |
| 连接拒绝 | 服务器到达了但没人监听——服务没启动，或者端口配错了 |
| 连接超时 | 请求发出去没回应——中间有防火墙封了端口，或者 IP 本身错了 |

常见的排查场景：

- **SSH 连不上但 Ping 正常**：Telnet 测 22 端口如果超时，十有八九是安全组没放行 22，或者 SSH 服务挂了。
- **HTTP 请求超时但 Telnet 443 能通**：端口是通的，问题在 HTTP 请求本身——Host 头不对？TLS 握手失败？请求体过大？

常用端口对照一下，运维场景里测这几个基本够用：

| 端口 | 服务 |
| --- | --- |
| 22 | SSH / SFTP |
| 80 | HTTP |
| 443 | HTTPS |
| 3306 | MySQL |
| 6379 | Redis |

### 手机上改服务器配置：两分钟搞定线上紧急修复

运维里经常遇到这种情况：网站突然打不开了，SSH 登上去看日志发现 Nginx 某个配置参数写错了。如果你不在电脑前，WebTools 能让你在手机上完成修改→保存→reload 的全流程，两分钟搞定。

操作路径：用 SFTP 连接服务器，导航到配置文件所在目录（比如 `/etc/nginx/sites-available/`），长按文件选「编辑」。内置代码编辑器支持语法高亮，改完保存，然后切到 SSH 终端执行 `nginx -t && nginx -s reload` 就生效了。

PHP 配置修改类似，改完需要重启对应的 PHP-FPM 服务（`systemctl restart php8.x-fpm`）。定时任务（crontab）的修改也能在 SSH 终端里直接用 `crontab -e` 打开编辑器操作。

> [!WARNING]
> 修改配置前**一定要先备份**。在 SSH 终端里执行 `cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak`，改错了随时 `mv` 回来。改完**一定要跑语法检查**——Nginx 用 `nginx -t`，PHP 用 `php -l`，Apache 用 `apache2ctl configtest`。跳过这一步，配置写错了 reload 之后服务直接挂掉。

改完之后如果不生效，排查三个点：有没有改对文件（有些服务有主配置和站点配置两层）、有没有重启服务（部分配置光 reload 不够，必须硬重启）、SFTP 用户有没有写 `/etc/` 下文件的权限——权限不够的话换 SSH 终端提权再改。
