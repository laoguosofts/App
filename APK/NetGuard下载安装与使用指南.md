## ✨ NetGuard 是什么：Android 上最安静的无 Root 防火墙

NetGuard 是一款面向 Android 平台的网络防火墙工具，它通过创建本地 VPN 隧道的方式拦截和管理应用联网行为，**不需要 Root 权限**即可运行。这是它与同类工具（如 AFWall+、NetGuard 旧版）最核心的区别——后者通常要求设备已获取 Root 权限才能在 IP 层做精准拦截。

NetGuard 的核心理念很朴素：**每个应用独立控制 Wi-Fi 和移动数据两套联网开关**，不搞全局一刀切。你可以让视频 App 只在 Wi-Fi 下联网、让即时通讯仅蜂窝环境允许、让纯离线应用彻底断网。这种精细管控对于节省蜂窝流量、限制后台偷跑、隔离隐私敏感应用都非常有效。

在功能覆盖上，免费版已经足够应付绝大多数日常场景——应用级联网开关、黑白名单模式、亮屏/漫游/锁屏等状态条件叠加、自定义 DNS 服务器、IPv4/IPv6 双栈、TCP/UDP/ICMP 协议管理、Hosts 文件广告拦截（GitHub 渠道版），这些都是开箱即用的。Pro 付费版在此基础上增加了全球流量日志、地址级精细拦截、PCAP 导出、状态栏网速曲线等进阶能力，但对普通用户而言并非必需。

需要注意的是，NetGuard **不是 VPN 或代理**——它不会加密你的流量、不会隐藏你的 IP、不会处理入站连接。它的定位就是一个安静的守门人：判断每个出站连接该不该放行，仅此而已。开发者在 FAQ 里明确说过，不做流量加密是为了保持简洁和电池效率，如果你需要匿名上网能力，那得找真正的 VPN 工具。

适用人群非常广：蜂窝流量紧张想省着用的用户、对应用隐私行为敏感的隐私控、想给孩子设备做联网限制的家长、需要隔离某些广告 SDK 后台偷跑的重度玩家——只要你想对设备联网行为有主动权，NetGuard 都值得试。

## 🔧 安装步骤：Android 应用的常规安装流程

NetGuard 的安装和大多数 Android 应用没什么区别，但有几个细节值得留意。

### 前置条件

- Android 5.0（Lollipop）及以上系统——VPN 隧道机制从这个版本开始稳定
- **不需要 Root 权限**——这是 NetGuard 的核心卖点，全程通过 VPN 方式实现拦截
- 存储空间预留至少 20MB

### 安装流程

1. **获取 APK 文件**：从下载页拿到 APK，或者直接从 Google Play 安装
2. **允许未知来源安装**：如果是手动安装 APK，需要进入「设置 → 安全 → 未知来源」（不同品牌手机路径略有差异，部分机型在「设置 → 应用与通知 → 特殊应用权限 → 安装未知应用」），给文件管理器或浏览器开启安装权限
3. **点击安装包安装**：一路点确定，安装完成后桌面上会出现 NetGuard 图标
4. **首次启动授予 VPN 权限**：打开 NetGuard，第一次点底部的启动开关时，系统会弹出 VPN 请求对话框——勾选「始终允许」（或类似选项），这样以后切换防火墙状态就不会每次都弹窗

> [!WARNING]
> **VPN 权限授予后勿擅自撤销**：如果你在系统设置的 VPN 页面手动断开或删除了 NetGuard 的 VPN 配置，防火墙会立即停止工作。正确的关闭方式是回到 NetGuard 应用内部、点底部的大开关切换。

### 验证安装

启动防火墙后，留意两个确认点：

1. **状态栏出现钥匙图标**：这是 Android 通知当前有活跃 VPN 的固定标识（NetGuard 用 VPN 隧道实现拦截，所以必然出现）
2. **NetGuard 主界面底部开关变成蓝色**：表示防火墙已激活
3. **在应用列表里随便点开一个应用**，看 Wi-Fi 或移动数据开关是否能正常点击切换

如果三个条件都满足，说明安装成功。

## 📖 使用入门：从应用管控到高级配置

NetGuard 的能力可以分成几个层次来理解——基础的应用级联网开关是立即可用的核心，黑白名单模式帮你减少配置工作量，状态条件让策略更灵活，高级选项则面向有特殊需求的进阶用户。

### 第一层：应用级联网管控——四种策略组合

NetGuard 每个应用都有**两套独立的联网开关**：一套控制 Wi-Fi，一套控制移动数据。两套开关可以自由组合出四种策略：

| 组合 | Wi-Fi | 移动数据 | 典型场景 |
|---|---|---|---|
| 全开 | ✅ | ✅ | 绝大多数应用默认 |
| 只 Wi-Fi | ✅ | ❌ | 视频、云同步、大下载：只在 Wi-Fi 下允许 |
| 只移动数据 | ❌ | ✅ | 即时通讯、在线地图：仅蜂窝允许 |
| 全关 | ❌ | ❌ | 不联网的单机应用，或想彻底切断的应用 |

实际操作时，在 NetGuard 主界面点击应用名称左侧的展开箭头，就能看到 Wi-Fi 和移动数据的红绿状态按钮——点一下切换一次。

一个实用建议：先进入「设置 → 默认」切换到**白名单模式**（Wi-Fi 和移动数据都默认勾选「Block」），让所有应用默认禁止联网，然后**逐个放行**你真正需要联网的应用。这比黑名单模式更省心——你不需要去想哪些应用需要拦，只需要想哪些需要放。放行时优先处理几个核心系统组件：Play Store（`com.android.vending`）、Play Services（`com.google.android.gms`）、下载管理器（`com.android.providers.downloads`），否则后续应用更新会出问题。

### 第二层：黑白名单模式——帮你设置「默认值」

黑白名单模式解决的是「配置工作量」的问题——设备上有 100+ 应用时，逐个点开关不现实。

**黑名单模式**（默认全允许）：适合大多数用户，只手动拦截少数有问题的应用。进入「设置 → 默认」，保持「Block Wi-Fi」和「Block mobile data」都不勾选，就是黑名单模式。

**白名单模式**（默认全拦截）：适合严格管控场景——家长给孩子设设备、隐私激进场景、公共 Wi-Fi 下临时保护。进入「设置 → 默认」，勾选两个「Block」开关即进入白名单模式。

> [!NOTE]
> **切换模式不会覆盖已手动配置的应用**——已经点开过 Wi-Fi 或移动数据开关的应用，其状态在模式切换后保持不变。你可以先在黑名单模式下拦截几个应用，再切换到白名单模式，那些手动设置过的应用不会被重置。

Wi-Fi 和移动数据**可以独立切模式**——比如 Wi-Fi 用白名单（默认全拦）、移动数据用黑名单（默认全允许），灵活度很高。

### 第三层：状态条件——让策略随场景自动变化

状态条件是叠加在黑白名单基础上的额外规则，让应用联网行为随设备状态自动调整：

- **亮屏时允许**：屏幕点亮时临时放开通关，熄屏后恢复拦截——适合那些想让它们在你看设备时联网、但后台静默时不想让它们偷跑的应用
- **漫游时禁止**：蜂窝漫游环境下额外追加拦截条件，防止漫游状态下的流量消耗
- **锁屏模式下允许**：配合一键锁屏模式使用——锁屏模式下几乎所有应用都被拦截，只有勾选了这个选项的应用保持联网

在应用详情面板里勾选对应条件即可，设置完自动生效，无需保存。启用了条件限制的应用，图标旁会出现小图标叠加（📱亮屏 / 🔒锁屏 / 🌐漫游），一眼就能看到哪些应用有条件规则。

### 第四层：自定义 DNS 服务器——摆脱运营商 DNS 控制

Android 默认使用运营商提供的 DNS，可能会记录你的查询历史、主动污染或屏蔽某些域名。NetGuard 允许你在**高级选项**里设置自定义 DNS 服务器来替换。

关键规则：**必须同时填两台 DNS 才会完全替换系统默认 DNS**。只填一台的话，这台 DNS 会与系统默认 DNS 一起使用（部分替换）。如果想彻底摆脱运营商 DNS 的控制，两台都要填。

推荐几个隐私友好的 DNS 服务：

| DNS 服务 | 主 DNS | 备用 DNS | 特点 |
|---|---|---|---|
| Cloudflare | 1.1.1.1 | 1.0.0.1 | 全球最快、隐私友好、不记录 |
| Quad9 | 9.9.9.9 | 149.112.112.112 | 安全 DNS（拦截恶意域名）、隐私友好 |
| Google | 8.8.8.8 | 8.8.4.4 | 速度快、稳定，但有隐私顾虑 |

> [!WARNING]
> **某些运营商存在 DNS 劫持**——无论你在 NetGuard 里填什么 DNS 地址，DNS 请求都会被强制重定向到运营商自己的 DNS。遇到这种情况，需要在**路由器管理页面**里设置自定义 DNS，路由器层面绕开劫持比 Android 层面更有效。

DNS 设置完后建议验证一下效果：Chrome 地址栏输入 `chrome://net-internals/#dns` 清除缓存，再访问 `dnsleaktest.com`，看返回的 DNS 服务器 IP 是否是你设置的那两台。

### 第五层：Hosts 文件广告拦截（GitHub/F-Droid 版专属）

GitHub 和 F-Droid 渠道的 NetGuard 版本支持 Hosts 广告拦截功能（Play 版因 Google 政策被禁止提供）。工作原理是加载公共 Hosts 拦截列表（如 StevenBlack 等），让包含广告域名的流量在 IP 层被拦截。

值得注意的是，NetGuard 与 Pi-hole 这类 DNS 级拦截器的实现方式不同：它**默认允许所有 DNS 请求通过**——DNS 查询完成、拿到域名到 IP 的映射后，再在 IP 层判断是否拦截。这样做的好处是不会因为 DNS 层面的拦截导致应用超时重试、电池消耗增加，但代价是 Hosts 拦截的精准度略低于 DNS 级方案。
