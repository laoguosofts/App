## ✨ NoteGen 是什么

NoteGen 是一款面向个人知识管理的本地优先笔记工具。它把传统笔记软件的基础能力（Markdown 写作、标签组织、多平台同步）和 AI 能力结合在一起——不是简单地套一个对话框，而是让 AI 真正参与到你的笔记工作流里：帮你检索自己写过的内容、记住你的偏好、甚至跨会话延续上下文。

从功能形态上看，NoteGen 既可以当作一个纯粹的 Markdown 编辑器来用，也可以一路往 AI 知识库、长期记忆助手的方向深入。对写作内容多、笔记散落在不同时期、经常需要回头翻看旧素材的人来说，它的价值比单纯记笔记要大——很多人用它来攒素材库、写项目文档、整理技术学习笔记，核心诉求都是"写了之后能找回来，找回来之后能用上"。

NoteGen 基于 Tauri 框架，桌面端覆盖 Windows、macOS 和 Linux，移动端也有配套版本。它的同步层是可插拔的，支持常见的云存储服务，笔记文件本身是标准的 Markdown——这一点很重要，意味着你写的内容不被任何厂商格式锁死，随时可以导出带走。

## 🔧 多平台安装指南

NoteGen 的桌面端在三大平台上的安装体验差异不大，但每个平台有一些值得注意的细节。

### Windows 安装

Windows 用户下载 `.exe` 安装包后双击运行即可。安装过程中注意两点：

1. **安装路径选择**：默认装在 `C:\Program Files`，如果习惯把应用放在非系统盘可以自定义。但不管装在哪里，应用数据目录会独立存放在用户文件夹下，重装应用不会丢笔记数据。
2. **杀毒软件误报**：Tauri 框架的应用偶发被部分国产杀毒软件误判——如果下载后被拦截，可以在杀毒软件里把安装包和安装目录加入信任，不是病毒。

> [!WARNING] 装完务必核对版本号
> 首次安装后打开应用，在设置或关于面板里确认版本号与下载页标的一致。NoteGen 升级偶尔涉及数据库迁移，用旧版本打开新版本数据可能出问题，首次安装就确认版本能避免后续踩坑。

### macOS 安装

macOS 提供 `.dmg` 安装包。打开 DMG 后把 NoteGen 图标拖进 Applications 文件夹即可。首次运行时如果系统提示"无法打开，因为 Apple 无法验证开发者"，右键点击应用图标选择"打开"，在弹出的二次确认对话框里再点一次"打开"就能绕过 Gatekeeper。

### Linux 安装

Linux 桌面端提供三种分发格式，覆盖主流发行版：

| 格式 | 适用发行版 | 安装方式 |
|---|---|---|
| AppImage | 通用，无需 root | 下载后 `chmod +x` 赋予执行权限，直接 `./NoteGen-xxx.AppImage` 运行 |
| Deb | Debian / Ubuntu / Mint 等 | `sudo apt install ./notegen_*.deb` |
| RPM | Fedora / RHEL / openSUSE 等 | `sudo dnf install ./notegen-*.rpm` |

AppImage 最省心，不需要 root 权限，数据目录会创建在 `$HOME/.local/share/NoteGen`。想在系统菜单里看到图标，可以配合 AppImageLauncher 或者手动写一个 `.desktop` 文件。

> [!NOTE] Wayland 用户注意
> 在 Wayland 会话中，Tauri 应用的截图记录功能可能无法框选全屏窗口。这是 Tauri 框架对 Wayland 截图 API 支持还不完善导致的，临时方案是切换到 X11 会话使用。

### 依赖缺失的补救

NoteGen 基于 Tauri 2，绝大部分运行时依赖已经打包进安装包。如果 Linux 上运行时弹 WebKit 相关库缺失的错误，可以手动补：

- Ubuntu/Debian：`sudo apt install libwebkit2gtk-4.1-0`
- Fedora：`sudo dnf install webkit2gtk4.1`

## 📖 核心功能使用入门

这部分从四个维度展开：本地备份策略、知识库 RAG 检索、长期记忆机制，以及 Linux 平台的安装细节——覆盖了从基础防护到高级 AI 能力的完整链路。

### 本地备份：别把云同步当备份

很多人有一个误区：开了云同步就等于有备份了。实际上云同步和备份是两回事——远程删除会同步到所有设备，Token 泄露可能导致数据被清空，同步冲突处理不当也可能丢数据。本地 ZIP 备份才是独立于云同步的真正保险。

**手动导出**很简单：打开标题栏的同步状态菜单，选择"本地备份（全部）"里的导出操作，指定保存位置就行。备份包里包含应用数据库（记录、标签、聊天、画布等结构化数据）、配置文件，以及默认工作区中的文件。

> [!TIP] 自定义工作区要额外处理
> 如果你用了非默认路径的自定义工作区，备份 ZIP 不会自动包含那边的 `.md` 文件，需要手动把整个工作区目录复制出来。这一点很容易被忽略，切换工作区之前一定要记得。

自动备份在设置面板里配置：启用开关、设置频率（每天或每周）、保留快照数量（防止备份无限增长塞满磁盘）、指定备份目录。日常使用推荐每周自动备份加定期抽查备份能否正常打开——别等出事了才发现备份已经坏了。

**恢复的风险比导出大**——恢复会覆盖当前应用数据，而且 NoteGen 升级可能涉及数据库迁移，用旧版备份恢复到新版应用或者反过来都可能出问题。恢复前务必做两件事：先手动导出一份当前状态（万一恢复不是你想要的版本还能回滚），确认 ZIP 是 NoteGen 自己导出的（不要导入来源不明的文件）。

不同场景下的推荐策略：

| 场景 | 建议 |
|---|---|
| 日常使用 | 每周自动备份 + 定期抽查 |
| 重大版本升级前 | 手动导出一份 + 等同步完成再升级 |
| 切换工作区 | ZIP 导出 + 手动复制工作区目录 |
| 处理同步冲突前 | 先导出 ZIP（冲突处理是高风险操作） |
| 重要项目收尾 | 手动导出归档一份 |

最后一条底线：至少一份备份保存在**完全独立的存储设备**上——另一块硬盘、U 盘、或者不同于同步服务的外部云盘。只保存在当前电脑上，电脑坏了备份也没了。

### 知识库 RAG：让 AI 引用你的笔记

知识库 RAG（Retrieval-Augmented Generation，检索增强生成）是 NoteGen AI 能力的核心。它解决的问题是：你写了几百上千篇笔记，AI 对话时怎么让它**引用你自己的真实素材**而不是凭常识瞎编？

整个流程分四步：

1. 定期把你的 Markdown 笔记做向量化索引
2. AI 对话时，先在向量索引中检索和问题最相关的笔记片段
3. 把检索到的片段连同问题一起发给 AI 模型
4. AI 基于你的真实笔记内容生成回答

索引构建在后台自动进行——读取工作区所有 `.md` 文件，用嵌入模型把每段文字转为向量，保存到本地向量数据库，文件变更时做增量更新。嵌入模型可以用你配置的模型平台的嵌入 API，也可以用本地嵌入模型（比如 Ollama 的 `nomic-embed-text`）。

启用知识库开关后，每次 AI 对话都会自动检索相关片段作为上下文的一部分。你可以进一步限制检索范围——只搜特定文件夹、特定标签的笔记，或者调整返回片段数量和相似度阈值来平衡精度和召回率。

> [!NOTE] 检索不到内容怎么办
> AI 说"没找到相关内容"时，先排查四个原因：知识库索引还没构建完（看设置里的状态）、你的笔记里确实没写过相关内容、检索阈值设得太高、嵌入模型不适合你的笔记语言/领域。对应动作：等索引完成、手动触发重新索引、降低阈值、换更好的嵌入模型。

在笔记量很大、向量检索结果不够精准时，可以开启**重排模型（reranker）**——先用向量检索返回一批候选片段，重排模型对候选片段做更精确的相关性打分，重新排序后再发给对话模型。这一步能显著提升检索质量，尤其是在笔记量积累到一定规模之后。

和网络搜索相比，本地知识库在隐私、时效性和检索成本上都有明显优势：

| 维度 | 本地知识库 | 网络搜索 |
|---|---|---|
| 数据源 | 你的笔记 | 公开网页 |
| 隐私 | 100% 本地 | 会发送搜索词给模型 |
| 时效性 | 实时同步你的笔记 | 搜到的内容可能过时 |
| 检索成本 | 一次性索引后很快 | 每次都要联网 |

两者不是互斥的——网络搜索适合查外部最新信息，知识库适合挖自己的积累。

### 长期记忆：让 AI 跨会话"记住你"

知识库解决的是"AI 能引用你的笔记"，长期记忆解决的是"AI 能记住关于你的信息"。每次开新对话时，AI 会自动检索相关记忆，不用你每次重新自我介绍。

记忆分两种类型：

| 类型 | 举例 |
|---|---|
| 偏好 | "用户喜欢用中文回复"、"偏好简洁风格" |
| 事实 | "用户正在学习 Rust"、"做过 React 性能优化项目" |

记忆的来源有三个渠道：AI 在对话过程中自动提取（识别你表达的偏好或事实，主动存入）、在记忆管理面板手动添加、定期让 AI 扫描历史对话总结沉淀。

检索是语义匹配而非关键词匹配——你问"帮我整理一下这周的笔记"，AI 可能同时检索到"用户偏好简洁风格"（影响输出风格）、"用户主要在 Python 和 AI 方面做记录"（影响整理关注点）、"用户做过 React 性能优化项目"（如果这周有相关记录的话）。

> [!TIP] 定期清理过时记忆
> 记忆会积累，过时的条目（比如一年前的技术栈偏好）会干扰 AI 回答。建议在设置 → 长期记忆面板里定期检查，删掉过期或错误的，手动补充新的。

长期记忆和知识库 RAG 容易混淆，但职责完全不同：

| 维度 | 长期记忆 | 知识库 RAG |
|---|---|---|
| 存什么 | 关于你的偏好和事实 | 你写的笔记内容 |
| 来源 | AI 从对话提取或手动添加 | 从 `.md` 文件自动构建 |
| 用途 | 让 AI 更"懂你" | 让 AI 能"引用你的素材" |
| 生命周期 | 可能过时需要清理 | 自动增量更新 |

两者互补——记忆帮 AI 理解你这个人，知识库帮 AI 用上你写的东西。

隐私方面，记忆数据默认保存在本地应用数据目录。启用云同步后会随其他数据一起同步。敏感偏好建议保持同步，个人事实（比如住址、收入等）建议只存本地不同步。
