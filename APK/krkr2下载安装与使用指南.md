## ✨ 吉里吉里2 是什么

吉里吉里2（Kirikiri 2，常被爱好者简称 krkr2）是一款老牌的视觉小说/AVG 游戏引擎。它以轻量、灵活和完全脚本化的开发方式著称，让独立开发者和同人社团能够用 KAG 标签语言配合 TJS2 脚本快速搭建完整的互动叙事作品。

与 Unity、RPG Maker 等通用引擎不同，吉里吉里2 专注于 2D 叙事场景——立绘切换、背景渐变、剧情分支、选项系统、存档管理这些核心功能开箱即用，开发者的精力主要集中在故事内容和美术素材上，而不是折腾引擎底层。

引擎在日本同人圈有非常深的根基，大量商业 AVG（包括 Key 社部分作品）也使用过这个框架。国内玩家接触吉里吉里2 主要有两种场景：一是作为开发者自己做游戏，二是通过 Kirikiroid2 这款 Android 模拟器在手机上体验各种经典作品。

对于想入门 AVG 开发的新手来说，吉里吉里2 的学习曲线非常友好——KAG 标签用类似 HTML 的方括号语法，上手几乎没门槛；需要复杂逻辑时还有 TJS2 脚本层兜底，功能上限远超标签语言的表面能力。

## 🔧 安装指南

吉里吉里2 的安装分两种情况：作为开发者在 PC 上搭建开发环境，或者作为玩家在手机上安装 Kirikiroid2 模拟器体验游戏。两者的安装方式完全不同，这里分别说明。

### PC 开发环境安装

1. 从上面的下载页获取吉里吉里2 SDK 压缩包，解压到任意目录（推荐路径不含中文和空格，避免某些工具链出问题）。SDK 内部已经包含了引擎本体、开发工具和示例工程。
2. 找到 `krkr.exe` 或 `krkr64.exe`，这就是引擎的可执行文件。Windows 平台建议优先使用 64 位版本，内存上限更高。
3. 把 SDK 自带的示例工程目录（通常在 `sample/` 或 `test/` 下）直接拖到 `krkr.exe` 上测试引擎是否正常启动。如果能看到标题画面并正常点击推进，说明安装没问题。
4. 如果直接双击 `krkr.exe` 没有反应，通常是缺少 VC++ 运行时库。去微软官网下载并安装最新的 Visual C++ Redistributable 就能解决。

> [!WARNING] 版本核对
> 不同年代的吉里吉里2 游戏对引擎版本有要求。2010 年后的作品普遍需要 krkr2.24 或更高版本；如果启动后文字乱码或选项按钮不显示，大概率是引擎版本太低。

### Android Kirikiroid2 安装

1. 下载 Kirikiroid2 APK，由于是第三方模拟器，安装前需要在系统设置里开启「允许未知来源」。
2. 安装完成后，模拟器本体不自带任何游戏——你需要自己准备好 XP3 格式的游戏资源包。
3. 把游戏的 `data.xp3`（或多个 XP3 文件）拷到手机存储的 `Android/data/org.tvp.kirikiri2/` 目录下，模拟器启动时会自动扫描并列出可用的游戏。
4. 如果游戏需要额外的插件（如 Live2D 支持），Kirikiroid2 只有硬编码内置的插件，第三方 `.tpm` 插件无法在模拟器上直接加载——这一点在「插件扩展」部分会详细展开。

## 📖 使用入门

吉里吉里2 的核心设计是**标签驱动 + 脚本兜底**的双层架构。绝大多数剧情开发用 KAG 标签语言就能完成，遇到复杂逻辑时再下沉到 TJS2 脚本层。下面从三个维度带你入门。

### KAG 标签：剧情开发的主力工具

KAG（Kirikiri Adventure Game）标签语言用方括号语法，上手非常直观。一段典型的剧情脚本看起来是这样的：

```
; 注释用分号开头
主角：今天天气真好。
[click]

; 切换背景图
[bg storage="image/bg/school.tlg" time=500]
; 显示角色立绘
[chara storage="image/chara/hero.png" position="left"]

; 选项分支
[select]
[goto target="branch_a" text="去找她"]
[goto target="branch_b" text="继续工作"]
[selectcancel]
```

选项分支是 AVG 的灵魂。用 `[select]` 包裹一组 `[goto]` 就能实现玩家选择——点击不同选项跳转到剧情的不同分支点。跳转目标用 `@标签` 在 scenario 文件里标记，引擎遇到 `[goto]` 会自动定位过去。

这里有个容易混淆的细节：`jump` 和 `call` 都能跳转，但行为完全不同。`jump` 是**一去不回**，跳过去就停在那里；`call` 是**调用子流程**，执行完遇到 `[return]` 会回到原地继续。公共逻辑（比如播放一段 CG、切换 BGM）应该用 `call` 抽成可复用的子流程，而剧情分支才用 `jump`。

### 变量与条件控制

游戏的数值逻辑（好感度、属性、收集品）全部用变量承载。KAG 里可以直接用 `[set]` 设置、`[eval]` 输出、`[if]` 判断：

```
; 设置变量
[set variable="affection" value=0]

; 选项影响变量值
[select]
[goto target="good_ending" text="主动搭话"]
[goto target="normal_ending" text="擦肩而过"]

; 判断条件
[if exp="affection >= 5"]
她抬起头笑了一下，夕阳在她脸上镀了一层金边。
[else]
走廊里只剩下脚步声，没有回头。
[endif]
```

变量的作用域需要特别注意：KAG 用 `[set]` 设置的变量是**全局**的，跨 scenario 文件也能访问，存档时会自动保存。而 TJS2 里用 `var` 声明的是局部变量，KAG 标签层读不到。两种变量不要混用。

### TJS2 脚本：突破 KAG 的能力边界

KAG 标签覆盖了约 80% 的常用场景。当你需要精确控制图层、动态生成图片、同时播放多层 BGM、或者检测用户输入时，就需要在 TJS2 里直接调用引擎原生类。

**图层操作**是最高频的原生类调用。吉里吉里2 的视觉层全部由 `Layer` 类管理——背景图、角色立绘、文字框、特效层，每一层都是独立的 Layer 对象。你可以获取活动图层、创建自定义图层、设置位置/透明度、甚至用 `moveTo()` 做平滑移动动画：

```tjs
// 获取背景图层
var bgLayer = Layer.get(0);
// 移动到指定位置并淡入
bgLayer.moveTo(500, 300, 1000);  // 1000ms 内移动完成
bgLayer.fadeIn(500);
```

音频方面，`Wave` 类提供了 BGM、SE、语音三类独立通道的播放控制。一个比较实用的高级技巧是**双 BGM 混音**：吉里吉里2 支持同时播放两个 BGM 通道，主 BGM 在通道 0，环境音效或低音量旋律在通道 1，各自独立控制音量，能做出很有层次感的氛围。

### 打包发布：从开发到玩家手中

开发完成后，散落的 scenario/、image/、sound/ 目录直接发给玩家既不方便也不安全。吉里吉里2 官方提供了 Releaser 打包工具，把所有资源打成 XP3 归档，或者直接合成 PEXP3 单文件 EXE。

XP3 格式是推荐的分发方式——体积紧凑、可以和引擎本体分开，也方便 Kirikiroid2 在手机上加载。PEXP3 把引擎 + 资源合成一个 EXE，分发最省心（玩家拿到双击即玩），但代价是 EXE 体积大、部分杀毒软件会误报、且 Kirikiroid2 无法加载。

> [!TIP] 分法选择
> 想同时支持 PC 和手机玩家，最稳妥的做法是：PC 端用 PEXP3 单文件分发，另外单独上传 XP3 资源包给模拟器玩家。

打包前务必做一次完整检查：用新打的 XP3 在干净的 krkr.exe 上完整跑一遍从标题到结局的流程，存档读档、选项分支、CG 回放全部测过。很多路径问题（比如文件名大小写、相对路径层级）只有在打包后才会暴露出来。

### 插件扩展：引擎能力的无限延伸

吉里吉里2 的插件系统是其可扩展性的核心。引擎在 startup.tjs 之前扫描 `plugins/` 目录下所有 `.tpm` 文件并自动加载——这意味着插件注册的类在 startup.tjs 里就能直接调用。

社区主流插件覆盖了几个高频需求：

| 类型 | 功能 | 例子 |
| --- | --- | --- |
| 图形增强 | Live2D、PSD/PSB 分层动画、3D | Live2D Cubism Plugin |
| 音频扩展 | 更高版本的编解码器、位置音频 | oggdec.tpm |
| 网络 | HTTP 请求、WebSocket、在线存档 | net.tpm |
| 加密 | 存档加密、资源保护 | 商业游戏常用 |

插件的安全边界需要注意——它和引擎在同一个进程运行，没有沙盒。第三方来源的插件理论上可以访问所有文件和内存，只信自己编译或社区长期验证的插件。

另一个常见陷阱是 **Kirikiroid2 的插件兼容性**：Android 模拟器只有硬编码内置的插件，社区主流的 Live2D、PSB 等插件在模拟器上直接不可用。如果要做跨平台项目，提前测试插件兼容性是必须的步骤。
