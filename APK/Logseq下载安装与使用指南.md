## ✨ Logseq 是什么

Logseq 是一款以**块式大纲**为核心的个人知识管理工具。与传统"一篇笔记一个文件"的文档中心思路不同，Logseq 把每条内容都拆成独立的**块（block）**——你可以在块级别引用、嵌入、拖拽、重组，而双向链接和块级反向引用让零散笔记自然形成一张可探索的知识网络。

2026 年初，Logseq 官方将产品拆分为两个独立版本：**Logseq OG**（传统文件式，Markdown/Org 纯文本）和 **Logseq DB**（新架构，图谱用 Datascript 数据库存储）。OG 版本的核心承诺是"你的笔记就是一堆 Markdown 文件，Logseq 只是更好用的界面"——数据完全自由，任何编辑器都能打开，Git 完美同步。DB 版本则聚焦大图谱性能、实时同步和协作编辑等进阶能力。

不管选哪个版本，双向链接、层级属性、白板画布这三个核心特性都是 Logseq 区别于其他笔记工具的辨识度所在。

## 🔧 安装步骤

### 版本选择先确认

下载前先决定你要的是 OG 还是 DB 版本，两者下载源不同：

| 版本 | 核心差异 | 下载位置 |
| --- | --- | --- |
| Logseq OG | 图谱由纯 Markdown/Org 文件组成，无数据库 | GitHub `logseq/og` Releases |
| Logseq DB | 图谱用 Datascript 数据库存储，支持实时同步和协作 | 官方主站 Releases |

> [!TIP]
> 如果你看重数据自由、已经有大量 Markdown 笔记、或者习惯用 Git 管理文件，直接选 OG 版本。它的文件结构透明可审计，不绑定任何服务器。

### 桌面端安装

以 OG 版本为例，Windows 平台安装流程：

1. 从 GitHub Releases 下载对应系统的安装包（`.exe` 或 `.zip`）
2. 运行安装程序，选择安装目录
3. 首次启动时，Logseq 会提示你选择一个**本地文件夹**作为图谱目录——这个文件夹就是你的所有笔记的存放位置
4. 选择已有 Markdown 文件夹可直接导入，也可以新建空目录从零开始

> [!NOTE]
> 这个图谱目录就是你的全部数据所在——删除它等于删除所有笔记。建议定期备份，或者直接把它放进 Git 仓库同步。

### 移动端安装

iOS 和 Android 都有原生 App，搜索时注意版本标识：带「OG」字样的是文件式版本，不带的是 DB 版本。首次打开同样需要指定或创建图谱目录。OG 版本移动端的同步能力相对有限，通常依赖 iCloud、Syncthing 等文件同步工具。

### 安装后快速核对

启动成功后，左侧页面树应该能看到默认生成的日记页和几个示例页面；打开任意页面，在任意位置输入 `[[` 后弹出自动补全菜单——这说明双向链接功能已就绪。

## 📖 核心功能上手

### 双向链接：Logseq 的灵魂特性

双向链接的核心逻辑非常简单——你在任何块里写 `[[页面名]]`，Logseq 会自动创建两个方向的引用：从当前块指向目标页面，同时目标页面反向收录这个引用。你不需要手动维护"谁引用了我"的列表，反向引用面板（默认在页面右侧）会实时列出所有块级引用了当前页面的来源。

```markdown
- 我在研究 [[分布式系统]]，特别是 [[CAP 定理]] 的应用
```

输入 `[[` 后 Logseq 会弹出自动补全菜单，输入几个字母就能过滤到已有页面；如果目标页面还不存在，回车会自动创建一个空白页面。两种创建方式效果一致，区别只是自动创建会在当前块留下链接，手动创建（左侧边栏 + 按钮或快捷键 `Cmd/Ctrl+N`）不会在任何块里留下痕迹。

反向引用面板是日常高频使用的工具——写完一篇新笔记后忘了之前在哪些地方提过它？右侧面板一眼看清；写某个主题时突然显示有 5 个块引用了它，说明这些块里可能有你需要的素材。当一个页面的反向引用超过 20 个，通常意味着这个主题值得独立成一个大的知识节点。

> [!NOTE]
> 如果你用过 Obsidian：两者双向链接语法基本一致，但 Logseq 的块级引用和嵌入是**默认就常用**的功能，而不是需要特意开启的高级玩法。

### 层级属性：一处修改，全局生效

假设你有 50 本书的笔记页面，每个都要手动设 `icon:: 📚`。后来想改成 📖，如果没有层级属性就要改 50 次。层级属性的解决思路是：定义一个类型页面，给它设好默认属性值，所有标记了这个类型的页面自动继承。

设置分三步：先创建一个类型页面（比如叫 `book`），在里面写好默认属性；然后在每个书的页面里加一行 `page-type:: book`；以后想改图标或其他属性，只需去类型页面改一处，所有同类型页面自动更新。

继承规则有三个要点：**本地优先**——页面显式设置的属性不会被类型覆盖；**多类型**——一个页面可以有多个 `page-type::`，按声明顺序依次继承；**内置可用**——Logseq 内置了一些类型的默认值（比如 `journals`），你可以覆盖。理论上任何属性都能继承，不限于 icon——项目类型可以继承默认状态、人物类型可以继承角色标签。

> [!TIP]
> 层级属性和命名空间（用 `/` 做物理分组，比如 `[[编程语言/JavaScript]]`）是两个独立机制。命名空间解决"页面放哪"的物理分组，page-type 解决"页面是什么"的属性继承。一个页面可以同时有两者。

### 白板画布：让知识从文本跳向空间

白板是 Logseq 最独特的集成能力之一——你可以从左侧页面树、右侧反向引用面板、甚至直接选中编辑器里的块，**拖拽**到白板变成嵌入。四个可拖拽来源：页面树拖整个页面、反向引用面板拖具体引用块、编辑器拖选中的块、本地文件拖 PNG/JPG/PDF/视频。

嵌入后的操作全部保留：拖拽移动位置、点击折叠子块、**双击在画布上直接编辑**（源页面同步更新）、右键跳转到源页面或删除嵌入（只删画布上的，源块不受影响）。除了拖拽，还可以用粘贴创建嵌入——复制 block-id 粘贴会变成块嵌入，复制页面名会变成页面嵌入，复制 YouTube URL 会自动变成可播放的视频对象。

一个典型场景是论文素材板：给每篇论文的核心论点建块、打上标签，打开白板在反向引用里搜索标签，把所有论点块拖到画布上，用形状分组、连接器画线。每个嵌入块的内容都和源页面双向同步——在任何地方更新论点，画布上自动更新。

Portal 连接器是白板工具栏里的进阶工具，可以让画布上的元素和知识库里的页面建立"门户"关系，点击连线快速跳转。

### 关于 OG 版本的文件结构

OG 版本的图谱目录全是纯文本，典型结构：日记页（按日期命名的 `.md` 文件）、主题页面（按主题命名的 `.md` 文件）、`logseq/` 元数据目录（配置文件）、`assets/` 资源目录。每个 `.md` 文件就是一个页面，页面名等于文件名。这种透明结构带来数据完全自由、Git 完美同步、不绑定 Logseq 的核心优势，但也意味着超过几千页后启动和搜索会明显变慢，实时协作和移动端体验相对有限。
