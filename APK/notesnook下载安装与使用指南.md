## ✨ Notesnook 是什么

Notesnook 是一款主打端到端加密的跨平台笔记应用，核心设计思路是让服务器只当密文仓库——从注册那一刻起，你的主密码只在本地设备上参与加密运算，服务器拿到的永远是无法解密的密文。它支持 Windows、macOS、Linux、Android、iOS 以及 Web 端，免费版不限笔记数量，对隐私敏感或需要多端同步的个人用户来说是一个够用的选择。

除了加密底色，Notesnook 的 Notebook 组织结构是另一大亮点：一条笔记可以同时被多个 Notebook 引用（不是复制粘贴，是链接），嵌套层级也不封顶，对于写小说、做知识库这类需要跨主题组织内容的场景尤其顺手。免费版 Notebook 上限 50 个，Essential 版 500 个，Pro 和 Believer 计划不限。

## 🔧 安装前的准备与注意事项

在动手装 Notesnook 之前，有几件事值得先了解一下，避免装完才发现某些功能和预期不符。

**主密码一旦设定，服务器端无法重置**。这是零知识加密架构的必然结果——服务器看不到你的密码，也就没法帮你找回。注册完成后立刻会生成一串 Recovery Key（恢复密钥），这是你忘记主密码时唯一能保住笔记数据的东西，保管方式后面会单独讲。

### 各平台安装要点

**Windows**：下载 `.exe` 安装包后双击运行，安装路径可以自定义。首次启动会弹防火墙请求，放行即可，Notesnook 需要访问网络来同步加密数据。部分杀毒软件可能对本地加密运算的文件读写行为报误报，添加信任就能解决。

**Android**：Google Play 直接装最省心。如果从官网下载 `.apk`，首次安装需要在系统设置里允许"未知来源"安装。安装完成后建议先确认系统权限——存储权限和网络权限是必需的，通知权限可选。

**macOS / Linux**：macOS 从 App Store 或官网 `.dmg` 安装；Linux 提供 `.deb` 和 `.AppImage` 两种分发格式，`.AppImage` 双击即用，不污染系统包管理。

> [!NOTE]
> 免费版不支持实时同步（Pro 及以上才有），免费版用户的同步是手动触发的——改完笔记后记得点一下侧栏的同步按钮，或者在设置里把同步频率调高点。

### 版本核对

装完打开应用，先进入 Settings → About 核对版本号和官网的最新版本一致。加密应用对版本迭代比较敏感，旧版本可能存在已知漏洞或同步兼容性问题。

## 📖 使用入门：从零开始的实战指南

### 核心组织结构：Notebook

Notebook 是 Notesnook 里装笔记的容器，和传统"文件夹"不同的是，**一条笔记可以同时归属于多个 Notebook**。这是链接引用，不是复制——编辑任何一处，所有 Notebook 里看到的都是最新版本。比如你在写一本小说，角色介绍笔记可以同时被"第一章"、"第三章"、"角色总表"三个 Notebook 引用，不用复制粘贴三遍。

**创建 Notebook 的操作路径**：侧栏顶部点 Notebook 图标 → 右上角加号 → 输入标题和描述。**嵌套子 Notebook** 用右键：右键任意 Notebook → 属性 → 添加 Notebook。

**把笔记链接到 Notebook**：桌面端和 Web 端右键笔记 → Notebooks → Link notebooks → 勾选目标 Notebook。移动端长按弹出同样的菜单。一次可以勾选多个，链接成功后列表视图底部会显示该笔记所属的 Notebook 路径，点击路径直接跳转。

**从 Notebook 里移除笔记**不是删除笔记本身——只是取消了这层引用。笔记还在，只是不再显示在这个 Notebook 下。要彻底删除得走 Move to trash。

### Recovery Key：和主密码同等重要的备用钥匙

注册 Notesnook 后立刻生成的那串长字符串就是 Recovery Key，它的作用是在你忘记主密码时，解开数据加密密钥的备用钥匙。加密架构里的逻辑是：数据加密密钥用主密钥（从密码派生）保护，Recovery Key 则是解开这层保护的第二把钥匙。

三种恢复路径的对比：

| 你手上有 | 恢复结果 |
|---|---|
| Recovery Key | 用旧密钥解开数据加密密钥 → 重新加密到新密码 → 全部数据保留 |
| 只有 `.nnbackupz` 备份文件 | 从备份恢复到备份时的状态 → 备份之后写的内容丢失 |
| 两者都没有 | 清空账户重置 → 所有笔记永久删除 |

Recovery Key 是唯一能让你在忘记密码后完整保留全部数据的方式。**推荐的保管方式**：放进密码管理器（Bitwarden、1Password、KeePass 都行），和主密码存在同一条记录里——下次打开密码管理器时两个一起看到，不会漏。多设备冗余存一份，再云同步。

> [!WARNING]
> Recovery Key 不要只写在纸上（会丢、会湿、会褪色），不要只存在另一个受密码保护的文档里（那个密码你也可能忘），更不要直接复制在 Notesnook 里——主密码和 Recovery Key 放在同一个加密容器里，篮子倒了一起丢。

Notesnook 允许你重置 Recovery Key，操作在 Settings → Account → Reset recovery key。重置后旧 key 立即失效，记得把新 key 同步更新到所有保管位置。

### 同步状态怎么看

侧栏底部有一个同步状态小圆点，颜色告诉你当前的同步情况：

- **绿色**：全部设备已同步，无挂起变更
- **黄色**：有冲突（两台设备同时离线编辑了同一条笔记），需要手动处理
- **灰色**：当前设备处于离线模式，所有变更暂存本地

点击小圆点可以展开详细同步日志，显示最近几次同步的时间、条目数量和耗时。

**同步延迟最常见的四个原因**：

1. **网络问题**：WiFi 切换、VPN 波动、移动网络从 4G 掉到 2G 都会导致同步挂起。验证方法：看小圆点颜色 → 完全退出 Notesnook 再打开 → 恢复了就是网络临时问题。
2. **冲突阻塞**：两台设备同时离线编辑同一条笔记后，同步时 Notesnook 会生成冲突副本而不是自动合并。这不是"同步失败"，但冲突副本持续出现在列表里会让你感觉"同步没搞定"，手动确认保留哪份或合并后冲突才解决。
3. **实时同步被关了**：Pro 计划用户可以在设置里关闭实时同步改成手动触发，如果发现改了东西没同步又查不到冲突，先去设置里确认实时同步开关。
4. **服务器负载**：罕见但可能，Notesnook 有公开状态页面可以查。

即使长时间离线，所有变更先在本地加密存储，恢复网络后自动上传，不会丢失。冲突时生成两份副本让你选择，不会自动覆盖。

### 恢复备份是覆盖操作——三明治治法防丢数据

Notesnook 的恢复备份（Restore backup）是**就地覆盖**，不是合并也不是追加。它选择覆盖而不是合并的理由很直白：笔记应用的数据结构层级化，两份独立版本历史的合并逻辑会迅速变成一个复杂的冲突解决系统，Notesnook 走了简单直接的覆盖方案。

恢复 `.nnbackupz` 文件的具体行为：

- **备份里有、你现在也有**的笔记 → 还原成备份时的版本（备份之后做的编辑没了）
- **备份里有、你现在没有**的笔记（你之后删了）→ 被带回来
- **备份里没有、你现在有**的笔记（备份后新建的）→ 保留，不会被删除

最后一点很关键——恢复不会删备份之后新建的笔记，但这些新笔记里**同时存在于备份里的旧版本**的编辑会被还原。

**如果你想从旧备份里找回某篇笔记但不想丢新内容**，用三步三明治法：

1. 先创建一份当前状态的新备份（Backup now → Create backup → 保存 `.nnbackupz`）
2. 恢复旧备份：Restore backup → 选择旧文件。此时备份之后新建的笔记还在（覆盖操作不删它们），旧笔记的旧版本也被带回来了
3. 取出你需要的旧内容：手动复制到安全位置
4. 恢复第一步的新备份：把整个数据恢复到恢复前的状态

这样哪个方向都不会丢。恢复前还要先检查回收站（恢复会把备份之后删除的笔记带回来），确认备份文件是你能接受的版本，并且**关闭所有其他设备的 Notesnook 客户端**——恢复期间其他设备的同步可能会干扰，客户端会把服务器上的恢复过程当作冲突处理。
