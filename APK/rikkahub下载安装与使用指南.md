## ✨ RikkaHub 是什么

RikkaHub 是一款面向 Android 设备的 AI 客户端，核心理念是"把控制权还给用户"。它不像各大厂商的官方 app 那样把模型身份、系统提示词、工作方式全部硬编码好——你可以自由切换模型、自定义助手、注入提示词规则，甚至让 AI 在手机里拥有一个完整的 Linux 环境来执行真实任务。

它的适用人群很广：需要同时使用多家厂商模型的开发者、想把 AI 真正接到自己手机上做数据处理的研究者、追求"AI 自由权"的重度爱好者、以及只是想要一个干净不花哨的 AI 聊天工具的普通用户。RikkaHub 不是"又一个聊天机器人"，它更像一个 AI 工作台——给你一张桌子，上面摆着各种工具，你自己决定怎么用。

几个独一份的特性值得一提：Agent 工作区是基于 proot 的完整 Linux 容器，不需要 root，AI 能在你的 Android 上克隆 Git、装 Python、跑脚本；快捷消息和正则转换器让高频操作一键化；Fork 对话分支让你从任意位置分叉做 A/B 测试，安全探索不同方向。这些功能在同类产品里很少见到，尤其是都集中在一个 Android app 里。

## 🔧 安装与初始化

RikkaHub 目前主要面向 Android 平台，安装过程与普通第三方 APK 类似，但有几个注意点需要留心。

### 基本安装步骤

1. 从下载页获取最新 APK 文件，确认文件大小与版本号匹配后再点击安装
2. 如果是首次安装第三方来源，系统会弹出"未知来源应用"提示——进入设置开启对当前文件管理器或浏览器的安装权限即可
3. 安装完成后首次打开，app 会引导你完成基础配置：选择语言、授权存储权限、创建或选择助手模板

> [!WARNING]
> **务必核对版本号**：下载页可能同时列出多个历史版本，优先选择带 "Latest" 或日期最新的那个。旧版可能缺少安全补丁或关键功能（比如 v2.5.6 修复了 Fork 对话标题序号重复叠加的问题）。

### 关于存储空间的一点提醒

普通安装只需要几十 MB，但如果你打算使用 Agent 工作区功能——那个在手机上跑的完整 Linux 容器——请预留至少几百 MB 的存储空间。Rootfs 本身加上后续安装的软件包（git、python、pandas 等）会逐渐占用空间。工作区的名字只能用英文，不支持中文路径。

### 模型与 API Key 配置

安装完成后，你需要在 **设置 → 模型管理** 里添加自己的 API Key。RikkaHub 不会内置任何厂商 API Key——这是"你拥有完全控制权"的另一层含义。支持的模型提供商包括 OpenAI、Anthropic、Google、以及多家第三方转发服务商。添加时填写 Base URL、API Key、可选的代理地址，保存后就能在对话里切换使用。

## 📖 功能与使用入门

RikkaHub 的功能面很广，这里挑几个最有代表性、日常使用频率最高的来展开。

### 快捷消息：把高频操作变成一键触发

快捷消息是 RikkaHub 最实用的效率功能之一。简单说，它就是你预先写好的提示词模板，在聊天工具栏里一键就能发出去。

创建流程很简单：**设置 → 快捷消息 → 新建**，填标题和内容即可。内容可以是任何提示词，比如"请总结上文，用要点列出，不超过 5 条"，或者"把上一段翻译成英文，保持专业术语不译"。创建好之后，在某个助手的 **扩展 → 快捷消息** 里勾选附加，这个模板就会出现在该助手的对话工具栏上。同一个快捷消息可以附加给多个助手，编辑一次全局生效。

这里容易混淆的三个概念帮你理清楚：

| 功能 | 触发方式 | 作用范围 |
|---|---|---|
| **快捷消息** | 手动点击 | 立即发送到当前对话 |
| **预设消息** | 每次新对话自动 | 在用户输入之前注入开头 |
| **模式注入** | 助手激活时始终 | 在系统提示词指定位置附加 |

一句话记忆：快捷消息手动触发、预设消息对话开头自动、模式注入始终在上下文中。三者可以配合使用，互不冲突。

### 正则表达式转换器：在发送前后清理和格式化

如果说快捷消息是"输入侧的自动化"，那正则转换器就是"显示侧的自动化"。它让你可以在消息**显示或发送之前**运行查找替换规则，用途包括清理模型输出里的冗余格式、重新格式化引用、或者在不影响模型实际看到的内容的前提下修改界面显示。

每条规则包含四个关键字段：查找模式（标准正则）、替换为（支持捕获组 `$1`）、作用范围（用户消息 / 助手消息 / 两者）、以及一个 RikkaHub 独有的"仅视觉"开关。

"仅视觉"这个设计特别巧妙——举个例子，模型输出里的 Markdown 语法标记（`**加粗**`）渲染器已经处理好了，但界面上你还是能看到原始标记。开启"仅视觉"后，模型仍然收到完整的原始内容正常处理，但用户界面显示的是清理后的干净结果。模型知道、你看不到，两全其美。

> [!TIP]
> **常用正则场景**：清理模型输出里重复的开头段（有些模型会重复用户的问题），或者统一不同模型的 Markdown 标题格式。建议先在单条消息上测试正则效果，再推广到整个助手。

### Agent 工作区：手机里的完整 Linux

这是 RikkaHub 最硬核的功能——基于 proot 在 Android 上跑一个完整的 Linux 容器，**不需要 root 权限**。proot 是用户态的 chroot 替代方案，每个工作区独立拥有自己的文件系统和软件包管理器（apt）。

为什么说这个功能独一份？同类 AI app 的 Agent 能力要么跑在云端（消耗云资源），要么是服务商托管的代码沙箱（通常只支持 Python/JS）。而 RikkaHub 的工作区完全在你的手机上——数据不出设备、没有云端成本、AI 自行决定装什么包。

几个典型的使用场景：

- **克隆 Git 仓库并翻译 README**：让 AI 先装 git，clone 仓库，读取 README.md，翻译后写回 `README.zh-CN.md`
- **搜索资料 + 制作 PPT**：通过 MCP 搜索服务器获取资料，整理结构后调用工作区里的 Python 环境生成 PPTX
- **数据清洗**：导入 CSV，装 pandas 和 matplotlib，编写脚本去重、统计分布、生成图表

### Fork 对话：从任意位置分叉做 A/B 测试

很多时候你想从同一个起点探索不同方向——对比不同模型的回答、尝试不同的提示词、或者安全地试一些"可能让对话跑偏"的内容。传统做法是手动开新对话、复制粘贴历史，既麻烦又容易出错。

RikkaHub 的 Fork 功能让这件事一键完成：在对话中找到要分叉的位置（用户消息或助手回复都行），长按 → 三点菜单 → Fork。新对话**完整复制**分叉点之前的所有消息，从分叉点开始完全独立。原对话保持原样，分支对话在历史列表里独立出现，删除其中一个不影响另一个。

> [!NOTE]
> **节点版本 vs Fork 分支**：这两个容易混淆。节点版本是在同一条对话里、同一消息位置出现多个回复版本，可以左右切换对比；Fork 分支则是创建一个全新的独立对话来继续探索。一个是"同位置的备选"，一个是"新路径的延伸"。

几个实际场景：用 GPT-4o 问了一个问题，从你的问题处 Fork，在分支里切换到 Claude Sonnet 发送相同问题，直接对比两个回答的质量和风格；想试一个可能让对话跑偏的提示词，在 Fork 里试，跑偏了就放弃分支回到原对话；一个对话跑了 20 轮有很多废话，从干净的位置 Fork，新对话里只有精简历史，直接导出分享。

### 模型"认错自己"怎么办

RikkaHub 新用户经常遇到一个困惑：用的是 Claude Sonnet，但问模型"你是什么"，它说自己是 GPT-4o。这不是 bug——大语言模型本质上是"下一个 token 预测器"，没有自我认知。它对"我是谁"的回答完全取决于训练数据和上下文提示词。

官方 app 能答对，是因为它们在系统提示词里硬编码了身份指令（比如 ChatGPT app 的系统提示词开头就写着 "You are ChatGPT, a large language model developed by OpenAI"）。RikkaHub 故意不内置这些——因为你应该拥有控制权，而不是被厂商预设的身份绑架。

要让模型正确回答自己是谁，在助手的系统提示词里加上身份说明就行：

```markdown
你运行在 RikkaHub 上，当前使用的模型是 {{model_name}}。
你使用 {{model_id}} 作为底层模型标识符。
当前日期时间：{{cur_datetime}}。
```

其中 `{{model_name}}`、`{{model_id}}`、`{{cur_datetime}}` 都是占位符变量，发送时自动替换为实际值。如果你在对话中途切换了模型，助手的系统提示词会重新注入，模型就能"知道"现在用的是什么——前提是你在提示词里写了占位符。
