## ✨ GKD 是什么：用规则驱动屏幕点击的开源工具

GKD 是一款运行在 Android 上的**自定义屏幕点击应用**，核心思路是「引擎 + 规则」：应用本身只提供点击引擎，不内置任何写死的规则；你可以接入社区维护的远程订阅，也可以自己编写针对单个应用或跨应用的点击规则。它的工作依赖三个系统组件——无障碍服务负责读取当前屏幕的界面节点（相当于眼睛），高级选择器语法负责精确定位目标节点（相当于手），订阅规则集合负责告诉引擎「什么界面出现时点什么」（相当于大脑）。

官方用四个关键词概括 GKD 的卖点：**开源**（GPL-3.0 协议，任何人可以审查源码确认它读了什么、做了什么）、**高级选择器**（类似 CSS 的查询语法，支持 id、文本、尺寸、可见性、层级关系等条件组合）、**订阅规则**（本地规则随时改、远程订阅社区自动更新）、**快照审查**（把界面状态打包成快照分享给规则作者，远程协作解决「不知道这个界面怎么写规则」的问题）。

和市面上常见的「一键去广告」类工具相比，GKD 的架构决定了它的灵活性更高——普通工具内置规则包，装上就生效但遇到未覆盖的界面无能为力；GKD 则让规则的开关、范围、触发方式全部由你控制，颗粒度到单个应用的单个规则组。当然，灵活也意味着上手流程更长：先授权无障碍，再接入订阅，最后按需调整规则。

## 🔧 安装步骤：从下载到授权完成

GKD 的安装分成两个阶段：先装 APK，再给系统授权。两个阶段都有一些容易踩的坑，下面按顺序梳理。

**一、下载 APK 与核对版本**

1. 从上方下载入口获取 APK 文件，建议优先使用官方渠道以确保包名一致（`li.songe.gkd`）。
2. 下载完成后核对文件大小和版本号，避免装到被二次打包的修改版本。

> [!WARNING] 警惕第三方修改版
> GKD 是开源项目，开源特性意味着任何人都可以重新打包。请确认安装包签名与官方一致，不要从来路不明的网盘或论坛帖子下载，否则可能引入额外的后台行为。

**二、允许未知来源安装**

Android 系统默认禁止安装来自应用商店以外的 APK。执行以下操作：

1. 打开系统设置 → 安全 / 隐私 → 安装未知应用（不同品牌路径略有差异）。
2. 找到你用来下载 APK 的浏览器或文件管理器，开启「允许安装此应用的未知应用」开关。
3. 返回文件管理器，点击 APK 按提示安装。

**三、授权无障碍服务（必需）**

装完 GKD 还不能直接用——它需要无障碍服务才能读取屏幕节点和执行点击。

1. 打开 GKD 应用，首页会显示「无障碍权限未开启」的状态提示。
2. 点击跳转链接进入系统的无障碍设置页面。
3. 找到 GKD，打开开关并在弹出的确认对话框中点击「允许」。

> [!TIP] 为什么要无障碍？
> 无障碍服务是 Android 系统提供的官方能力，专门为残障辅助、自动化等场景设计。GKD 用它读取界面节点信息并执行模拟点击，整个过程不需要 root，也不涉及任何隐私数据上传。

**四、可选：授予写入安全设置权限（高级授权）**

部分高级功能需要额外的「写入安全设置」权限。通常有两种途径获取：

| 方式 | 操作 | 适合人群 |
| --- | --- | --- |
| adb 命令 | 电脑连接手机，开启 USB 调试后执行 `adb shell pm grant li.songe.gkd android.permission.WRITE_SECURE_SETTINGS` | 熟悉电脑操作的用户 |
| Shizuku | 安装 Shizuku 应用，通过其接口授权 | 不想碰 adb 的用户 |

> [!NOTE] adb 授权失败怎么办
> 部分品牌系统（小米 HyperOS/MIUI、OPPO ColorOS、魅族 Flyme）会在 shell 层面拦截运行时权限授予。典型报错关键词是 `grantRuntimePermission: Neither user 2000 nor current process has android.permission.GRANT_RUNTIME_PERMISSIONS`。解除方法见下文「常见问题速查」章节。

授权完成后回到 GKD 首页，状态指示器应显示全部绿色——到这里安装流程就走完了。

## 📖 使用入门：从第一条规则到跨应用自动化

装好并授权的 GKD 还不会自动帮你点任何东西——引擎已就绪，但规则还是空的。这一节从最简单的用法开始，逐步深入到订阅管理、规则编写和快照协作。

**一、最快上手：接入远程订阅**

不想自己写规则的话，社区已经维护了大量实用订阅。

1. 打开 GKD 首页 → 订阅 → 点击「添加订阅」。
2. 输入订阅链接（社区常见的维护组会在文档里公布），或扫描二维码。
3. 添加后点击订阅项进入规则列表，你会看到按应用分类的一整套规则组，每个规则组可以独立开关。

接入订阅后，最常见的场景——跳过开屏广告——已经生效了。订阅会自动更新，规则作者会持续维护和扩充。

**二、全局规则：一条搞定所有应用的通用点击**

应用规则绑定单个包名，而全局规则挂在订阅的全局层，**对所有应用生效**。「跳过所有开屏广告」这类跨应用场景，用全局规则一条就能覆盖。

全局规则的编辑入口在：首页 → 订阅 → 本地订阅 → 全局规则。点开是独立的规则列表，与某个具体应用无关。

下面是一条通用开屏广告跳过规则的示例，重点在规则组上的几个控制参数——它们是全局规则防误触、防耗电的关键：

```
{
  key: 0,
  name: '开屏广告',
  fastQuery: true,
  matchTime: 10000,
  actionMaximum: 1,
  resetMatch: 'app',
  rules: [
    {
      key: 0,
      matches: '[text*="跳过"][text.length<10][visibleToUser=true]',
    },
  ],
}
```

选择器的含义是：找可见的、文字包含「跳过」且文字长度小于 10 的节点。加上长度限制是为了避免误点「跳过本集片头」这类正常按钮。四个控制参数的作用如下：

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `matchTime` | 10000 | 只在应用启动后 10 秒内匹配，广告期过了就不再扫屏 |
| `actionMaximum` | 1 | 最多执行 1 次点击，防止反复触发 |
| `resetMatch` | app | 切换应用后重置计数，下次开屏重新生效 |
| `fastQuery` | true | 使用快速查询通道，降低匹配开销 |

> [!TIP] 全局 vs 应用：能用精确就别用宽泛
> 全局规则里每个宽松的选择器都会在所有应用的每次界面变化时跑一遍，这是耗电与误触的双重来源。经验法则：能用应用规则精确解决的，不要提升到全局。

**三、触发记录：看见引擎在做什么**

写了规则、接了订阅，但不确定 GKD 到底有没有命中？去首页找「触发记录」。这里会列出每一次规则命中的时间、应用、规则名称——如果记录一片空白，要么规则没写对，要么匹配条件太严格根本没命中；如果同一条规则在短时间内疯狂触发，说明防误触的参数需要收紧了。

**四、快照审查：远程协作写规则**

遇到一个界面不知道怎么写选择器？GKD 提供了快照机制——把当前屏幕的界面节点打包成快照 zip 文件，发给社区或规则作者，对方在本地用审查工具打开就能看到和你一模一样的界面结构，然后直接给你写好规则。

快照分本地和分享两种链接，这里有一个高频陷阱：

- **分享链接（正确）**：通过快照页面右上角的分享功能生成，指向已上传到公开空间的快照文件，任何设备打开都能加载完整内容。
- **地址栏链接（错误）**：直接从浏览器地址栏复制的，这是你本地会话里的私有链接，别人打开只会显示「快照缺失」。

正确做法：抓好快照后先完成上传，然后**从分享入口复制链接**，而不是浏览器地址栏。如果不想上传，也可以直接把 zip 文件通过聊天软件或邮件发给对方——对方导入自己的 GKD 或审查工具即可，完全规避上传环节。

**五、adb 授权失败的排查思路**

走高级授权时，`SecurityException: Neither user 2000 nor current process has android.permission.GRANT_RUNTIME_PERMISSIONS` 是高频报错。这不是 GKD 的问题，是厂商系统在 shell 层面加了权限监控。解除方法因品牌而异：

| 系统 | 操作 |
| --- | --- |
| HyperOS / MIUI（小米、POCO） | 开发者选项中开启「USB 调试（安全设置）」——注意不是普通的「USB 调试」 |
| ColorOS（OPPO、一加） | 开发者选项中关闭「权限监控」（或打开「禁止权限监控」） |
| Flyme（魅族） | 开发者选项中关闭「Flyme 支付保护」 |

解除限制后重新执行命令即可成功。如果小米设备开了「USB 调试（安全设置）」还是报错，可以尝试在命令前加 sudo 提升权限。实在不行就换路走 Shizuku 授权，不用碰 adb。
