## ✨ Immich 是什么

Immich 是一个开源的自托管照片与视频管理系统——你把它部署在自己的服务器上，手机、平板、电脑就能把照片自动备份进去，然后在任何设备上按时间线、人脸、地图、相册等多种方式浏览和整理。它的定位很明确：给那些不想把私人照片交给云相册、但又想要现代相册所有便利功能的用户一个可信赖的选择。

Immich 的核心能力覆盖了照片库从导入到整理再到协作的完整链路：手机端自动备份可以做到即拍即传；时间线按拍摄时间倒序组织几万张照片也不乱；人脸识别能自动把同一个人归组，你只需要给一组命名；地图视图在一张世界地图上把所有照片的拍摄位置打点；伴侣共享则能把整个库对配偶开放，新照片自动互看而不需要手动建共享相册。

适合谁用？第一类是已经有家庭服务器或 NAS 的用户——Docker Compose 一条命令就能把 Immich 跑起来；第二类是有多设备照片备份需求、又在意隐私的个人和家庭；第三类是已经积累了大量照片文件、想找一个能真正「接管」而不是简单复制的工具的资深用户。Immich 不做的事也要说清楚：它不是免费版的某款云相册，部署和运维需要一点技术基础，官方也不提供托管服务。

## 🔧 安装步骤

Immich 的安装分两端：服务器端是自托管的核心，手机端是日常使用的入口。

**服务器端：Docker Compose 是主流路径。** 准备一台装了 Docker 和 Docker Compose 的机器（本地 Linux 服务器、群晖威联通 NAS、云服务器都行），创建一个目录，放入官方仓库的 `docker-compose.yml` 和 `.env.example`（改名成 `.env` 后修改里面的 `UPLOAD_LOCATION` 等路径变量指向你期望存储照片的目录），然后一条命令 `docker compose up -d` 就能拉起整套服务。首次启动后访问服务器的 2283 端口，在网页端注册第一个管理员账号。

> [!TIP]
> 务必核对版本号。Immich 的 App 和服务器需要版本对齐，商店审核常让 App 更新晚几天，服务器先升级了就会撞上登录失败或功能异常。升级前先看一下手机 App 的当前版本号，再决定服务器要不要升。

**手机端：** 安装完成后打开 App，输入服务器地址（内网 IP 或外网域名），用刚才注册的管理员账号登录。登录成功后第一件事是去设置里打开「自动备份」，选择要备份的相册目录——从这一刻起，新拍的照片和视频就会自动上传到 Immich 服务器。

**安装完成的核对标准：** 网页端时间线里能看到一张自动生成的示例照片（Immich 的 logo 占位图）；手机 App 设置里能看到服务器连接状态显示为「已连接」；管理端的 Server Stats 页面能看到存储占用和用户配额信息。这三条全绿，说明安装链路已经打通。

## 📖 使用入门

时间线是 Immich 所有浏览的起点——网页端和手机 App 的首页都是它。理解了时间线的结构和操作，就掌握了日常使用的一半。照片按拍摄时间倒序排列，最新的在顶部，以「年-月」为分组标题。手机端捏合可以缩放网格，从单张细看到整月俯瞰；网页端有缩放滑块做同样的事。批量操作是常用动作：长按或点击进入多选模式后，可以把选中的照片加入相册、打标签、归档、下载或删除。

**三种云状态图标是新手最容易困惑的地方。** 每张照片右下角的小图标表示它在手机和服务器两端的分布：云朵图标代表「已备份」——从这台手机上传、原件还在手机上；仅服务器图标意味着照片只在服务器上，可能是从网页端或其他设备上传的，也可能是本机已经执行过「释放空间」把原件清理了；没有图标就是「仅本机」——这份还没离开过你的手机，需要去自动备份设置里检查备份范围。判断口诀：看到「仅服务器」不要慌，照片好好在服务器上；看到「无图标」才需要关心。

时间线上没有的照片去哪了？几类「消失」是有意设计。归档的照片从时间线和文件夹视图隐藏但仍可搜索，适合证件照、截图这类「留着但不想天天看见」的内容。锁定文件夹比归档更进一步，需要额外验证才能打开，是私密照片的归宿。回收站是删除的第一站，期满才真正清除，误删先来这里翻。如果以上都不是，检查搜索或筛选条件有没有残留。

**外部库功能**是 Immich 给已经有大量存量照片的用户准备的——你可以把硬盘上已经按目录组织好的照片直接「挂」进 Immich，文件原地不动，不复制也不移动。操作上是在 Docker Compose 文件里加一行 volume 挂载已有目录（比如 `- /mnt/photos:/mnt/photos:ro`），然后在网页端创建外部库填入容器内路径，手动触发一次扫描，照片就开始进入时间线。读写模式的选择很关键：默认的读写模式下 Immich 可以写 XMP 旁路文件、回收站清空时能真删原文件；加了 `:ro` 只读挂载的话 Immich 对该目录只读，编辑功能不可用、回收站清空时被删的照片会「复活」回时间线。取舍口诀：想让 Immich 全权管理选读写，想保证 Immich 绝对不碰原始文件选只读。

> [!NOTE]
> 外部库的备份是一个容易被忽视的点。外部库的文件不在 `UPLOAD_LOCATION` 里，数据库备份和服务器备份的覆盖清单默认不包含它。挂了外部库的家庭，文件层备份一定要覆盖挂载源目录，别让外部库成为备份体系的漏网之鱼。

**伴侣共享**解决的是另一个场景：夫妻或亲子之间，你拍的我都想看。共享相册要手动挑照片，伴侣共享则直接换了粒度——把整个照片库对指定用户开放，设置一次，之后你拍的所有新照片自动出现在对方的浏览范围里。设置在网页端或手机 App 的共享页，添加伴侣、从用户列表选择对方、发起，对方接受后生效。伴侣可以下载原件（家庭内部默认互信设计），但各自的浏览历史、收藏、人脸命名都在自己账号下互不污染。归档和锁定文件夹里的内容不会被共享，私密分层依然有效。什么时候退回共享相册：需要给多个人开放同一组照片时，只想让对方看某个主题时，或者对方不该下载原件时。

**常见问题排查**的通用心法是分层定位——先确认哪一层出问题（手机网络 → 服务器容器 → 任务队列 → 机器学习），再逐项排查。登录失败先核对 App 与服务器版本是否同线；只传照片不传视频几乎总是反向代理没放开大请求体（视频是大头）；后台备份长时间不动多半是手机系统电池策略杀后台；缩略图任务数永远大于照片数是设计如此（每张照片 3 种缩略图 + 每张人脸 1 张小图）；全库导入后一切很慢是正常现象——任务队列在消化积压，可以暂停智能搜索和人脸识别让它夜里再跑。自签名证书和 Basic Auth 属于实验性特性，视频播放和上传经常出问题，官方明确建议改用受信任证书或 VPN 方案。

| 想确认什么 | 去哪看 |
| --- | --- |
| 容器是否健康 | `docker compose ps` |
| 任务是否在跑/失败数 | 管理端 Job Queues |
| 存储占用与用户配额 | 管理端 Server Stats |
| App 侧报错详情 | App 设置里的日志页 |
