## ✨ Gopeed 是什么

Gopeed（全称 Go Speed，中文译名「够快下载器」）是一款用 Golang 写后端、Flutter 做前端的开源多协议下载工具。名字里的 Go 一语双关——既指下载速度够快，也指驱动下载核心的 Go 语言。协程实现的多任务并发与多连接分段传输，是它敢打「高速」标签的底气。

它不是那种套壳 Electron 的轻量玩具——Go 核心编译成动态库和 Flutter 界面直接通讯，安装包体积和内存占用都比同类桌面工具明显更小。开源协议选了 GPLv3，源码完全公开，任何人都能审查、修改甚至自行编译，整个项目靠社区捐赠和反馈维持迭代。

覆盖范围在下载器里算罕见：同一套后端核心，官方直接提供了 Windows / macOS / Linux 桌面客户端、Android 安装包、iOS 自签包、无界面的命令行工具，还有可远程访问的 Web 版和 Docker 镜像——八种形态一套核心，NAS 玩家和多设备用户基本都能找到合适的部署方式。

和市面上常见的下载器相比，Gopeed 的核心卖点可以浓缩成三件事：**协议广**（HTTP/HTTPS + BitTorrent + 磁力链接 + ed2k）、**覆盖全**（连 iOS 自签包都给了）、**可编程**（REST API + JavaScript 扩展 + MCP 接口三条自动化通道同时开着）。如果你在找一款不靠广告、不靠会员限速、能自己审计源码的下载器，它是值得认真试的选项。

## 🔧 安装步骤

各平台安装包形态不同，但整体都属于「下一步 → 完成」的轻量流程，下面分几个常见场景说明需要注意的点。

### Windows

1. 运行 `.exe` 安装包，UAC 弹窗点「是」。
2. 选择安装路径——默认装在 `Program Files` 下即可，不需要管理员权限以外的特殊配置。
3. 安装完成后主程序会自动注册浏览器接管（详见「浏览器接管」一节），如果没生效，可以在设置里手动开启。

> [!WARNING]
> Windows Defender 偶尔会对小众开源工具报误杀。如果遇到隔离提示，把安装目录加入杀毒排除项即可——这类误报在 Go 写的开源项目里比较常见，不是程序本身有问题。

### Android

1. 下载 `.apk` 到手机，打开前先在系统设置里允许「未知来源」安装（不同厂商 ROM 路径略有差异，一般在安全设置里）。
2. 点击安装包完成安装，首次启动会请求存储和网络权限，都允许即可。
3. Android 端功能完整，但浏览器接管受系统限制——大多数情况下只能手动粘贴链接。

### macOS

1. 打开 `.dmg`，把 Gopeed 拖进「应用程序」文件夹。
2. 首次启动系统会拦截「来自未知开发者」，去「系统设置 → 隐私与安全」里点「仍要打开」即可。
3. 安装完成后在设置里勾选「登录时启动」比较实用——后台常驻才能稳定接管浏览器下载。

### Linux / Docker（进阶）

Linux 桌面版的安装方式差异较大——Debian/Ubuntu 可以用 `.deb` 包，Fedora/RHEL 用 `.rpm`，Arch 有 AUR。更省心的方式是直接跑 Docker 镜像：一条 `docker run` 就能拉起 Web 版服务端，数据目录映射到宿主机卷，后续升级只需要重新拉镜像重启容器。

### 核对版本号

> [!TIP]
> 装完别急着用，先在「设置 → 关于」里核对一下版本号是否和你下载的安装包一致。Gopeed 更新频率不低，偶尔会遇到下载页链接指向了新版本但文件名还没改的情况。

## 📖 Gopeed 使用入门

### 创建第一个下载任务

桌面端最常用的方式就是复制链接后在 Gopeed 里粘贴。程序会自动识别链接类型——HTTP 直链、磁力链接、ed2k 地址，甚至 BT 种子文件都能直接拖进窗口。任务创建后默认进入「下载中」队列，界面上会实时显示速度、进度和剩余时间。

多任务并发数默认 5，可以在设置里调整——机械硬盘用户建议保持默认，SSD 用户开到 8~10 问题不大。每个任务的分段数也能单独调，热门资源分段多一些速度会更稳，但会增加磁盘随机写入。

### 浏览器接管：让点击下载自动进 Gopeed

桌面端装完后一般会自动注册浏览器扩展或协议处理器。主流浏览器（Chrome、Edge、Firefox）点下载链接时，会先询问是浏览器自己下还是交给 Gopeed——选 Gopeed 就能走多线程了。

Linux 桌面版是个例外，官方文档明确提示：由于 Linux 桌面环境的协议处理器行为不统一，自动接管大概率不生效。如果遇到这种情况，可以在主程序里开启 TCP 接口（设置 → 高级 → 通讯协议 → 切到 TCP），然后在浏览器扩展里手动添加这个远程下载服务器，走远程推送模式。

### 远程推送：把下载任务扔给 NAS

这是 Gopeed 比较独特的使用方式——主程序可以跑在 NAS 或家里的服务器上，自己的笔记本/手机只当控制端。Web 版、Docker 版甚至局域网里的桌面版都能被扩展连接。

配置流程四步走：

1. 服务端开启接口，记下端口号并重启。
2. 浏览器扩展里添加远程下载服务器，填地址和端口。
3. 如果服务端设了接口令牌，扩展里填同一个令牌。
4. 保存后在扩展弹窗里确认连接状态，随便找个链接测一下。

> [!WARNING]
> 服务端一旦暴露在公网，必须开启身份认证——接口令牌或基础认证至少启一个，否则任何人扫到端口都能往里塞下载任务。

### JS 扩展：把复杂解析交给社区

Gopeed 的扩展机制是纯 JavaScript 写的，不需要编译、不需要后端。官方示例仓库里放了两条开发路线的参考实现：

| 路线 | 适用场景 | 形态 |
| --- | --- | --- |
| Node + cheerio | 需要解析网页 DOM、爬页面找直链 | 完整 Node 项目，webpack 打包 |
| 纯 JS fetch | 目标站点有现成 API，不需要解析 HTML | 单文件，零依赖 |

两条路线的骨架是一样的——manifest.json 清单声明事件和 URL 匹配规则，入口脚本把解析出的文件列表写回上下文。安装扩展的方式也简单：在扩展页面粘进仓库地址（子目录扩展记得加 `#` 子目录名），创建匹配的链接试一下解析结果就行。

### 和同类工具的横向对比

选下载器本质是在选「你愿意为哪些能力付出什么代价」。拿 Gopeed 和几个常见工具放一起看：

| 能力 | Gopeed | Motrix | IDM | 迅雷 |
| --- | --- | --- | --- | --- |
| HTTP/HTTPS | ✅ | ✅ | ✅ | ✅ |
| BitTorrent | ✅ | ✅ | ❌ | ✅ |
| 磁力链接 | ✅ | ✅ | ❌ | ✅ |
| ed2k | ✅ | ❌ | ❌ | ❌ |
| 全平台（含移动端） | ✅ | 仅桌面 | 仅 Windows | 全平台 |
| 免费使用 | ✅ | ✅ | 付费 | 免费但有广告 |
| 开源 | GPLv3 | MIT | 闭源 | 闭源 |
| 非 Electron 架构 | ✅ | ❌ | ✅ | ❌ |
| 开放 API | ✅ | ✅ | ❌ | ❌ |
| JavaScript 扩展 | ✅ | ❌ | ❌ | ❌ |

三个最值得拎出来说的差别：

一是**移动端覆盖**——IDM 和 Motrix 都没有正经的手机版，Gopeed 连 iOS 自签包都提供了（虽然要自己签名），这在下载器里几乎是独一份。

二是**BT 能力**——IDM 完全不支持 BT，Motrix 虽然支持但版本更新节奏近两年明显放缓，Gopeed 的 BT 引擎和 HTTP 核心共用同一套 Go 协程框架，磁力链接和 ed2k 协议也一起覆盖了。

三是**可编程性**——三者里只有 Gopeed 同时提供 REST API、JS 扩展和 MCP 接口。想把下载流程自动化、或者自己写个定制扩展，这是唯一的选择。

迅雷的情况不太一样——它有多年积累的离线加速节点和资源缓存，这是 Gopeed 没有的。但代价是广告、会员限速和隐私争议。如果你主要下冷门资源、看重软件本身干净无干扰，Gopeed 更合适；如果你依赖热门资源的离线加速，那迅雷的定位还是无可替代。
