## ✨ Blackbox 是什么

Blackbox 是一款安卓端的免 Root 虚拟化引擎，核心定位是在一台设备上创建独立的虚拟环境，让应用在不修改系统的前提下运行。它把虚拟化的核心能力打包成一个轻量级容器——多开分身、数据隔离、Xposed 框架支持、虚拟定位、设备改机——这些传统上需要 Root 才能做到的事情，在 Blackbox 里都走引擎层面的方案，手机本体保持原厂状态。

项目完全开源，采用 Apache 2.0 协议发布。虚拟化的核心实现集中在 Bcore 模块，官方提供了三步集成示例和完整的核心 API 文档，对开发者和重度用户都比较友好。从社区的反馈来看，它的主要优势集中在三个点：**免 Root 即开即用**、**引擎内置 Xposed 框架**、**数据隔离干净彻底**。

适合使用 Blackbox 的场景大致分四类：第一类是需要同应用多实例并行的用户——游戏玩家养多个号、小团队分账号运营、个人把工作和生活账号分开；第二类是需要干净测试环境的开发者或重度用户——把来源不明的安装包装进虚拟环境试玩，测试完整个删掉，不污染主机；第三类是想用 Xposed 模块但不想 Root 的人；第四类是想研究或复用虚拟化引擎本身的开发者。

不太适合的场景也需要提前说明：追求官方级稳定性的人要谨慎，项目本身声明稳定性未经大量测试，崩溃和不兼容是常态；新系统机型用户也需要留意——引擎目前支持范围止于 Android 12 左右，更新的系统没有官方适配承诺；希望在真机级性能下玩大型 3D 游戏的用户也要有心理预期，虚拟化本身会带来一定的性能开销。

## 🔧 安装步骤

Blackbox 本身是一个安卓应用，安装流程和普通 APK 没有本质区别，但因为它的定位是虚拟化引擎，装完之后的配置环节有几个要点不能跳过。

### 下载与校验

1. 从下载页获取最新版本的安装包，记下文件大小和版本号；
2. 安装前确认手机的「允许未知来源」权限已开启（不同安卓版本的路径略有差异，一般在「安全设置」或「隐私设置」分组下）；
3. 如果下载的安装包来自第三方渠道，建议核对官方公布的 MD5 或 SHA256 值，避免装到被篡改的版本。

> [!WARNING]
> 安装包来源务必选择官方渠道或可信的镜像源。虚拟引擎拥有较高的进程权限，被篡改的版本可能带来安全风险。

### 安装与首次启动

1. 点击安装包完成安装，全程静默，没有额外的授权弹窗；
2. 首次启动时引擎会请求存储权限——这是必须的，虚拟环境的数据目录需要读写空间；
3. 首次启动完成后，主界面会显示一个空的容器列表，这就是后续装应用的地方。

### 装完核对

- 打开应用进入主界面，应该能看到完整的容器管理界面和右上角的菜单入口；
- 进入「软件设置」→「XP 管理」分组，确认开关已就绪；
- 如果是首次安装，引擎内部不会有任何残留数据，这是正常的。

## 📖 上手与进阶使用

Blackbox 的核心能力围绕「容器」展开——每个容器（用户）里可以装一份独立的应用，所有容器互相隔离、数据互不干扰。以下是日常使用中最常见的操作路径和进阶玩法。

### 多开分身：同一个应用多实例并行

多开是 Blackbox 最基础也最常用的功能。操作流程很直观：创建一个新容器 → 把应用装进这个容器 → 启动。引擎内部对应用的安装和启动提供了两种入口：已装在系统里的应用可以直接给包名调用引擎接口安装，还没装过的则传 APK 文件路径。每种安装方式都需要指定目标容器的用户 id，引擎把应用装进哪个容器、运行在哪个容器，完全由这个 id 决定。

日常使用中，每个分身可以创建独立的桌面快捷方式，一步直达对应的容器实例，避免频繁切换容器。

### Xposed 框架：免 Root 装模块

传统 Xposed 玩法需要解锁并 Root 设备，门槛和风险都不低。Blackbox 把框架内置进了虚拟环境，整个启用过程就是软件设置里的一个开关：主界面右上角三点菜单 → 软件设置 →「XP 管理」分组下找到「启用 Xposed 框架」开关，打开即可。

开关打开后，虚拟环境内就具备了 Xposed 框架的运行能力，原本灰色的「模块管理」入口也会变为可用。原理上，框架作用范围被限制在虚拟环境内部——虚拟应用由引擎托管，引擎自己在进程层面就完成了模块逻辑的注入，全程不碰系统分区。对应的边界也很明确：**模块只对虚拟环境内的应用生效**，系统里直接运行的应用不受影响。启用后记得去模块管理界面把模块导进来，框架本身不产生任何效果，模块才是功能载体。

> [!TIP]
> 首次启用 Xposed 框架后如果出现应用未按预期生效的情况，按社区经验可以尝试重启一次引擎（完全杀掉进程再打开）。

### 隔离机制：数据、进程、权限三层互不干扰

Blackbox 的隔离不是一个附加功能，而是引擎的定义本身。理解它背后的三层机制，能帮你预判哪些数据会隔离、哪些不会。

**数据目录隔离**是第一层：每个虚拟应用的数据都存放在引擎的私有数据目录内，且按容器分开。同一应用的两个分身各自有自己的数据目录，聊天记录、登录凭证、缓存文件互不可见；清掉一个分身的数据，另一个分身毫发无损；这些目录都在引擎的私有空间内，系统里的其他应用也读不到。

**进程与运行时隔离**是第二层：虚拟环境内的每个应用运行在引擎托管的独立进程中，引擎负责把它们对系统接口的调用翻译到虚拟上下文。分身 A 崩溃不会连带分身 B，杀进程也只影响对应实例；应用以为自己在正常的安卓环境里，读到的是引擎提供的虚拟身份信息——这也是设备改机和虚拟定位能够生效的底层原因。

**权限体系隔离**是第三层：虚拟应用申请的权限走引擎层的处理，与系统权限分开管理。在 Blackbox 里给应用授权麦克风，不代表系统里的同名应用拿到了这个权限，反之亦然。

> [!NOTE]
> 设备硬件本身是共享的——网络、传感器、电池、存储介质都是同一套物理资源。所有分身共用设备的网络身份和 IP，这也是虚拟定位存在 IP 定位边界的原因。

### 开发者集成：把引擎嵌入自己的工程

项目完整开源，官方提供了三步集成示例，对想把虚拟引擎嵌入自己工程的开发者来说门槛不高。最小集成路径只有三步：

1. **初始化引擎**：在宿主应用的 `Application` 生命周期里挂载引擎上下文。`attachBaseContext` 阶段调用 `doAttachBaseContext` 越早越好，`onCreate` 阶段完成 `doCreate`；
2. **安装应用到虚拟环境**：两种入口——已装在系统里的直接给包名，只有安装包的传 APK 文件路径。两种方式都要传入目标容器的用户 id；
3. **启动虚拟应用**：包名加用户 id 调用引擎的 `launchApk` 方法，引擎接管后续的进程创建与环境构造。

官方给集成者的一条关键建议是：**条件允许时把 `targetSdkVersion` 降到 28 或以下**，兼容性更好。此外宿主应用本身也要考虑覆盖 32 位和 64 位应用的范围。
