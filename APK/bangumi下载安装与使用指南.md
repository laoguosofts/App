## ✨ Bangumi 是什么：一款纯粹的追番工具

Bangumi 是番组计划（bgm.tv）社区推出的官方客户端，定位很明确——给喜欢看动画的人一个按星期追新番、标记观看进度、参与社区讨论的随身伴侣。它不做在线播放，不做内容聚合，核心就是帮你记「我在追什么」「今天更了没」「看了几集了」这几件事，外加一个相对活跃的社区氛围。

这款客户端目前主要支持安卓平台，由独立开发者 czy0729 维护更新，社区数据与 bgm.tv 网站实时同步。如果你已经是番组计划的老用户，手机端会让你在通勤路上、睡前刷更新这件事变得顺手很多；如果还没注册过账号，先逛一逛每日放送页也能不登录看个热闹。

## 🔧 安卓安装与版本核对

### 渠道选择

客户端的官方发布渠道只有 GitHub Releases，安装包会在开发者发布新版本时同步更新。如果你所在网络访问 GitHub 不稳定，可以通过本站下载页获取整理好的转存版本。

> [!WARNING] 注意
> 客户端曾经上架 Google Play 但已被举报下架，目前没有任何官方的应用商店版本。如果在应用市场搜到同名应用，请务必核对包名是否为 com.czy0729.bangumi，非官方渠道的套壳应用存在安全风险。

### 安装步骤

1. 从上述渠道下载 APK 安装包（当前收录版本约 36MB）；
2. 点击安装时，系统会弹出「是否允许安装未知应用」的提示，按手机引导允许对应来源即可；
3. 安装完成后打开应用，首次启动会请求网络与存储等基础权限，按需授予。

### 如何核对拿到的是正确的安装包

担心下载到非官方版本，可以核对以下几个特征：

| 核对项 | 正确值 |
| --- | --- |
| 包名 | com.czy0729.bangumi |
| 体积 | 约 36MB |
| 图标 | 看板娘风格插画 |
| 应用名 | 显示为 Bangumi |

包名是开发者身份标识，套壳应用对不上这一点；体积和 MD5 校验则可以在下载页找到对应版本的详细信息做交叉比对。

### 系统版本提醒

客户端对安卓版本有一定要求，如果安装时系统报「解析失败」，大概率是系统版本过低或安装包下载不完整，可以先核对系统版本再重新下载。

## 📖 使用入门：从追番到社区的完整闭环

### 每日放送：按星期追新番的核心入口

打开客户端，最先值得熟悉的页面就是每日放送——这是每个追番人每天都可能刷一遍的页面。它按星期一到星期日分栏排列当季正在播出的番剧，每一条目的信息包括：

- 放送时间（通常精确到几点，部分条目有具体到分钟的更新时间）；
- 条目的封面图和译名；
- 你自己的收藏状态标记（在追的条目会有明显标识）。

数据由开发者每季度主动更新元数据，日志里反复出现的「新增 20XX Sx 元数据」说的就是这个。新季度开始时放送表会逐步补全信息，刚开播几天条目不全属正常现象，过一周再来刷就齐了。

#### 追番季的每日工作流

1. 早上或睡前打开每日放送，定位今天的星期一栏；
2. 对照自己的收藏列表，快速扫一遍今天有没有追的番更新；
3. 看完之后回到客户端标记观看进度；
4. 第二天在时间胶囊里就能看到相关的讨论热点。

#### 几个实用细节

- **换季是大事**：每年 1/4/7/10 月是新番换季，放送表会整体翻新，旧季条目站内仍可查询；
- **放送时间以日本时间为主**：换算成北京时间常在深夜，第二天早上再点格子标记进度更符合实际观看节奏；
- **不追新番也有用**：想补某季口碑旧作时，按星期翻当季放送表比按年份搜索更直观，能快速看到同一档都有哪些选择。

### 注册与登录：看没问题，记和说需要账号

客户端与番组计划网站共用同一套账号体系——在网站注册，在客户端登录，数据互通。注册流程是常规的邮箱注册，建议顺手把昵称和个人资料完善了，想参与维基编辑的用户是必须完善资料的。

#### 登录方式

1. 打开客户端，进入需要账号的页面（如时间胶囊）或设置里的账号入口；
2. 选择登录，客户端会拉起授权流程，浏览器或内置页面完成登录后授权；
3. 授权通过后，你的收藏、进度、动态会实时同步到账号上。

> [!NOTE] 授权过期处理
> 老用户偶尔会遇到授权过期的情况，表现为刷不出个人数据或反复要求重新授权。如果更新到最新版本后仍然出现，清除客户端数据重新授权通常能解决。

#### 不登录能用到什么程度

未登录状态下，条目浏览、搜索、排行榜、每日放送这些公开内容全部可用。但以下动作需要账号：

- 标记收藏状态、点格子记进度；
- 打分、写吐槽、发评论；
- 时间胶囊的个人动态与好友流；
- 小组发言、日志发布。

简单说：**看没问题，记和说需要账号**。

### 跨站同步：把历史追番记录搬过来

如果你的追番记录散落在哔哩哔哩、豆瓣等平台，不想一条条手动补录，客户端提供了一个「其他站点有限同步到番组计划」的功能，可以帮你做一次性的历史记录迁移。

#### 「有限同步」是什么意思

这个功能的定位是**一次性或低频的历史记录导入**，不是持续的双向互通：

- 能做：把其他平台上的标记记录（看过/在看这类状态与评分）批量导入番组计划，作为初始数据；
- 不能做：导入后你在番组计划上的新标记不会回写到哔哩哔哩或豆瓣，各平台记录从此独立生长。

#### 适合什么场景用

| 场景 | 是否适合 |
| --- | --- |
| 从豆瓣/B站搬历史记录，从此以番组计划为主阵地 | 适合，省下大量手工补录 |
| 两个平台都想继续维护记录 | 不适合，只能一次导入作为起点 |
| 只想导入评分不想导入状态 | 先小范围试导，确认字段符合预期再全量 |

#### 使用建议

1. **导入前先确认账号和平台选择**：导入是不可逆的批量写入，搞错了就得手动清；
2. **导入后抽查**：随机翻几部作品的收藏状态与评分，确认映射正确再继续使用；
3. **冲突处理**：目标条目已有你在番组计划上的记录时，导入的覆盖逻辑在不同版本可能有变化，建议先在少量条目上验证再全量操作；
4. **同步入口位置**：功能入口在客户端的设置或工具区，具体位置随版本变动，可以在设置分组里慢慢找。
