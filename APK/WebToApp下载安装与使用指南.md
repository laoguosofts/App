## ✨ WebToApp 是什么

WebToApp 是一款运行在 Android 设备上的本地应用打包工具，核心理念是「把网页变成独立的手机 App」——不需要服务器、不需要云构建、不需要付费订阅，整个打包过程在自己手机上完成，APK 文件直接生成到设备本地。

它的能力远不止简单的网页封装。除了最基础的 URL → WebView APK，WebToApp 还支持离线整站抓取、前端构建产物直接打包、多站点聚合排版，以及一套完整的服务端运行时方案——在手机上原生启动 PHP、Node.js、Python、Go、WordPress 项目，让移动端也能跑后端逻辑。

功能层面，WebToApp 内置了广告拦截、JS/CSS 注入、TLS 指纹伪装、资源加密、V1/V2/V3 全套签名方案、AAB 导出等实用特性，面向的是不想折腾 Android Studio 和原生开发、但又需要快速产出可分发 APK 的独立开发者、技术爱好者和小团队。

## 🔧 安装与首次启动

WebToApp 的安装方式分两种：应用商店下载和直接侧载 APK。两种方式都能正常运行，区别主要在于更新渠道。

### 侧载 APK 的注意事项

从非应用商店来源安装 APK 需要开启未知来源授权，步骤因 Android 版本略有差异：

1. 下载完成后点击 APK 文件
2. 系统弹出「禁止安装」提示时，进入「设置」
3. 找到当前文件管理器或浏览器，开启「允许安装未知应用」
4. 返回安装界面继续完成安装

> [!WARNING]
> Android 11 及以上对未知来源的管控更严格，每个请求安装来源都要单独授权一次。如果装完某个来源想关掉，去「设置 → 应用 → 特殊访问权限 → 安装未知应用」里逐个关闭即可。

### 启动后的第一步

打开 WebToApp 直接进入「我的应用」界面——这里是整个应用的中枢，顶部有搜索框、主题切换和语言切换，中间是已创建应用的卡片网格，底部有大号「创建应用」按钮。首次使用时网格是空的，跟着引导点底部按钮就能开始建第一个应用。

### 高级功能开关

默认情况下创建面板只显示 6 种基础类型：网页、多站点、HTML、离线包、前端、画廊。服务端运行时（PHP、Node.js、Python、Go、WordPress）和单媒体播放器（图片、视频）需要手动开启。开启路径：右上角三点菜单 → 关于页面 → 高级功能开关。打开后返回创建面板，网格会扩展到全部 12 种类型。

## 📖 从类型选择到构建签名：完整上手流程

### 选对类型的快速判据

创建应用时面对 12 种类型卡片，不需要一开始就纠结每个细节——选错了随时可以回到「编辑核心配置」修改。一个实用的选择思路：

| 你的素材 | 选什么类型 |
| --- | --- |
| 只有一个网址想变成 App | 网页 |
| 多个网址想打包到一起 | 多站点（支持标签页、卡片、信息流、抽屉四种布局） |
| 有本地 HTML 文件或 ZIP 包 | HTML |
| 想先抓整站再离线运行 | 离线包 |
| React/Vue/Vite 构建产物 | 前端 |
| 需要完整后端能力 | 开启高级功能后选对应的运行时 |
| 媒体展示为主 | 图片 / 视频 / 画廊 |

每种类型打开后都是类型专属表单（网页类型填 URL，Node.js 类型填项目目录和启动命令），然后共享一套通用配置卡片。

### 构建对话框里的几个关键选项

在「我的应用」里找到目标应用卡片，点三点菜单选择「构建 APK」。弹出的构建对话框有六项需要决定：

- **浏览器引擎**：系统 WebView 或 GeckoView（Firefox 内核）。只要用了拦截、注入、脚本、扩展、加密这些能力，就选系统 WebView——GeckoView 下这些功能没有对应实现。纯网页封装或需要 Firefox 指纹时才选 GeckoView，且 GeckoView 仅提供 arm64-v8a 版。
- **资源加密**：AES-256-GCM 加密打包进 APK 的离线资源，需要系统 WebView。
- **隔离 / 后台运行 / 通知**：按需勾选，服务端运行时类应用通常需要后台运行。
- **全量重建**：跳过增量判断，从模板 APK 重新打包。遇到预览正常但导出功能丢失的情况时，先勾上这个重跑一遍。

### 构建过程在做什么

后台构建器依次完成：复制 shell 模板 APK → 修改包名 → 替换图标和启动画面 → 裁剪权限 → 嵌入序列化后的 app_config.json → 重新对齐原生库（16KB 页）→ 用 V1/V2/V3 方案签名 → 产出最终 APK。全程在设备 CPU 上完成，不联网、不排队，普通网页封装大约 2-5 分钟，带服务端运行时的类型会更久。

> [!NOTE]
> WebToApp 内置 Google 官方 apksig 库，默认同时启用 V1（JAR 签名，兼容所有 Android 版本）、V2（Android 7.0+ 加速校验）、V3（Android 9.0+ 密钥轮换）。证书由用户自行管理，支持创建新证书、从 PEM / PKCS12 导入、导出查看指纹。

### Python 运行时：手机上跑 Flask 和 Django

开启高级功能后可以选 Python 类型，这是 WebToApp 比较有特色的能力——在 Android 上原生启动 CPython，让 Flask、FastAPI、Django 这类 Python 后端直接在手机上运行。

创建流程：选 Python 卡片 → 填项目目录、启动命令、端口号 → 填应用名称和图标 → 保存。首次运行时构建器会在应用存储目录执行 `pip install -r requirements.txt`，和电脑上的逻辑完全一致。

但 pip 在手机上装包有个实际限制：纯 Python 包（requests、flask、django）没问题，原生扩展包（numpy、pandas、pillow）需要预编译的 arm64-v8a wheel。如果 pip 在手机上找不到对应平台的 wheel，会尝试从源码编译——arm64 源码编译大概率失败。推荐的做法是在电脑上先 `pip download --only-binary=:all:` 对应 arm64 平台的 wheel 文件，放进项目目录让 pip 从本地安装。

Django 项目适配还有几个注意点：`runserver host` 必须绑定 `127.0.0.1`；`settings.py` 的 `ALLOWED_HOSTS` 要加上 `127.0.0.1`；数据库推荐 SQLite；`STATIC_ROOT` 需要正确设置并在启动前执行 `python manage.py collectstatic`。

> [!TIP]
> 如果追求更好的移动端性能和更快的冷启动，可以考虑用 Go 重写后端逻辑。Go 编译成单个原生二进制，启动比 Python 解释器快很多，也不需要 pip install 这类依赖安装步骤。每种服务运行时类型都有内置示例项目，第一次接触时先用示例跑通完整流程。

### 预览正常但导出功能丢失？两条路径的差异

这是 WebToApp 开发者最常遇到的坑之一：预览时广告拦截、JS 注入、指纹伪装都生效，导出 APK 安装到真机后这些功能全没了。

根因是 WebToApp 有两条不同的执行路径。**宿主路径（预览）**走的是构建器自身的 classpath，配置直接从内存里的 Room 对象读取，没有序列化环节。**Shell 路径（导出）**则是从嵌入 APK 内部的 app_config.json 里读配置，经过序列化和反序列化两个环节。如果某个配置字段在这两个环节里有格式不匹配或者字段定义不完整，导出 APK 里就会丢失这个功能。

根据开发者的经验，最容易出现漂移的配置项包括：资源加密的密钥读取、JS/CSS 注入的路径格式、MV3 扩展的 CRX 文件位置、hosts 去广告的规则列表长度、TLS 指纹伪装的 GCM 加密配置。

遇到这种情况按顺序排查就行：

1. **全量重建**——构建对话框里勾上「全量重建」重新构建一次，很多漂移只是增量构建缓存没刷新
2. **来回切配置**——在「编辑核心配置」和「编辑通用配置」之间切换一次，确保所有字段都正确序列化到 Room 数据库
3. **检查配置 JSON**——WebToApp Agent 有导出当前应用配置 JSON 的工具，查看 JSON 是否完整
4. **重启构建器**——彻底关闭 WebToApp 后重新打开，Room 数据库缓存有时也会导致读取不一致

日常使用时养成几个习惯能大幅减少漂移：大改配置后先保存、等几秒再构建；不要连续快速改配置后立即构建；关键配置（加密、注入、去广告）在导出 APK 里重点验证；每隔几次构建勾一次全量重建。

### 找到导出的 APK 并分享

构建完成后，从「我的应用」右上角三点菜单打开「文件管理」，所有导出的 APK 和 AAB 文件都在这里。文件管理支持预览 APK 详细信息（包名、签名证书、权限列表）、安装到本机、分享到其他应用（微信、Telegram、网盘等）、删除旧产物。分享通过 Android 系统的分享菜单完成，WebToApp 自身不带远程分享功能。

如果计划上架 Google Play，在构建对话框里选「导出 AAB」格式即可——签名在设备上完成，用自己的开发者账号提交。
