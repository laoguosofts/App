## ✨ App Manager 是什么

App Manager 是一款面向 Android 高级用户的应用管理工具。它的核心能力远不止于备份 APK——批量卸载、自定义签名安装、配置文件一键触发、拦截追踪器、root 下访问应用私有目录……这些功能组合起来，让它成为刷机、迁移、精简系统时的得力助手。

App Manager 支持三种权限档位：无 root 基础版、ADB 增强版、root 完整版。权限越高可用功能越多，但即使没有 root，基础的备份、导出、批量操作也能正常使用。日常场景覆盖从新机初始化、系统瘦身到刷机前后的数据完整备份。

> [!NOTE]
> App Manager 的部分高级功能（如自定义签名安装、批量清除应用数据、root 下文件管理器）需要 ADB 或 root 权限才能执行，但功能本身在应用里都可见，只是执行时会提示权限不足。

## 🔧 安装与权限配置

### 下载与核对

安装前建议核对两件事：一是文件大小是否与下载页标注一致，避免传输损坏；二是版本号与目标设备系统版本兼容——App Manager 对 Android 版本有最低要求，老设备可能跑不了最新版。

### 未知来源授权

如果从非应用商店渠道安装，需要在系统设置里允许「未知来源」或「安装未知应用」权限：

1. 打开系统设置 → 安全 → 安装未知应用
2. 找到当前使用的文件管理器或浏览器
3. 勾选「允许」

> [!WARNING]
> 未知来源授权是全局生效的，装完 App Manager 后建议回退为禁止，避免其他应用未经确认就被静默安装。

### 三种权限档位的差异

| 档位 | 所需条件 | 可用功能 |
|---|---|---|
| 基础 | 无 root，普通安装 | 备份、导出、批量卸载用户应用、冻结（需 device admin） |
| ADB | 开发者选项 + 电脑端 adb | 额外支持批量清数据、批量清缓存、App Ops 设置 |
| Root | Magisk / Supersu | 完整功能：自定义签名安装、系统应用操作、文件管理器访问 /system 和 /data/data/ |

ADB 和 root 都是可选的。先装基础版体验，有需要再升级权限档——App Manager 会自动检测当前权限并启用对应功能，不需要重装。

## 📖 使用入门

### 自定义签名安装——解决覆盖安装的签名不匹配

Android 应用的覆盖安装有个硬性门槛：新 APK 的签名证书必须和旧版完全一致。如果从不同渠道拿到同一个应用但签名不同，常规做法是先卸载旧版再装新版——卸载就意味着数据丢失。App Manager 的自定义签名功能可以在安装前给新 APK 换成旧版的签名，签名一致了就能直接覆盖安装，数据完整保留。

配置签名在「设置 → APK 签名」里进行，核心参数有四个：默认签名方案、密钥库位置（.jks 或 .keystore 文件）、密钥库密码、别名。如果没有自己的 keystore，App Manager 可以生成一个内置密钥存在 Android KeyStore 里——方便但设备绑定，换设备后内置密钥也没了，不适合长期分发。

Android 的签名方案从 v1 到 v4，演进脉络清晰：

| 方案 | Android 支持 | 特点 |
|---|---|---|
| v1 (JAR) | 全部 | 经典方案，文件级改动就会导致签名失效 |
| v2 | 7.0+ | 安装验证更快，防篡改更强 |
| v3 | 9.0+ | 支持密钥旋转，签名密钥自动轮换不影响覆盖安装 |
| v4 | 11+ | 增量安装加速，部分 APK 不用重新签名 |

App Manager 默认用 v2 + v1 同时签，兼顾兼容性和验证速度。安装时弹出的对话框里可以选择保留原签名、用自定义签名或临时换另一个签名，签名完成后会验证签名有效性并展示新证书的 Subject、指纹、有效期等信息，方便确认。

典型场景：签名不同但想保留数据时，先完整备份旧版，卸载旧版，打开新版 APK 选自定义签名并输入旧版签名证书，新版换成旧签名后直接覆盖安装——数据丝毫不丢。

### 配置文件——把常用操作存成一键触发器

配置文件（Profile）是 App Manager 里非常实用但容易被忽略的功能。它把一组预设的操作存成可反复触发的集合，类似游戏里的「一键连招」。比如省电模式可以冻结 10 个预装耗电应用 + 清所有缓存 + 把网络策略设为后台 WiFi only；隐私模式一键阻止所有选中应用的追踪器组件 + 设置 App Ops 只前台允许；刷机前批量完整备份所有用户应用；通勤模式把常用地图/通讯设为不受电池优化，把游戏设为受限。

创建流程很简洁：三点菜单 → 配置文件 → 右上角 + → 进入配置编辑页。编辑页分两个选项卡：「配置」选要执行哪些操作（冻结、卸载、清缓存、备份、恢复、拦截追踪器、App Ops、网络策略、电池优化等），「应用程序」用筛选器或手动勾选决定作用于哪些应用。命名保存后还可以创建桌面快捷方式——桌面上点一下直接触发整组操作。

配置文件和批处理是互补关系：批处理是临时操作，每次多选应用、执行一次就结束；配置文件是持久化的，定义好之后可以反复用、还能通过 Tasker 等自动化应用自动触发。建议先用批处理探索和尝试哪种操作组合适合自己，试好后存成配置文件长期使用。

### 批量卸载——系统预装也能清

批量卸载是批处理菜单里最常用的功能之一。长按应用列表进入多选模式，底部批处理菜单里有卸载选项，选中多个应用后一键执行。三种卸载模式各有场景：普通应用卸载直接清理应用和数据；系统应用更新卸载时会给两个选项——卸载更新回到厂商预装的旧版本（数据保留），或彻底移除应用；如果同一个应用签名变了需要卸载重装，App Manager 可以一条龙完成：先备份数据、卸载、装新版、还原数据。

批量操作前建议先用筛选器锁定安全目标：先筛「用户应用」排除系统应用避免误删，或反过来清预装时筛「系统应用 + 已更新」把厂商加的更新清掉。App Manager 的筛选器支持多条件叠加，可以精确选出目标集合后再批量操作。批处理失败不影响其他项——某个应用卸载失败不会中断整批流程，执行完会列出每项的结果。

### 内置文件管理器——root 下的轻量逆向工具

App Manager 内置了一个轻量文件管理器，定位是配合 App Manager 使用场景的补充，而不是取代 Solid Explorer、CX 这类专业文件管理器。打开路径是三点菜单 → 标签（Labs）→ 文件管理器。

在 root 权限下，文件管理器能访问 `/system`、`/data/data/`、`/etc` 等所有分区，甚至在只读分区也能写。最实用的能力是浏览应用私有目录 `/data/data/<包名>/`，配合 App Manager 的共享偏好编辑器和代码编辑器，相当于一套轻量的逆向工具链。非 root 时只能浏览内部存储、SD 卡、USB OTG 等普通可读目录，不能写系统分区和应用私有目录。

内置文件管理器最有价值的几个配合场景：打开 APK 自动触发 App Manager 安装流程（比系统默认安装器多了自定义签名等选项）、快速导航到 App Manager 备份目录访问已备份的 APK、root 下直接从文件管理器里恢复备份。日常文件管理还是建议用专业文件管理器——内置版功能有限，不支持云盘、SMB、FTP 等协议。

### 权限管理与追踪器拦截

App Manager 的权限管理基于 App Ops 框架，可以精确控制每个应用在什么条件下使用哪项权限——比如只允许某个导航应用在前台时获取位置，后台时禁止。追踪器拦截功能基于静态分析，在安装或扫描 APK 时识别常见的追踪器组件（如 Google Analytics、Mixpanel、AppsFlyer 等），可以一键阻止这些组件的广播接收器和服务，切断追踪路径。

配合配置文件使用效果最好：创建一个隐私模式配置文件，把常用社交、电商应用的追踪器全部标记为阻止，把 App Ops 统一设为只前台允许，点一下桌面快捷方式就完成整套隐私加固。
