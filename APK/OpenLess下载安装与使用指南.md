## ✨ OpenLess 是什么——给重度 AI 用户的语音输入 + Prompt 重构工具

OpenLess 是一款跨平台桌面应用，它的定位不是普通的语音输入法，而是为经常和 ChatGPT、Claude、Cursor 等 AI 工具打交道的人设计的。简单说，它做两件事：**把你说的话准确转成文字**，然后**用 LLM 把口语化的表达自动重组成结构化的 AI Prompt**。

普通语音输入法不管你说什么，输出的都是逐字稿——语气词、重复、停顿全在那里，你还得手动整理才能喂给 AI。OpenLess 的「清晰结构」模式跳过了逐字转写这一步，直接把你的口语需求重新组织成带层次、有约束的 Prompt。比如你对着麦克风讲一段 30 秒的乱序想法，松开热键后出来的是用编号清单和子项组织好的结构化文本，可以直接粘贴给 ChatGPT 让它帮你写邮件、写代码或写报告。

OpenLess 支持三大桌面平台：Windows、macOS 和 Linux。Linux 端 v2.0 起完全抛弃了 Tauri + WebKitGTK 方案，改用 Rust egui/eframe 原生渲染，启动更快、依赖更少。默认提供四种内置模式（清晰结构、纯转写、润色、翻译），同时内置了一个风格市场，社区贡献的风格包可以一键导入使用。如果你对 system prompt 有自己的偏好，也可以在「风格」tab 里从零创建自定义风格包，写好规则后绑定一个全局热键，在任何应用里按一下就能切换到这个风格开始录音。

ASR（语音识别）和润色 LLM 的凭据全部走操作系统级的安全存储（macOS Keychain、Windows 凭证管理器、Linux keyring），不会明文落到磁盘上。首启时需要授予麦克风、辅助功能、全局快捷键监听等权限，这些配置都是一次性的，后面正常使用。

OpenLess 的用户画像很明确：AI 写作者、独立开发者、产品经理、内容创作者——任何每天要和 AI 工具频繁交互、又不想在打字写 Prompt 这件事上浪费时间的人。

## 🔧 安装步骤——三平台各有差异，装前先核对版本

### Windows 安装

Windows 端安装最直接。从下载页拿到安装包后双击运行，按向导提示选择安装路径即可。首次启动时系统会弹出麦克风权限请求，点允许。快捷键监听器会随应用启动自动注册，托盘图标右键可以看到当前状态。

> [!WARNING]
> 如果安装后发现全局快捷键没反应，先打开 OpenLess 的设置页面，检查「权限」一栏里的快捷键监听器状态——如果显示「未启动」，手动点一下让它重新注册。

### macOS 安装

macOS 端首次启动需要处理一个额外的安全环节。OpenLess 运行后会自动请求三项权限：

| 权限 | 设置位置 | 关键提醒 |
| --- | --- | --- |
| 麦克风 | 系统设置 → 隐私与安全性 | 必须开，否则语音识别拿不到音频 |
| 辅助功能 | 系统设置 → 隐私与安全性 | 必须开，快捷键监听和光标注入靠它 |
| 输入监控 | 系统设置 → 隐私与安全性 | 部分 macOS 版本需要额外授予 |

> [!TIP]
> 辅助功能授权后必须**完全退出并重新启动 OpenLess**——点窗口的红叉没用，要用 `Cmd + Q` 彻底退出再打开，授权才会生效。

### Linux 安装——有 glibc 硬门槛

Linux 端的安装门槛是三个平台里最高的。v2.0 起改成了 Rust 原生 Host，只提供 `.deb` 和 `.rpm` 两种包，而且要求系统 **glibc ≥ 2.39**。这意味着 Ubuntu 22.04（glibc 2.35）不能用，需要 Ubuntu 24.04 LTS 或 Fedora 40+、openSUSE Tumbleweed 等同等版本。

安装前先跑一条命令确认 glibc 版本：

```
ldd --version | head -1
```

符合条件就可以直接用包管理器装。Debian / Ubuntu 用户：

```
sudo dpkg -i openless_<版本号>_amd64.deb
sudo apt-get install -f  # 补依赖
```

Fedora / RHEL / openSUSE 用户：

```
sudo rpm -i openless_<版本号>_x86_64.rpm
```

Linux 端没有自动更新机制，每次升级需要手动下载新包覆盖安装。默认录音快捷键是 `Ctrl + /`，和 macOS 的右 Option、Windows 的右 Control 不同——Linux 桌面环境对全局修饰键的处理比较分散，用 Ctrl 组合更通用。如果你用 fcitx5 输入法框架，OpenLess 还提供了 clipboard addon 的集成，可以直接读取选中的文字做润色查询。

### 装完怎么核对

不管哪个平台，装完启动后都去 OpenLess 主窗口的概览页看一眼：ASR 和 LLM 两个状态卡片显示「已配置」是绿底，说明凭据和服务都通了；如果还是灰的「未配置」，说明后面还要填 ASR 和润色 LLM 的凭据。

## 📖 使用入门——从第一次录音到风格包定制，一篇说透

### 首次配置：麦克风、权限、ASR + LLM 凭据

OpenLess 完整跑通需要四个环节都就位：麦克风能录到声音、全局快捷键能监听到按键、ASR 能把音频转成文字、润色 LLM 能把文字重组成 Prompt。权限四件套（麦克风、辅助功能、快捷键监听器）装完启动时系统会自动请求，记得全部点允许。但 ASR 和 LLM 的凭据不会自动填——这部分要手动去设置页面录入。

默认推荐的组合是**火山引擎 ASR + 火山方舟 Ark 润色**，国内网络延迟低、价格友好。打开 OpenLess → 设置 → AI 服务与模型，先添加语音识别渠道，再添加语言模型渠道：

**ASR 渠道**需要填的字段：服务选择（Standard 或 Agent Plan）、App ID、Access Token、Resource ID。**LLM 渠道**需要填的：服务选择（普通 Ark / Agent Plan / Coding Plan）、API Key、Model ID（比如 `doubao-pro-32k`）、Endpoint（默认填火山方舟的地址即可）。两个渠道都填完后各自点一下「验证」，成功了状态卡片就会变绿。

> [!NOTE]
> 所有凭据存操作系统安全存储，不会明文落盘。唯一例外是 v1.x 旧版本的明文配置文件——升级到 v2.x 时 OpenLess 会自动读一次旧 JSON、写进 Keychain/凭证管理器，然后删掉旧文件。

### 清晰结构模式：OpenLess 的核心卖点

普通语音输入法不管你说什么都输出逐字稿。OpenLess 的「清晰结构」模式跳过了逐字转写，直接把你的口语化需求重组成 AI 可以直接理解和执行的结构化 Prompt。举个例子：

你对着麦克风讲一段乱序的想法：「嗯就是我需要给上次客户发的那个 proposal 回复一下对吧，团队内部讨论过了整体方向没问题但是有几个细节要改，首先交付时间太急了想往后推两周，然后预算那边他们报价比预期的高了大概百分之二十能不能谈一下，还有整体上是很想合作的这个一定要给对方个积极信号语气不要太生硬」

清晰结构模式出来的是：

```
回复客户关于之前的 proposal。内部讨论后整体方向没问题，有几个细节需要调整：

1. 交付时间
   (a) 当前时间线太紧，希望能往后推两周
2. 预算
   (a) 他们报价比预期高约 20%，可以重新谈一谈

整体表达对合作的积极态度，语气保持友好，不要太生硬。
```

这个输出已经是结构化、有层次、带约束的 Prompt，可以直接粘贴给 ChatGPT 让它帮你写邮件正文。清晰结构模式做了五件事：去掉所有语气词和重复、提取信息点、用编号和子项组织层次、补全你没说出口的隐含约束、全程保持你的原始意图不做替你决定的事。

对于重度 AI 用户来说，这个差异是数量级的——从「打一个 Prompt 要反复调整 5-10 分钟」变成「按住热键讲 30 秒」。

### 四种内置模式怎么选

OpenLess 默认提供四种模式，覆盖不同场景：

| 模式 | 输出 | 适合场景 |
| --- | --- | --- |
| 清晰结构 | 结构化 Prompt | 喂给 ChatGPT / Claude / Cursor 写需求、写代码、写邮件 |
| 纯转写 | 逐字文字 | 会议记录、访谈整理、需要保留原话的场景 |
| 润色 | 优化后的文本 | 已有初稿想改得更通顺、更专业 |
| 翻译 | 翻译结果 | 跨语言沟通场景 |

切换模式有多种入口：托盘图标右键菜单、状态胶囊滚轮、主窗口概览页的模式切换器。

### 创建自定义风格包——把你的 Prompt 偏好固化下来

内置四种模式覆盖常见场景，但如果你有特定的输出格式偏好（比如每次都要按「背景 / 目标 / 约束 / 输出格式」四段来），或者需要在不同项目间快速切换不同的 system prompt，创建自定义风格包是最实用的功能。

在 OpenLess 主窗口切换到「风格」tab，底部有「新建风格包」入口。创建过程分五步：

**第一步**，给风格包起个带场景关键词的名字，比如「工程 commit 简洁」。

**第二步**，写 system prompt——这是风格包的核心。建议按三段结构来写：角色定位（告诉 LLM 它要扮演什么角色）、处理规则（具体的转换规则，用 bullet 列出来）、输出格式（明确告诉 LLM 输出长什么样）。比如一个 git commit 风格包的 prompt 可以这样写：

```
你是一个资深的 Node.js 开发工程师，擅长编写简洁规范的 git commit message。

处理规则：
- 去掉所有口语化表达和语气词
- 用技术术语而非口语
- 根据改动类型选择 commit 标签：feat / fix / refactor / docs / test / chore
- subject 控制在 50 字符以内，不换行

输出格式：<type>: <subject>
示例：feat: add user profile page
```

**第三步**，保存。新风格包会出现在「风格」tab 的列表里。

**第四步**，测试。切换到刚创建的风格包，按住热键录一段音，看输出是否符合预期。不满意就回到编辑页继续调 prompt。

**第五步**（可选），绑定全局热键。在风格包详情页可以给它绑一个专属热键，比如给「工程 commit 简洁」绑 `Ctrl + Shift + C`。以后在 VS Code 里写完代码，按一下热键就切到这个风格，按住录音快捷键口述改动意图，松开后直接得到规范的 commit message。

风格包还可以导出成 ZIP 分享给同事，对方用「导入 ZIP」就能直接用。

### 日常使用节奏：热键触发 → 录音 → 松开 → 文字出现在光标位置

配置全部就绪后，日常使用就是一套流畅的四步节奏：

1. 把光标定位到要输入文字的地方（ChatGPT 对话框、代码编辑器、邮件正文）
2. 按下全局录音快捷键（macOS 默认右 Option、Windows 默认右 Control、Linux 默认 `Ctrl + /`）
3. 对着麦克风把你想说的话讲出来
4. 松开快捷键，屏幕边缘的状态胶囊会先显示「录音中」，几秒后文字直接出现在光标位置

整个过程不需要打开 OpenLess 主窗口，托盘图标和状态胶囊就够了。如果输出结果需要微调，在当前输入框里直接修改就行——OpenLess 不会覆盖你手动编辑过的内容。
