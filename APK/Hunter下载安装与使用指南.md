## ✨ Hunter 是什么

Hunter 是一款面向 Android 平台的环境痕迹检测工具。它的核心定位不是杀毒、也不是清理软件，而是帮你看清自己的手机上到底留下了哪些技术性痕迹——Root 残留、调试器附加、模拟器特征、Frida 注入、系统镜像被修改的痕迹，这些普通用户看不见但对某些应用和安全场景至关重要的信号，Hunter 都会逐条扫出来。

对于做逆向分析、安全研究的人来说，Hunter 是调试环境自检的利器；对于普通玩机用户，它可以帮你确认二手机有没有被前任 Root 过、第三方 ROM 有没有藏奇怪的东西、自己的设备指纹是不是在某个环节被改了。

Hunter 的核心设计哲学有三条：**全程本地分析、不读私人数据、普通权限就能跑**。它只扫 Android 系统自己暴露的状态信息——进程、挂载点、属性值、Build 字段这些，不碰聊天记录、相册、通讯录。扫描结果留在本机，关掉网络也能正常跑完所有主要检测项。

## 🔧 安装步骤

Hunter 是 Android 平台的独立 APK，安装流程和大多数第三方应用一致：

1. **下载 APK**：从下载页获取最新版本，注意核对文件大小和版本号——避免下载到过期包或二次打包的修改版
2. **开启未知来源授权**：如果是 Android 8.0 以上系统，第一次安装外部 APK 会弹出「允许从此来源安装应用」的提示，勾选允许即可；如果系统设置里把安装权限关了，进「设置 → 安全 → 安装未知应用」手动给文件管理器或浏览器开权限
3. **安装并打开**：安装完成后在桌面找到图标点开，首次启动会请求一些系统信息读取权限（这些都是普通应用权限，不需要 Root）

> [!WARNING]
> 部分定制 ROM 或安全防护软件会对第三方 APK 做额外拦截，提示「此应用可能有害」——这是系统的通用安全提醒，关掉即可，Hunter 本身不会修改你的系统分区。

### 安装后核对

第一次打开 Hunter 后，建议在首页做两件事：

- 看一眼「设备基线」页的 CPU 架构是不是 arm64-v8a（真机）、传感器列表是不是完整——这能帮你确认自己是不是装在了模拟器上
- 检查应用版本号，确保和下载页标注的版本一致

## 📖 从扫描结果看手机的秘密

Hunter 打开后首页就是检测列表，点一下「开始扫描」，几秒之内就能跑完十几项检测。每一项都会标红或标绿，红代表检测到了痕迹、绿代表没发现。下面按几个最常见的场景分别说怎么看。

### Magisk & Root 检测：Root 过的痕迹藏不住

这是 Hunter 检测列表里的第一项，也是讨论最多的一项。它同时扫四种线索：已安装应用列表里有没有 Magisk Manager 或其他 Root 管理应用、系统挂载点有没有 Magisk 的 magic mount 痕迹、`ro.debuggable` / `ro.secure` 等系统属性值是否被改过、SU 二进制文件的路径和权限。

正在用 Magisk 且没开隐藏的话，这项必然报红——Magisk 的残留不可能完全无痕迹。开了 Magisk Hide 但隐藏配置不全，大概率还是会被扫到。即使卸了 Magisk 但没清理干净，残留文件和挂载点也可能触发。

> [!TIP]
> 如果你完全没做过 Root 却看到这项报红，需要认真排查：ROM 本身是不是预装了 Root（部分定制 LineageOS 会自带）？手机是不是二手机、前任机主没卸干净？还是极少数情况下老机型的分区结构被误判了？Hunter 详情页会列出它检测到的具体路径，顺着路径去文件管理器核对比单纯看结论有用得多。

Magisk & Root 检测回答的是「设备上有没有 Root 残留」，而 Magisk Hide 检测回答的是「Magisk 的隐藏功能对 Hunter 自己能不能生效」——两者是不同维度的检测。你开了 Magisk Hide 之后，先跑 Magisk & Root 检测看还有没有残留；如果还报红，再看 Magisk Hide 检测的详情，它会列出干扰隐藏的进程和服务。

### 反调试 & Unidbg：进程有没有被外部干预

反调试（Anti-Debug）和 Unidbg 检测在 Hunter 里是同一项，因为它们都和「进程有没有被外部力量干预」相关。反调试检测的是当前进程有没有处于被调试状态——它读 `/proc/self/status` 里的 `TracerPid` 字段（非零就表示有调试器附加）、检测 `ptrace` 系统调用的状态、检查 `debuggerd` 是否在运行。Unidbg 是一款让 Android SO 文件在 PC 上模拟执行的工具，Hunter 会判断当前环境是不是在 Unidbg 的模拟执行环境里。

用 IDA 或 gdb 正在调试时，反调试必然触发；用 Unidbg 模拟执行时，Unidbg 检测必然触发。某些游戏反作弊框架内部用了反调试，也可能留下痕迹被扫到。

反调试报红但你没在调试怎么办？大概率是以下几种：某款应用自带的反调试机制在运行（银行、游戏、加密钱包常用）、Frida 或 LSPosed 等框架的注入触发了反调试信号、系统自带的调试权限状态残留（解锁开发者选项后可能留下属性值）。Hunter 详情页会给出具体的信号来源——TracerPid 值、检测到的进程名等，顺着路径去排查。

Unidbg 报红在真机上几乎不会出现——因为 Unidbg 是 PC 工具，真机上正常不会触发。真机看到 Unidbg 报红，大概率是误判（某些 ROM 的特定属性值和 Unidbg 环境巧合），先按误报处理。

反调试检测和 Frida & IDA 检测互相印证：反调试报红 + Frida 报红，几乎可以确认有调试环境在运行；反调试报红但 Frida 不报，可能是框架注入或应用自带反调试。

### 模拟器 & 云手机：红是正常的

模拟器或云手机上跑 Hunter，大概率会报多项红——这是预期结果，不是故障。模拟器 / 云手机检测必然红（x86 架构 + 假设备参数太明显）、设备指纹通常红（模拟器的指纹是假的）、ISO 强检测可能红（模拟器用的是定制系统镜像）。这三项红在模拟器上可以直接忽略。

值得查的是另外几项：Frida & IDA 红说明你的模拟器里可能集成了 Frida（如果你自己没装过，可以查模拟器的安全设置）；inline hook / GOT 红可能是模拟器框架本身有注入；Magisk & Root 红取决于你有没有在模拟器里装 Magisk。

> [!NOTE]
> Hunter 在模拟器里只能告诉你「模拟器上的环境」，和你的实体手机完全无关。想测真机，把 APK 装到实体手机上再跑。云手机分两类——真实硬件云手机（远程控制实体手机）可能检测为真机、也可能因为远程控制框架被检测；模拟器型云手机和普通模拟器一样必然被检测。

如果你的实体手机被 Hunter 报了模拟器，按这个顺序排查：进 Hunter 的设备基线页看 CPU 架构是不是 arm64-v8a、传感器列表是不是完整；检查是不是精简 ROM，部分定制 ROM 的属性值和模拟器巧合；跑 Momo / Ruru 交叉验证，只有 Hunter 一个报红大概率是误报；还不行就刷回官方固件重测。

### 隐私边界：它读什么、不读什么

Hunter 在扫描过程中需要读取的系统数据包括：Android ID、IMEI、MAC 地址、Build 属性、进程列表、挂载点信息、已安装应用列表、系统属性（`getprop` 输出）、`/proc` 目录下的状态文件、部分敏感路径的文件列表。这些全部通过 Android 的公开系统 API 或公开文件路径获取，不需要 Root 权限。

但它**不读取任何私人数据**——不访问聊天记录、相册、文档、下载文件夹、通讯录、短信。它只扫系统状态、进程、属性，这些本质上就是 Android 系统自己暴露给普通应用的信息。

和很多商业化安全工具不同（它们会把扫描结果上传云端做「智能云检测」），Hunter 的检测结果只存在本机。关掉移动数据和 Wi-Fi 后跑一遍扫描，你会发现扫描正常完成、结果正常显示——网络只影响检测规则能不能拉取更新，不影响已有的检测逻辑。

检测报告也不上传：扫描完成后首页直接显示，关掉应用就没了（除非应用内部存了历史记录）。要清除历史记录，在系统设置里找到 Hunter，清空应用数据即可。

### 结果解读的几个误区

不要看到一项报红就紧张得不行——Hunter 报红只是告诉你「检测到了某种痕迹」，不等于「你的手机被黑了」。举几个例子：

- 模拟器报红是模拟器本身的设计使然，不是你的手机有问题
- 设备指纹报红在二手机上很常见，前任机主可能改过
- Frida 报红可能是你装的某个玩机工具带了注入框架，自己没留意

正确的姿势是：看详情页、交叉验证、结合自己的使用习惯判断。Hunter 给的是线索，不是定论。
