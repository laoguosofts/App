## ✨ AstrBot 是什么

AstrBot 是一款基于大语言模型的多平台智能聊天机器人框架，支持接入 QQ、企业微信、Discord、Telegram 等主流消息平台，通过统一的配置面板和插件生态快速搭建属于自己的 AI 机器人。它的核心定位是把模型能力和消息渠道解耦——你只需要接好模型 API、选好目标平台，剩下的消息路由、会话管理、权限控制、知识库挂载都由框架一站式处理。

框架内置了可视化 WebUI 管理面板，日常操作基本不需要碰代码：配置模型参数、管理指令开关、编辑人格设定、挂载知识库文档，全在浏览器里点一点就能完成。同时也保留了 JSON 代码编辑模式，适合熟悉配置结构的用户做精细化调整。

AstrBot 采用插件化设计，社区提供了大量可用插件——从网页搜索、图片生成到定时任务、数据统计，装上即生效，不需要自己写代码。如果你有开发能力，也可以基于框架的插件接口扩展自定义功能。

这款框架适合三类用户：想给自己的 QQ 群或频道装一个 AI 助手的个人用户、希望快速搭建企业内部智能问答系统的小团队、以及打算基于 LLM 做二次开发的极客玩家。它的部署门槛不高，Python 环境或 Docker 二选一，十几分钟就能跑起来。

## 🔧 安装指南

AstrBot 支持多种部署方式，桌面客户端最适合新手，Docker 和源码部署适合有一定技术基础的用户。不同方式的数据存储位置不同，但运行后的面板操作完全一致。

### 桌面客户端安装

桌面客户端是最省心的选择——下载对应平台的安装包，双击运行即可。安装完成后首次启动会自动初始化数据目录并生成默认管理员账号。安装过程中如果操作系统弹出安全提示，选择继续即可；macOS 用户可能需要在系统偏好设置里允许应用运行。

### Python 环境部署

1. 确认本地 Python 版本 ≥ 3.10，推荐使用包管理器 **uv** 一键安装：`uv tool install astrbot`
2. 安装完成后执行 `astrbot` 启动，框架会自动下载 WebUI 静态文件并监听默认端口
3. 首次启动后浏览器访问管理面板，按向导创建管理员账号

### Docker 部署

Docker 适合追求环境隔离、希望一键重建的用户。核心思路是拉取官方镜像、挂载数据卷、暴露端口：`docker run -d -p 8000:8000 -v $(pwd)/data:/data astrbot/astrbot`。容器内手动安装的 Python 依赖在重建容器后会丢失，镜像更新后记得补装。

> [!WARNING]
> 无论哪种部署方式，**升级前务必备份 data 目录**——里面包含了全部配置、对话记录、知识库索引和插件数据，升级操作有概率导致配置结构不兼容。小版本升级通常问题不大，跨大版本（如 v3 升 v4）建议等社区反馈稳定后再操作。

### 安装完成后的验证

启动成功后浏览器打开面板地址，能看到登录界面说明框架正常运行。用创建好的管理员账号登录，进入「关于」页面核对版本号，确认与下载时的版本一致。如果登录后面板空白或报 404，大概率是静态文件没就位，可以手动从 Releases 下载 dist.zip 解压到 data/dist 目录覆盖。

## 📖 使用入门

### 配置文件——机器人行为的总纲

机器人的一切行为——用哪个模型、怎么唤醒、谁能用管理员指令、挂哪个知识库——都落在配置文件里。AstrBot 支持多份配置文件并存，每个消息平台实例可以绑定一份独立配置，互不干扰。比如 QQ 群机器人用便宜模型加活泼人格，企微客服机器人用强模型加严谨人格，切换只改绑定关系。

配置优先级从高到低是：会话规则（按会话临时覆盖）> 平台绑定的配置文件 > 全局默认值。理解了这个三层结构，排查行为异常时就能快速定位是哪一层在生效。

面板里编辑配置有两种模式：可视化表单和代码编辑。表单模式分区清晰，按 AI、平台与消息、访问控制、插件四个板块逐项填写，改完**必须点右下角保存**——表单不会自动生效，这是新用户最常踩的空转坑。代码模式适合改复杂结构，编辑 JSON 后先点「应用此配置」把改动灌回表单，再点保存，两步都做完才算保存成功。

### 指令管理——集中掌控所有斜杠命令

机器人在聊天里响应的斜杠指令（如 /help、/reset）一部分内置、一部分由插件注册。「指令管理」页把所有已注册指令集中到一张表里，支持按插件、类型、权限过滤，配合搜索框快速定位。每个指令都可以单独开关，也可以重命名——比如把某插件的英文指令换成自己顺手的名字。

典型的使用场景包括：装了一堆插件后指令列表爆炸，关掉用不到的指令让 /help 列表清爽；两个插件注册了同名指令，重命名其中一个解决冲突；按权限过滤出管理员指令，复核敏感操作是否只对管理员开放。

> [!NOTE]
> 系统插件提供的核心指令（/help、/reset 等）在指令管理页默认隐藏，避免误关导致基础功能异常。禁用插件会连带其注册的全部指令失效，此时指令管理页里它们的开关状态可能与实际表现不一致，先查插件状态再排查。

### 升级与数据维护

data 目录是整套系统的全部家当——核心配置、数据库、对话记录、知识库索引、本地技能包、各插件数据子目录都在里面。不同部署方式的 data 位置不同：桌面客户端在用户目录下的 .astrbot，新版启动器在 .astrbot_launcher，Docker 部署在宿主机挂载的 data 目录。

备份策略的最低要求是定期打包整个 data 目录，升级前必打一份。知识库文档和索引的删除不可恢复，原始资料永远另存一份在 data 之外。改大版本配置前把核心配置文件单独抄一份，出问题时这是最快的回滚依据。

升级方式按部署路径选择：Docker 用户换新镜像重建容器；uv 用 `uv tool upgrade astrbot`；启动器和桌面客户端内更新或重装；源码部署 `git pull` 后重装依赖。面板文件随框架启动自动检查更新，也可以用管理员指令 /dashboard_update 手动触发。

升级后常见异常及处理：

| 异常现象 | 可能原因 | 修复方法 |
| --- | --- | --- |
| 密码正确登不进面板 | 旧面板缓存与新后端不兼容 | 删除 data/dist，重启框架，浏览器强制刷新 |
| 面板显示 404 | 静态文件没就位 | 从 Releases 下载 dist.zip 解压进 data |
| 插件集体罢工 | 大版本升级后插件接口变动 | 逐个更新插件，点一键重载，顽固的等插件作者适配 |
| 行为和以前不一样 | 跨大版本配置结构重构 | 按新版文档重配，不要硬改旧配置文件 |

### 开源协议与合规边界

项目采用 GNU AGPL-v3 许可证，最关键的条款是「网络使用即分发」——如果你修改了源码并用修改版对外提供网络服务（比如架付费机器人），必须开源修改部分。纯个人使用、内部使用不触发这条义务。插件作为独立作品，授权方式由插件作者自定。

官方还附带最终用户许可协议（EULA），约束使用行为本身——不要拿它做违法的事，不要用于骚扰、刷量等滥用场景。中国大陆用户建议使用符合当地法律法规、由模型厂商官方提供或经过备案的模型服务（如 DeepSeek、Moonshot、GLM、MiniMax、Qwen），未经备案的第三方模型服务可能带来服务不可用或法律风险。

插件市场的内容由社区上架，官方明确声明无法完全保证安全性。装插件前看一眼来源和代码仓库，是这个生态里的基本自保动作。
