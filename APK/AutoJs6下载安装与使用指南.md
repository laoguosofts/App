## ✨ AutoJs6 是什么

AutoJs6 是一款运行在 Android 平台上的 JavaScript 自动化工具，它继承了原版 Auto.js 的开源基因，在 Rhino 脚本引擎的基础上构建了完整的无障碍服务自动化体系。简单来说，它让你用几行 JavaScript 代码就能操控手机——自动点击、滑动、识别界面元素、监听系统事件，甚至同时跑多个脚本引擎并行执行任务。

从 2022 年初第一个正式版本发布至今，AutoJs6 已经走过了从「稳定基础」到「功能扩展」再到「成熟架构」的演进路径。v6.0 到 v6.2 阶段主要是修复原版遗留 bug、补齐文档和主题色适配；v6.3 到 v6.5 引入了 OCR 模块和 VSCode 插件生态，远程开发体验逐步完善；v6.6 起架构趋于稳定，重心转向插件化、异步 API 和开发者体验打磨。当前最新稳定版 v6.7.0 于 2026 年 3 月发布，是迄今为止最大的一次版本更新——Rhino 引擎升级到 v2.0.0-SNAPSHOT，新增插件中心、版本历史、回收站等实用功能，OCR 支持 Paddle Lite 双引擎切换，HTTP 模块补齐异步方法，还带来了 cvt、fmt、zip、mediainfo 四个全新的工具模块。

AutoJs6 适合三类用户：想摆脱重复操作的普通用户（自动签到、批量清理）、需要快速验证自动化流程的开发者、以及已经在使用原版 Auto.js 但想要更好体验的老玩家。它的核心能力覆盖了无障碍服务操控、UiSelector 选择器定位、悬浮窗交互、图片识别 OCR、多引擎并发、系统事件监听、本地存储和加密解密等完整链条。

> [!NOTE]
> 从原版 Auto.js 4.1.1 Alpha2 升级到 AutoJs6 时，大部分脚本可以直接运行，少数依赖 Rhino 旧行为的代码需要小幅调整。v6.x 系列内部 API 基本保持向后兼容，但跨大版本升级（比如从 v6.2 跳到 v6.7）建议对照文档更新日志检查差异。

## 🔧 安装步骤

AutoJs6 运行在 Android 设备上，安装过程和普通 APK 略有不同——因为它需要无障碍服务权限才能正常工作。按以下步骤操作：

1. **下载 APK 文件**：打开下载页，根据你的设备架构选择对应版本。绝大多数手机用 arm64-v8a，少数老设备可能需要 armeabi-v7a。文件大小约 30~50MB，下载完成后建议核对文件体积是否在合理范围内。

2. **允许安装未知来源应用**：Android 8.0 及以上需要单独给浏览器或文件管理器授予安装权限。路径通常是「设置 → 安全 → 安装未知应用 → 选择你用来下载的应用 → 允许」。

3. **安装并启动**：点击 APK 完成安装后首次打开，系统会弹出「无障碍服务未开启」的提示。这时进入系统无障碍设置页，找到 AutoJs6，打开开关并确认授权。

> [!WARNING]
> 无障碍服务权限是 AutoJs6 正常工作的必要条件，关闭后所有脚本都会立即停止。建议同时在系统后台策略中把 AutoJs6 设为「允许自启动」和「不限制后台运行」，避免被系统回收。

4. **授予额外权限**：首次运行脚本时，可能还需要授予「所有文件管理权限」（用于读写本地脚本和数据）、「通知权限」（用于发送脚本运行状态通知）、「悬浮窗权限」（用于显示运行日志浮窗）。这些权限可以在设置 → 权限管理中集中查看和调整。

5. **核对版本号**：安装完成后，在编辑器里执行 `log(autojs.version.toString());` 就能看到当前版本信息，确认与下载页标注的版本名和版本号一致即可。

## 📖 从入门到实战的使用路径

拿到 AutoJs6 之后，怎么从零开始写出第一个能跑的脚本？下面按「理解引擎 → 写第一段代码 → 利用工具 → 进阶扩展」的顺序梳理。

### 理解 Rhino 引擎的限制

AutoJs6 使用 Rhino 作为 JavaScript 引擎，它不是浏览器环境——没有 DOM、没有 fetch、也不完整支持 async/await。这意味着在浏览器里写过 JS 的人需要调整一下习惯：定时器用引擎层提供的 setTimeout/setInterval，不要依赖 Promise；sleep() 会阻塞整个引擎，想延迟执行就用 setTimeout 或者开一个新引擎。

### 代码编辑器的核心功能

AutoJs6 内置的 IDE 不是简单的文本编辑器，它具备智能代码感知能力：输入内置 API 名称时会自动弹出补全提示并显示参数类型和返回值；长按变量名可以安全重命名，所有引用位置自动同步；支持一键格式化整理代码缩进；语法高亮区分关键字、字符串、注释、数字和内置 API。v6.7 还新增了「多功能键盘」，可以自定义常用符号的快捷按钮，预设代码片段（比如输入 `log` 自动展开成 `console.log("");`），专为手机上单手写脚本优化。

> [!TIP]
> 如果经常在电脑上写脚本，推荐用 VSCode 搭配 AutoJs6 Extension——支持断点调试、智能重构和桌面级体验。VSCode 插件通过 LAN 或 ADB 两种模式连接手机，写完直接远程执行，比在小屏幕上敲代码高效得多。

### 并发模型：定时器、多引擎和事件监听

Rhino 没有浏览器那样的完整事件循环，但 AutoJs6 通过三层机制覆盖了异步需求。最基础的是全局版本的 setTimeout 和 setInterval，由引擎层直接提供，同一引擎内的定时器排队执行，脚本退出时自动清除。

当需要真正的并发执行时，engines 模块才是正确选择——它可以启动新的脚本引擎实例，让多个脚本并行跑在各自的引擎里。比如同时启动一个签到引擎和一个清理引擎，然后用 engines.waitForAll() 等全部完成。引擎之间通过 globalThis 共享数据，子引擎可以读取和修改主引擎定义的全局变量。

第三层是 events 模块，用来监听 Android 系统事件——屏幕解锁、物理按键、应用启动、通知到达、电量变化等都能触发回调。比如监听屏幕解锁后自动执行某个脚本，或者监听特定应用启动时弹出悬浮窗提示。

| 机制 | 适用场景 | 注意点 |
| --- | --- | --- |
| setTimeout/setInterval | 单引擎内延迟或定期执行 | sleep() 会阻塞整个引擎，改用 setTimeout |
| engines.execScript | 真正的并发，多个任务同时跑 | 跨引擎不要共享 UI 操作，会冲突 |
| events.on | 响应系统或应用事件 | 脚本退出前记得 clearInterval 避免定时器泄漏 |

### 插件中心和实用工具箱

v6.7 带来的插件中心让 AutoJs6 的功能可以按需扩展。入口在主页抽屉按钮或标签页，目前发布的插件包括 Paddle OCR（基于 Paddle Lite 引擎的高精度中文 OCR，比默认的 ML Kit 更准）。安装后在脚本里切换 `ocr.mode = "paddle"` 就能使用，其他用法和 ML Kit 完全一样。

除了插件，AutoJs6 还内置了丰富的工具模块：

- **notice 通知模块**：发送系统级通知，支持标题、内容、声音、震动、呼吸灯和大文本样式，适合脚本运行状态推送
- **qrcode 二维码模块**：生成和解析二维码，还能直接从屏幕截图里识别二维码内容
- **crypto 加密解密**：MD5、SHA-1、SHA-256 哈希，以及 AES 对称加密解密
- **cvt 和 fmt**：字节单位转换和格式化输出，`fmt.bytes(1048576)` 直接得到 `"1.00 MB"`
- **zip 压缩解压**：支持带密码保护的 zip 文件
- **mediainfo**：读取视频文件的时长、宽高、比特率、编码格式等信息
- **storage 本地存储**：简单的 KV 存储，支持任意可序列化对象，比写文件方便得多

> [!NOTE]
> sqlite 和 zip 等文件操作需要先授予「所有文件管理权限」，否则会抛权限异常。插件的权限也是按需单独授权的——比如 Tasker、Shizuku 的集成都需要分别配置。

### 版本查看和升级建议

在编辑器里执行以下代码可以快速确认版本信息：

```javascript
log(autojs.version.toString());
log("版本号: " + autojs.version.versionCode);
log("版本名: " + autojs.version.versionName);
```

升级时建议始终保持最新稳定版，v6.x 系列内部 API 基本向后兼容。跨大版本升级时留意版本日志中的 breaking change 说明，必要时在沙箱里先测一下旧脚本的兼容性。
