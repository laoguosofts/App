## ✨ Safe Haven：把应用来路摊开给你看的安卓商店

Safe Haven 是 ColourSwift 团队推出的一款安卓应用商店，它的核心诉求很明确——解决安卓生态里第三方应用"来路不明"的问题。在 Google Play、F-Droid、IzzyOnDroid 之外，它选择了一条差异化路线：不跟大商店比体量，也不跟自由软件社区比许可严格度，而是把每个应用的来源信息、扫描状态、签名历史全部拆开展示在详情页上，让用户自己判断要不要装。

Safe Haven 最特别的地方在于它**不承诺绝对安全**。官方文档里坦诚写道"Nobody can claim to be perfectly safe"（没人能说自己绝对安全）——扫描引擎有漏报和误报，签名锁定防得住被动篡改但防不住密钥被盗，社区投稿的应用天然缺少开发者归属声明。它不做"安全认证"，做的是**"可审计性"**：把能公开的都公开，让具备判断能力的用户自己权衡。这种坦诚反而让它的整个信任体系更有说服力。

项目整体开源，客户端代码（安卓 App）采用 MIT 协议，后端服务（Cloudflare Workers + S3 + Scanner Python 服务）采用 AGPL-3.0 协议。客户端可以自由集成进其他项目，服务端的任何修改都必须公开——对普通用户来说，你能直接从代码里看到它做了什么网络请求、展示了哪些数据，这是对"它没有偷偷干别的"最直接的证明。

## 🔧 安装步骤

Safe Haven 是一款安卓应用商店客户端，安装流程和普通 APK 类似，但有几个注意点需要留意。

### 从下载页获取 APK

1. 打开下载页，找到最新版本的 APK 文件
2. 核对文件大小和版本号——详情页的扫描记录里会显示该版本的签名哈希，方便后续比对
3. 下载完成后，建议用文件管理器确认 APK 的 SHA-256 哈希值和下载页标注的一致

### 安装到安卓设备

1. 将 APK 文件传输到安卓设备（浏览器直接下载、USB 传输或云盘均可）
2. 如果是第一次从浏览器安装 APK，系统会提示"允许安装未知来源应用"——需要在系统设置中授予对应浏览器或文件管理器的安装权限
3. 点击 APK 文件，按屏幕提示完成安装
4. 安装完成后首次打开，建议先进入设置页检查版本信息是否和安装包一致

> [!TIP]
> 如果系统弹出"此 APK 会覆盖已有应用"的提示，确认你之前安装的是 Safe Haven 官方版本再继续。如果之前装过同名应用但签名不同，安卓系统会拒绝覆盖安装，这种情况建议先卸载旧版本再装新的。

> [!WARNING]
> 不要从非官方渠道下载 Safe Haven 的 APK。第三方重新打包的版本可能已经被篡改签名，安装时安卓系统会直接拒绝——但如果有人换了包名伪装，就需要你自己核对签名哈希了。

## 📖 Safe Haven 的五层信任机制与日常使用

Safe Haven 的使用体验围绕一个核心设计展开：**五层信任机制**。它不做"安全 / 不安全"的二元判断，而是把能拿到的事实拆成五个独立维度，每个维度在应用详情页上对应一个颜色不同的标志。五个标志全亮代表当前能拿到的信息最完整；亮几个看几个；一个都没有的条目，和随便从网上搜一个 APK 没本质区别。

### 五层标志分别说什么

第一层是**源码登记**——应用条目关联了公开的源码仓库链接（GitHub、GitLab 或 Codeberg），用户可以直接点进去看提交历史、Issue 和 Release 记录。它只说一件事：有地方可以去查。有些商业应用选了不开源，那这个标志就不会有，这不是 Safe Haven 漏了，是应用本身没有公开源码。

第二层是**已验证源码**——这是五层里可信度最高的标志。开发者需要在自己的源码仓库根目录放一个叫 `.safehaven` 的文件，文件内容是 Safe Haven 后台给的唯一 token。服务端定期抓取这个文件比对，匹配成功就确认了"仓库管理员自己证明了 Safe Haven 上的条目是我提交的"。有人冒充不了这个标志。

第三层是**未验证上架**——应用条目是社区贡献的或自动化发现的，还没有被原始开发者认领。这个标志默认是红色警示色，让用户一眼就能区分。有这个标志意味着"来路还没确认"，开发者随时可以回来完成认领。

第四层是**APK 扫描**——每个 APK 上架前必须过一遍扫描管线，跑在独立的 Linux VPS 上，核心服务叫 `safehaven-scanner`。扫描管线依次做五件事：计算 SHA-256 哈希检测重复提交、从 manifest 提取真实版本号和包名做比对、提取签名密钥哈希、可选地跑 VX-TITANIUM 引擎（字节结构解析 + ML 分类器检测混淆恶意载荷）、查每两小时更新一次的本地 SQLite 威胁数据库。注意 Safe Haven 自己也承认商业扫描有误报和漏报，VX-TITANIUM 引擎使用签名数据库 + 哈希查找 + ML 分类器，不依赖 YARA 规则。

第五层是**签名锁定**——首次扫描时记录 APK 签名密钥哈希，之后每次复扫比对。哈希变了就触发 `signing_key_changed` 标志，应用进入人工审查。安卓系统安装时也会检查签名（同包名不同签名会拒绝覆盖安装），但 Safe Haven 把这个检查前置到了上架流程里，让用户在安装前就能看到签名是否和历史一致。

> [!NOTE]
> 五层标志是独立判断的，不做合并评分。"已验证源码"不代表"扫描通过"，"扫描通过"不代表"签名没被篡改"。Safe Haven 刻意不做综合安全评分，因为权重怎么算都会有争议。

### 提交评分的规则与常见失败

Safe Haven 支持用户给应用打分（1~5 星整数），但防刷机制相当严格。每台设备对每个应用**只能评一次**——客户端首次提交时生成设备唯一 token，把 `SHA256(token + packageName)` 提交给服务端，服务端存这个哈希，同一个哈希再次出现就直接忽略。每 IP 每小时最多 10 次评分提交，多台设备在同一根网线下共享这个限额。

评分功能最常见的失败原因有三个：你已经评过了（客户端可能根本不允许再次提交）、达到了 IP 限频、网络请求超时被 Cloudflare Workers 拦截。如果想重新评分，需要卸载 Safe Haven 再装（会重新生成 device token），但不推荐这么做。

评分数据是聚合公开的——索引里只有 ratingSum 和 ratingCount，不记录任何可识别的评分者信息，这既是保护隐私，也是防止爬虫反推刷分行为模式。Top Charts 是设备端实时计算的，输入从索引里拿，所以刚提交的评分不会立刻在榜单上体现，索引同步通常需要几分钟到几小时。

### 开发者徽章：一行代码加到 GitHub README

Safe Haven 为每个进目录的应用提供了"Get it on Safe Haven Store"徽章——类似 Google Play 和 F-Droid 的下载徽章。徽章有 SVG 和 PNG 两种格式，SVG 推荐用于 README 和博客（矢量图、缩放不失真、加载快）。开发者用标准 Markdown 语法把徽章嵌入，点开直接跳到应用在 Safe Haven 的详情页。

从 v2.0.8 起，徽章链接支持深链接：手机上已安装 Safe Haven 客户端会自动唤起并跳到对应包名的详情页，未安装则打开浏览器落到 Web 前端页面。一个应用同时在多个商店上架时，README 里可以把多个商店的徽章并排放在一起，互不冲突。

加徽章的前提是应用已经进了 Safe Haven 目录、开发者已完成 `.safehaven` 文件握手验证。如果应用被移除，徽章链接会变成 404，需要开发者手动更新——Safe Haven 不会主动通知。

### 和其他商店的定位差异

Safe Haven 和几个主流替代商店的定位刻意错开：和 F-Droid 比，它没有自由软件和可复现构建的许可门槛，从 F-Droid 和 IzzyOnDroid 同步已有应用，收录侧重开源和独立应用；和 Google Play 比，它的安全机制完全透明，把扫描结果直接展示给用户看；和 Aurora Droid 这类 F-Droid 客户端替代品比，它是独立商店，有自己的后端和扫描管线，不依赖 F-Droid 仓库。

### 你装应用时最该看什么

详情页上的信息很多，按优先级排序：先看有没有**已验证源码**标志（开发者自己在管的应用最靠谱），再看源码仓库最后一次提交时间判断维护活跃度，然后看扫描记录里的签名哈希和你本地装的版本对不对得上，没有验证标志时重点看扫描结果里有没有恶意代码检出。
