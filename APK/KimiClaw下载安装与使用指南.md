## ✨ KimiClaw 是什么

KimiClaw 是 Kimi 推出的个人 Agent（智能体）运行平台。你可以把它理解成一个可独立运行、长期在线的 AI 助手——它不只是聊天，而是能持续执行任务、调用工具、接入各种外部渠道，甚至让多个 Agent 协同工作。

KimiClaw 有三种部署形态：**云端托管版**（最省心，Kimi 帮你管服务器）、**Android 终端版**（跑在手机上、操控手机 App）、**桌面端**（Mac/Windows 本地部署，数据全在本地）。三者底层都是 OpenClaw 网关，能力对等，区别只在运行位置和数据归属。

核心能力可以归纳为四点：

1. **长期在线**：不同于网页对话关了就断，KimiClaw 实例是持久运行的，可以定时触发、后台执行。
2. **多渠道接入**：内置微信、飞书等聊天渠道插件，扫码几步就能在常用的通讯工具里直接和 Agent 对话。
3. **多 Agent 协作**：Kimi Conductor 可以把多个 Claw 拉进一个群聊，自动拆分复杂任务、分工执行、汇总结果。
4. **技能扩展**：接入 ClawHub 技能库，5000+ 技能一键安装，相当于给 Agent 装插件。

适合谁？如果你只是偶尔问个问题，普通的 Kimi 对话就够了；但如果你需要让 AI 帮你持续跑任务、跨渠道响应、或者让多个 AI 协同完成一个复杂项目，KimiClaw 就是为这个场景设计的。

## 🔧 如何创建你的第一个 KimiClaw

KimiClaw 没有传统的"安装包双击安装"概念——它的"安装"就是在 Kimi 平台上创建一个实例。三种形态的创建流程略有不同，下面分别说。

### 云端托管版（推荐新手）

这是最省心的方式，90% 的用户从这里开始。

1. 打开 **kimi.com/bot**，登录你的 Kimi 账号
2. 页面中央会有一个 **创建 Kimi Claw** 按钮，点击它
3. 等待 1-3 分钟——Kimi 会在云端自动完成所有配置：分配虚拟机、部署 OpenClaw 网关、接入默认模型（Kimi K2.6 Thinking）、关联会员额度、分配 40GB 云端存储空间、连接 ClawHub 技能库
4. 配置完成后设置一个昵称（建议 2-8 个字符，带点角色辨识度，比如"投研小爪"）
5. 进入网页端对话界面，开始使用

> [!TIP]
> 创建完成后去设置页面看一眼：模型默认是 Kimi K2.6 Thinking，如果你的使用场景对模型有特殊要求（比如更快的响应、更低的成本），可以在这里切换。

### Android 终端版

想让 Agent 操控手机 App、或者用闲置手机做一个 7×24 在线的 Agent，选这个形态。创建后 Agent 跑在你的 Android 设备上，可以调用手机的各种能力。

### 桌面端（Mac / Windows）

适合隐私敏感或有深度自定义需求的用户。创建流程和云端版类似，但数据完全保存在本地电脑上，没有 40GB 云端存储，Agent 只在电脑开机时在线。

| 形态 | 部署方式 | 数据位置 | 在线条件 | 适合谁 |
|---|---|---|---|---|
| 云端托管 | kimi.com/bot 一键创建 | Kimi 云端 | 7×24 | 绝大多数用户 |
| Android 终端 | 手机上安装 | 本地手机 | 手机开机 | 想操控手机、闲置设备复用 |
| 桌面端 | Kimi 桌面应用内创建 | 本地电脑 | 电脑开机 | 隐私敏感、开发者、深度自定义 |

> [!WARNING]
> 桌面端和 Android 终端版都需要 Kimi 会员等级达到 **Allegretto 或以上** 才能使用。云端托管版的额度会自动关联到你的会员账户。

### 怎么核对创建成功

创建完成后你应该能看到：

- 网页端或对应客户端出现 Claw 的头像、昵称、对话窗口
- 设置页面能看到模型信息、存储用量、聊天渠道配置
- 对话一个简单问题（比如"你好"）能得到正常响应

如果卡在"正在配置"超过 5 分钟没变化，刷新页面或重新走一遍创建流程即可。

## 📖 从对话到协作——KimiClaw 进阶使用

创建好实例只是起点，下面聊聊怎么把 KimiClaw 真正用起来。

### 基础对话

创建完成后直接在网页端或客户端就能对话——界面很简洁：顶部是 Claw 头像和昵称，中间消息区，底部输入框。和普通 Kimi 对话的区别在于，这个 Claw 是**你的专属实例**，有独立的记忆空间，可以长期保持上下文。

### 接入常用聊天渠道

不想每次都打开网页？KimiClaw 支持接入微信、飞书等聊天渠道，直接在你常用的通讯工具里和 Agent 对话。以微信为例，2025 年 3 月 22 日之后创建的 Claw 已经内置微信插件，四步完成绑定：

1. 在 Claw 设置里找到 **聊天频道 → 微信**，进入连接界面
2. 页面显示二维码，用微信扫一扫（同手机的话先截图再从相册识别）
3. 微信里点击"连接"，等待 10-30 秒完成
4. 回到微信就能直接和 Claw 对话了

> [!NOTE]
> 每个微信账号只能绑定一个 KimiClaw。要换绑的话先在旧 Claw 里解除连接，再去新 Claw 扫码。

飞书、企业微信等渠道的接入流程类似，都是扫码确认的模式，按页面引导走就行。

### 多 Agent 群聊协作

这是 KimiClaw 最有特色的能力。你可以把多个 Claw（云端版、Android 版、桌面版都行）拉进一个群聊，让它们在 **Kimi Conductor** 的调度下分工完成复杂任务。

群聊里有两个角色：

- **Conductor（指挥）**：由 Kimi 自动分配，负责理解整体目标、拆解成子任务、调度 Claw 分工执行、汇总结果
- **Claw（龙虾）**：你自己的各个 Agent 实例，接收指挥分配的具体任务、执行并汇报

什么时候用群聊？举几个典型场景：

- **复杂项目分工**：做一份多城市攻略，让一个 Claw 搜餐厅、一个搜酒店、一个生成可交互网页地图——Conductor 自动拆分调度，比你手动在不同对话间切换高效得多
- **多视角评估**：纠结要不要接一个外包项目，让几个 Claw 分别从钱、时间成本、长期发展这几个角度分析，互相挑战覆盖盲区
- **多专业协作**：出一期播客，一个 Claw 做背景调研和提纲、一个写逐字稿、一个出封面设计描述
- **角色扮演**：让几个 Claw 扮演不同哲学家，你抛一个问题让它们辩起来
- **多设备协调**：每天早上 9 点，一个 Claw 读天气和日历、一个生成穿搭建议、一个列今日三件事，用音箱播报

| 对比维度 | 单聊（一个 Claw） | 群聊（多个 Claw） |
|---|---|---|
| 谁来规划 | 你自己 | Conductor 自动规划 |
| 谁来执行 | 这一个 Claw | 多个 Claw 分工 |
| 记忆空间 | 独立记忆 | 各 Claw 保持独立记忆 |
| 适用任务 | 简单直接的对话 | 复杂多步骤项目 |
| 额外开销 | 无 | 至少 2 个 Claw 实例 |

> [!TIP]
> 群聊里用 `@` 可以直接点名某个 Claw，让它跳过 Conductor 的调度直接响应。适合你知道具体该找谁干的场景。

### 技能扩展

KimiClaw 连接了 ClawHub 技能库，里面有 5000+ 现成技能可以一键安装。从设置页面进入技能库浏览，找到需要的技能点安装就行——相当于给你的 Agent 装插件，能做的事情一下子多了很多。

### 命令行与终端

对开发者来说，KimiClaw 还提供了网页端命令行终端，可以直接执行 OpenClaw 底层命令，做一些高级配置和调试。这个入口也在设置页面里。

### 三端选择总结

还在纠结选哪种形态？简单回顾：

- **90% 用户选云端托管**：不用管服务器、7×24 在线、省心
- **想操控手机或用闲置手机**：Android 终端版
- **数据必须在本地、需要深度自定义**：桌面端（Mac/Windows）

三种形态的能力完全对等，只是运行位置不同。你甚至可以同时创建多个不同形态的 Claw，拉进一个群聊里协同工作。
