## ✨ DataBackup 是什么

DataBackup 是一款开源的 Android 应用备份与恢复工具，专注于把你手机上装的每个应用完整打包出来——包含 APK 安装包本身和应用的数据目录（比如微信聊天记录、游戏存档、App 内部设置）。它不需要 root 就能备份大部分应用，但 root 后能覆盖更多系统级应用和私有数据。

这款工具的核心定位很明确：**把手机上的应用状态完整快照下来，随时恢复**。适合刷机党、换机用户、喜欢折腾 ROM 的玩家，也适合想给常用应用做个定期备份的普通用户。它把每个应用的 APK 和数据分别打成 tar 包，再用 zstd 压缩成 `.tar.zst` 格式——公开标准格式，不绑死 DataBackup 自己，将来换工具也能解压查看。

DataBackup 有两种构建版本和四种架构变体可选，分发渠道包括 GitHub Release 和 F-Droid。最新版本基于 v2.0.12 编写，安装包体积约 12.78 MB，要求 Android 8.0 及以上。

> [!NOTE]
> **foss 还是 premium？** 绝大多数用户选 foss 版本就对了——功能完全一致，只是不带 Firebase 相关的统计和推送，更干净。premium 不是付费版的意思，只是构建配置不同，仅当你特别需要 Firebase Cloud Messaging 推送通知时才考虑。

## 🔧 安装与版本选择

DataBackup 安装本身很简单，但选对版本和架构是关键——装错架构可能安装失败或装上后打开即闪退。

### 确认设备架构

每个构建（foss 和 premium）都提供四种 CPU 架构变体：

| 变体 | 适用场景 |
| --- | --- |
| **arm64-v8a** | 绝大多数现代 Android 手机（64 位 ARM），首选 |
| **armeabi-v7a** | 老旧 32 位 ARM 设备，近十年的手机基本不用 |
| **x86** | 极少数 Intel x86 架构 Android 设备 |
| **x86_64** | PC 模拟器（如蓝叠、夜神），以及少数 x86_64 设备 |

近十年的手机直接认准 **arm64-v8a** 就行。如果不确定，可以用 AIDA64 或 CPU-Z 等工具查看，也可以在 DataBackup 的欢迎向导里走一遍 ABI 验证步骤，它会自动检测并提示。

### 安装流程

1. 从下载页或 F-Droid 获取对应架构的 APK 文件
2. 在手机设置中开启「未知来源」允许安装第三方应用
3. 点击 APK 文件完成安装
4. 首次启动时跟随欢迎向导完成 Root 授权（可选但强烈建议——不 root 只能备份部分应用）

> [!WARNING]
> **务必核对版本号和架构**：下载后先核对文件名中的架构标识（arm64-v8a / x86_64 等）与设备匹配，安装完后打开 App 确认版本号与下载页标注一致。

## 📖 使用入门

### 备份的核心逻辑

DataBackup 的备份过程分两步：先把每个应用的 APK 和数据目录分别打 tar 包，再用 zstd 压缩成 `.tar.zst` 格式。APK 和数据分开压缩的好处是恢复时可以只解其中一个——比如只想恢复游戏存档而不想重装 APK，或者想提取某个旧版 APK 单独安装。

选择 zstd 而非 gzip 或 xz 是因为它在速度和空间之间找到了现代平衡点：压缩速度是 gzip 的 3~5 倍、xz 的 10 倍以上，压缩率比 gzip 好约 20%，解压速度也是三者中最快的。对于一次要处理几十上百个应用的备份场景，这个速度优势直接体现在等待时间上。

### 备份到本地

本地备份是最简单直接的方式：进入 DataBackup 主界面，勾选你想备份的应用（支持全选和分类筛选），选择本地文件夹作为备份目录，点击开始。备份产物会按应用名创建子目录，里面分别放 APK 包和数据的 tar.zst 文件。

### 备份到 NAS（以群晖为例）

有 NAS 的用户可以直接把备份产物落到 NAS 上，省手机存储空间还更安全。

**前置条件**：一台配置好局域网访问的群晖 NAS（DSM 7.x 或 6.x 均可），DataBackup 已完成 Root 授权。

**操作步骤**：

1. **群晖上开 WebDAV**：DSM → 套件中心安装「WebDAV Server」，勾选启用 HTTPS（推荐，传输加密），HTTPS 默认端口 5006
2. **创建备份共享文件夹**：DSM → 控制面板 → 共享文件夹，新建一个共享文件夹（比如命名为 `databackup`），确保你的 DSM 登录账号有读写权限
3. **DataBackup 里填连接**：进入云端设置 → WebDAV，填写 URL（`https://<NAS内网IP>:5006/webdav/`）、DSM 用户名、密码、路径（共享文件夹名），点「测试连接」确认成功后保存
4. **备份时选云端目录**：回到备份主界面，选备份目录时选择刚才配置的 WebDAV 连接，之后正常勾选应用开始备份

> [!TIP]
> **内网先测通**：如果手机和 NAS 在同一个局域网，直接用内网 IP 最简单。外网访问需要路由器端口转发或群晖 QuickConnect / 公网 IP + 动态 DNS。备份完成后建议也在手机本地留一份，双重保险比单一云端更稳。

**常见问题**：

| 问题 | 排查方向 |
| --- | --- |
| 连接测试报 403 | DSM 防火墙确认 5005/5006 端口已放行，或检查 IP 拦截规则 |
| TLS 证书错误 | DSM WebDAV 可能用自签名证书，测试阶段可勾选「忽略证书验证」，长期建议配正规证书 |
| 备份速度特别慢 | 检查 NAS 磁盘状态和路由器 Wi-Fi 速率；局域网内 WebDAV 备份几十个应用大约 2~5 分钟属正常 |

### 跨用户数据还原

DataBackup 还支持把一个用户的备份还原给另一个用户——比如把主空间（Owner）的应用数据同步一份到分身（Work Profile），或者换了新分身空间后快速导入主空间的应用配置。

**操作步骤**：进入恢复界面，选择备份目录和应用，在恢复设置里把「恢复到用户」切换成目标用户（比如 Work Profile），然后正常跑恢复流程。DataBackup 会把备份数据写入目标用户对应的数据目录。

> [!WARNING]
> **跨用户还原的数据安全边界**：这项功能会把备份里的应用数据完整复制到目标用户的数据目录——微信聊天记录、支付宝登录态都可以跨用户还原。如果本意是两个用户数据隔离，就别乱用。另外，目标用户必须先手动装好同名应用（仅恢复数据模式），极少数安全敏感应用（某些银行 App、企业管理 App）可能检测到数据目录异常而拒绝启动，这种情况只能卸载重装。
