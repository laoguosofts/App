## ✨ MikuMikuDance 是什么

MikuMikuDance（简称 MMD）是一款由日本开发者 Higuchi Yuu 于 2007 年发布的免费 3D 动画制作软件。它最初是为虚拟歌手初音未来设计的，如今已经发展成为一个拥有海量社区模型、动作、特效资源的 3D 创作生态。

MMD 的核心能力可以概括为三件事：**加载 3D 角色模型、为模型 K 骨骼关键帧动画、使用 Bullet 物理引擎让头发裙摆自动飘动**。你可以把它理解为一个轻量级的 3D 动画舞台——不需要复杂的建模技能，直接从社区下载现成的 PMD/PMX 模型、VMD 动作文件和舞台场景，就能快速编排一段舞蹈或剧情动画。

版本选择上，社区目前最推荐的稳定版本是 **9.26 和 9.32**。9.26 发布于 2019 年，虽然不是最新版，但部分特效插件仅针对这个版本开发；9.32 是最新稳定版，修复了 64 位版本的若干 Bug。对于绝大多数用户来说，**64 位架构 + 9.32 版本**是首选——64 位版本没有 4GB 内存限制，可以轻松处理多模型+大舞台场景。

值得一提的是，社区还有一个活跃的分支项目 MikuMikuMoving（MMM），在原版基础上加入了多轨时间轴、非线性编辑、更新版本的 Bullet 物理等功能。

## 🔧 MMD 安装与系统要求

### 系统兼容性

MMD 是 Windows 专属软件，**不支持 Linux / macOS**（Wine 兼容层有成功案例但不推荐新手尝试）。支持的系统范围覆盖 Windows 7 SP1 到 Windows 11。推荐在 Windows 10 64 位下运行——这是社区反馈最稳定的平台，Win11 虽然也能跑，但部分用户报告了兼容性问题。

### 硬件配置

MMD 对硬件要求不算苛刻，但物理演算和实时渲染会吃资源：

| 项目 | 最低配置 | 推荐配置 |
|------|---------|---------|
| CPU | 双核 2GHz+ | 四核 3GHz+（i5 / Ryzen 5 以上） |
| 内存 | 4GB | 8GB 以上 |
| 显卡 | 支持 DirectX 9.0c 的独显（集显也能跑） | GTX 1060 / RX 580 以上 |
| 硬盘 | 100MB 安装空间 | 模型资产另计，建议预留 10GB+ |

### 安装步骤

MMD 采用绿色发布——下载后解压到任意目录即可运行，**不需要传统安装向导**。但有几个关键注意点：

1. **解压路径必须纯英文**。MMD 对非 ASCII 字符的支持非常糟糕——文件路径中出现中文、日文或空格，都可能导致模型加载失败、贴图丢失、特效无法识别甚至物理演算崩溃。这是新手最常踩的坑。
   > [!WARNING]
   > 铁律：把 MMD 解压到 `D:\MMD\MikuMikuDance932\` 这样的纯英文路径下。`C:\Users\张三\桌面\MMD中文版\` 这种路径 100% 会出问题。模型文件和贴图路径同理，尽量保持英文。

2. **安装 Visual C++ 运行库**。这是 MMD 启动失败的头号原因。MMD 9.32 依赖 **Visual C++ 2015-2022 Redistributable**，x64 和 x86 两个版本都要装。Windows 10/11 通常自带 DirectX 9.0c，一般不需要额外安装。

3. **双击 MikuMikuDance.exe 启动**。首次启动会弹出一个窗口提示你选择界面语言，选中文即可。如果提示缺少运行库，回到第一步补装。

### 32 位 vs 64 位怎么选

MMD 同时提供两个架构版本，选择规则很简单：

- **64 位版（x64）**：绝大多数人直接选这个。没有 4GB 内存限制，多模型场景更从容。
- **32 位版（x86）**：唯一理由是你非常依赖某个只支持 32 位的老插件。内存上限约 2GB，模型多了容易爆内存。

## 📖 使用入门：从角色加载到动画输出

MMD 的学习曲线不算陡峭，但要真正用好需要掌握几个核心系统。以下是基于社区常用的工作流，整理出来的关键操作要点。

### 模型、动作、场景的三件套

MMD 的创作素材主要来自社区分享：

- **PMD / PMX 模型**：3D 角色模型文件，包含骨骼绑定、贴图、物理刚体等信息。PMX 是 2010 年后的主流格式，兼容性更好。
- **VMD 动作文件**：骨骼关键帧数据，直接加载就能让模型跳舞、做动作。
- **舞台 / 场景**：PMX 格式的静态场景模型，或者 BMP/PNG 格式的背景图片。

在 MMD 界面左侧的模型列表面板点击「读取」，依次加载模型、动作和舞台。模型加载后会出现在视口中央，VMD 动作加载到模型后，拖动时间轴就能看到动画回放。

### Bullet 物理引擎：让头发裙摆动起来

MMD 5.00（2009 年）引入了 Bullet Physics 2.75 物理引擎，这是 MMD 历史上的一个转折点——在此之前，头发和裙摆需要手动 K 每一帧，现在物理引擎自动模拟出自然的摆动效果。

物理系统基于两种刚体类型：

**动力学刚体（Dynamic Rigid Body）**——会被物理引擎主动模拟的刚体，用于头发、裙摆、耳坠、手链等需要动态效果的部位。它们有碰撞体积、受重力影响、有质量和弹性系数。你动头的时候头发会飘，就是因为动力学刚体在重力和碰撞作用下跟随头部运动方向做自然摆动，而不是被骨骼"拽着走"。

**运动学刚体（Kinematic Rigid Body）**——完全跟随绑定骨骼的刚体，用于角色的躯干、头、手臂、腿等部位。它们本身不做物理计算，碰撞体积只用来阻挡动力学刚体。

一个完整的模型里，身体各部位是运动学刚体，头发/裙摆/配饰是动力学刚体。当身体运动时，动力学刚体因为碰撞和重力被带动起来。两者之间通过**关节约束（Constraint）**连接，约束类型包括固定、铰链、球形、弹簧等——决定了两个刚体之间能怎么动。

### 物理开关的四种控制层级

物理演算会消耗不少计算资源，MMD 提供了多个层级的开关来灵活控制：

**全局物理开关**在播放控制条上，影响场景里所有模型。关掉它，所有动力学刚体冻结，头发裙摆保持默认姿势——K 骨骼姿势的时候先关物理，否则头发会被物理拉着走和你 K 的骨架冲突。

**单模型物理开关**在模型列表面板里，每个模型有独立的物理复选框。多模型场景里可以让部分模型关物理以提高性能。

**部分物理**是更细粒度的控制——只关闭某几根骨骼的物理，比如只关头发保留裙摆。

**物理烘焙**（Physics Bake）则是一次性操作——让物理引擎跑完一遍模拟，把每一帧的结果写入关键帧。烘焙后动画完全确定性，每次播放一模一样，后续不再需要物理引擎计算。烘焙前一定要存备份，因为它是破坏性操作，会覆盖原来的骨骼关键帧。

> [!TIP]
> 物理穿模（头发穿过身体、裙子穿过腿）是最常见的问题。根源通常是刚体体积太大、碰撞组设置不当、关节约束太松或物理步进频率太低。大多数社区模型已经配好了物理，新手不要轻易改刚体设置——改坏了头发会飞上天或粘在头上不动。真遇到严重穿模再用 PMX Editor 调整。

### PNG 序列导出：最高画质的输出方式

MMD 社区公认的最高质量导出方式是 **PNG 序列**——每一帧单独导出为一张无损 PNG 图片。

PNG 序列对比 AVI 有显著优势：画质无损零压缩、支持 Alpha 透明通道（导出后可以只保留角色不带背景）、后期灵活度高可以逐帧独立处理。代价是文件体积大——1080P 每帧约 2-5MB，3 分钟视频就是 12-30GB，导出前务必确认磁盘空间充足。

导出流程：文件菜单 → PNG 出力 → 设置输出目录（纯英文路径）、文件前缀、帧范围、帧数填充位数（建议 6 位如 000001）→ 是否包含背景（合成用选透明）→ 开始渲染。导出过程中 MMD 会卡住，这是正常的逐帧渲染，不要强杀进程。

想导出带透明通道的 PNG（只有角色没有背景），可以安装社区的 **o_Png 插件**，比原生 PNG 输出快 2-5 倍，还支持并行渲染和元数据导出。

### 后期合成建议

导出 PNG 序列后，需要用视频合成软件把它们变成最终视频：

| 软件 | 适合人群 | 说明 |
|------|---------|------|
| DaVinci Resolve | 专业/免费首选 | 免费版够用，色彩调整强 |
| Premiere Pro | 专业/准专业 | 行业标准 |
| After Effects | 特效合成 | 支持 Alpha 通道 |
| Blender | 免费开源 | 全功能，自带合成节点 |
| 剪映/CapCut | 新手 | 简单、中文界面 |
| ffmpeg | 命令行用户 | 批量处理效率高 |

PNG 序列是原始素材，归档时不要只留最终 MP4——如果以后需要重新合成或改效果，原始 PNG 是唯一无损来源。建议压缩成 ZIP 归档（PNG 序列的 ZIP 压缩率很高），和 PMM 项目文件、原始音频、VMD 动作用同一归档包。

### 性能优化要点

物理演算+多模型+重特效是 MMD 性能消耗的三大来源。FPS 掉得厉害时，可以按以下顺序排查：

1. 先关物理——如果 FPS 立刻飙升，说明物理演算在拖后腿
2. 关掉不需要的模型的物理，或把物理结果烘焙成关键帧
3. 导出 PNG 序列时关闭不影响最终画面的 MME 插件
4. 调高物理步进频率和子步能减少穿模，但也增加计算量——先尝试缩小刚体体积，再考虑调全局参数
