## ✨ Amarok 是什么：二十年仍在迭代的收藏管理型播放器

Amarok 是一款 GPL 开源的本地音乐播放器，核心卖点不在"能出声"而在"会管理"——它把音乐收藏当成一个真正的资料库来对待，而不仅仅是播放列表的集合。软件起源于 2003 年，2.x 时代曾是 KDE 桌面生态的标志性播放器之一，沉寂多年后于 2024 年以 3.0 版本重新发布，目前仍在活跃迭代中（3.3 于 2025 年 7 月发布）。

与常见的轻量播放器不同，Amarok 的目标用户是**曲库规模较大、有整理需求**的听众：几百首以上的本地音乐、需要评分统计筛选、希望围绕一首歌拿到周边信息的场景下，它的完整收藏体系才真正发挥价值。

软件本身不收费、没有会员、没有广告——开源社区作品，不存在商业模式。任何地方遇到"付费版""解锁版"的说法都可以直接判定为捆绑了别的东西。

> [!NOTE] 平台定位
> Amarok 的开发团队几乎都在 Linux 环境下工作，**当前版本（3.2.2 及以后）没有 Windows 和 macOS 的官方安装包**。Linux 用户可以放心安装，非 Linux 平台请先阅读后文的平台说明再决定。

## 🔧 安装步骤

### Linux（主力支持平台）

Linux 上的安装是最顺畅的，两条主要途径任选其一：

| 途径 | 适用场景 | 操作 |
|------|----------|------|
| 发行版仓库 | 追求稳定、随系统更新 | `sudo apt install amarok`（Debian/Ubuntu）或对应包管理器命令 |
| Flatpak | 非 KDE 桌面用户、跨发行版通用 | `flatpak install flathub org.kde.amarok` |

> [!TIP] 非 KDE 桌面也能用
> Amarok 依赖部分 KDE 库才能运行，但在 GNOME、XFCE 等其他桌面环境下正常工作，代价是安装时会带入 KDE 相关的依赖库（磁盘占用稍大）。**Flatpak 版自带完整运行时**，非 KDE 用户推荐优先选这条途径。

### Windows 和 macOS：没有官方安装包

这一点必须明确说明白：

- **Windows**：上一个真正发布过 Windows 安装包的版本是 **2.8.0（2013 年）**，距今已十余年，界面和功能停留在两代之前。当前 3.x 版本理论上可以自行编译，但官方没有提供发行版，也没有持续的 Windows 测试保障。
- **macOS**：与 Windows 类似，源代码开放但无官方安装包，历史上 2.x 时代曾短暂提供过渠道，同样早已停更。

> [!WARNING] 别下载来路不明的第三方包
> 网上流传的所谓 Windows 安装包大多是那个 2013 年的 2.8.0 古董版，与当前 3.x 完全是两代软件。下载非官方打包文件要格外当心安全风险。

### 装完怎么核对

首次启动后在「帮助」菜单里找「关于 Amarok」，确认版本号是 3.x 系列（3.0 及更新）即可。如果看到版本号是 2.x，说明装到了老古董，建议卸掉重来。

## 📖 使用入门：从建收藏到用好上下文

### 第一次启动该干什么

顺序就三步，别搞复杂：

1. **指定收藏目录**：启动向导里选择你存放本地音乐的文件夹
2. **等首次扫描**：Amarok 会遍历目录、读取元数据、建立索引，曲库大的话这个过程会花一些时间
3. **开始听**：扫描完先别急着调设置，用一两天再回来按真实习惯改布局

> [!NOTE] 界面差异提醒
> 网上很多教程的截图来自 2.x 时代，界面与 3.x 差异很大。以你实际装到的界面为准，不用纠结"为什么和教程不一样"。

### 上下文视图：Amarok 的招牌功能

如果只挑一个让 Amarok 区别于其他播放器的界面元素，上下文视图（Context View）当仁不让——它占据主窗口中部，围绕你正在听的那首歌，把散落在网络各处的相关信息聚到一起。

信息按 **applet（小部件）** 为单位组织，每个 applet 负责一类：

- **当前曲目**：封面、评分、位置标记、元数据入口
- **歌词**：当前歌曲的词（依赖歌词脚本）
- **Wikipedia**：艺人/专辑/曲目的百科词条
- **相似艺人**：基于在线音乐社区数据的推荐
- **照片**：按艺人名抓取的图片
- **吉他/贝斯谱**：能搜到的演奏谱
- **专辑**：本地收藏里该艺人的其他专辑
- **演出预告**：该艺人的近期演出信息
- **频谱分析器**：简单的音频可视化

大多数 applet 的内容跟着「当前播放曲目」自动切换——切到下一首，歌词、百科、照片一起换。想手动翻看百科又怕被切歌打断？新版本加了「停止自动更新页面」的开关，可以让百科停留在你正在看的那一页。

> [!TIP] 找回丢失的上下文视图
> 如果哪天发现窗口中间空了一块，去「查看」菜单把「上下文」勾回来即可。反过来说，纯当后台音乐盒用的用户也可以收起它，把窗口留给播放列表。

### 队列管理：临时插播不打乱列表

场景很常见：歌单正按顺序播着，你突然想"下一首必须放这首"，但又不想打乱整个列表的排列。**队列（Queue）** 就是干这个的——它是一层叠在播放列表之上的临时指令：

- 队列里的歌 **优先于列表自然顺序**，播完队列回到列表继续
- 队列 **不改变列表本身**，插播十首列表原样不动
- 队列是临时的，播掉一首少一首

一句话：**列表是今晚的节目单，队列是导演临时插的口播**。

往队列里加歌的方式：

- **快捷键 Ctrl+D**：选中行直接入队（再按取消）
- **右键菜单**：选中行右键选加入队列
- 可以一次选中多行批量入队

三个典型用法：

1. **派对控场**：歌单自动播着，朋友点歌一首一首 Ctrl+D 进队列，节目单不乱
2. **睡觉前**：队列里放最后一首轻的，配合「在这首之后停止播放」，到点自然安静
3. **马拉松播放**：长列表里发现两首必须连播的歌，都进队列排好

队列状态退出时会随会话保存、重启后恢复，但别拿它当歌单存——它的定位始终是临时指令。

### 关于均衡器

这个问题在用户中出现频率很高。答案与版本/引擎有关：历史上均衡器依赖特定的音频后端（旧时代是 Phonon 的 gstreamer 后端），3.3 起引擎统一为 GStreamer。找均衡器先确认自己的版本号，再翻「工具」菜单——找不到不代表功能不存在，先排除版本差异。
