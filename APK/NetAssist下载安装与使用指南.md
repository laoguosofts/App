## ✨ NetAssist 是什么

NetAssist 是一款面向嵌入式和网络开发场景的免费调试工具——简单说就是一个带界面的 TCP/UDP 客户端/服务端。它帮工程师们搞定那些拿着命令行工具干起来很别扭的事：抓一下设备发过来的原始字节、发一段测试指令回去验证协议、长时间跑着存日志、从文件喂批量数据包……凡是跟"网络上有东西在收发，我需要看清楚并介入"沾边的场景，NetAssist 基本都能顶一下。

它支持 TCP Client / TCP Server / UDP 三种工作模式，收发数据可以在 ASCII 和 HEX 之间一键切换，内置了自动校验位、IEEE 754 浮点转换、数据字段波形解析等一堆实用工具面板——把平时散落好几个工具的活整合到了一个窗口里。

NetAssist 在网络调试、嵌入式开发、IoT 协议验证这几个圈子里用的人不少，版本更新频率也稳定，V5 系列在收发引擎和文件存储上做过几次大的优化，尤其是长时间跑着不崩这件事上口碑还行。

## 🔧 安装步骤

NetAssist 的 Windows 安装有两种方式可选：绿色版解压即用，或者跑安装包走一遍向导。

**绿色版**适合不想往系统里装东西的场景：下载 zip 压缩包，解压到任意目录（路径里最好别有中文，个别老版本可能有编码问题），双击 `NetAssist.exe` 就能启动。首次运行如果被 Windows SmartScreen 拦了，点"更多信息 → 仍要运行"即可——这种签名校验提示在小众工具上比较常见。

**安装包方式**则会往 Program Files 里写文件，同时注册开始菜单快捷方式和卸载项。安装路径可以自定义，建议保持默认值省心。

安装完成后建议做一个快速校验：打开程序看一下窗口标题栏的版本号是否跟你下载的一致，然后随便建一个 UDP 本地回环连接（目标 `127.0.0.1`，端口随便填），在发送框里敲几个字发出去，如果接收区能收到同样的内容，说明收发链路没问题。

> [!WARNING]
> 旧版本（V3 及更早）在 Windows 10/11 上可能出现 HEX 模式显示乱码的问题，如果遇到建议直接下最新版。

## 📖 使用入门

### 接收区：让你看清每一条进来的数据

打开 NetAssist 连上目标之后，接收区是你最常盯着看的地方。默认情况下收到什么就显示什么，但如果开了"日志接收模式"，每条数据的前面会自动加上**精确到毫秒**的时间戳前缀——比如 `[2026-10-13 18:30:12.456]` 这样的格式。这个功能在分析时序问题的时候特别好用。

时间戳能帮你干几件事：检查心跳包间隔是不是稳定、调试请求发出到响应回来中间花了多久、把 NetAssist 的接收日志和服务端或交换机的日志在时间轴上对齐来定位偶发问题。普通模式和日志模式随时可以切换——切换只对后续新数据生效，已经显示在接收区里的历史数据不会跟着变。

接收区的数据可以直接保存到磁盘文件，两种保存模式各有分工：

| 保存模式 | 内容格式 | 适合场景 |
| --- | --- | --- |
| 数据文件 | 原始字节流，不带任何额外信息 | 固件下载、传感器原始数据落盘，后续用二进制工具分析 |
| 日志文件 | 每条记录带时间戳前缀 | 保留完整交互流程，事后复盘或 grep 关键字 |

保存有两个容易忽略的细节：一是 NetAssist **不会自动创建目标文件夹**，路径里的目录必须先建好；二是文件写入用追加模式——同一次会话里接收的数据会一直往同一个文件末尾写。V5.0.6 之后推荐开启**滚动日志存储**，让单个文件到达设定大小（比如 100MB）后自动切新文件，避免超过 4GB 上限。

长时间运行时接收区本身也有滚动机制，超过一定行数最旧的记录会被丢弃防止内存爆掉。V4.3.16 起接收区支持**右键搜索**——数据量大起来之后找特定记录不用肉眼翻，直接右键搜关键词就能定位。V5.0.3 之后还加了**字段波形解析**功能：可以从收到的数据里提取特定偏移量的数值（比如某个 2 字节整数），用波形图显示它随时间的变化趋势，配合时间戳同时看数值曲线和对应的具体时刻。

### 发送区：简单指令到批量脚本的灵活度

发送区默认是手动输入内容然后点发送，但实际工作中经常需要发一些量大的东西——几百字节的十六进制测试向量、一段完整的 HTTP 请求报文、预先准备好的协议数据包。这种情况下**从文件导入**就很顺手：勾选之后选一个文件，文件内容直接读入作为本次发送的数据。文件内容的发送方式取决于当前模式：ASCII 模式按文本原样发，HEX 模式按二进制读每个字节转成十六进制。

V5.0.13 起批量发送列表里的每一项都可以单独选择"从文件导入"，这意味着你能把一套多步骤的测试流程编排成一个序列：先发一条 `AT+VER?` 查版本，延迟几十毫秒之后发一个二进制固件文件，再发一条重启指令等一秒。点一次发送就按顺序走完整个流程。

文件较大时可以启用**分包发送**——把文件按设定的包大小（比如 64 字节或 256 字节）拆成多个小包依次发，包之间的间隔也可以单独设置。V5.0.14 之后分包发送还支持自动附加结束符，适合对端协议要求每个数据包带固定标记（比如 `0x7E` 或 `\r\n`）的场景。

> [!TIP]
> 发送数据时别忘了自动校验位功能——NetAssist 可以在发之前帮你算好 CRC16/CRC32 或其他校验值并附加到末尾，验证协议帧完整性的时候省很多事。

### IEEE 754 浮点转换：读懂设备上报的 HEX 字节

调试嵌入式设备时经常遇到这样的事：从网络上抓到一串字节 `41 2C 00 00`，需要知道它代表什么数值。很多设备用 IEEE 754 标准来编码浮点数——单精度 4 字节、双精度 8 字节，每个值由符号位、指数、尾数三部分组成。NetAssist 工具面板里自带的 IEEE 754 转换器就能帮你秒解。

使用方式很直观：输入十六进制串，选精度（float 或 double），选字节序（小端或大端），点转换就出十进制浮点数。反过来输入浮点数也能转成 HEX。

**字节序是最容易踩的坑**。x86 架构的 Windows/Linux 都是小端（低字节在前），但很多工业协议和网络传输默认用大端。同一个 HEX 值用不同字节序解释，结果可能天差地别。比如 `41 48 00 00`：

- 小端 float → `12.5`（看起来合理）
- 大端 float → `2.202214E-38`（显然不对）

所以如果转换结果看起来像天文数字或者接近 0，先把字节序反过来试一下——合理的物理数值（比如温度不会是 0.0000001）通常就是正确答案。也可以让设备发一个已知值（比如让它发 `0.0`），拿到 HEX 后反推它用的是哪种字节序。

### 一些实用小技巧

- 历史发送记录面板会自动记住每次发过的内容，下次想重发同样的数据直接从列表里选，不用重新输入。V5.0.13 起历史记录、批量发送、快捷指令三个面板都支持关键字搜索。
- 接收区显示模式可以随时在 ASCII 和 HEX 之间切换——ASCII 模式看文本协议舒服，HEX 模式看二进制协议不漏字节。
- 如果需要长时间稳定跑着收数据，建议开启"滚动日志存储"并把单文件上限设小一些（比如 50MB），避免单次运行产出的文件过大。
