## ✨ GodotHub 是什么

GodotHub 是一个围绕 Godot 游戏引擎生态打造的聚合管理工具。它把引擎版本管理、项目集中管理、插件资源库、社区讨论这些分散的需求整合到一个界面里，让独立开发者不必在多个网页和工具之间来回跳转。

对 Godot 用户来说，最直接的痛点是：引擎版本多、每个项目绑定的版本不同，切换起来麻烦；社区里好用的插件散落在各处，找到后还要手动下载、解压、放到 addons 目录；多项目并行开发时，项目列表杂乱无章，找起来费劲。GodotHub 就是为解决这些场景而生的。

主要功能覆盖四个方向：**引擎版本管理**（国内镜像加速下载、一键切换）、**项目集中管理**（分组、收藏、快速打开、版本绑定）、**插件资源库**（行为树、状态机、AI 框架、逻辑工具，自动安装到项目目录）、**社区与资源聚合**（教程、代码片段、Android 端离线缓存）。

适合谁用？如果你是 Godot 引擎的独立开发者、学生、或者正在学习游戏开发的新手，需要频繁切换引擎版本、尝试不同插件、管理多个项目，GodotHub 能帮你省掉很多重复劳动。团队开发也能用，但目前功能定位更偏向个人开发者的轻量管理。

> [!NOTE]
> GodotHub 本身不是 Godot 引擎的替代品——它是引擎的"管家"。你仍然需要 Godot 编辑器来写代码、搭场景、运行游戏，GodotHub 负责把引擎、插件、项目这些资源管起来。

## 🔧 安装步骤

桌面端和 Android 移动版的安装流程差异较大，分别说明。

### 桌面端（Windows / macOS / Linux）

1. 从下载页获取对应平台的安装包
2. Windows 用户运行 `.exe` 安装程序，按提示选择安装路径（建议非系统盘，便于后续升级覆盖）
3. macOS 用户打开 `.dmg`，把 GodotHub 拖进 Applications 文件夹
4. Linux 用户解压 `.tar.gz` 或使用包管理器（部分发行版提供 AUR / Homebrew 配方）

安装完成后首次启动，GodotHub 会弹出初始化向导：

- 让你选择 Godot 引擎的默认安装目录（或者自动扫描已有的 Godot 安装）
- 让你选择项目文件的默认存储位置
- 让你选择下载镜像源（国内用户推荐选国内镜像，速度更快）

> [!WARNING]
> 如果你的系统上已经安装过 Godot 引擎，初始化向导会自动探测到并询问是否纳入管理。选择"是"之后，这些引擎版本会出现在 GodotHub 的版本列表里，后续项目可以直接绑定使用。

### Android 移动版

1. 从 Google Play 或官方下载页获取 APK
2. 如果手动安装 APK，需要在系统设置里允许"未知来源"应用安装
3. 安装完成后首次打开，会请求存储权限（用于缓存教程和插件列表）

### 安装后核对

装完之后可以做两个快速检查确认没问题：

- **版本号核对**：在 GodotHub 设置 → 关于 里确认版本号和下载页一致
- **引擎列表**：进入"引擎管理"页面，如果之前有 Godot 安装应该能看到；没有的话点"下载引擎"试一下，看镜像源是否可用

## 📖 使用入门

### 项目快速打开的几种方式

在项目管理界面找到目标项目，**直接双击**是最常用的方式——GodotHub 会用该项目绑定的引擎版本启动 Godot 编辑器并加载项目，整个过程不需要手动指定引擎版本、不需要浏览文件路径。

在项目条目上**右键**可以打开更多操作菜单：

- **用指定引擎打开**：临时用另一个引擎版本打开（不修改默认绑定，适合测试兼容性）
- **打开项目文件夹**：在文件资源管理器里直接跳转到项目目录
- **修改绑定版本**：快速修改引擎绑定，不需要进设置界面
- **从列表移除**：只是从 GodotHub 的管理列表里移除，不会删除项目文件本身
- **删除项目**：谨慎操作——会同时删除 GodotHub 的记录和项目目录

GodotHub 会记录**最近打开的项目**，在项目管理界面顶部提供快速入口。这个列表独立于 Godot 编辑器自己的"最近项目"记录——即使你手动清理了 Godot 的最近记录，GodotHub 里还能看到。

项目多了以后，推荐用好**分组和收藏**功能：

- **收藏夹**：把正在做的项目标为收藏，置顶显示
- **分组**：按"正在开发 / 暂停维护 / 老项目"等分组整理，找起来更快
- **搜索框**：项目列表支持实时搜索，输入项目名称就能过滤

### 逻辑脚本与 AI 行为类插件

行为树（Behavior Tree）是实现游戏 AI 的经典模式。GodotHub 里收录的行为树插件提供可视化编辑器节点，可以在 Godot 编辑器里直接拖拽搭建 AI 逻辑，不用手写复杂的 GDScript。

常见使用场景：

- 敌人巡逻、追击、攻击的状态切换
- NPC 对话选择
- 玩家队友 AI
- Boss 多阶段行为切换

选择行为树插件时，注意它是否和当前 Godot 引擎版本完全兼容——Godot 的节点 API 在 4.x 里有变化，老版本插件可能在 4.5+ 下行为异常。

有限状态机（FSM）是另一种常见的 AI 模式。Godot 内置了 AnimationTree 可以做状态机，但如果需要更完整的逻辑控制（非动画驱动的行为切换），可以考虑专门的 FSM 插件。

还有一类实用逻辑工具，不完全是 AI，但能帮你写逻辑脚本更方便：

| 插件类型 | 解决什么问题 | 典型场景 |
|---|---|---|
| **事件总线** | 跨节点、跨场景的事件通信 | 减少代码耦合、模块间解耦 |
| **命令模式** | 实现撤销/重做、宏操作 | 编辑器工具、复杂交互 |
| **输入管理** | 自定义输入映射的可视化编辑器 | 多平台输入适配 |
| **存档系统** | 自动序列化玩家数据、统一存档接口 | 游戏存档/读档 |
| **本地化多语言** | 文本替换、语言切换工具 | 游戏国际化 |

在 GodotHub 里安装插件的步骤很顺畅：在插件库找到合适的插件 → 点击下载（走国内镜像，几秒完成）→ GodotHub 会自动把插件解压到当前项目的 `addons/` 目录 → 在 Godot 编辑器里打开 **项目 → 项目设置 → 插件**，勾选启用 → 按插件文档的指引把插件节点或脚本加到场景里。

> [!TIP]
> 部分插件在 GodotHub 里附带快速上手教程，从安装到跑起第一个 Demo 通常五分钟内可以完成。

### 镜像下载失败或速度异常慢

下载引擎或插件时遇到网络问题很常见。症状大致可以归为四类：一开始就失败、速度异常慢、下载到一半中断、下载完成但文件损坏。

**一开始就失败**的可能原因：镜像源本身挂了（GodotHub 维护者可能正在更新某个资源，短暂不可用）、你的网络连不上镜像服务器、或者 GodotHub 版本太旧（新镜像域名旧版本不认识）。处理方式：在 GodotHub 设置里切换到备用镜像或官方源重试、更新 GodotHub 到最新版、在社区板块搜"镜像挂了"看看是不是普遍问题。

**速度异常慢**——走了国内镜像但速度还是只有几十 KB/s，常见原因是带宽运营商之间互联不好（比如用联通宽带但镜像服务器在电信机房）、镜像服务器在高峰时段（晚上 8~11 点）负载高、或者 DNS 解析被劫持。处理方式：切换到另一个镜像源试试、避开高峰时段、用 Speedtest 测一下本地带宽。

**下载中断**不用慌——GodotHub 支持断点续传，关掉下载重新开始，已经下载的部分会被复用，不会从零开始。如果反复中断，大概率是网络不稳定，可以暂停其他占用带宽的应用，或者取消后切换镜像源重新开始。

**下载完成但文件损坏**——GodotHub 默认会做文件完整性校验（MD5 或 SHA），校验不通过会提示重新下载。如果校验没报错但实际解压失败，可以手动在浏览器里打开镜像源找到同一个文件手动下载试试。极端情况下可能是磁盘空间不足或下载时的写入错误。

如果你的开发机在公司网络下，可能需要配置代理——GodotHub 设置里支持 HTTP/HTTPS 代理配置，填写公司网络管理员提供的代理地址和端口即可。配置完成后下载速度可能从几 KB/s 变回正常。

### Android 离线缓存与数据同步

Android 版 GodotHub 支持一定程度的离线使用：已加载的教程页面和代码片段缓存到本地，没网时可以继续阅读；已浏览过的插件列表缓存在本地，没网时可以查看但不能下载；社区帖子已加载的内容离线可见，但不能发帖或回复；引擎版本信息已同步的版本列表离线可见。

需要联网才能完成的核心动作：引擎版本检查、插件下载标记同步、社区发帖回复、镜像源切换。

Android 端和桌面端各自独立运行、独立存储数据。它们之间的互通方式是**手动标记、各端各取**：

- Android 端在插件库浏览时标记的插件 → 回到桌面端，打开 GodotHub → 插件列表里能看到"已在移动端标记"的插件，点击就能下载
- 桌面端标记的引擎版本更新 → Android 端下次联网时同步更新通知

这套同步机制轻量、不依赖账号体系（降低隐私顾虑），但也意味着多设备之间没有实时同步。

长期使用后，手机上会积累教程图片、插件封面、社区帖子截图等缓存文件。GodotHub 设置里提供**一键清理缓存**功能，可以释放存储空间而不影响核心功能——缓存清理只会删临时下载的资源文件，不会删你主动标记的插件、收藏的教程等持久化数据。

Android 端的本地数据安全方面：所有数据存在应用专属目录里，卸载 App 时自动清除；不读取系统其他应用的存储内容；联网通信只和 GodotHub 自己的服务器交互，不对外发送非必要数据。
