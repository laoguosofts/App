## ✨ NetX 是什么

NetX 是一款面向普通用户和小型网络管理员的局域网管理与网络诊断工具，最初发源于 Android 平台，后续扩展到 iOS 和 Windows。它把网络管理员常用的一整套命令行工具——ARP 扫描、Ping、Traceroute、端口探测、WOL 远程唤醒——全部做成了图形界面，让不懂 `ipconfig` 和 `tracert` 的普通用户也能快速摸清家里或办公室的网络状况。

核心能力可以归为三类：**设备发现**、**诊断排错**、**远程控制**。扫完一网段，NetX 会列出每台在线设备的 IP、MAC、主机名和厂商，点进详情页还能看开放端口、启动 WOL 魔法包、跑 Traceroute 跟踪到某台服务器的路由路径。内置的 MAC 厂商数据库预打包在应用里，扫完直接告诉你哪台是苹果手机、哪台是小米音箱、哪台是 Realtek 杂牌网卡——连网都不用上。

对于家里有 NAS、需要远程开机下载任务的用户，或者经常遇到"Wi-Fi 满格但网速跑不动"的场景，NetX 能帮你把问题从"感觉"变成"看得见的数据"：是哪家运营商的国际出口在堵、还是路由器本身丢包、或者只是某台设备占满了带宽。

## 🔧 NetX 安装步骤

NetX 在三个主流平台都可用，安装流程各有特点。下面按平台分别说明，选你自己设备对应的步骤走即可。

### Android 安装

1. 从官方下载页获取 APK 文件，传到手机存储
2. 打开手机 **设置 → 安全（或隐私）→ 未知来源**，允许从文件管理器安装 APK
3. 用文件管理器找到 APK 文件，点击安装
4. 安装完成后首次启动，NetX 会请求 **网络位置权限**——这是扫描局域网必需的，必须允许；Android 12 及以上还需要 **附近设备权限**

> [!WARNING]
> 部分国产 ROM（MIUI、ColorOS、OneUI）会把网络位置权限藏得比较深，找不到的话可以在应用信息页手动授予。没开这个权限的话，局域网扫描会跑不起来，只能看到自己一台设备。

### iOS 安装

1. 在 App Store 搜 NetX，直接点安装
2. 首次启动请求 **本地网络权限**，必须允许，否则扫不到任何设备
3. iOS 版受系统沙盒限制，端口扫描和 WOL 功能比 Android 版弱一些，但 Ping、Traceroute、MAC 查询等核心功能完整可用

### Windows 安装

1. 从官方下载页获取 `.exe` 安装包
2. 双击运行，选择安装路径，默认 `C:\Program Files\NetX`
3. 安装过程中 Windows Defender 可能弹出提示——这是因为 NetX 需要创建原始 socket 做网络扫描，属于正常行为，选"仍要运行"即可
4. 首次启动需要 **管理员权限**（右键 → 以管理员身份运行），否则扫描功能会被系统拒绝

> [!TIP]
> 安装完可以在 NetX 的"关于"页核对版本号。如果遇到功能异常，优先卸载再从官方下载页重装，避免第三方渠道的修改包。

## 📖 NetX 使用入门

安装好打开 NetX，第一件事就是点 **扫描**。它会对你当前 Wi-Fi 所在的子网做一次 ARP 广播，几秒钟之内就能把家里的所有设备列出来。扫完之后你会看到一张清单——每一行是一台在线设备，显示 IP、MAC、主机名和厂商。下面从这张清单出发，一步步介绍 NetX 的核心玩法。

### 设备扫描：快速摸清局域网

点主界面的"开始扫描"按钮，NetX 会向整个子网发送 ARP 请求帧。任何在线的设备——手机、笔记本、路由器、NAS、智能音箱——都会自动回应自己的 MAC 地址。扫描结果可以按 IP、厂商或在线状态排序，方便你从一堆设备里快速定位。

扫完的清单里，NetX 已经帮你查过每台设备的 MAC 厂商。比如你看到一台 MAC 前缀对应 **Xiaomi** 的设备，大概率是米家的音箱或扫地机；对应 **Apple** 的就是 iPhone、iPad 或 Mac；对应 **TP-Link** 的多半是路由器或中继器。如果遇到"未知厂商"，那就值得留意了——可能是没备案的蹭网设备，也可能是比较小众的智能硬件。

### MAC 厂商查询：识别陌生设备

清单里点进任意一台设备的详情页，能看到更详细的信息，包括开放端口列表、Ping 测试、Traceroute 入口，以及一个 MAC 地址查询按钮。MAC 地址是网卡的物理身份，由 48 位二进制写成六组两位十六进制，比如 `A4:83:E7:12:34:56`。其中前三组是 IEEE 分配给各厂商的 **组织唯一标识符**（OUI），通过这一段就能反查出网卡的生产者。

NetX 的厂商数据库是预打包在应用里的，覆盖了数千家常见厂商，包括 Apple、Xiaomi、ASUS、Huawei、Lenovo、Samsung、TP-Link、Tenda 等等，查询不需要联网。点击查询按钮后，NetX 截取 MAC 地址的前三组作为 OUI，在本地数据库里匹配，几毫秒就能返回结果。如果查询不到，说明这台设备用了比较小众的网卡，你可以结合主机名和 IP 段辅助判断。

### 远程唤醒（WOL）：出门在外也能开家里的电脑

远程唤醒是 NetX 最实用的功能之一。家里电脑开着但不在身边，或者 NAS 需要临时开机下载任务，WOL 魔法包能让设备自动唤醒。WOL 的原理很简单：向目标设备的 MAC 地址发送一个特定格式的 UDP 广播包，网卡收到后通知主板加电启动。

在 NetX 里用 WOL，只要设备在扫描清单里出现过，点进详情页就能看到 WOL 按钮。默认情况下魔法包是在同一局域网内广播的——手机在家的 Wi-Fi 上、电脑在家，直接点 WOL 就能唤醒。

但如果你在外面（蜂窝数据 4G/5G）想唤醒家里的电脑，魔法包出不了家宽的 NAT，这时候就需要额外配置。NetX 支持三种跨公网 WOL 方案，按难度和安全性分三档：

| 方案 | 配置难度 | 安全性 | 说明 |
| --- | --- | --- | --- |
| 路由器端口转发 | 中 | 较低 | 把外部 UDP 端口转发到内网广播地址 |
| 路由器自带 WOL | 低 | 中 | 梅林 / OpenWrt / 小米路由器等固件内置支持 |
| VPN 接入 | 高 | 高 | 连 WireGuard / OpenVPN 后等于在家局域网 |

最常用的是端口转发方案：登录路由器管理页，新建一条规则，把外部 UDP 端口（默认 9）转发到家里的 **局域网广播地址**（通常是 `192.168.1.255`）。保存后如果路由器支持 DDNS，最好也启用一下——因为很多家庭宽带是动态公网 IP，重启路由器后 IP 会变，DDNS 域名能帮你记住。然后在 NetX 的设备详情页 → WOL 设置里，把目标 IP 改成你家的公网 IP 或 DDNS 域名，端口保持 9，发 WOL 包就能从外面唤醒了。

> [!NOTE]
> 端口转发方案会把路由器暴露在公网，务必只开放 WOL 用的那个 UDP 端口，不要顺带打开别的。有条件的话优先选路由器自带 WOL 功能或 VPN 方案，更安全也不容易误配置。

### Traceroute：看数据包经过了哪些路由节点

Traceroute 是网络诊断的核心工具。它向目标地址发送一系列 TTL 递增的 UDP 包，每经过一个路由器 TTL 减 1，减到 0 时那个路由器就回复一个 ICMP Time Exceeded——这样就能拿到从你这里到目标每一跳的 IP 和延迟。Windows 上对应的命令叫 `tracert`，但 NetX 把它做成了图形界面。

从菜单进入诊断工具 → Traceroute，输入目标 IP 或域名，点开始。每一跳会实时显示跳数、路由节点 IP、三个数据包的往返延迟（毫秒）和主机名（如果有）。Pro 版还提供交互式地图视图，在世界地图上标出每一跳的地理位置。

Traceroute 最典型的用法是 **定位网络卡顿的位置**：

- 如果 ping 某个海外网站延迟很高（300ms+），跑 Traceroute 看前 3~5 跳延迟——如果这几跳已经很高，问题在你家到运营商这段
- 如果国内部分跳数延迟正常、出了国才开始暴涨，问题在国际出口或海外目标服务器
- 如果某一跳连续丢包，那一跳的路由器可能超载或故障

和 Ping 配合使用效果最好：Ping 先确认通不通、整体延迟多少，Traceroute 再帮你找到瓶颈具体在哪一跳。

| 路径 | 典型跳数 |
| --- | --- |
| 自家 Wi-Fi → 网关 | 1~2 跳 |
| 家宽 → 运营商出口 | 3~5 跳 |
| 国内 → 国内 | 5~10 跳 |
| 国内 → 海外 | 10~20 跳 |

### IP 子网计算器：算清楚网段

日常用不到但关键时刻很有用的一个工具。IP 计算器帮你快速算出 IP 网段的网络地址、广播地址、主机范围和 CIDR。当你需要配置 VLAN、划分子网、或者对网络做排错时，给定一个 IP 和子网掩码，NetX 自动输出所有需要的参数。

支持三种输入方式：IP + 子网掩码（比如 `192.168.1.100` + `255.255.255.0`）、IP + CIDR（比如 `10.0.0.5/16`）、IP 段反推。比如输入 `192.168.1.100` 和 `255.255.255.0`，NetX 会告诉你网络地址是 `192.168.1.0`、广播地址是 `192.168.1.255`、主机范围是 `.1` 到 `.254`、可用 254 台设备。

> [!TIP]
> 多数家庭场景用不到 IP 计算器——路由器自动做 NAT 了。但在做 VLAN 规划、VPN 网段划分、给多台服务器分配固定 IP 段时，这个工具能省掉你手算二进制的功夫。
