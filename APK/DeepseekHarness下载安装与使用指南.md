## ✨ DeepseekHarness 是什么

DeepseekHarness（简称 dsh）是 DeepSeek AI（深度求索）开发并开源的 Agent Harness——给大语言模型装上的一套"身体与神经系统"。如果说模型本身只会在对话框里输出文本，那 dsh 负责让这些指令变成真实世界里的动作：读本地文件、跑 shell 命令、调用浏览器、管理多轮会话、派发子任务，并把每一步操作记录在案。

核心架构基于 Cordis 插件系统，工具层、会话层、安全层、调度层全部以插件形式存在，可按需替换而非硬编码。开源协议为 MIT，源代码与开发者文档公开在 GitHub 仓库 deepseek-ai/deepseek-harness，属于开发者预览版（v0.1 起步），核心插件与接口仍在快速迭代。

三件套关系：电脑端运行 dsh 网关与插件体系、手机 App 提供移动端远程控制界面、插件则按需下载校验后生效。常见误区需要澄清——它不是聊天产品（那是 DeepSeek Chat 的定位），也和字节跳动的同名项目无关；它本身不提供模型，而是让你接入任意模型后在自己的电脑上搭建、运行、定制专属智能体。

## 🔧 安装与配置要点

dsh 的安装分两块：电脑端（运行网关与插件系统）和手机 App（移动端远程控制界面）。

**电脑端部署**：在你的操作系统上安装 dsh 本体后，它会在本地启动一个网关服务，插件按需加载。开发者预览版阶段建议保持版本更新——早期版本可能存在兼容性问题。启动后通过本机地址访问管理界面，在那里完成插件安装与初始配置。

**手机 App 安装**：从应用商店下载对应平台的 App。首次打开需要与电脑端完成配对——支持局域网配对（扫码或密钥输入）和远程配对两条路径。

> [!TIP]
> 同一台电脑的局域网配对和远程配对是**两条独立授权**，设备列表里可能显示两条记录，属正常现象。重新验证变化的地址后，相同身份的记录会自动合并并保留名称。升级插件会自动迁移旧凭据，通常无需重新配对。

## 📖 从设备管理到远程访问：实用指南

### 已配对设备管理

电脑端的 dsh 网关可以同时服务多台移动端设备。App 内置统一的设备列表，每条记录显示自定义名称、连接方式、来源地址和可达状态。

状态判断逻辑值得了解：**绿色**表示网关可达，**灰色**则涵盖检测中、暂不可达、配对已过期或电脑端已移除四种情况。可达性检查直接验证 dsh 网关而不依赖 ICMP 协议，所以临时断网不会被误判成电脑端撤销了你的授权。

启动行为有两种可选模式，在 App 列表右上角设置里切换：

| 模式 | 表现 | 适用场景 |
| --- | --- | --- |
| 直接进入 dsh（默认） | 单设备直接连接；多设备优先连上次用的，其次按最近连接时间 | 日常使用，大多数人 |
| 显示设备列表 | 每次启动先让你选电脑 | 经常在多台电脑间切换 |

日常操作方面，点按设备行即可发起连接；设备行右侧的「…」菜单（或长按）可编辑名称、立即检测、重新配对或删除本地记录——删除操作有二次确认和短暂撤销窗口，但撤销仅恢复本机记录，无法恢复电脑端已撤销的授权。会话内如果想切换电脑，可以在 dsh 设置 → 通用设置 → 切换电脑，也能长按左上角抽屉开关直接返回列表。

电脑端撤销后的表现：设备在线时会立即收到撤销通知并断开；离线期间被撤销的话，下次检测会显示「配对已过期」，需要重新走一次配对流程。

### 自建 FRP 远程通道

默认的远程访问依赖公共服务，如果已有 VPS 且希望避开带宽限流，可以用 FRP 自建远程通道。FRP 方案的自助程度最高，但也需要承担服务器运维责任——手机端不需要单独安装 FRP 客户端，所需组件由 dsh 插件按需下载并校验。

有两条接入路径：

**路径一：托管部署（从零建）**

1. 电脑端进入「移动访问 → 远程」，展开「自建连接」，选择自建 FRP
2. 填写 frps 服务器信息和公开 HTTPS 域名或公网 IPv4
3. 部署方式二选一：复制受限的 frps + Caddy 模板手动部署；或在 Ubuntu/Debian + systemd 环境下用 SSH 密钥一键部署
4. 部署完成、公网 HTTPS 就绪后生成远程配对二维码，手机 App 扫码完成配对

托管架构里，VPS 上的明文 vhost 只允许回环访问，公网 HTTPS 由 Caddy 提供，流量经 HTTP vhost 转发到电脑上的 dsh 回环网关。

**路径二：接入既有 frps（不动服务器）**

已有 frps 服务器的话选这条路——dsh 插件不安装、不改动你的服务器。公开 CA 档仍需要受限 HTTP vhost 与 Caddy 配合；自签档则用 frps TCP 透传到电脑端 HTTPS 网关（配对时固定远程 CA）。两档都不开放任意 FRP 配置。

> [!WARNING]
> 安全硬要求：自动部署与一键清理前必须先到 VPS 控制台核对 SSH 主机指纹；一键部署只支持 SSH 密钥，不支持密码登录；共享 Token 不会出现在状态、诊断或接入清单响应里，含 Token 的配置复制进剪贴板后请粘贴完及时清除。

清理工作分两端：本机面板一键清理即可卸载它托管的全部文件；VPS 端必须单独清理——用面板提供的卸载脚本或一键清理，或按部署指南手动删除。接入既有 frps 的路径本来就不改服务器。另外注意中国大陆 VPS 上的未备案域名可能被云厂商拦截，此时改用公网 IPv4 模式。

### 高频连接问题排查

**配对与认证**：反复提示重新配对或续期 401 时，先更新插件和 App 到最新版本，从当前移动访问入口重试。同一域名上的其他服务或旧 Cookie 可能干扰认证，浏览器用户重新扫一次二维码就能更新本插件的认证 Cookie，无需清除所有网站数据。设置请求返回 403 时，检查 dsh 的 Host/Origin 信任校验——iframe、反向代理或浏览器扩展都可能改变请求来源，用本机直接访问做对照验证。

**局域网类**：日志提示「保存的网卡当前未连接」说明电脑换了接入方式（Wi-Fi 换网线之类），插件记住的网卡对不上号。重跑 dsh-mobile setup 或重新完成一次局域网配置即可，dsh 本体不受影响。设置报 EACCES、EPERM 或锁文件失败，属于文件权限问题，检查报错文件的权限与启动环境即可。

**远程链路类**：页面能打开但一直「重连中」需要区分 WebSocket 升级失败、慢速数据同步、心跳超时三种情况——处理路径不同。慢链路（限速通道、计量网络）下可尝试按确切路径启用 WebSocket 压缩（默认关闭），并对比实际传输量。远程诊断显示「电脑经代理可访问」但手机还是连不上，说明电脑端经代理完成了 HTTPS 探测，不代表手机或隧道可用，得用手机流量实际连接来判断。
