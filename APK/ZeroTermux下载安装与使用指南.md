## ✨ ZeroTermux 是什么

ZeroTermux 是在原版 Termux 基础上构建的增强发行版，核心差别在于引入了多容器隔离机制——你可以在同一台 Android 设备上同时拥有多个互相独立的 Termux 用户空间，各自维护自己的软件包、家目录和配置，互不干扰。原版 Termux 是单实例模型，装包、配置、环境全堆在一起，一旦搞乱只能清数据重来；ZeroTermux 用 proot 在用户空间做了一层轻量隔离，把这些问题一次性解决。

除了多容器，ZeroTermux 还内置了发行版一键部署（Ubuntu、Kali 等）、图形桌面支持、容器备份恢复、社区资源入口等功能，对不想手写 proot 命令、希望图形化管理环境的用户来说门槛低了很多。适合 Android 上跑 Linux 开发环境、渗透测试实验、脚本自动化的人群，也适合想在手机上玩 Linux 发行版但又不想折腾 root 的普通玩家。

## 🔧 安装步骤

ZeroTermux 以 APK 形式分发，安装流程和普通 Android 应用一致，但有几个注意点：

1. **允许未知来源安装**：首次安装第三方 APK 需要在系统设置里授予「允许安装未知来源应用」权限，路径通常为「设置 → 安全 → 安装未知应用」，找到你用来下载 APK 的浏览器或文件管理器，打开权限开关。
2. **核对版本号**：下载完成后对比文件大小和版本号，避免拿到过期的第三方修改包。安装包体积通常在 30MB~50MB 之间，新版可能更大。
3. **授予存储权限**：首次打开 ZeroTermux 时，应用会请求访问手机存储的权限，允许它才能读写 `/sdcard/xinhao/` 下的备份、脚本、字体等共享文件。
4. **终端启动确认**：正常启动后应该看到 shell 提示符 `$`，输入 `uname -a` 可以查看内核信息，`pkg list-installed` 确认包管理器正常工作。

> [!WARNING] 杀毒误报提醒
> 部分手机安全中心可能对 ZeroTermux 的容器隔离机制产生误报，这是因为 proot 需要创建虚拟文件系统映射到应用内部存储。来源可信的安装包可以忽略误报，但如果从第三方渠道下载，务必先在实验容器里验证。

## 📖 使用入门

### 容器隔离：ZeroTermux 的核心差异

容器是 ZeroTermux 最重要的概念——它内部的独立 Termux 实例。每个容器有自己独立的 PREFIX 目录（存放所有通过 pkg 安装的二进制包）和独立的家目录（存放 `.bashrc`、`.config`、用户脚本等），容器之间互不干扰。这个机制解决了原版 Termux 长期存在的几个痛点：

- **开发环境和日常环境混装冲突**：日常用的 curl、wget、git 和开发需要的 clang、python、node 版本可能打架，用容器隔离后各装各的、互不牵连。
- **不同发行版并行**：想同时玩 Ubuntu 和 Kali？原版 Termux 装完一个发行版再装另一个，`$PATH` 和 `$LD_LIBRARY_PATH` 会互相覆盖；容器隔离后每个容器内部独立运行自己的发行版，切换无缝。
- **实验场安全**：想试试新脚本或执行危险操作？在实验容器里折腾，搞崩了直接删容器重建，主力环境毫发无损。

容器 vs 其他隔离方案的对比：

| 方案 | 隔离级别 | 复杂度 | ZeroTermux 支持 |
|---|---|---|---|
| 多容器（ZeroTermux） | 用户空间（proot） | 菜单操作，零命令 | 原生支持 |
| proot 手动跑 | 用户空间 | 手写 proot 命令 | 支持，但不推荐 |
| chroot | 用户空间 | 需要 root | 不支持 |
| 虚拟机（QEMU） | 完整系统 | 重、耗资源 | 支持，但另一个入口 |

> [!TIP] 容器和发行版是两回事
> 很多用户会搞混：容器是 ZeroTermux 里的隔离层（轻量、菜单操作），发行版（Ubuntu / Kali 等）是在容器内部运行的完整 Linux 用户空间。一个容器里可以装一个发行版，也可以不装发行版、只用原生 Termux 环境。

### 切换与删除容器

容器的 PREFIX 路径在 ZeroTermux 启动时就确定了，所以切换容器后必须**完全退出应用再重新打开**，让应用重新读取新的路径配置。

删除容器有严格的操作顺序要求——**必须先切换到其他容器再删**，不能删除当前正在使用的容器。ZeroTermux 启动时会根据当前激活的容器名来找对应的 PREFIX 目录，如果在切走之前直接删了正在用的那个容器，下一次启动就会找不到路径、报环境错误。正确的删除步骤：

1. 在容器切换界面里切换到另一个容器（比如默认的无名称容器）
2. 按提示重启 ZeroTermux
3. 再次进入容器切换界面
4. 点选要删除的容器，在确认弹窗里点删除

删除容器会一并清除该容器的完整 PREFIX 目录、家目录以及容器里发行版的所有文件，但**不会删除** `/sdcard/xinhao/` 下的共享文件（备份包、字体、ISO 等）——这些是跨容器共享的。ZeroTermux 的删除是物理删除，不会进回收站，删之前建议先对那个容器做一份备份。

### 备份恢复：菜单 vs 命令行

ZeroTermux 提供了两种备份方式，各有适用场景：

| 对比项 | ZeroTermux 菜单备份 | termux-backup 命令行 |
|---|---|---|
| 包含 PREFIX | ✅ | ✅ |
| 包含家目录 | ✅ | ❌ |
| 包含发行版 | ✅ | 视发行版安装位置而定 |
| 压缩格式 | tar.gz / tar.bz2 / tar.xz | 所有 tar 支持的格式 |
| 易用性 | 菜单点几下 | 命令行 |
| 恢复方式 | 新建容器恢复 | 覆盖当前 PREFIX |
| 风险等级 | 低（恢复到新容器） | 高（直接覆盖 PREFIX） |

菜单备份已经能覆盖大多数需求，但在以下场景下命令行方案更灵活：想备份到非默认路径（指定目录、外部存储、管道传到外部）、想用更高效的压缩算法（zstd、lzop 等）、只想备份 PREFIX 的二进制包而把家目录配置手动迁移。

命令行备份的基本用法：

```bash
termux-backup /path/to/backup.tar.gz
```

压缩算法由文件扩展名决定，常用的有 gzip（快、兼容性好）、xz（压缩率最高、速度慢）、zstd（平衡，推荐）。恢复时用 `termux-restore`，但**警告**：这个命令会删除 PREFIX 里所有不在备份里的文件且不询问确认，强烈建议恢复前先对当前环境做一份完整备份。

### 社区资源与安全

ZeroTermux 内置了线上功能入口，提供论坛、下载站和公共仓库三个渠道。论坛是用户交流的主渠道，可以看新版本更新说明、用户分享的安装教程、环境包和恢复包作者的发布页；下载站提供第三方恢复包、脚本包、发行版离线包；公共仓库是社群共享的脚本、配置和工具集合，直接托管在 GitHub 上。

> [!WARNING] 第三方资源安全红线
> 无论从哪个渠道获取资源，必须遵守三条原则：先在实验容器里跑、恢复包先验来源、脚本看内容后再执行。不要把第三方恢复包当成官方备份来信任，也不要直接在主力环境里运行未知脚本。
