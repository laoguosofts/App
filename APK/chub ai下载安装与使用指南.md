## ✨ Chub AI 是什么

Chub AI 是一个面向角色扮演（Roleplay）场景的 AI 聊天前端平台，它的核心定位是让玩家能够发现、创建、分享各种各样的 AI 角色卡，并在一个功能完整的聊天工作台里与这些角色进行沉浸式对话。平台本身不提供模型，而是作为前端接入你自己的 API Key，支持多种主流后端模型。

与同类前端相比，Chub AI 在几个方向上做得比较突出：一是角色卡生态相当活跃，大量创作者持续发布新角色；二是聊天树分支功能允许同一条消息生成多条回复、在不同剧情之间切换，这在互动式小说和角色调试场景下非常好用；三是 Stage 扩展机制让社区开发者可以通过 iframe 沙箱为平台增加各种辅助工具。

适合谁用？如果你是想体验角色扮演聊天的普通玩家、想自己动手写角色卡的创作者、或者需要一个稳定前端对接自有模型的高级用户，Chub AI 都能覆盖。

## 🔧 安装与访问注意事项

Chub AI 的主要形态是 Web 平台，不需要传统意义上的安装步骤——打开浏览器访问官网注册登录就能用。不过在实际使用中，有几个常见的"类安装"环节值得提前了解。

### 反病毒软件拦截问题

不少用户报告 Avast、AVG 等反病毒软件会把 Chub AI 的域名标记为可疑站点，访问时直接被浏览器拦截或出现连接重置。触发原因主要是反病毒引擎对成人向角色扮演内容的启发式判定，以及对陌生域名的临时封禁。

> [!WARNING]
> 如果遇到访问被拦截，先别慌——按下面的顺序排查，大部分情况都能解决：
> 1. 把 Chub 相关域名加入反病毒白名单（网站白名单/排除项）
> 2. 临时关闭反病毒的"网页防护"模块测试
> 3. 换浏览器试试（有用户反馈 Chrome 被拦但 Edge 正常）
> 4. 以上都不行再考虑换一款反病毒软件

### 区域访问限制

某些地区可能因本地法规出现访问受限的情况，这和反病毒拦截是不同性质的问题，处理方式也不一样。如果确认是区域限制，官方一般会建议使用 VPN 方案。

### API Key 准备

Chub AI 作为前端，需要你提供自己的模型 API Key 才能真正开始聊天。常见的支持后端包括主流的几家模型服务商。Key 的获取和充值流程取决于你选择哪家后端，准备好之后在平台的设置里填入即可。

## 📖 使用入门

下面按初次使用的典型路径，从发现角色到深入调试，把几个关键环节的实操要点串起来。

### 找一个角色开始聊天

登录后首页就是角色发现区，按分类浏览或者直接搜索都能快速找到感兴趣的角色卡。点进角色详情页可以看到名字、头像、一句话简介、详细描述和标签这些信息，先扫一眼确认风格对不对。

> [!TIP]
> 选角色卡时，**标签和描述的匹配度**往往比名字更重要。标签决定了角色会出现在哪些分区，描述里能看到创作者对角色背景和设定的用心程度——写得越具体，通常聊天体验越好。

### 聊天树分支：一条消息，多种走向

进入聊天后最值得尽快熟悉的功能就是聊天树分支——这是 Chub AI 文档里明确声称"和其他前端不一样"的特性。

操作很简单：在任意一条 AI 回复上找到右下角的 Swipe 按钮点一下，系统就会生成一条新的替代回复，和原回复并列。左右箭头可以在多条回复之间切换预览，选中满意的那条之后继续对话，新消息会自动挂在你选中的分支下面。

这个功能在几个场景下特别好用：

- **互动式小说**：每个关键决策点让 AI 生成 2~3 种可能走向，你来选接下来的剧情
- **写卡调试**：新写的角色卡回复风格还没摸透，多 swipe 几次就能挑出最贴合设定的那条
- **卡文时破局**：当前 AI 的回复方向不太对，直接 swipe 出一个新思路比硬接下去自然得多

如果想看清当前对话的完整分支结构，点汉堡菜单 → View Full Chat Tree，会弹出树状视图，从根到叶有一条路径高亮表示你当前所在的分支。

> [!NOTE]
> 每个分支独立保存，切换不会丢内容。但分享聊天时只会分享你当前选中的那条分支，整个树不会暴露出去。重要节点才分支就好，分支太多树视图会变得拥挤。

### 自己动手写一张角色卡

玩了一阵子之后难免手痒想自己写角色卡。Chub AI 的角色创建面板里有几个容易被忽视但很影响最终效果的字段，这里把它们的填写要点列出来。

**名字（Name）**是必填项，公开显示。目前 Unicode 字符限制已经解除，理论上可以用任何字符，但建议写得短而有辨识度——方便玩家在搜索结果里一眼认出。

**头像（Avatar）**可选，但一张清晰有代表性的立绘或插画比空头像竞争力强太多。注意别用违规图片，官方明确说过这类图可能触发送款方审查。暂时没有头像可以先留空，之后补上不影响发布。

**一句话简介（Tagline）**是强烈推荐填的字段，写成 elevator pitch 的感觉：一两句话讲清楚角色是什么、有什么特色。与其写"一个高中生"，不如写"成绩倒数但运动神经超强的田径队王牌，暗恋你很久却不敢说"——后者一看就有故事。

**详细描述（Description）**决定了搜索匹配效果，写得好能让更多人搜到你的角色。建议 100~300 字，把角色背景、故事线、适合的场景都交代清楚。

**标签（Tags）**直接决定角色出现在哪些分区。官方会给一些推荐标签，也可以自定义。选标签时想想你希望角色被什么人发现——比如写中文角色加上 Chinese 标签，精准度比滥打一堆标签高得多。

发布前可以先搜索一下有没有同名或高度相似的角色，太撞了建议改名；标签控制在 2~5 个比较好，太多反而稀释了信号。

### Stage 扩展：让社区工具帮你干活

Stage 是 Chub AI 的扩展机制，社区开发者可以为平台增加各种辅助工具。不过在使用 Stage 之前，理解它的安全架构很重要。

Stage 以 iframe 形式运行在独立的安全沙箱里，拿不到你在 Chub 上的登录态、API Key、密码等敏感信息，也无法跨域访问其他 Stage。平台还会禁止 alert、confirm 这类弹窗来防止欺骗。带 "Verified" 标记的 Stage 是经过开发团队检查的，相对更安全。

> [!WARNING]
> 沙箱隔离防不住社会工程攻击。Stage 虽然技术上偷不到你的 Key，但它可以在 UI 里诱导你"请输入 API Key 以激活某功能"。官方反复强调：**永远不要在任何 Stage 里输入密钥或密码**，遇到需要登录或密钥的 Stage 直接跳过就好。
