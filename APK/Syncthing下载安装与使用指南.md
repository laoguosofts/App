## ✨ Syncthing 是什么：去中心化的跨设备文件同步

Syncthing 是一个开源的对等（P2P）文件同步工具——它的定位不是「又一个网盘」，而是让你自己的多台设备直接互相同步文件：手机、笔记本、台式机、NAS、甚至家里跑 Linux 的小主机，只要都装上它、配对过同一个文件夹，文件变更就会在设备之间直连分发，不经过任何第三方服务器。

它的核心特征很鲜明：**去中心化、不收费、无文件大小/空间限制、端到端加密传输**。每台设备既是客户端也是服务端，没有任何单点故障，也没人会对你的同步目录做内容扫描。对于在意隐私、数据主权，或者不想被网盘厂商限流、限速、清空间的用户来说，它提供了一条完全不同的路。

典型的使用场景包括：多台电脑之间的工作资料同步、手机照片自动备份到家里的 NAS、开发团队的代码草稿跨机衔接、家庭媒体库在不同房间的设备间保持一致。只要文件需要在两台及以上设备之间保持同步，Syncthing 都能覆盖——它甚至支持不同平台、不同文件系统（macOS 默认大小写不敏感，与 Linux 混用时要留意大小写冲突）。

它有两种主要形态：**基础包**是官方发布的核心本体，一个命令行守护进程加一套基于浏览器的管理界面（默认监听 127.0.0.1:8384）；**集成包**是社区维护的完整应用，带系统托盘图标、随登录自启、文件管理器集成等能力，官方推荐新用户从集成包起步。

## 🔧 安装步骤：按平台选对版本

Syncthing 的官方下载页分成两层结构：**集成包**和**基础包**，理解这个分流是选对版本的前提。集成包由社区维护，带操作系统级的托盘图标、自启动、文件监视等能力；基础包就是官方核心本体，没有图形外壳，一切通过浏览器里的管理界面操作。所有集成包底层跑的都是同一套核心，差别只在外层封装。

**版本选择对照**：

| 用户类型 | 推荐形态 | 说明 |
| --- | --- | --- |
| Windows 新手 | Windows 安装器 / SyncTrayzor | 安装向导会处理自启动，SyncTrayzor 还带托盘工具和文件监视 |
| macOS 用户 | 官方 macOS 应用包 | 常规 Mac 应用，直接装进「应用程序」，登录启动项由系统设置管理 |
| Linux / NAS / 服务器 | 基础包 / 发行版包 | 多数发行版仓库已带它，Debian/Ubuntu 可加官方 apt 源取最新版本 |
| 想完全掌控配置 | 基础包 | 没有 GUI 外壳，一切通过 Web 管理界面操作 |

当前官方发布的主线版本是 v2.1.6 系列，覆盖 x86/ARM 的 64 位与 32 位架构，另含 Loong64、MIPS、RISC-V、IBM z 系列等特殊架构。普通电脑选对应系统的「Intel/AMD (64-bit)」包即可；NAS 等特殊设备先查厂商文档。

### Windows 安装要点

Windows 新手最省心的路线是**Windows 安装器**或 **SyncTrayzor v2**。安装向导会处理路径选择、自启动配置和任务计划注册。如果用基础包手动安装，解压后在配置目录里运行 `syncthing.exe -generate` 生成默认配置，再以 `-no-console` 参数注册到任务计划即可实现开机自启。

> [!WARNING]
> Windows 用户在升级到 v2.0 及以上版本后，`.stignore` 忽略规则文件的转义字符从反斜杠改为**竖线 `|`**（反斜杠在 Windows 是路径分隔符）。如果升级后发现规则行为不对，先检查这里。想沿用反斜杠写法，在 `.stignore` 文件首行加 `#escape=\`。

### macOS 安装要点

macOS 用户直接用官方应用包最省事：下载 `.dmg`、拖进「应用程序」、首次启动时系统会问是否允许——这是因为签名方式的问题，右键打开一次即可绕过 Gatekeeper 的警告。

习惯命令行的用户可以用 homebrew：

```bash
brew install syncthing
brew services start syncthing
```

base/paypal 安装完成时 brew 会输出用 launchctl 注册服务的提示，照着执行就能变成随登录自启的后台服务。

### Linux 与 NAS 安装要点

Debian/Ubuntu 用户直接 `apt install syncthing`，或添加官方 apt 源获取更新版本。Arch、Fedora 等发行版仓库也都已收录。NAS 用户（群晖、威联通等）通常能在社区仓库找到预编译包，或用 Docker 跑基础包。

自启动统一用 systemd（Linux）或 launchd（macOS）：Syncthing 官方文档里给了完整的 systemd user service 文件和 macOS launchd plist 模板，解压发布包即可在 `etc/` 目录下找到。macOS 手动配置时记得把 plist 里四处 `USERNAME` 替换为你的实际用户名——这是最高频的配置错误。

## 📖 使用入门：从首次启动到集群跑通

### 首次启动与设备配对

第一次启动后打开浏览器访问 `http://127.0.0.1:8384`，就能看到管理界面。界面语言默认英文，在 Settings → General 里可以切换。

每台 Syncthing 设备都有一个**唯一的设备 ID**（在 GUI 的 Action → Show ID 里可以看到二维码和长字符串）。配对就是把一台设备的 ID 添加到另一台的已知设备列表里。GUI 里是 **Add Remote Device** 按钮，把对方设备 ID 粘进去就行。两台设备互相配对后，在其中一台添加共享文件夹（添加文件夹时选择哪些已知设备可以访问它），另一台的 GUI 会弹提示让你接受——接受后同步就开始跑了。

> [!TIP]
> Syncthing 用 NAT 穿透和中继服务器处理直连——大多数情况下两台设备都在 NAT 后面也能连上。但如果两边都在严格的 NAT 后面（比如公司内网），可能需要手动配置 TCP 端口转发，或者用 Syncthing 的中继功能兜底。

### 文件夹共享与版本管理

添加文件夹时需要决定**同步模式**：

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| Send & Receive | 双向同步，所有设备平等 | 绝大多数场景 |
| Send Only | 本机作为只读源，其他设备的变更不会覆盖本机 | 把一台电脑当主库 |
| Receive Only | 本机只接收，不推送 | 备份机、只读终端 |

每个文件夹都有独立的版本策略设置：GUI 里点文件夹的 Edit，看 Versioning 选项卡。推荐开启 **Simple Versioning**（保留最近 N 个版本）或 **Staggered Versioning**（按时间阶梯保留，更节省空间），这样某个设备误删或覆盖了文件，还能从其他设备的版本池里救回来。

### v2.0 升级注意事项

如果你是从 v1.x 升级上来的，v2.0 有两个**一次性的行为变化**需要提前知晓：

1. **数据库迁移**：v2.0 把索引库从 LevelDB 整体换成了 SQLite。首次以 v2 启动时会执行一次迁移，配置较大的用户可能耗时较长。这是一次性操作，迁移完成后新库的表现和可维护性都更好——官方原话是「更容易理解与维护，希望能少些 bug」。旧数据库会被留在原地以备回滚，所以升级前**只需要备份同步目录本身**，数据库层有兜底。

2. **删除记忆保留期**：v2.0 起已删除条目不再永久保留，默认 **15 个月**后被遗忘。含义是：一台设备离线超过 15 个月再回来，集群已经不记得它错过的删除操作。官方给了配置入口可以调整起始时间，有超长离线周期设备的用户需要留意这一项。

> [!NOTE]
> v1 与 v2 设备可以混合组网——协议层兼容，不必所有设备同时升级。但迁移只发生在「首次以 v2 启动」的那台设备上。逐台升级比一次性全集群同时动更稳妥。

### 日志排障与审计

大多数情况下 Syncthing 跑得很安静，但遇到连接问题、同步卡住、文件冲突时，先看日志总没错。

**默认日志在哪**取决于你的运行方式：

- 命令行前台运行 → 直接看控制台（stdout）；
- Windows 安装器/基础包 → 配置目录里的 `syncthing.log`（路径可用 `syncthing --paths` 查看）；
- systemd 管理的进程 → `journalctl --user -u syncthing`；
- GUI 集成包 → 在管理界面 Help → About → Paths 标签里直接看。

日志里几个高频信号：

| 日志片段 | 含义 |
| --- | --- |
| `My ID: ...` | 本机设备 ID |
| `Established secure connection ...` | 与某设备建立加密连接 |
| `Detected NAT type: ...` | NAT 类型，影响直连成功率 |
| `database is corrupt` | 索引库损坏——官方说几乎总是硬件问题（坏内存或坏盘），停程序、删索引库、重启，代价是所有共享文件夹重新全量哈希 |
| `Folder marker missing` | 文件夹标记丢失，通常是手动改了文件夹路径或权限被破坏 |

GUI 里的 **Recent Changes** 只显示本进程启动以来的变更。需要持久的完整活动记录时用 `--audit` 参数启动，程序会把 JSON 格式的事件流写进 `audit-日期_时间.log`。注意一个边界：重连后的审计只见「最新一次变化」——离线期间对方设备的多步修改在索引交换后被压缩为一个结果。

### 提升稳定性的小技巧

- **自启动要开**：Syncthing 是后台守护进程，随系统登录启动才能保证文件同步不中断。Windows 安装器和 macOS 应用包默认会注册自启动；Linux/NAS 用户用 systemd。
- **登录后别弹浏览器**：自启动场景下每次登录都自动开浏览器标签会很烦。在 Settings → General 里关掉 **Start Browser** 选项，之后管理界面按需手动访问 127.0.0.1:8384。
- **进程跑两份是正常的**：Windows 任务管理器里看到两个进程别慌——一个是监视进程（monitor），负责捕获日志、管理重启与自升级；另一个是真正干活的进程。这是设计行为，不是异常。
- **混合系统留意大小写**：macOS 和 Windows 默认大小写不敏感，Linux 默认敏感。混用环境下如果出现同步冲突，先排查是不是两个设备同时创建了仅大小写不同的文件。
- **调试日志别常开**：连接类疑难杂症在 INFO 级看不清时，可用环境变量提高特定模块的日志级别（STTRACE），排完记得改回来——调试日志量很大，会拖慢 I/O。
