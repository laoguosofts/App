## ✨ AppBlock 是什么

AppBlock 是一款专注于 Android 平台的应用与网站拦截工具——它不提供什么花哨的功能，核心就一件事：**让你在想专注的时候，真的打不开那些会分散注意力的东西**。社交媒体、视频平台、购物网站、甚至某个特定的关键词页面，统统可以被加入拦截清单，配合定时计划和严格模式，从根源上切断你"忍不住点开"的可能。

和同类工具相比，AppBlock 的优势在于它的**拦截精度**和**防反悔机制**。拦截层面，它通过无障碍服务持续监控手机上的活动窗口，无论是 App 还是浏览器里的 URL，只要命中黑名单就会被一层自定义屏蔽页面覆盖。防反悔层面，严格模式提供了 Timer 锁定、Approval 担保人、PIN 码、充电器检测等多种解锁门槛，让你在执行专注计划的过程中无法轻易绕过拦截。

AppBlock 支持的拦截范围也不局限于手机应用——网站拦截覆盖 Chrome、Firefox、Edge、Brave、Samsung Internet 等 25 款以上浏览器，配合域名匹配、完整 URL 匹配和关键词匹配三种方式，可以精准地屏蔽某类内容而不是整个平台。Allowlist 白名单模式则把逻辑反过来：只放行你指定的网站，其余全部拦截，适合需要把手机变成"只能访问工作/学习资源"的极简终端。

> [!TIP]
> 品牌适配是很多用户忽略的关键一步。AppBlock 能不能稳定运行，很大程度上取决于你有没有把它正确加入各品牌的后台白名单。拦截突然失效时，90% 的原因是权限被系统回收或进程被杀。

这款工具适合谁？如果你有以下困扰——每天刷短视频刷到停不下来、工作时手机一响就忍不住摸鱼、想让孩子的手机只能访问教育类内容——AppBlock 都能帮上忙。它的定位很明确：不是一个"效率提升全家桶"，而是一个专注做好拦截这一件事的实用工具。

## 🔧 安装与权限配置

AppBlock 是 Android 平台专属应用，安装过程本身并不复杂，但**权限配置直接决定拦截能不能生效**——很多人装完发现不好用，问题就出在权限没给全。

### 下载与安装

1. 从上面的下载入口获取安装包，或在 Google Play 搜索 AppBlock 直接安装
2. 如果是从外部安装包安装，需要在系统设置里允许"未知来源应用安装"
3. 安装完成后先别急着打开，先把下面的权限配置做完

### 五步权限检查清单

不管你用的是小米、华为、三星还是 Pixel，按以下顺序检查一遍，拦截稳定性基本能解决：

1. **电池优化白名单**：系统设置 → 电池 → AppBlock → 设为"无限制"或"不优化"
2. **锁定后台任务**：打开多任务界面 → 找到 AppBlock 卡片 → 下拉或长按出现锁头图标 → 锁定
3. **自启动权限**：系统设置 → 应用自启动 → AppBlock → 允许
4. **后台弹出界面**：系统设置 → 特殊权限 → 后台弹出界面 → AppBlock → 允许
5. **通知权限**：保持开启（严格模式到期、用量提醒都依赖它）

> [!WARNING]
> 如果你升级了手机系统（比如 MIUI 升到 HyperOS），**所有白名单设置需要重新做一遍**——新系统的清理规则通常更激进，之前的配置会被重置。

### 各品牌的特殊处理

不同品牌的后台管理策略差异很大，以下是几个主流品牌的针对性操作：

| 品牌 | 关键设置 | 注意事项 |
| --- | --- | --- |
| 小米 MIUI/HyperOS | 省电策略→无限制、自启动打开、多任务锁定 | HyperOS 升级后全部重配 |
| 华为 HarmonyOS/EMUI | 后台保护→允许活动、启动管理→允许自启动 | 关闭智能省电模式 |
| 三星 One UI | 电池优化→未限制、自动运行→打开 | 关闭"保护电池"选项 |
| OPPO ColorOS | 关闭后台冻结、允许后台弹出界面 | —— |
| vivo OriginOS | 控制中心→后台白名单添加 | —— |
| Pixel/原生 Android | Android 14+ 检查后台活动限制→无限制 | 原生系统最宽松，通常不用额外配置 |

### 验证配置是否生效

AppBlock 内置了自检功能：打开 AppBlock → Profile → Help → Troubleshooting，核对所有权限状态是否都显示正常。如果某项权限被系统回收，在这里能直接看到提示。

## 📖 使用入门

权限配置到位后，就可以开始使用 AppBlock 的核心功能了。我们从最常用的场景讲起，逐步覆盖到严格模式和故障排查。

### 基础拦截：把想屏蔽的东西加进清单

AppBlock 的拦截分两类：**应用拦截**和**网站拦截**，两者可以独立运行也可以叠加。

**应用拦截**的操作很直观：在 AppBlock 主界面点"Blocklist"，勾选你想屏蔽的应用就行。比如微信、抖音、淘宝——勾上就直接进了黑名单。还可以设置定时计划，比如"工作时间 9:00–18:00 屏蔽微信"。

**网站拦截**稍微复杂一点，它通过浏览器扩展或无障碍服务实现，覆盖 Chrome、Firefox、Edge、Brave、Samsung Internet 等 25 款以上浏览器。网站拦截有三种匹配方式：

- **域名匹配**：输入 `twitter.com`，该域名下所有页面都会被拦（包括 `x.com` 的重定向）
- **完整 URL 匹配**：输入 `twitter.com/home`，只拦这个特定页面，适合只想屏蔽某个板块
- **关键词匹配**：输入 `shorts`，所有 URL 中包含 `shorts` 的页面都会被拦，适合拦某类内容

> [!NOTE]
> 部分浏览器的链接预览/悬浮卡片功能会动态加载 URL，AppBlock 可能在预览阶段识别不到真实 URL。遇到这种情况，手动把完整链接或关键词加入 Blocklist，或改用完整 URL 匹配。

### Allowlist 模式：反向拦截的正确用法

Allowlist 是 Blocklist 的反向逻辑——**只允许白名单内的网站，其余全部拦截**。这不是一个"高级用户专属"的功能，恰恰相反，它适合有极端专注需求的场景：

- 把手机变成"只能访问学习/工作网站"的极简终端
- 给孩子的手机设置只能访问教育类网站
- 配合严格模式，彻底切断所有干扰源

Allowlist 模式下还可以设置**例外**（白名单内的某些特定页面反而被拦），也可以设置**浏览器级规则**（某个浏览器开启 Allowlist，另一个正常使用）。不过要注意一个已知限制：如果你同时开启了 Website Allowlist 并把 Chrome 本身加入了 App 黑名单，白名单会失效——解决方法是确保 Chrome 和 Google Search 同时在 App 允许列表里。

### 严格模式：让你真的解不开

基础拦截靠的是"你不想解就不解"，但真正让 AppBlock 有口碑的是它的**严格模式**——设计初衷就是"让你不能轻易解开"。严格模式提供了多种解锁门槛：

- **Timer 锁定**：设一个时间（比如 7 天），时间不到就是解不开
- **Approval 担保人**：指定一个人，只有他审批通过才能解锁
- **PIN 码**：设置一个密码，解锁需要输入
- **充电器检测**：只有插上指定充电器才能解锁
- **Cooldown 冷却期**：尝试解锁后需要等待一段冷却时间才能再次尝试

> [!WARNING]
> Timer 时长建议保守一点，不要上来就 30 天——先试 3 天 7 天，确认自己真的能接受再逐步加长。PIN 码别和手机锁屏密码一样但要记死，担保人要选靠谱的人。

### 紧急解锁：真被锁死了怎么办

严格模式总会有意外：Timer 设了 7 天突然有事要用、担保人联系不上、PIN 码忘记了。这时候走 AppBlock 内置的紧急解锁流程：

1. 打开 AppBlock → Profile（更多）→ Help → Contact Support
2. 在客服对话框输入 "Contact support" 跳过机器人，进入人工客服表单
3. 选择 "Emergency Unblocking"（紧急解锁），回答几个验证问题
4. 完成后严格模式会一次性解除

老版本（v7.5.2 之前）没有内置紧急解锁按钮，需要手动发邮件到 support@appblock.app，附上 Google Play 订单截图和 Profile 页面截图验证身份，官方通常 24–48 小时内回复一次性解锁码。

紧急解锁有两层安全设计防止滥用：只解除当前这一轮严格模式，不会永久禁用严格模式功能；每次使用后下次再用需要重新输入一个随机验证字符串。

### 常见故障：计划结束了怎么还在拦

这是 AppBlock 官方已经确认的一个 bug——某些设备上定时计划到期或暂停后，应用仍然显示屏蔽页面，不会自动解除。官方解释说这个 bug 难以稳定复现，可能与 Android 系统版本、品牌 ROM 的后台管理策略、无障碍服务状态有关。

症状很明确：计划时间已过、AppBlock 计划列表显示已停止，但被拦应用打开后屏蔽页面仍然出现。目前最稳定的临时解法就是**重启手机**——重启会刷新无障碍服务的所有会话，清除残留的拦截状态。

如果重启也不行，可以尝试：完全关闭 AppBlock → 手动关闭并重新打开无障碍服务（系统设置 → 无障碍 → AppBlock 开关关闭再打开）→ 再次测试。

减少触发概率的建议：不要频繁手动暂停/恢复计划，手机重启后确认 AppBlock 已自启动生效，避免多个计划的结束时间过于密集。如果你能稳定复现这个 bug，鼓励通过 AppBlock 内的 Contact Support 提交反馈，附上手机型号、Android 版本、AppBlock 版本号和复现步骤。
