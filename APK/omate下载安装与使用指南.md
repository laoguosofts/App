## ✨ OMate 是什么

OMate 是一款面向 AI 角色互动的开源客户端，核心思路是把 AI 模型的对话能力和成熟的角色卡生态结合起来。它兼容酒馆 SillyTavern 的角色卡格式（V1/V2/CCV3 全版本），支持自建角色、导入社区卡、长期记忆自动提取、知识库向量检索等功能，让 AI 角色从"一次性对话"变成能记住你、能持续互动的虚拟伙伴。

OMate 自身不绑定任何特定模型服务——你可以接入任意兼容 API 的中转站或官方接口，模型参数（max_tokens、temperature、top_p 等）通过模型参数栏透传。这意味着你可以根据自己的使用场景自由搭配：想玩深度剧情续写就挂思考型模型（R1 系列）、要快速出消息就用轻量的快速模型。

适合的人群很明确：喜欢和 AI 角色互动、想要跨对话连续感的用户；想自建角色卡但又依赖酒馆社区生态的创作者；以及对模型参数有调优需求的进阶玩家。

## 🔧 安装步骤

OMate 的安装流程因平台而异，但核心步骤是一致的：拿到安装包 → 完成基础配置 → 接入模型 API → 导入或创建角色。

### Android 平台

1. 从下载页获取 APK 安装包
2. 首次安装时，系统会提示"未知来源"授权——进入系统设置 → 安全 → 开启"允许安装未知应用"
3. 安装完成后打开，进入"模型配置"环节

> [!WARNING]
> 部分国产 ROM（小米、OPPO、vivo）会在安装过程中弹出额外的安全验证，需手动确认信任该应用。

### Windows 平台

1. 下载页获取安装包或绿色版压缩包
2. 如果是安装程序，双击运行后选择安装路径（建议放在非系统盘）
3. 如果是压缩包，解压即可运行，无需安装

### 首次启动必做配置

打开应用后，第一个要完成的是**模型 API 配置**：

1. 进入设置 → 模型配置
2. 填写服务商提供的 API 地址和密钥
3. 选择模型名称
4. 在"模型参数"栏根据需要追加参数串（如 `max_tokens=2048&temperature=0.7`）

> [!TIP]
> 接入思考型模型（R1 系列）时，务必把"请求超时时间"从默认 10 分钟调到 20~30 分钟，否则 AI 还在推理请求就会被断开。普通快速模型保持默认即可。

## 📖 使用入门

### 导入角色卡——最快上手的方式

OMate 完整兼容酒馆 SillyTavern 的角色卡格式。导入有两种方式：

- **从 PNG 图片导入**：酒馆社区的角色卡以 PNG 形式分发，图片里内嵌了 V2 和 V3 两种数据块。OMate 会自动识别版本并优先读取最新的 V3（CCV3）块，字段最完整
- **从 URL 导入**：如果社区提供了角色卡的直链，直接粘贴 URL 即可拉取

导入后可以在 OMate 里自由编辑角色设定，改完还能导出回酒馆兼容的 PNG/JSON/charx 格式——OMate 会保留原卡的所有字段作为底稿，实现双向流转不丢数据。

### 自建角色——从零打造专属 AI

如果社区没有你想要的角色，在角色页面点右上角加号 → 新建角色，从头创建：

**基本信息**：角色名称（必填，会显示在聊天界面和角色列表）、头像（可选，上传图片即可）、简介（一句话描述，显示在角色卡片上）。

**角色设定字段**是决定 AI 扮演效果的核心：

| 字段 | 作用 |
|---|---|
| 第一条消息 | 角色与你对话时的标准开场白，建议带场景感而非干巴巴的"你好" |
| 替代问候语 | 多条备选开场白，每行一条，第一条消息为空时轮播显示 |
| 性格特点 | 角色的个性、习惯和行为模式——写具体细节比写形容词更有效 |
| 场景设定 | 角色所处的环境和情境，给 AI 提供对话的"舞台背景" |
| 对话示例 | 展示角色说话风格的样本——AI 会参考示例的句式、用词、语气来模仿 |
| 系统提示词 | 硬性规则指令，如"不要打破第四面墙""自称小护士" |

> [!TIP]
> 对话示例是最有效的风格锚点。举个例子：与其写"开朗乐观"，不如在对话示例里放几句带具体场景的台词——AI 会照着这个语气模仿，效果比抽象描述好得多。

### 长期记忆——让 AI 记住你

长期记忆是 OMate 区别于普通 AI 聊天工具的关键功能。开启后，每次对话结束 AI 会自动从互动内容中提取重要信息并保存——下次聊天时这些记忆会作为上下文的一部分注入，对话就有了跨对话的连续感。

**开启方式**：聊天界面 → 右上角齿轮 → 记忆标签页 → 打开"启用长期记忆"开关。

**记忆设置**：

- 自动提取记忆：开启后每次对话后自动分析提取新记忆；关闭则只使用已有记忆
- 记忆时间标记：为每条记忆添加时间戳（如"记录于 2024 年 1 月 15 日"），方便 AI 建立时间线
- 记忆数量限制：100 ~ 5000 条可调，超过限制自动删除最早的条目

> [!NOTE]
> 长期记忆的提取和总结由"总结模型"完成。如果没有单独配置总结模型，OMate 会用对话模型代替——效果略差但能正常工作。

长期记忆和知识库（知识书）是不同的东西：

| 特性 | 长期记忆 | 知识库 |
|---|---|---|
| 内容 | AI 自动从对话中提取的关于**你**的信息 | 你主动放进去的**资料** |
| 触发方式 | 自动注入（优先级高） | 语义向量检索（按需取回） |
| 管理方式 | AI 自动管理数量和时间 | 你手动上传和管理 |
| 典型内容 | "用户说过喜欢猫""用户的生日是 3 月" | "小说全集""产品手册" |

### 模型参数调优

OMate 把模型参数的控制权交给用户，在 API 配置的"模型参数"栏以查询串格式透传服务商支持的采样参数：

```
temperature=0.7&top_p=0.9&max_tokens=2048&frequency_penalty=0.5
```

几个关键参数的作用：

| 参数 | 作用 | 调优建议 |
|---|---|---|
| temperature | 温度，越高越有创造性 | 想让 AI 活泼点就调高一档，想稳定输出就调低 |
| top_p | 核采样阈值，越低越保守 | 配合 temperature 使用，两者都调 AI 回复会更集中 |
| max_tokens | AI 回复的最大 token 数 | 限制 AI 说多长——不是越长越好，太长可能发散 |
| frequency_penalty | 频率惩罚 | 减少 AI 重复同一句话的概率 |

> [!WARNING]
> max_tokens 控制的是 AI **下行**回复的上限，不要和"最大上行字数"搞混——后者在聊天设置里调整，控制的是**上行**发送给 AI 的总内容量（包括历史消息、世界书、记忆等）。上行字数调太小会导致历史对话被截断，AI 遗忘之前的内容。

### 请求超时的排查

如果 AI 回复经常中途断开，按以下顺序排查：

1. 检查请求超时设置是否足够长——思考型模型至少 20 分钟
2. 检查服务商 API 稳定性——换一个中转站试试
3. 在 OMate 的"上下文与思考日志"里看有没有超时提示
