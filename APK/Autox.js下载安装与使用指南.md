## ✨ Autox.js 是什么

Autox.js 是一个运行在 Android 平台上的 JavaScript 脚本引擎，核心功能是**用代码控制手机，让设备替你完成重复性操作**——模拟点击、滑动屏幕、找图找色、识别文字、甚至调用网络接口都能覆盖。它的前身是 Auto.js，由社区开发者 kkevsekk1 在原版作者 hyb1996 停止维护后接掌并持续迭代，目前 v7.x 系列是这条社区维护线的主力产物。

Autox.js 的独特之处在于**无需 Root 权限**——通过 Android 的无障碍服务 API 就能实现自动化控制，降低了使用门槛。它的 API 覆盖面相当广，核心模块包括：无障碍服务（模拟点击、滑动、按键、文本输入）、选择器 API（类似 Google UiAutomator，用代码定位 UI 控件）、图像识别（截屏 + OpenCV 模板匹配）、PaddleOCR（让脚本读懂屏幕文字）、悬浮窗录制（可视化录制操作自动生成 JS 代码），以及把脚本项目打包成独立 APK 分发的能力。v7.2.4 版本进一步引入了 Node.js 运行时、TypeScript 支持和 Jetpack Compose UI，生态更加完善。

需要澄清的几点：Autox.js 不是按键精灵（它靠控件选择器而非纯坐标录制，跨分辨率兼容性好得多）、不是 Auto.js Pro（Pro 是商业化闭源版本，目前因合规整改暂停对外服务）、也不是 AutoJs6（AutoJs6 是另一个独立分支，两个分支方向不同）。它只支持 Android，iOS 自动化需要另找方案。

典型的使用场景非常广泛：普通用户用来做 APP 签到打卡、自动抢红包；办公人士批量转发消息、自动填写表单；游戏玩家写挂机脚本、自动刷副本；开发者和 QA 用来做 App 自动化测试和回归验证。写代码的人和不写代码的人都能用它——前者写脚本，后者用打包好的 APK。

项目基于 Mozilla Public License v2.0 开源，附加了非商业性使用条款，公开的 APK 只有 arm64-v8a 架构。

## 🔧 Autox.js 安装与初始化配置

Autox.js 是 Android 应用，安装流程和普通 APK 类似，但首次使用需要完成几项关键的权限配置，否则脚本跑不起来。

### 安装步骤

1. **下载 APK**：从下载页获取最新版本的安装包，确认文件架构为 arm64-v8a（目前公开分发的版本仅此架构，32 位设备需自行编译或换 AutoJs6 分支）。

2. **允许未知来源安装**：如果系统弹出「禁止安装未知来源应用」，需要进入系统设置，为当前浏览器或文件管理器开启「允许安装未知来源应用」权限。不同 ROM 的路径略有差异——小米在「设置 → 应用管理 → 特殊权限 → 安装未知应用」，华为在「设置 → 安全 → 更多安全设置 → 安装未知应用」。

3. **完成安装**：点击 APK 完成安装后，桌面上会出现 Autox.js 的图标。

### 首次启动必须配置的权限

> [!TIP]
> 以下权限**缺一不可**，跳过任何一项都会导致脚本执行时静默失败。建议按顺序逐一完成。

1. **无障碍服务**：这是 Autox.js 的核心依赖。进入「设置 → 无障碍 → 已下载的服务」，找到 Autox.js 并开启。开启后系统会弹出一个确认对话框，提醒无障碍服务可以观察你操作的所有内容——这是 Android 的标准安全提示，Autox.js 不会上传你的操作数据。

2. **悬浮窗权限**：Autox.js 的悬浮录制面板和控制台需要悬浮窗权限。进入「设置 → 应用 → Autox.js → 权限 → 悬浮窗」，允许显示在其他应用上方。

3. **电池优化白名单**：国产 ROM（小米、华为、OPPO、VIVO 等）会激进地杀后台进程。把 Autox.js 加入电池优化白名单，是脚本能否稳定运行的关键。在系统电池优化设置中找到 Autox.js，设为「无限制」。

4. **自启动管理**：在系统自启动管理应用（通常在安全中心或手机管家中），把 Autox.js 标记为「允许自启动」，确保手机重启后它能自动恢复运行。

## 📖 Autox.js 使用入门：从写第一个脚本到高级自动化

### 第一个脚本：Hello World

Autox.js 自带内置 IDE，打开后点击右下角「+」新建脚本，输入以下内容：

```javascript
auto.waitFor();  // 等待无障碍服务就绪
toast("你好，Autox.js！");
```

点击运行，屏幕下方会弹出一个 Toast 提示。这就是你的第一个自动化脚本。

### 核心 API 概览

Autox.js 的 API 可以分成几组，理解它们就能覆盖大部分使用场景：

| API 类型 | 功能 | 典型用途 |
| --- | --- | --- |
| 选择器 API | 按属性定位屏幕控件 | 点击按钮、读取文本、遍历列表 |
| 坐标操作 | 像素级点击、滑动、手势 | 游戏、自绘 App（无控件树） |
| 图像识别 | 截屏 + 模板匹配 | 在未知布局中定位特定图片 |
| OCR | 识别屏幕文字 | 需要读取屏幕内容的场景 |
| shell | 执行系统命令 | 高级操作，需要 Root |

### 选择器 API：自动化的主力方案

选择器 API 建立在 Android 控件树之上，类似 Google UiAutomator。它的优势是**跨分辨率兼容**——你写的是语义定位（比如「找一个文本为"确定"的按钮」），不管在什么分辨率的手机上都能工作。

```javascript
auto.waitFor();

// 找到文本为"确定"的按钮并点击
let btn = text("确定").findOne();
btn.click();

// 也可以链式组合多个条件
let confirmBtn = className("Button").text("确定").findOne();

// 获取控件的位置，手动点击中心
let b = confirmBtn.bounds();
click(b.centerX(), b.centerY());
```

### 坐标操作与多指手势：游戏和自绘 App 的备选

不是所有 App 都有标准的控件树——游戏引擎（Unity、Unreal）完全自绘，部分银行、安全类应用屏蔽了无障碍事件。这时候就得退回到坐标像素操作：

```javascript
// 基础坐标操作
click(540, 1200);              // 点击指定坐标
longClick(540, 1200);          // 长按
swipe(100, 1500, 1000, 500, 300);  // 从 (100,1500) 滑到 (1000,500)，耗时 300ms

// 多指手势：两指捏合（类似缩放）
gestures(
    [0, [540, 1000], [440, 1000]],   // 手指 A 向左移动
    [0, [640, 1000], [740, 1000]]    // 手指 B 向右移动
);
```

> [!WARNING]
> 坐标操作的致命缺点是**分辨率绑定**——`click(540, 1200)` 在 1080x2400 的手机上有效，换到 720x1600 的手机就点偏了。必须用相对比例计算或配合图像识别来缓解这个问题。

推荐的跨分辨率写法：

```javascript
let w = device.width;
let h = device.height;

// 点击屏幕中心偏下
click(w * 0.5, h * 0.7);

// 更稳妥：先找图，拿到图的中心坐标再点击
let img = captureScreen();
let result = images.findImage(img, "confirm_button.png");
if (result) {
    click(result.x, result.y);
}
```

### 后台保活：让脚本不被系统杀掉

很多人遇到过「脚本跑着跑着突然停了」「锁屏后就不跑了」的问题——这不是脚本坏了，是 Android 的后台管理策略在起作用。Android 的后台优先级从高到低依次是：前台 App、前台服务（带通知栏常驻通知）、普通后台进程、缓存进程。Autox.js 大部分时间在后台进程层级，内存紧张时系统随时可能把它杀掉。

**四层保活方案**（按推荐顺序叠加）：

| 层级 | 手段 | 效果 |
| --- | --- | --- |
| 系统配置 | 电池白名单 + 自启动 + 后台弹出 | 基础保活，必做 |
| 脚本自身 | 前台服务通知 + 无长 sleep | 脚本运行期间保活 |
| 状态检测 | 检查无障碍 + 自动恢复 | 权限丢了也能救回来 |
| 外部守护 | Tasker 周期性检查 + 自动重启 | 进程死了也能拉起来 |

脚本层面要避免长时间 sleep——长 sleep 期间进程什么都不做，最容易被系统回收。更安全的写法是用短 sleep + 循环：

```javascript
// 危险：长 sleep
sleep(3600000);

// 安全：短 sleep + 循环 + 轻量操作
for (let i = 0; i < 3600; i++) {
    sleep(1000);
    // 每个循环检查一次无障碍服务是否还在
    if (!auto.service) {
        console.warn("无障碍服务丢失");
        // ... 恢复逻辑
    }
}
```

### 与 Tasker 联动：真正的自动化触发器

Autox.js 内置了 Tasker 插件接口，可以被 Tasker 调用。Tasker 是 Android 上最强大的自动化触发器 App——它能监听时间、位置、网络、电量、屏幕状态、来电短信等各种事件，然后触发 Autox.js 执行指定脚本。

配置起来很简单：

1. 确保 Autox.js 已安装（v7+ 版本默认包含 Tasker 插件能力）
2. 在 Tasker 里新建任务，Action 里搜索 "Autox.js" 或 "Run Script"，选择要运行的脚本
3. 新建配置文件（Profile）定义触发条件——比如「每天早上 8 点」「连上公司 Wi-Fi」「充满电」

常见的联动场景：

| 场景 | Tasker 配置 |
| --- | --- |
| 每天自动签到 | 时间触发器 → 每日 09:00 → 运行签到脚本 |
| 连上公司 Wi-Fi 自动开邮箱 | 上下文触发器 → Wi-Fi SSID 匹配 → 打开邮箱并自动登录 |
| 游戏挂机自动续跑 | 应用触发器 → 游戏在前台 → 启动挂机脚本；退出 → 停止脚本 |
| 充到 100% 自动关闭提示 | 状态触发器 → 电量 100% 充电中 → 关闭充电提示 |

Autox.js 自身也有 timers 模块可以做定时，但它需要 Autox.js 进程保持存活，可靠性不如 Tasker（Tasker 的定时走系统闹钟 API）。简单场景用 Autox.js 自带的 timers 就行，复杂的条件触发还是推荐 Tasker。
