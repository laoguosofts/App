## ✨ Enpass 是什么——一款不依赖自家服务器的本地密码管理器

Enpass 是一款跨平台的密码管理器，支持 Windows、macOS、Linux、iOS、Android 和浏览器扩展。它的核心思路很明确：所有密码数据都以加密数据库文件的形式存在你的本地设备或你自己选择的云盘里，Enpass 不运营任何后端服务器，不会把你的密码上传到任何第三方。

这种设计带来了两个直接好处：一是没有订阅费用，买断一次终身使用；二是安全边界清晰——你的密码库文件在哪里，你的数据就在哪里。用户需要做的就是把这个加密文件放到一个靠谱的同步位置（Google Drive、Dropbox、OneDrive、iCloud Drive、Nextcloud 甚至本地文件夹 + 局域网同步都行），然后在多台设备上同时访问。

除了基本的登录条目存储，Enpass 还能管理信用卡、银行卡、身份证、软件密钥、附件、TOTP 两步验证器，以及越来越受关注的 Passkey 无密码登录。标签系统支持多维度灵活筛选，Vault 分离可以把个人、工作、家庭密码库互相隔离，备份恢复机制覆盖了从误删到设备丢失的各种灾难场景。

适合谁用：看重本地控制权、不想按月付费、需要多平台同步、家里有密码共享需求的个人或小型团队。如果你接受"我自己的密码文件我自己托管"这个前提，Enpass 的方案在体验和安全之间做了一个相当务实的平衡。

## 🔧 安装步骤——多平台安装注意点

Enpass 支持六大平台，安装过程整体轻量，但不同平台有一些值得留意的细节。

### Windows / macOS / Linux 桌面端

1. 从下载页获取安装包（Windows 为 `.exe`，macOS 为 `.dmg`，Linux 提供 AppImage、deb、rpm 多种格式）
2. 双击安装包按向导完成安装，桌面端默认安装路径无需额外配置
3. 首次启动会引导你创建主密码——这是整个密码库唯一的钥匙，务必设置一个足够强壮且你能记住的主密码
4. 创建完密码库后，选择存储位置：本机文件夹或已登录的云盘目录（Enpass 会引导授权 Google Drive / Dropbox / OneDrive / iCloud Drive）

> [!TIP]
> 主密码一旦丢失就无法找回——加密数据库没有后门，Enpass 团队也解不开。建议把主密码写在一个你能信任的地方（比如密码管理器之外的物理介质），而不是指望"忘记密码"功能。

### iOS 安装

1. App Store 搜索 Enpass 下载安装
2. 首次启动创建主密码，然后选择 Vault 存储位置——iOS 上常见选择是 iCloud Drive（系统原生集成，无需额外授权）或 Google Drive / Dropbox（跳转对应 App 授权）
3. 如果之前在桌面端已经创建好了 Vault，直接选"添加已有 Vault"登录相同的云盘账号即可同步

### Android 安装

1. 从 Google Play 或官网获取 APK 安装（官网版本更新更及时）
2. 官网 APK 安装时如果遇到"未知来源"提示，需要在系统设置中允许该来源
3. 存储位置选择逻辑与 iOS 类似，Google Drive 是最顺畅的集成方式

> [!WARNING]
> 安装后核对版本号是个好习惯——Enpass 的浏览器扩展版本需要和桌面端版本匹配才能正常工作。如果扩展连接不上，优先检查两端版本是否一致。

## 📖 使用入门——从第一次创建到日常操作

### 第一次创建 Vault 与多设备同步

Vault 是 Enpass 的核心容器，所有密码条目都存在 Vault 里。建议第一个 Vault 作为你的主密码库，存放在 Google Drive 或 Dropbox 这类跨平台同步顺畅的云盘上。创建完成后，在第二台设备上打开 Enpass，选择"添加已有 Vault"，登录同一个云盘账号，几秒钟后就能看到完整的密码条目。

> [!TIP]
> 云盘选择建议：如果家庭成员也需要访问同一个 Vault，推荐创建一个专门用于家庭共用的独立云账号（比如一个专门的 Gmail），而不是用你日常使用的主云盘账号。这样权限干净、成员进出灵活、数据隔离清楚——将来解散共享时，删掉这个账号或移除 Enpass 授权即可，不会牵连你的个人文件。

### Passkey 无密码登录——告别输密码的体验

Passkey 是 Enpass 近年跟进的重点功能，体验比传统密码登录顺畅很多。核心区别在于：密码登录需要你输入一串字符、浏览器把它提交到服务器；Passkey 登录则是你的本地设备用私钥签名一个挑战码、配合生物识别确认即可——钓鱼网站没法让你的设备签名，所以天生防钓鱼。

#### 登录的三种典型场景

第一种是浏览器扩展自动发现。你访问一个支持 Passkey 的网站（比如 GitHub、Google 登录页），浏览器检测到你的 Enpass Vault 里有对应的 Passkey，弹出选择器让你挑用哪个。选 Enpass → 用主密码或生物识别解锁 Enpass → 授权完成 → 登录成功。全过程 3~5 秒，完全不需要输入密码字符串。

第二种是移动端系统级集成。在 iOS Safari、Android Chrome 或原生 App 内，系统会直接弹出 Passkey 选择器（iOS 上看起来像 Face ID 的快速确认框），点击选择 Enpass → 用 Face ID 或指纹确认 → 登录完成。

第三种是已有账号但还没创建 Passkey。网站登录页会显示"用 Passkey 登录"的选项，点击后如果设备上没有对应的 Passkey，会引导你去账号设置里先创建一个。

#### 多 Passkey 与离线使用

同一个网站你可能有多个账号（主账号 + 测试账号），每个账号各有一个 Passkey。浏览器弹出的选择器会列出所有可用的 Passkey，每个带账号名标识，选哪个登录哪个。

Passkey 登录完全发生在本地——私钥存在你的 Enpass Vault 里，签名验证不依赖持续的网络连接。如果你的 Vault 存在本机文件夹或局域网同步里，完全不依赖云，Passkey 照样能用。Enpass 锁定时如果要使用 Passkey，会先提示你解锁 Enpass（输入主密码或生物识别），不会绕过主密码保护。

#### Passkey 常见问题排查

浏览器没有弹出选择器时，先确认三件事：Enpass 是否已设为默认密码管理器、目标网站是否真的支持 Passkey（某些网站只支持硬件安全密钥）、Enpass 里该网站的条目是否确实有 Passkey 字段。弹出了但点了没反应，检查桌面端是否在后台运行、是否已解锁、浏览器扩展是否正确安装并连接。

要撤销某个 Passkey，推荐去网站端操作（登录网站 → 账号设置 → Passkey 区域 → 删除），这是最彻底的方式。在 Enpass 内删除条目只是本地删除，网站端的公钥可能还在。

### 标签与筛选——让条目不再混乱

Enpass 的分类是固定分组（一个条目属于且只属于一个分类），但实际使用中一个条目可能同时属于多个维度——GitHub 账号同时是"开发工具"和"工作账号"，Netflix 同时是"流媒体"和"家庭共用"。标签（Tags）就是为这种跨维度组织设计的：一个条目可以有多个标签，标签不需要提前定义，随时可以创建。

#### 添加标签与侧边栏筛选

桌面端编辑条目时找到"标签 / Tags"字段，直接输入标签名按回车确认；移动端操作逻辑相同。标签的价值体现在侧边栏的多层筛选上：Vault 切换（主库 / 工作库 / 家庭库）→ 分类筛选 → 标签筛选（点击多个标签相当于 AND 逻辑，只显示同时带这些标签的条目）→ 收藏标记 → 按字母索引 → 全文搜索框。搜 `github` 可以快速找到所有 GitHub 相关条目，全文搜索覆盖标题、备注、字段值和标签名。

#### Vault / 分类 / 标签 三者关系

| 维度 | 粒度 | 能否组合 | 适合场景 |
|------|------|---------|---------|
| Vault | 最大 | ❌ | 工作 / 生活分离、家庭共用、纯安全隔离 |
| 分类 | 中 | ❌ | 登录 / 信用卡 / 软件密钥等条目类型 |
| 标签 | 细 | ✅ | 跨维度筛选（工作 + GitHub、家庭 + 流媒体） |

一般建议：Vault 做最粗的隔离（个人 vs 工作 vs 家庭），分类表示条目本身是什么类型（登录还是信用卡），标签做灵活的多维度筛选（这个条目属于哪些场景）。

标签命名建议保持简短（1~4 个字或英文单词）、风格统一（全英文小写或全中文）、不要近义词重复（`work` 和 `job` 选一个），需要层级时用连字符（如 `finance-bank`、`finance-credit-card`）。

### 家庭 Vault 云端分享的具体步骤

Enpass 本身没有"多人协作"的订阅功能，但因为 Vault 就是一个加密文件，所以分享 Vault 本质上就是在云盘上分享这个文件。推荐的做法是用一个独立的云账号来存家庭共用 Vault，而不是在你的主云盘里配置复杂的权限。

#### Google Drive 方案

1. 用专门的家庭邮箱（比如 `family.enpass@gmail.com`）创建 Google 账号并登录 Drive
2. 创建文件夹 "Family Enpass Vault"，把家庭共用 Vault 文件放进去
3. 右键文件夹 → 共享 → 输入每个家庭成员的 Gmail → 权限设为"编辑"
4. 家庭成员在自己设备上打开 Enpass → 添加已有 Vault → 选 Google Drive → 用家庭邮箱临时登录 → Enpass 自动扫描 Drive 找到加密数据库文件 → 输入 Vault 密码 → 完成后**回到浏览器退出家庭邮箱登录**

#### Dropbox / OneDrive 方案

思路和 Google Drive 类似：主云盘里创建共享文件夹 → 把 Vault 存进去 → 右键文件夹共享 → 给家庭成员邮箱发邀请 → 家庭成员接受邀请后在自己的 Dropbox / OneDrive 里能看到这个文件夹 → Enpass 添加已有 Vault 时扫描到共享文件夹 → 选中 → 输入密码。

#### iCloud Drive 与 Nextcloud

iCloud Drive 的分享机制由 Apple 原生管理，macOS 上 Finder → iCloud Drive → 创建文件夹 → 放 Vault → 右键共享 → 添加人 → 输入 Apple ID 邀请。需要注意 iCloud 文件夹分享可能要求对方在同一个 Apple 家庭组里。

Nextcloud 是自建方案，更灵活：创建文件夹上传 Vault → 文件分享 → 创建公共链接或组共享。Enpass 连接 Nextcloud 有两种方式——直接 Nextcloud 文件夹同步，或 WebDAV 方式（通用地址格式 `https://你的Nextcloud地址/remote.php/dav/files/用户名/Family Enpass/`）。

> [!NOTE]
> 每次给新成员分享 Vault 或修改 Vault 密码后，让家庭成员登出共享云账号（如果用了临时登录），考虑修改 Vault 密码，定期让所有家庭成员各做一份本地备份。

### 备份恢复——数据丢失时的完整流程

需要从备份恢复的场景通常有五种：Vault 加密数据库文件损坏导致无法解锁、误删关键条目且云存储版本历史过了保留期、主密码修改后 Vault 无法用新密码解锁、换了新设备需要恢复数据、云存储账号被封禁或清空。

#### 恢复前的准备工作

恢复操作会覆盖或创建一个 Vault，动手前确认四件事：备份文件的主密码（加密的备份文件需要创建时相同的主密码才能解密——忘了就彻底没救）、备份文件完整且大小正常、恢复目标位置（推荐创建新 Vault 来放恢复的数据，原 Vault 保留作为"最后保险"，不要上来就覆盖现有 Vault）、换设备场景下把备份文件传输到新设备（AirDrop、云盘下载、USB、网络共享都行）。

#### 恢复步骤

桌面端恢复：Enpass → File → 恢复（Restore）→ 选择 `.enpassbackup` 备份文件 → 选恢复目标位置（创建新 Vault 或覆盖现有 Vault）→ 输入备份文件的主密码（不是你当前 Enpass 的主密码）→ 等待几秒钟到一两分钟 → 恢复完成后新 Vault 出现在列表里。

移动端恢复：确保备份文件已在移动设备上（AirDrop 传输、云盘下载）→ Enpass 设置 → Vaults → 添加已有 Vault → 从备份恢复 → 选择备份文件 → 选存储位置 → 输入备份密码。

#### 恢复后的四步验证

恢复完成后先不要急着删旧数据，按以下顺序逐一验证：

1. **条目数量和关键条目**：解锁恢复后的 Vault，快速浏览条目列表确认总数量大致正确，抽查 5~10 个关键条目（邮箱、银行、GitHub）确保能打开、字段完整、密码正确，抽查密码历史确认历史版本存在
2. **附件**：打开几个有附件的条目，附件能正常预览或下载
3. **TOTP 认证码**：打开几个带 2FA 的条目，确认 TOTP 字段里有密钥、认证码能正常生成
4. **Passkey**：打开创建过 Passkey 的网站条目，确认 Passkey 字段存在

验证通过后，等云同步完成后在另一台设备上再验证一次，然后删除旧的损坏 Vault（Enpass 里移除 + 云盘里手动删除旧数据库文件），最后确认恢复后的 Vault 重新开启了自动备份。

#### 恢复失败的常见排查

提示"密码错误"时，说明你输入的主密码和创建备份时用的不一样——可能是创建备份时用的是旧主密码（后来改过）、输入时大小写不对、或者有中文输入法下输入英文密码的键盘布局问题。建议把你历史上用过的所有主密码版本都试一遍。

提示"文件损坏"时，备份文件可能在传输过程中损坏了——重新从源位置拷贝一份、换一个传输方式（比如用 AirDrop 而不是 USB）、或者试试更早的备份。

极端情况下如果 Enpass 备份文件也坏了，还可以从云存储的版本历史里恢复——Google Drive 右键文件 → 管理版本、Dropbox 点击文件 → 版本历史、OneDrive 右键 → 版本历史、iCloud.com → 找到文件 → 还原到之前的版本。免费版云存储的版本历史通常保留 30 天，如果损坏发生在这个窗口内，这是最后的救命稻草。

> [!WARNING]
> 灾难恢复的终极边界：如果设备丢了 + 云账号被封 + 本地自动备份也没了 + 手动备份副本也丢了 + 主密码也忘了 → 无解。加密数据库没有后门。这就是为什么"定期做备份 + 把备份存多个独立位置"如此重要。
