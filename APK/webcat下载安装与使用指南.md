## ✨ WebCat 是什么：把网页开发链装进手机的编辑器

WebCat 是一款专为安卓设备设计的网页开发集成环境，把代码编辑、实时预览、JSON 配置和 APK 打包等原本需要电脑才能完成的工作，全部搬到了手机端。它的核心定位很明确——给那些不想被电脑绑定的前端开发者、学生党和自由职业者一个"随时随地写网页"的工具。

和其他手机上的代码编辑器不同，WebCat 从一开始就瞄准了**移动编码 + 本地打包**这两个场景。你可以在地铁上改完一段 HTML，点运行立即看到渲染效果，甚至一键打包出可安装的 APK 交给客户试用——全程不碰电脑、不依赖云端。

它的用户群横跨好几个场景：计算机专业的学生在课堂上跟着老师敲示例、前端工程师在通勤碎片时间推进小项目、自由开发者在现场给客户演示原型、不会原生开发但想用 HTML/CSS/JS 做轻量安卓应用的开发者。当然边界也要说清楚——几百个文件的大型桌面级项目、需要原生 UI 组件的复杂交互、依赖 Git 团队协作的工程，WebCat 就不太适合了，这些还是得上电脑。

## 🔧 安装步骤

WebCat 是安卓平台的应用，安装过程和普通 APK 类似，但有几个注意点值得提前知道。

### 从官方下载页安装

1. 打开下载页，根据你的设备架构选择对应的 APK 文件
2. 将 APK 传到手机（直接手机浏览器下载或用数据线/网盘传输）
3. 打开文件管理器找到 APK，点击安装

> [!WARNING]
> 安装时系统可能弹出「未知来源应用」提醒。这是安卓的安全机制，不是 WebCat 本身的问题。进入系统设置 → 安全 → 允许安装未知来源应用，开启后再重新点击安装即可。某些定制 ROM（小米、华为等）可能需要在「特殊权限」或「安装未知应用」里单独授权文件管理器或浏览器。

### 版本核对小技巧

下载完成后，建议先核对一下文件大小和版本号：

- 下载页会标注每个版本的 APK 大小和版本号，实际下载的文件应该和标注对得上
- 如果下载到的文件比标注小很多，大概率是下载不完整，删掉重下
- 安装完成后打开 WebCat，进入设置 → 关于，确认显示的版本号和你下载的一致

### 安装后的首次启动

首次打开 WebCat 会请求存储权限——必须允许，否则无法读写工程文件。有些机型还会弹出后台运行权限的请求，建议允许，避免长时间编辑后被系统杀进程丢失进度。

## 📖 使用入门

### 项目管理：把你的工程带在身上

WebCat 采用工程化的项目管理方式，每个项目就是一个独立的文件夹，里面包含 HTML、CSS、JS、图片、配置文件等完整结构。打开 WebCat 后首先看到的是项目列表界面，你可以：

- **新建空白项目**：从零开始，WebCat 会自动创建基础的 index.html、style.css、main.js 三件套
- **导入已有项目**：从手机存储中选择一个包含网页文件的文件夹导入
- **共享空间导入**：把项目放到共享空间里，方便在不同设备或不同 App 之间传输

> [!TIP]
> 项目管理界面支持轻松切换不同工程——在项目列表里直接点选即可打开另一个项目，不用每次都回到文件管理器重新找。对同时在搞好几个原型的开发者来说，这个功能特别省事。

### 代码编辑核心功能

WebCat 的编辑器做了不少手机端的适配：

**语法高亮**：HTML、CSS、JavaScript、JSON 各有专属配色方案，标签、属性、字符串、数字、注释颜色各异，一眼能看清代码结构。

**格式化**：无论是紧凑的单行 CSS 还是缩进混乱的 HTML，一键格式化立刻变得层级分明。反过来，格式化好的代码也能挤成单行——从浏览器 DevTools 复制出来的 CSS 片段经常需要先格式化才能改。

**实时预览**：写完代码点一下运行，WebCat 内置的 WebView 会立刻渲染出效果。手机屏幕小，这种"写一行看一行"的即时反馈比在电脑上改完再切浏览器省了大量时间。

### JSON 文件编辑（5.21 版本起）

5.21 更新专门新增了 JSON 文件的编辑支持，这对打包 APK 来说是个关键提升。之前在手机上改 manifest.json 或其他 JSON 配置文件时，没有专门的语法支持，逗号漏写、引号配对错误很容易出现，而且 WebCat 不会提示，等到打包 APK 才报错。

现在 JSON 文件和纯文本文件在编辑器里有了明显区别：键名、字符串值、数字、布尔值、null、大括号、方括号、冒号、逗号各有各的颜色——少写一个逗号会立刻在视觉上显得突兀。加上格式化功能，拿到一份紧凑的单行 JSON（比如从浏览器 DevTools 复制来的），格式化后立刻变成可读结构。

**改 JSON 的正确姿势**建议按这五步走：打开文件 → 改字段值 → 点格式化让缩进对齐 → 肉眼扫一遍大括号和中括号是否配对 → 保存。走完基本不会出低级错误。

### 多窗口并行编辑

多窗口是解决手机屏幕太小、单窗口切来切去浪费时间的利器。常见的触发方式有：在文件列表里长按文件选择「在新窗口打开」、编辑界面顶部或底部的分屏按钮、或者从文件管理器拖入文件开新窗口。

WebCat 会根据屏幕方向自动适配分屏方式：竖屏手机默认上下分屏（两个文件一上一下），横屏时自动切成左右分屏。两个编辑区域各自独立操作——光标位置、滚动位置、缩放比例可以不同，关闭其中一个不影响另一个的自动保存进度。

多窗口的典型场景包括：
- **对比修改**：打开两个相似文件并排看差异
- **引用复制**：一个窗口选中代码片段，直接复制粘贴到另一个
- **结构 + 样式对照**：一个窗口写 HTML 结构，另一个窗口同步写 CSS 选择器
- **长文件分段写**：长函数在窗口 A 看上半部分，窗口 B 看剩下的

> [!NOTE]
> 分屏状态下预览功能仍然正常，但预览会占满整个屏幕，会临时打断分屏，关掉预览后自动回到分屏状态。部分低配手机分屏后可能感觉有点卡，属于正常现象——编辑区渲染量变大了。

### 打包 APK：自定义图标

WebCat 能直接把你的网页工程打包成可安装的 APK，这是它区别于普通手机编辑器的核心能力之一。打包前有一个常见的需求：换掉 WebCat 默认的猫形图标，换成你自己项目的 Logo。

**方法一：打包界面直接选图**（最简单）

在打包前的配置界面里有图标选择区域，点进去可以从相册选图、用相机拍照、或者从工程文件里选已有图片。选好后 WebCat 会自动处理成标准的安卓图标格式。

**方法二：修改 manifest.json**（精确控制）

工程根目录下有一个 manifest.json 文件，里面有 icons 字段，列出了 WebCat 打包时会用到的所有图标配置。简化结构大概是这样：

```
{
  "icons": {
    "mdpi": "icons/icon-48.png",
    "hdpi": "icons/icon-72.png",
    "xhdpi": "icons/icon-96.png",
    "xxhdpi": "icons/icon-144.png",
    "xxxhdpi": "icons/icon-192.png"
  }
}
```

每一行对应安卓不同屏幕密度下的图标尺寸，WebCat 打包时会自动取最高分辨率的图做缩放——实际上你只需要准备一张 192×192 的 PNG，其他尺寸让 WebCat 自动处理就行。图标格式要求是 PNG（支持透明背景）、方形、不要超过 1024×1024。

换完图标打包安装后，桌面图标和设置里的应用图标都应该变成你换的那个。如果没变，大概率是 manifest.json 里的路径写错了。
