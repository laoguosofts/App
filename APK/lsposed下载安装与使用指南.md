## ✨ LSPosed 是什么

LSPosed 是当前 Android 生态里最主流的 Xposed 框架现代实现。它不修改任何 APK、也不需要刷机，而是在应用运行时拦截方法调用，把模块代码插到原方法的前后甚至替换返回值——这套机制由最早的 Xposed 框架奠定，LSPosed 则是接过了 EdXposed 的衣钵，用自研的 LSPlant 钩子引擎和 Zygisk 注入方式，让这套经典思路在当代 Android 的安全机制下继续跑通。

框架的核心优势来自 Xposed 机制本身：跨版本可用、完全可逆、多模块叠加。同一个模块只要应用没重写相关代码，就能跨应用版本、跨 ROM 工作；所有改动只在内存里，停用模块重启即恢复原样；多个模块可以同时改同一个方法，按优先级依次生效——这些特点都是直接修改 APK 做不到的。

LSPosed 需要 root（Magisk + Zygisk），作用范围是系统级的——它面向想让模块对整机生效的人。官方生态里还有一个名字很像的兄弟项目 LSPatch，不需要 root，但只作用于被打补丁的那一个 APK，系统框架层面的钩子完全碰不到。两者不是竞争关系，而是互补关系：要系统级玩模块选 LSPosed，不想解锁 Bootloader、只想给单个应用加功能就试 LSPatch。

> [!TIP] 谁适合用
> - 已解锁 Bootloader 并 root 了 Android 设备、想折腾模块的用户
> - 希望多个模块同时生效且互不冲突的深度玩家
> - 需要改系统界面、状态栏这类全局行为的场景（LSPatch 无能为力）

> [!WARNING] 前置门槛
> LSPosed **必须**配合 Magisk（或 KernelSU）的 Zygisk 功能才能运行。如果你没 root，直接往下看安装步骤只会一头雾水——先搞定 root 再来。

模块生态方面，模块本质就是普通 APK，来源是框架管理器里的"仓库"页，线上收录一千多个模块。给老 Xposed 写的模块与给新框架写的模块混编，装之前需要看清模块要求的 API 版本是否与当前框架匹配。

## 🔧 安装与激活

安装 LSPosed 分为两个阶段：Magisk 模块安装和框架激活。整个过程约五分钟，不需要刷机包。

### 前置条件核对

动手前先确认三件事：

| 检查项 | 合格状态 | 不合格怎么办 |
| --- | --- | --- |
| Bootloader | 已解锁 | 先完成厂商解锁流程 |
| Magisk / KernelSU | 已安装且版本较新 | 安装或更新到最新版 |
| Zygisk | Magisk 设置中已开启 | 进入设置 → 开启 Zygisk → 重启 |

> [!WARNING] Zygisk 是硬要求
> 没开 Zygisk 就装 LSPosed，框架装完也不会激活——白折腾。打开 Zygisk 后需要重启一次让它生效。

### 安装步骤

1. 打开 Magisk（或 KernelSU）管理器应用
2. 进入 **模块** 标签页，点击右上角「从本地安装」
3. 选择下载好的 LSPosed Magisk 模块 ZIP 文件
4. 等待安装完成后，管理器会提示重启——执行重启
5. 系统启动后，通知栏会收到「LSPosed 已加载」的系统通知，这说明框架已成功激活

### 安装后验证

框架激活后会在系统里注册一个拨号代码入口。在**系统自带的电话 / 拨号应用**里，像打电话一样输入：

```text
*#*#5776733#*#*
```

输入到最后一位的瞬间（不需要按拨号键），LSPosed 管理器界面自动弹出。5776733 在电话键盘上对应的字母恰好拼出 "LSPOSED"，社区里戏称"暗号对了，门就开了"。

> [!NOTE] 暗码没反应的排查顺序
> 1. 先看 Magisk 模块页框架条目是否启用
> 2. 重启后有没有出现"已加载"通知？完全没有就是激活问题
> 3. 是不是在第三方拨号应用里输的？换回系统拨号器
> 4. 个别 ROM 禁用了拨号代码分发，改用 ADB 方式进入

## 📖 开始使用与模块管理

框架装好后，真正的玩法才刚刚开始——所有的功能扩展都来自模块。这一节把管理器里最常用的操作和常见问题一并讲清楚。

### 管理器界面速览

框架激活后通过通知或暗码进入管理器，首页是"概览"页，显示三个关键状态：

- **框架状态**：显示"已激活"表示运行正常
- **API 版本**：模块依赖这个版本号，装模块前要核对
- **已安装模块数量**：一目了然当前装了多少个模块

左侧或底部导航还有模块列表、仓库、日志三个核心页面。

### 安装与启用模块

装模块分两步：先从仓库下载，再在管理器里启用并配置作用域。

1. 进入 **仓库** 页，浏览或搜索想要的模块
2. 点击模块卡片进入详情页，查看兼容性说明——重点看要求的 API 版本是否与框架匹配
3. 点击「下载」按钮，安装完成后回到 **模块** 页
4. 找到刚装的模块，打开右侧的开关
5. 点进模块卡片，进入 **作用域** 设置——这是**模块失效原因占比最高的一项**

作用域就是"这个模块要对哪些应用生效"。如果想改系统设置、状态栏，就勾上系统相关的应用；如果只改某个特定 App 的界面，就只勾那个 App。没勾目标应用的，模块装了也白装。

勾完作用域后，目标应用必须**强停再打开**；涉及系统框架的模块要**重启手机**。改了配置没重启进程，等于没改。

### 拨号盘暗码之外的入口

官方钦定三种进入管理器的方式：通知栏的常驻通知、拨号盘暗码、以及 adb shell 命令。新版框架移除了桌面快捷方式逻辑，所以找不到图标是正常的。

### 模块失效排查清单

装了模块没效果？按这个顺序查，每一步通过再进下一步，别瞎试：

1. **框架本身活着吗** —— 概览页状态卡片是否"已激活"？显示未安装或未激活的，先解决框架问题
2. **模块开关开了吗** —— 模块页确认开关是打开状态。有些系统升级或框架更新后开关会被复位
3. **作用域勾了吗** —— 这是失效原因占比最高的一项，没勾目标应用就勾上
4. **应用重启过吗** —— 勾完作用域后目标应用必须强停重开
5. **版本兼容吗** —— 模块要求的 API 版本与当前框架是否匹配？模块许久未更新而系统刚升过大版本，可能已经不支持

以上五步都走完还不行，去日志页翻模块日志：有报错信息就按报错搜（多数是已知问题）；一片安静连注入记录都没有，就回到第三步重查作用域。最后一招是"冷启动流程"：停用模块 → 强停应用 → 重新启用 → 重新勾作用域 → 再强停应用。仍无效时带着日志页截图去模块作者的发布页反馈，注明框架版本、系统版本与复现步骤。

### LSPatch 免 root 方案对比

如果你的设备无法解锁 Bootloader，或者不想对整机动刀，可以考虑 LSPatch——同一技术脉络下的单应用补丁方案：

| | LSPosed | LSPatch |
| --- | --- | --- |
| 需要 root | ✔ 需要（Magisk + Zygisk） | ✘ 不需要 |
| 作用范围 | 系统级，所有勾选的应用 | 只作用于被打补丁的那一个 APK |
| 系统框架钩子 | ✔ 支持 | ✘ 不支持 |
| 应用更新 | 更新后模块照常工作 | 应用每次更新都要重新打补丁 |
| 签名影响 | 不动 APK | 重新签名，可能破坏部分应用 |

想改系统界面、状态栏这类全局行为，只有 LSPosed 做得到——LSPatch 天生碰不到系统框架，装依赖系统框架的模块只会一片空白。选工具前先想清楚要动的是"整机"还是"单个应用"。
