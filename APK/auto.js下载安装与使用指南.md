## ✨ Auto.js 是什么

Auto.js 是一款运行在 Android 平台上的自动化脚本工具，核心能力是通过 JavaScript 代码模拟人的操作——点击、滑动、长按、输入，同时读取屏幕上的控件信息（文本、ID、类名等），把手机上那些重复、机械、耗时的操作交给脚本自动完成。

它的定位很清晰：**让不会编程的人也能写出自己的自动化脚本，让会编程的人能更高效地操控手机**。日常场景覆盖面很广——APP 内签到、批量点赞回复、游戏辅助操作、跨 APP 数据搬运、定时任务触发……只要是你觉得「这事儿我不想手动做第二遍」的场景，都可以用 Auto.js 来试。

Auto.js 内部使用 Rhino JS 引擎（开源 Java 实现的 JavaScript 引擎），支持 ES5 全套语法和部分 ES6 特性（let/const、箭头函数、模板字符串）。需要注意的是，原版 4.1.1 版本不支持 async/await、Promise 和 class 继承；如果需要完整的 ES2021 支持，可以考虑 Auto.js Pro 9.x 或 AutoX.js 等后续分支。

> [!NOTE]
> Auto.js 的运行需要开启**无障碍服务**（Accessibility Service）——这是 Android 系统提供的自动化接口，脚本通过它才能读取屏幕控件并模拟操作。不开启无障碍 = 脚本完全无法运行，这是所有新手第一次使用时最容易漏掉的前置步骤。

## 🔧 安装步骤

Auto.js 的安装过程和普通 APK 类似，但有几个细节需要注意。

### 1. 允许未知来源安装

因为安装包不是从 Google Play 或国内应用商店获取的，Android 系统默认会拦截安装。在安装前，需要手动开启「允许安装未知来源应用」权限：

1. 打开手机**设置** → **安全**（或**隐私**）→ **安装未知应用**
2. 找到你用来下载 APK 的浏览器（比如 Chrome），将其开关设为**允许**
3. 部分 ROM 会把这个选项藏在更深层，比如小米 MIUI 在「隐私保护 → 特殊权限设置 → 安装未知应用」

### 2. 核对安装包信息

在安装之前，建议核对一下下载文件的基本信息：

| 检查项 | 说明 |
| --- | --- |
| 文件大小 | 和下载页标注的体积大致匹配，偏差超过 10% 就需要警惕 |
| 版本号 | 确认是你想要的版本，不要装错旧版 |
| 来源 | 只从可靠渠道下载，不要随便装论坛或群文件里转发的包 |

> [!WARNING]
> 杀毒软件可能会对 Auto.js 安装包报毒或弹窗警告，这是因为 Auto.js 需要申请无障碍服务权限，行为特征和恶意软件类似。只要确认来源可信，可以忽略警告继续安装。

### 3. 安装并启动

点击 APK 文件执行安装，等待完成后在应用列表找到 Auto.js 图标点开。首次启动会弹出一串权限请求，以下几个是必须允许的：

- **无障碍服务**：核心权限，不允许则脚本无法运行
- **悬浮窗**：用于显示布局分析器、运行日志等浮动界面
- **文件存储**：用于保存脚本文件和读取配置
- **后台运行**：防止系统杀进程导致脚本中断

开启无障碍服务的路径：**设置 → 无障碍 → 已下载的服务 → Auto.js → 开启开关**。

### 4. 验证安装成功

启动 Auto.js 后，界面能正常显示项目列表和悬浮窗，说明安装基本成功。可以在终端控制台输入 `console.show()` 测试控制台是否正常弹出。

## 📖 使用入门

Auto.js 的核心工作流可以概括为：**写脚本 → 运行 → 看效果**。脚本本身就是 JavaScript 文件，后缀 `.js`，运行时由 Auto.js 内置的 Rhino 引擎解释执行。下面从语言基础、操作模式、控件定位三个层面展开，帮你建立完整的知识框架。

### JavaScript 语言要点

Rhino JS 引擎对 ES5 语法是全量支持的，变量、函数、数组、对象、正则、Date、Math 都能用。ES6 方面，`let`/`const`、箭头函数、模板字符串、解构赋值也支持，但 `async/await`、Promise、复杂的 class 继承在原版中不可用，写脚本时需要注意这个边界。

变量声明推荐统一用 `let` 和 `const`，`const` 用于常量不会被修改的值，`let` 用于会重新赋值的变量。函数定义既可以用传统的 `function` 关键字，也可以用箭头函数简写——对于简单的回调和单语句函数，箭头函数更清爽。

```javascript
// 推荐写法
let appName = "淘宝";
const MAX_RETRY = 3;

const delay = (ms) => sleep(ms);

function clickButton(text) {
  text(text).waitFor().click();
}
```

控制流方面，if/else、switch、for、while、forEach 都能正常使用。Rhino 有几个历史遗留的小坑值得留意：`typeof null === "object"`（这是 JS 全局问题），早期版本没有 `const` 关键字，Date.parse 行为可能和浏览器略有差异，不支持 ESM 模块语法，只能用 `require()`。

### 自动化操作的两套模式

Auto.js 提供了**两套根本不同的操作方式**，理解它们的适用边界是写出稳定脚本的关键：

**基于控件的操作（推荐）**：通过选择器定位到具体的界面控件，然后调用其方法。比如 `text("签到").click()` 直接点击文本为「签到」的控件。这种方式不受屏幕分辨率和控件位置变化的影响——手机换了、APP 界面微调了，脚本依然能正常工作，是生产脚本的首选。缺点是目标 APP 必须暴露控件树信息，大多数常规 APP 没问题，但游戏画面、视频播放器、特殊渲染的界面可能就抓不到控件。

**基于坐标的操作（兜底）**：直接操作屏幕坐标，比如 `click(500, 1000)` 点击屏幕上的某个像素点。这种方式任何界面都能用，包括游戏画面，但坐标是硬编码的——换了一台分辨率不同的手机，或者 APP 界面改版导致按钮位置偏移，脚本就会点错位置。

查看坐标的方式：悬浮窗打开「布局分析」后，触摸屏幕时左上角会实时显示坐标，或者在手机开发者选项里开启「显示指针位置」。

除了点击，还有长按、滑动、拖拽、多点触控等手势操作。滑动常用于长列表翻页，`swipe(起点x, 起点y, 终点x, 终点y, 耗时ms)` 控制滑动的路径和速度。拖拽可以模拟按住控件拖到另一个位置的操作。手势 API 能同时操控多根手指，比如双指捏合缩放。

### 等待的正确姿势

控件不会瞬时出现——APP 加载、网络请求返回、动画过渡都需要时间。盲等 `sleep(2000)` 虽然能解决问题，但不够优雅：加载快了浪费时间，加载慢了可能还没等到目标出现脚本就往下跑了。

Auto.js 提供了 `waitFor` 方法做智能等待：`text("确认").waitFor(10000).click()` 会最多等 10 秒，目标控件一出现就立即返回。能用 `waitFor` 就别用 `sleep`，这是提升脚本响应速度和稳定性的好习惯。

### 控件定位的选择器优先级

当控件能被识别时，Auto.js 提供了多种定位手段。**推荐的优先级从高到低**：

| 优先级 | 选择器类型 | 说明 | 稳定性 |
| --- | --- | --- | --- |
| 1 | resource-id | 资源 ID，布局分析器里显示为 `com.example.app:id/xxx` | ⭐⭐⭐ 最稳 |
| 2 | text + className 组合 | 同时匹配文本和控件类型 | ⭐⭐ |
| 3 | textContains / descContains | 模糊匹配文本或描述 | ⭐⭐ |
| 4 | className + bounds | 限定在某个屏幕区域内 | ⭐ |
| 5 | 纯 className | 只按控件类型匹配 | ⭐ 最泛 |
| 6 | 坐标点击 | 最后手段 | ❌ 最不稳定 |

resource-id 是最推荐的定位方式，每个 Android 控件在源码里可以赋一个唯一 ID，APP 改版时通常不会随意修改 ID（改 ID 会破坏其他地方的引用）。完整写法是带上包名前缀，比如 `id("com.taobao.taobao:id/rl_search")`，比简写的 `id("rl_search")` 更精确、不会有重名风险。

综合选择器可以把多种条件链式组合，进一步缩小匹配范围。比如：

```javascript
id("btn_submit")
  .className("android.widget.Button")
  .textContains("提交")
  .click();
```

条件越精确，匹配越准，脚本越稳定。

### 数据处理三件套

Auto.js 的数据处理围绕三个核心能力展开：**JSON 序列化、剪贴板、HTTP 请求**。

JSON 是脚本间数据交换的通用格式——`JSON.parse()` 把字符串转成对象，`JSON.stringify()` 把对象转成字符串。配合文件读写 API，可以把运行时的配置、统计数据持久化到本地存储。

剪贴板适合在 Auto.js 和其他 APP 之间传递简单文本数据——比如从浏览器复制一个链接，脚本里用 `clipboard.getText()` 读出来处理。

HTTP 模块支持 GET 和 POST 请求，`http.get(url)` 返回响应对象，`res.body.string()` 取响应体文本，`res.statusCode` 查状态码。支持带 query 参数、自定义 headers、设置超时时间。请求过程要放在 try/catch 里，异常时打印错误信息而不是让脚本静默崩掉。

```javascript
try {
  var res = http.get("https://api.example.com/data", { timeout: 10000 });
  if (res.statusCode == 200) {
    var data = JSON.parse(res.body.string());
    log("获取成功：" + JSON.stringify(data, null, 2));
  } else {
    log("HTTP " + res.statusCode);
  }
} catch (e) {
  log("网络错误：" + e.message);
}
```

### 快速上手的建议路径

第一次接触 Auto.js，建议按这个顺序逐步深入：

1. **跑通一个最简单的脚本**——打开 Auto.js，新建项目，写一行 `toast("Hello Auto.js")`，点击运行。确认无障碍服务已开启、悬浮窗正常显示。
2. **熟悉控件定位**——打开布局分析器，在常用 APP 上点目标控件，观察它的 resource-id、className、text 等属性。
3. **写一个实用小脚本**——比如在淘宝自动搜索某个关键词：打开淘宝 → 点击搜索框 → 输入文字 → 等待搜索结果出现。这个场景能同时练到 APP 启动、控件定位、输入、等待。
4. **逐步加入循环、条件判断**——让脚本能应对界面不同状态，比如签到按钮不在时跳过、网络异常时重试。
5. **引入数据处理**——把剪贴板、HTTP、JSON 用进来，让脚本能和外部系统交换数据。

> [!TIP]
> 调试脚本时善用 `console.show()` 打开控制台，用 `log()` 打印关键变量的值，比靠 toast 看日志直观得多。脚本执行过程中随时可以从通知栏或悬浮窗点击停止按钮中断，不会卡死手机。
