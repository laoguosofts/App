## ✨ Tor Browser：以隐私为默认的匿名浏览器

Tor Browser 是一款基于 Firefox 深度定制的独立浏览器，核心设计目标是通过 Tor 网络实现用户身份与浏览行为的最小化暴露。它将每次网页请求通过三层随机中继节点转发，使得服务器只能看到最后一跳出口节点的 IP，而非用户的真实地址。这种洋葱路由架构让追踪者难以串联起你的浏览活动，即使是本地网络管理员、ISP 或搜索引擎也无法轻易获取你访问了什么内容。

与普通浏览器配合隐私插件的方案不同，Tor Browser 从底层就内置了反指纹机制：统一字体渲染、Letterboxing 窗口固定尺寸、Cookie 与标签页隔离、Canvas/WebGL 指纹屏蔽、自动切换 HTTPS 等。这些特性组合起来让所有 Tor Browser 用户在网站看来拥有相同的"浏览器指纹"，而非各自独特的标识特征。

Tor Browser 内置了三档可切换的安全级别（标准、较安全、最安全），覆盖从日常浏览到高风险场景的不同需求；当网络环境封锁 Tor 时，还支持通过 obfs4、Snowflake、meek-azure 三种可插拔传输让流量伪装成普通 TLS 或 WebRTC 连接，绕开深度包检测和 IP 封禁。

## 🔧 Tor Browser 安装步骤

Tor Browser 是绿色便携软件，安装过程比普通浏览器更简洁——它不会向系统注册表写入大量信息，解压后即可独立运行，方便在多个设备间迁移或放在 U 盘上使用。

### Windows 平台安装

1. 从官方下载页面获取最新版本的 exe 安装包
2. 双击运行安装程序，选择解压目录（默认是桌面或程序文件目录，可自由指定）
3. 解压完成后，进入 Tor Browser 文件夹，双击 `Start Tor Browser.exe` 即可启动
4. **注意**：部分安全软件可能会误报 Tor Launcher 组件——这是因为 Tor 的连接行为与普通程序不同，确认文件来源可信后添加信任即可

> [!WARNING]
> **务必核对文件哈希值**。Tor 项目官方提供了每版本的 SHA256 校验值，在下载页面底部可查。安装前校验哈希能防止中间人攻击或恶意替换。

### macOS 平台安装

1. 下载 dmg 镜像文件
2. 打开 dmg，将 Tor Browser 图标拖入 Applications 文件夹
3. 首次启动时如果系统弹出"来自未知开发者"的提示，前往系统设置 → 隐私与安全性，在底部点击"仍要打开"
4. 右键点击 Tor Browser 图标选择"打开"，确认安全提示即可运行

### Linux 平台安装

Tor Browser 的 Linux 版本是 tar.xz 压缩包，解压即用：

```bash
tar -xJf tor-browser-linux64-XX.X.X.tar.xz
cd tor-browser_zh-CN
./start-tor-browser.desktop
```

> [!TIP]
> Linux 用户也可以通过发行版包管理器安装，但官方推荐使用独立压缩包版本——它包含自更新机制，能及时跟进安全补丁。

### Android 平台安装

Tor 在 Google Play 上提供正式发行版"Orbot"配合"Tor Browser for Android"使用，也可以从 F-Droid 或官方 APK 渠道直接获取。Android 版需要授予"未知来源"安装权限（如果从第三方来源安装），且部分功能（如可插拔传输的精细配置）在移动版中被简化。

### 安装完成后的首次验证

启动 Tor Browser 后，Tor Launcher 会自动建立到 Tor 网络的连接。在默认网络环境下通常几十秒内完成，首次连接会下载网桥列表并构建三跳电路。连接成功后，浏览器自动打开 Tor 项目的检查页面，确认你的 IP 显示为 Tor 出口节点而非真实地址。

## 📖 Tor Browser 使用入门：从连接配置到安全级别切换

Tor Browser 的强大之处在于它把复杂的隐私技术封装成了相对直观的界面。下面从实际使用的角度，拆解几个高频场景下的配置与操作要点。

### 连接 Tor：可插拔传输与网桥

在绝大多数网络环境下，Tor Launcher 的默认自动配置就能顺利建立连接。但当 ISP 或网络审查系统识别并封锁 Tor 的特征流量时——比如已知的 Tor 中继 IP 被封禁、TLS 指纹被深度包检测（DPI）识别——需要启用可插拔传输（Pluggable Transport）来绕过封锁。

Tor Browser 内置了三种可插拔传输，覆盖从简单到复杂的各种封锁场景：

| 传输方式 | 原理 | 伪装成 | 需要网桥 | 适用场景 |
|---|---|---|---|---|
| **obfs4** | 流量扰乱成随机数据 | 加密的随机 TLS | ✅ 需要 | 最常用，能绕过多数封锁 |
| **Snowflake** | 通过 WebRTC 走 P2P | 正常 WebRTC 连接 | ❌ 不需要 | 封锁最严的场景 |
| **meek-azure** | 通过微软 Azure CDN 中继 | 正常访问微软网站 | ❌ 不需要 | obfs4 也被封时的备选 |

#### 什么时候用哪一种

场景判断逻辑很清晰：

1. **普通封锁（只封已知 Tor 中继 IP）**：先用 obfs4 → 从 BridgeDB 获取 obfs4 网桥地址填入
2. **深度包检测（DPI）**：先试 Snowflake → 伪装成 WebRTC P2P，最不容易被识别
3. **obfs4 和 Snowflake 都被封**：试 meek-azure → 流量看起来像是在访问微软服务器

#### 配置步骤

**首次连接时**：启动 Tor Browser，点击 Tor Launcher 界面的"配置"按钮 → 勾选"Tor 在我的国家受到审查" → 在下拉菜单里选择一个内置网桥（obfs4 或 Snowflake 或 meek-azure）。

**运行中切换**：点击浏览器菜单按钮（三条横线）→ "偏好设置" → 左侧栏选择"洋葱" → 找到"网桥"部分，勾选"使用网桥"，从下拉菜单选择传输方式。

> [!NOTE]
> Snowflake 是 Tor 项目最新、最有想象力的传输方式。它的原理是：你的 Tor Browser 连接到 Snowflake 调度器，调度器把你分配给某个运行着 Snowflake 扩展的普通 Chrome/Firefox 用户，流量通过 WebRTC 在双方之间 P2P 传输。对审查系统来说，这看起来完全就是一个正常的实时音视频通话。优势是不需要网桥地址，IP 池极其庞大；劣势是速度不如 obfs4，依赖在线 Snowflake 用户的数量。

#### 传输方式切换策略

如果默认传输连不上，按以下顺序逐个尝试：obfs4 + 最新网桥地址 → Snowflake → meek-azure。每切换一次，让 Tor Launcher 重新构建电路。总有一种能穿透。

| 问题 | 原因 | 解决 |
|---|---|---|
| 选了传输方式还是连不上 | 该方式也被封了 | 换一种，或获取新的网桥 |
| Snowflake 连接特别慢 | 分配到的 Snowflake 用户网络不好 | 多试几次，或换 obfs4 |
| meek-azure 失败 | 微软 CDN 在当前网络也有问题 | 换 Snowflake |

### 三档安全级别：隐私与可用性的权衡

Tor Browser 的安全级别通过一个简单的滑块控制，让你不用手动调整 NoScript 规则或 about:config 设置，就能在隐私和可用性之间选一个合适的平衡点。访问方式：点击地址栏旁边的盾牌图标，然后点击菜单里的"设置"。

三档核心差异可以用一张表看清：

| 功能 | 标准 | 较安全 | 最安全 |
|---|---|---|---|
| JavaScript（HTTPS/HTTP） | ✅ 全部允许 | ❌ 全部禁用 | ❌ 全部禁用 |
| 自定义字体 | ✅ 允许 | ❌ 禁用 | ❌ 禁用 |
| WebGL | ✅ 允许 | ❌ 禁用 | ❌ 禁用 |
| HTML5 媒体 | 自动播放 | 点击播放 | 点击播放 |
| Canvas 指纹 | ✅ 启用 | ❌ 限制 | ❌ 限制 |

#### 怎么选——决策框架

Tor Browser 的安全设计底层逻辑是"统一而不是隐藏"——让你和所有其他 Tor 用户看起来一样，而不是尝试让你隐身。这个"统一"策略在 JavaScript 开启时才能完整发挥作用，但 JavaScript 本身又可能暴露你。三档级别就是在这个矛盾里找位置。

```
日常浏览普通网站           → 标准
访问半可信/敏感网站        → 较安全（推荐默认）
提交敏感信息/高风险场景     → 最安全
```

#### 四种典型威胁模型

| 你的威胁 | 推荐级别 | 附加措施 |
|---|---|---|
| 广告生态追踪浏览行为 | 标准或较安全 | 基础反追踪已足够 |
| 企业/学校网络管理员监控 | 较安全 | 可插拔传输/网桥隐藏目标网站 |
| 国家/ISP 深度包检测 | 较安全 + Snowflake/obfs4 | 审查绕过优先级最高 |
| 记者/举报人高风险场景 | 最安全 | 禁用所有扩展、考虑 Qubes OS + Whonix/Tails |

> [!TIP]
> 实际使用建议：默认设为"较安全"——比标准多了一层 HTTP 网站防护，损失的只是字体定制（对大多数人无感知）。遇到网站打不开再临时降为"标准"，用完立即切回。敏感操作前手动升到"最安全"。

#### 动态切换节奏

安全级别不用固定死在一档，Tor Browser 切换几乎瞬间完成。推荐的日常节奏：起床 → 较安全（默认）→ 浏览新闻查资料保持较安全 → 某个网站需要脚本时 NoScript 临时信任或临时升到标准 → 敏感操作前升到最安全 → 操作完成立即降回较安全。

#### 常见误区

**误区一：开着 Tor Browser 就得最安全级别**——错。大多数用户不需要最安全级别，日常用"较安全"更平衡。

**误区二：切换安全级别会清除我浏览过的内容**——错。切换只影响新的页面加载，已经打开的标签页不受影响（需刷新才生效）。

**误区三：最安全级别就绝对安全**——错。最安全级别只是消除了最大的攻击面（JavaScript），但你仍可能在浏览纯文本内容时被关联身份。

**误区四：安全级别越高越好**——错。Tor 项目明确建议大多数用户使用标准或较安全级别。最安全级别是为特殊场景设计的，长期用只会让你放弃 Tor Browser 回到普通浏览器，反而降低整体安全。

### 合法 .onion 服务：不止暗网

.onion 服务的名气往往与暗网挂钩，但实际上大量正规机构都在运营自己的 .onion 入口，让用户在加密环境下访问官方内容。Tor 项目、媒体机构、隐私公司、加密通讯服务商都有自己的 .onion 站点。

#### 知名合法 .onion 服务示例

| 类别 | 服务 | 用途 |
|---|---|---|
| 隐私搜索 | DuckDuckGo | Tor 默认搜索引擎 |
| 加密邮箱 | TutaNota | 端到端加密邮箱，Tor 入口在设置里 |
| 新闻媒体 | BBC News / NYT / Deutsche Welle | 加密环境下访问国际新闻 |
| 举报平台 | SecureDrop | 匿名提交敏感信息给新闻机构 |

#### 验证 .onion 地址的正确方法

论坛帖子、聊天群里转发的 .onion 地址可能是钓鱼。验证三步法：

1. 用 Chrome/Firefox 打开该服务的普通 HTTPS 官方网站，查找"Tor 镜像"相关链接
2. 官方网站公开的 .onion 地址应该和你手头的一致，以官方渠道为准
3. 只信官方渠道发布的地址

#### 合法 vs 非法 .onion 内容的判断框架

| 判断维度 | 合法特征 | 非法特征 |
|---|---|---|
| 是否在普通互联网有公开官方网站 | ✅ | ❌ 只在 .onion 里有 |
| 是否接受比特币以外的支付 | ✅ 有法币通道 | ❌ 只接受加密货币 |
| 是否有明确的服务条款和法律声明 | ✅ | ❌ |
