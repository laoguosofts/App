## ✨ Alist 是什么

Alist 是一个轻量的网盘聚合程序，它把你手上各家网盘（阿里云盘、夸克、OneDrive、百度网盘等）的账号集中挂载到同一个界面下，统一浏览、搜索、播放和分享。核心逻辑很简单：后端对接各家网盘的开放接口，前端提供一套跟文件管理器差不多的网页界面，WebDAV 协议对外暴露文件流，播放器、同步工具、备份软件都能直接连上用。

适合的人群大致三类：第一类是手头有好几家网盘账号、切换来切换去嫌麻烦的，用它做一个统一入口；第二类是想在电视、播放器上直接看网盘视频不想下载落盘的，靠 WebDAV 直连就能边下边播；第三类是有一定动手能力的自建玩家，跑在自己的服务器或 NAS 上当全家的数据中枢。

它本身不存储任何文件，所有文件物理上还在各自的网盘里，程序只做转发和接口适配——这意味着存储上限等于你各家网盘加起来的容量，也意味着速度和稳定性取决于网盘那边的接口状况。搭建门槛不高，Windows、Mac、Linux 都能跑，Linux 有官方一键脚本最省心，NAS 各品牌也有现成的 Docker 镜像。

## 🔧 安装步骤

### Linux 服务器（一键脚本）

Linux amd64 和 arm64 平台官方提供一键脚本，是服务器部署的首选。步骤很直接：

1. **SSH 登录服务器**，切换到 root 或带上 sudo 权限；
2. **复制官方文档上的一键安装命令**（正式版与测试版脚本分开，按需要选），粘贴到终端执行；
3. **脚本自动完成**下载程序、创建目录、注册 systemd 服务三件事，默认装到 `/opt/alist`。

> [!TIP]
> 如果想装到别的目录，把目标路径作为第二个参数传给脚本即可，必须是绝对路径，比如 `/root/alist`。

装完后程序交给 systemd 管理，日常操作就那几条：

| 操作 | 命令 |
| --- | --- |
| 启动 | `systemctl start alist` |
| 停止 | `systemctl stop alist` |
| 重启 | `systemctl restart alist` |
| 看状态 | `systemctl status alist` |
| 开机自启 | `systemctl enable alist` |

另外脚本还装了一个交互式管理器，直接输入 `alist` 或 `alist-manager` 就能进入菜单，覆盖改密码、更新版本、卸载这些常用操作，不想记 systemd 命令的用这个就行。

### Windows 桌面版

Windows 用户下载压缩包解压后，**必须在解压后的程序文件夹内启动**——双击 `alist.exe` 或在该文件夹内开终端执行程序都行。

> [!WARNING]
> 这一点很容易踩坑：如果你从别的目录开终端、用完整路径去启动这个程序，程序读 data 配置的目录就会跑偏，导致管理员密码、挂载的存储全都读不到。正确姿势是在程序文件夹的地址栏里输入 `cmd` 回车，再在弹出的终端里执行 `alist` 相关命令。

启动后浏览器访问 `http://localhost:5244` 进入界面，首次启动需要拿管理员密码登录后台——密码由程序自动生成，用 `alist admin` 命令在**正确的目录下**就能看到。

### 装完核对

不管哪个平台，装完后做三件事确认没问题：

1. 浏览器访问本地地址（默认 5244 端口）能打开登录页；
2. `alist admin` 或 systemd 状态命令能正常返回；
3. 后台能看到数据目录（data/）下已生成配置文件，版本号和下载时的一致。

## 📖 核心功能与日常使用

### 挂载网盘与统一浏览

登录后台后进入「存储」页，按各家网盘的要求填好授权凭证（多数是 OAuth 扫码或 Cookie 粘贴），保存后 Alist 就把这些网盘的目录结构全部拉进来，前台页面呈现为一棵合并的文件树。多个盘的文件按目录层级平铺在一起，搜索、排序、打开操作和本地文件管理器完全一致。

> [!NOTE]
> 挂载的存储支持单独设置「禁用索引」和「禁用预览」，不想让某个大网盘参与全局搜索、或者不想对某个私有目录生成缩略图，在存储配置里关掉对应的开关就行。

### 全局搜索的正确打开方式

默认情况下搜索是关的（前台会提示 Search not available），要先构建索引。步骤很简单：

1. 后台「索引」页选一个搜索引擎并保存；
2. 点「构建索引」等它跑完；
3. 前台 Ctrl+K 或点搜索框就能用了。

四种搜索引擎怎么选直接看这张表：

| 引擎 | 中文支持 | 速度 | 资源占用 | 适合场景 |
| --- | --- | --- | --- | --- |
| 数据库（全文） | 差 | 快 | 低 | sqlite 数据库用户，文件名以英文为主 |
| 数据库（非全文） | 较准 | 稍慢 | 低 | **MySQL 数据库用户推荐这个** |
| bleve | 模糊匹配 | 快 | 高 | 文件名中文多，能接受全量重建 |
| meilisearch | 需自建 | 快 | 独立进程 | 专业用户，追求极致搜索体验 |

经验法则：sqlite 用户全文非全文随便挑；MySQL 用户直接用非全文搜索；中文文件多优先非全文或 bleve。

配置上还有几个实用项：**忽略路径**（构建时跳过某些大网盘）、**自动更新索引**（新文件被访问时自动补索引，默认关闭）、**更新索引**（只重建指定路径，适合新增了一批文件不想全量跑的场景）、**最大索引深度**（默认 20 层，超深目录只索引前 20 层）。

> [!WARNING]
> 两个常见坑要提前注意：一是 sqlite 构建索引报 database is locked——构建期间别在后台改配置，开了自动索引的先关掉再重启；二是「全文搜索」搜的是**文件名**不是文件内容，别指望它做全文检索用。

### 播放器直连 WebDAV

「网盘里的电影能不能直接在电视上放」是 Alist 最经典的使用场景。原理很简单：播放器通过 WebDAV 协议访问 Alist 的 `/dav` 接口，Alist 按存储策略取文件流（要么 302 直连网盘，要么经代理中转），播放器边下边播，不用先落盘。

各平台推荐的播放器组合：

| 平台 | 播放器 |
| --- | --- |
| Windows | PotPlayer、KMPlayer、Kodi |
| 安卓 | NPlayer、Kodi、reex |
| iOS / Apple TV | Infuse、VidHub、NPlayer |
| 电视盒子 | VidHub、NPlayer、Kodi |
| Mac | IINA、Infuse、VidHub |

配置套路都是同一个：添加 WebDAV 源，地址填 Alist 站点的 `/dav` 路径，账号密码和网页端登录用的一样。播放器的解码能力远强于浏览器，浏览器放不了的高码率、特殊编码视频交给 PotPlayer 或 Infuse 基本都能正常播放。

进阶玩法：用目录合并功能把多家网盘的影片目录拼成一个统一的「媒体库」再暴露给播放器，体验最好；本地存储的视频想生成海报墙缩略图，配合 ffmpeg 就能实现。

### 登录类问题排查

碰到登录问题别慌，按症状对号入座：

- **密码明明对却登不上**：第一嫌疑是你查密码的目录不是程序真正读的目录。程序按「执行命令时所在目录」读 data 配置，在桌面开终端启动别处的程序，密码就生成在桌面那套数据里。Windows 在程序文件夹地址栏输 cmd 回车，Linux 先 cd 到程序目录再跑 admin 命令。
- **连续输错被锁定**：连续 6 次密码错误会触发保护性锁定，页面提示 Too many unsuccessful sign-in attempts。解法是重启程序，锁定状态会自动重置，然后先确认账号密码再登录。
- **登录时要求输 OTP 动态码**：说明这个账号开了两步验证，填验证器上的 6 位数字就行；验证器丢了要走解除流程。
- **提示 invalid regular expression 或 n.replaceAll is not a function**：前者是浏览器装的油猴答题类插件和页面脚本冲突，禁用插件即可；后者是浏览器内核太老缺新字符串方法，升级浏览器或在设置里加 polyfill 脚本。
- **未登录能看但权限不对**：那是访客账号（guest）在起作用，想全站私有就去后台停用 guest。
