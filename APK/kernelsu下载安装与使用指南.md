## ✨ KernelSU 是什么——Android root 的现代内核方案

KernelSU 是一个运行在 Android 内核层面的 root 方案，自 0.9.0 版本起支持 GKI（通用内核镜像）设备。它的核心思路不同于传统的 Magisk 等用户空间方案——直接在内核里实现 root 权限管理，带来更小的性能开销和更高的兼容性。

对普通用户来说，KernelSU 解决的是「安全获取 Android 超级用户权限」这个老问题。它内置了权限管理器、模块系统和完善的安全机制，既满足刷模块、改系统、跑自动化脚本的玩家需求，也通过 GKI 适配和安全模式照顾到日常主力机用户的稳定性诉求。

自 0.9.0 起，KernelSU 在 GKI 设备上提供两种运行模式供选择：LKM（可加载内核模块）模式不替换原有内核，通过修补 boot 或 init_boot 的 ramdisk 部分加载模块；GKI 模式则直接用 KernelSU 编译的通用内核镜像替换设备原内核。两种模式各有适用场景，日常主力机优先选 LKM，OTA 友好且升级方便，还能随时临时取消 root；模拟器、WSA、Waydroid 等容器环境适合 GKI，直接换内核最省事；三星等开启 KNOX 的设备或冷门机型则倾向 GKI 模式，通用性更强。

## 🔧 安装前准备与安装步骤

刷机有风险，动手之前有几件事必须做。

### 备份原厂 boot 镜像——全流程的保命一步

任何刷机操作都可能出问题，原厂 boot 镜像是你唯一的后悔药。刷错格式、刷错 KMI、版本不匹配导致开不了机时，用 fastboot 刷回原厂 boot 一般都能恢复。

获取原厂 boot 有三条路：

1. **从官方固件包提取**：找到对应机型的线刷包或卡刷包，线刷包直接解压可得 boot.img；如果是 payload 格式的卡刷包，用 payload-dumper-go 之类的工具解出来。
2. **已 root 状态下从设备导出**：如果设备已经有 root（比如从 Magisk 迁移），用 dd 命令从对应分区块设备导出 boot 或 init_boot 镜像。
3. **让 KernelSU 管理器自动备份**：从 3.3.0 版本开始，管理器的自动备份机制增强了不少——用「直接安装」选项时会自动备份原厂 boot，以备增量 OTA 时临时还原；备份文件的 SHA1 会写进修补后的 boot 镜像，备份本体存放在 `/data/adb/ksu/ksu_backup_$SHA1`；无 root 首次安装时，用「选择并修补一个文件」修补后也可以勾选「备份为原厂镜像」。

> [!WARNING]
> 备份至少保留两份——电脑上一份，网盘或 U 盘一份。只存在手机本体的备份在无法开机时帮不上忙。

还原命令很简单，一条搞定：

```
fastboot flash boot boot.img
```

### 解锁 Bootloader

KernelSU 的安装前提是设备 Bootloader 已解锁。不同品牌手机的解锁方式略有差异，但通用思路一致：进入开发者选项打开 OEM 解锁，然后在 fastboot 模式下执行 `fastboot flashing unlock`。解锁会清除设备所有数据，这一步请务必先完成整机数据备份。

### 三种安装场景对应三种选项

打开 KernelSU 管理器，安装界面提供三个选项，各自适用场景不同：

| 你的处境 | 用哪个选项 |
| --- | --- |
| 全新安装，手机无 root | 选择并修补一个文件 → fastboot 刷入 |
| 已用临时引导拿到临时 root | 直接安装 |
| LKM 模式日常升级 | 直接安装 |
| 系统刚完成 OTA | 安装到另一个分区 |
| 想在刷入前留下原厂备份 | 修补文件方式勾选「备份为原厂镜像」 |

- **选择并修补一个文件**：选这个选项后，挑选你的原厂 boot 或 init_boot 镜像，管理器自动完成修补。修补产物通常存放在 Download 目录，之后用 fastboot 刷入即可永久获取 root。这是无 root 设备的第一台电梯，所有手动刷入流程都以它产出的修补镜像为原材料。
- **直接安装**：手机已经有 root 时用这个选项，管理器自动获取设备信息、自动修补官方固件并直接刷入当前分区，同时自动备份原厂 boot。临时引导拿到临时 root 后的正式安装，以及 LKM 模式的日常版本升级，都走这条路。
- **安装到另一个分区**：只在支持 A/B 分区的设备上出现，管理器修补后装到另一个槽位。核心用途是 OTA 后保 root——系统更新完成后，直接用这个选项装到对侧分区，重启即同时拥有新系统与 KernelSU。

> [!NOTE]
> 三个选项的共同前提都是原厂 boot 备份已完成。修补与刷写只动 boot/init_boot，但出错时的恢复全靠那份备份。

## 📖 使用入门——模块管理、安全模式与日常维护

KernelSU 安装完成后打开管理器，左侧侧栏可以看到模块页、超级用户列表、配置中心等入口。

### 模块安装与管理

KernelSU 的模块机制沿用了 Magisk 模块的思路，但实现上更轻量。在管理器模块页可以看到已安装的模块，点击模块卡片能查看详情、禁用或卸载。模块安装主要有两种方式：一是在管理器内下载安装，二是手动下载模块包后，在模块页点击右上角加号选择本地 zip 包刷入。

> [!TIP]
> 模块不要贪多，只装真正需要的。第三方模块质量参差不齐，刷入多个模块出问题时排查成本很高。每次只装一个，装完重启确认没问题再装下一个。

### 超级用户权限控制

超级用户列表会记录所有请求 root 权限的应用。默认情况下，新应用首次请求权限时会弹窗确认，你可以选择「允许」「拒绝」或「只这一次」。在超级用户列表里可以随时修改已有应用的授权状态，也能手动添加或移除条目。

### 安全模式——救砖的第一道防线

刷入某个模块后开不了机或卡在启动画面，最轻的恢复手段就是安全模式。进入后所有模块被禁用，系统可以正常启动，你再从容地卸载问题模块。

触发方法很简单：按电源键开机，看到品牌 logo 后**连续按音量下键三次**——注意节奏是按下-松开、按下-松开、按下-松开，不是按住不放。KernelSU 在内核模块初始化时就注册了音量键监听，到开机动画前才注销，所以启动太快的设备可能抓不到按键，多试几次把握好开机第一屏的节奏。

很多系统自带安全模式，KernelSU 会联动进入模块禁用状态。安全模式实现在内核里，不担心按键事件被问题模块拦截，这正是它比用户空间方案可靠的地方。

进入安全模式之后：

1. 打开管理器模块页，确认全部模块已禁用
2. 对最近新装的嫌疑模块执行卸载
3. 卸载后重启恢复正常

有两个边界要注意：initrc 注入的代码在安全模式下仍会执行，如果模块在 initrc 里写了不合理的代码导致无法启动，安全模式救不了，需要走 Recovery 清理；late-load 模式下 initrc 注入本就不可用，相关风险面更小。

### LKM 与 GKI 选型回顾

LKM 和 GKI 两种模式各有侧重，简单做个对比：

| 对比项 | LKM 模式 | GKI 模式 |
| --- | --- | --- |
| 是否替换原内核 | 否，保留原内核 | 是，整颗换掉 |
| OTA 友好度 | 高 | 一般 |
| 升级方式 | 管理器内直接安装 | 需重新刷入镜像 |
| 临时 root | 支持 | 不支持 |
| 临时卸载 | 可卸载 LKM，不必刷分区 | 需刷回原内核 |

手机日常主力机优先 LKM，升级方便、OTA 省心，还能随时临时取消 root；模拟器、WSA、Waydroid 等容器环境优先 GKI，直接换内核最省事；三星等开启 KNOX 的设备或冷门机型，LKM 可能无法运作，用 GKI 模式。

模式不是终身绑定，装完 LKM 后想换成 GKI，随时可以用 fastboot 刷入通用内核镜像；反过来刷回原厂 boot 再重打 LKM 补丁也可以。

### 日常升级与 OTA 后保 root

LKM 模式下，日常升级 KernelSU 版本就是在管理器里点直接安装，一键完成无需电脑。OTA 升级后，系统更新到另一个槽位，KernelSU 不会自动跟进。这时用「安装到另一个分区」选项，管理器会自动修补并装到对侧分区，重启即同时拥有新系统与 KernelSU。如果 OTA 前没有装到另一个分区，更新后直接走「直接安装」也能补救——只是需要重启一次。

> [!NOTE]
> OTA 后如果发现 KernelSU 丢失，不必慌，用管理器的直接安装选项或手动刷入修补后的 boot 镜像即可恢复。关键是备份好原厂 boot，就不会变砖。
