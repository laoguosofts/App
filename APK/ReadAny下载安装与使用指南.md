## ✨ ReadAny：AI 驱动的本地知识库阅读器

ReadAny 是一款面向重度阅读者的本地优先阅读器，核心思路是把「读完一本厚厚的技术书却记不住内容」这个老问题，用 AI 工具链从根本上解决。它支持 EPUB、PDF、Markdown 等常见格式，内置了语义搜索、AI 对话、TTS 语音朗读和五色标注笔记系统——这些功能组合在一起，让阅读不再是单向的信息接收，而是一个可以反复检索、提问、沉淀成知识资产的过程。

适合谁用：经常啃厚部头技术书、英文专著的开发者和研究者；想把零散阅读整理进个人知识库的终身学习者；喜欢边听边学、习惯高亮标注的效率党。ReadAny 的跨平台覆盖桌面端（Windows / macOS / Linux）和移动端（Android / iOS），数据存储在本地，不强制上云。

## 🔧 安装步骤

ReadAny 的桌面端基于 Tauri 框架构建，安装过程简洁无捆绑；移动端走正规应用商店分发。以下分平台说明注意点：

**桌面端（以 Windows 为例）**

1. 从下载页获取安装包（`.msi` 或便携版 `.exe`），核对文件大小和版本号是否与下载页一致
2. 双击运行安装程序，便携版可直接解压到任意目录运行，无需管理员权限
3. 如果 Windows Defender 弹出 SmartScreen 提示，确认文件来源后选择「仍要运行」即可——这是新签名应用的常见情况，不是病毒
4. 首次启动后进入设置向导，选择语言、导入已有书库（可选）、配置 AI 提供商（后续可再配置）

> [!WARNING]
> 桌面端的 AI 功能依赖网络（云端 API）或本地 Ollama 服务。如果首次启动不配置 AI，核心阅读功能仍可正常使用，只是语义搜索和 AI 对话暂时不可用。

**Android / iOS 移动端**

1. 在 Google Play 或 App Store 搜索 ReadAny 安装即可
2. Android 版允许安装未知来源 APK（仅限从官方下载页获取的签名包），但应用商店版自动更新更方便，优先推荐
3. 首次启动时授予存储访问权限以读取本地书籍文件；语音朗读功能需要麦克风权限（可选）

## 📖 核心功能与使用入门

ReadAny 的功能链条可以概括为「标注 → 向量化 → 搜索/对话 → 导出」四个环节。下面按实际使用顺序展开。

### 五色高亮 + Markdown 笔记：把阅读变成可检索的知识集合

ReadAny 的五种颜色高亮不是装饰，而是一套知识分类编码系统：

| 颜色 | 推荐用途 |
| --- | --- |
| 红色 | 核心论点 / 关键概念 / 作者明确主张的观点 |
| 蓝色 | 支撑论据 / 数据 / 引用来源 |
| 绿色 | 行动要点 / 可执行的建议 / 代码片段 |
| 黄色 | 疑问 / 想进一步了解的内容 / 不确定的地方 |
| 紫色 | 佳句 / 想分享的段落 / 有趣的观察 |

推荐的做法是**跨书统一颜色语义**——你在 A 本书用红色标记核心论点，在 B 本书也坚持红色表示同类含义。这样当你后续在 Obsidian 或 Notion 里看到不同颜色的高亮时，一眼就知道它们的性质，不需要重新回忆每本书的颜色约定。

标注操作本身很顺手：桌面版按住鼠标拖动选中文字 → 松开后弹出颜色工具条，一键高亮；右键高亮段落可以改颜色、加笔记、删除。移动版长按屏幕选中 → 拖动两端手柄调整范围 → 点击上方颜色圆圈完成。快捷键可自定义，默认 `Ctrl+H` 快速高亮。

高亮不是终点。在任何高亮上点击「加笔记」按钮，可以写一段 Markdown 格式的笔记——支持加粗、斜体、代码块、引用块。笔记和高亮段落关联在一起，导出到 Obsidian 时高亮文本和你的笔记会成对出现。右侧边栏能看到当前书籍的所有高亮集合，支持按颜色分组、按章节分组、关键词搜索、批量选中导出。读完一本书后打开侧边栏，你能直观地看到自己实际抓了多少要点。

### Edge TTS 语音朗读：100+ 种声音，听书也能高质量

ReadAny 选择微软 Edge TTS 作为默认语音合成引擎，理由很实在：完全免费、覆盖 100+ 种声音（英语、中文、日语、韩语、法语……）、中文声音的断句和语调质量不错、无需额外安装语音数据。这让 TTS 开箱即用，不像不少其他阅读器需要找 API Key 或下载大体积的语音包。

中文声音方面，常用的有晓伊（女声，普通话）、云健（男声，普通话）、晓梦（女声，更温和）、晓辰（男声），每个声音都可以在设置里先预览再决定。语速调节范围 0.5x 到 2.0x，默认 1.0x，重度听书的人常常调到 1.2x-1.5x 来加快吸收节奏。音调有 -50 到 +50 的微调，一般保持 0 即可。设置在朗读会话中实时生效，边听边调也没问题。

> [!NOTE]
> Edge TTS 是云端服务，需要联网才能工作。如果完全离线，可以在设置里切换到系统自带的 TTS（Windows SAPI / macOS VoiceOver），但声音选择会少很多，中文质量也有差距。部分中文声音首次选中时会自动下载对应的语言包（几 MB 到几十 MB），属于正常现象。

后台播放方面，桌面版最小化窗口后 Edge TTS 会继续联网请求朗读，网络断开会自动暂停、恢复后从断点继续。移动版的后台朗读更彻底——锁屏、切到其他 App 都能继续播放，Android 通知栏可以直接控制播放/暂停和进度。

TTS 和 AI 辅助的组合尤其适合语言学习场景：边听英文原著，遇到没听懂的段落暂停 → 选中刚才的段落 → 让 AI 解释 → 理解后继续播放。也可以让 AI 先生成当前章节摘要，再边听边验证摘要里的要点是否准确。

### 语义搜索：不再依赖 Ctrl+F 猜关键词

传统阅读器的搜索是纯关键词匹配，你搜「并发修改」只会命中含有这四个字的段落。但如果作者讲的是「处理同时发生的数据变更」，你就搜不到了——这在检索技术书籍时尤其痛苦，因为概念常常换一种说法。

ReadAny 的语义搜索从根本上解决了这个问题：你搜的是**意思**，不是字。它背后用的是向量嵌入技术——把文字转换成数字向量，意思相近的文字在数学空间里离得近。「处理并发数据变更」和「同时发生的数据修改」会被映射到相近的向量，不管用词是否精确一致。

但纯向量搜索也有弱点——可能漏掉精确匹配的专有名词和代码标识符（比如你想找一个具体的函数名）。所以 ReadAny 采用**混合检索**策略：

1. **BM25 关键词匹配**：传统搜索引擎的标准算法，精确匹配你的搜索词，适合找变量名、函数名、专有名词、精确引文
2. **向量相似度匹配**：把你的搜索词也转成向量，在向量空间里找最接近的分块，适合找意思相近但用词不同的段落、同义词覆盖、模糊记忆的概念
3. **合并与排序**：两路结果用 RRF（Reciprocal Rank Fusion）算法综合排序，不会漏掉精确匹配，也能覆盖模糊语义

嵌入模型的选择直接影响搜索效果。ReadAny 推荐的几个选项：

| 模型 | 类型 | 特点 |
| --- | --- | --- |
| text-embedding-3-small | 云端（OpenAI） | 质量稳定，1536 维 |
| nomic-embed-text | 本地（Ollama） | 开源免费，中文支持不错，768 维 |
| bge-m3 | 本地/云端 | 多语言强项，中文语义质量高 |
| DeepSeek embedding | 云端 | 国内访问友好，速度快 |

对国内用户来说，DeepSeek embedding 或 bge-m3 是性价比很高的选择。向量化发生在两个时机：导入书籍时自动触发（前提是已配置嵌入模型），或者导入后手动在书籍设置里点「开始向量化」。一本 300 页的书大约需要几十秒，向量化完成后语义搜索立即生效，向量索引存在本地 SQLite 中。

> [!TIP]
> 很多用户只配置了 AI 对话模型就跑来看语义搜索，结果返回空——这是最常见的排查项。嵌入模型和对话模型是两个独立的配置项，需要分开配置。如果用 Ollama 本地部署，记得先 `ollama pull nomic-embed-text` 拉取嵌入模型。

### AI 对话：针对书籍内容的问答

AI 对话功能让你可以直接向书籍提问，比如「这本书里讲的观察者模式和策略模式有什么区别？」或者「作者对并发编程给出了哪些具体建议？」。ReadAny 会把相关的段落作为上下文传给 AI，让回答不脱离本书内容。

AI 提供商配置支持云端和本地两种路线：OpenAI / Claude / Gemini / DeepSeek / 硅基流动等云端 API，或者 Ollama 本地模型。国内用户推荐 DeepSeek 或硅基流动（两者走国内节点，速度快价格低），不想走云端的话 Ollama + qwen2.5-coder 或 llama3 也够用。

遇到 AI 对话不响应时可以按这个顺序排查：首先检查提供商配置的 API Key / Base URL 是否正确，点「测试连接」按钮确认连通；其次检查网络和代理设置（Tauri 应用继承系统代理，国内直连 OpenAI/Claude 大概率被墙）；再检查账户余额或限额（云端 API 按用量计费，余额为零或达到月度上限会返回 403 / 429）；最后看本地日志（设置 → 开发者选项开启后，再次触发 AI 对话即可查看错误码——401 是 Key 无效、429 是请求过频、500+ 是服务端故障）。
