## ✨ SauceNAO 是什么

SauceNAO 是目前二次元领域最强的反向搜图工具——给它一张图，它就能告诉你这张插画、动漫截图、cos 照片的原始出处、作者是谁、在哪个图站发布的。它背后维护着 60 多个索引数据库，覆盖 Pixiv、Danbooru、Twitter、Anime、MangaDex 等主流二次元内容平台，总计数十亿张图片的像素级指纹。

核心原理说起来不复杂：SauceNAO 给你上传的图片和数据库里每一张图都算一个"指纹"（一串数字），然后比较两个指纹有多像。相似度越高，命中越靠谱。整个过程不需要 AI 语义理解——它不认识图里画的是初音未来还是路飞，只关心像素排列的相似程度。也正因为如此，它对二次元风格的识别准确率比通用反向搜图工具（比如 Google 图片搜索、TinEye）高出一大截。

适合谁用？如果你是二次元爱好者、插画收集者、cos 圈同好、或者经常在社交平台看到喜欢的图但找不到出处的人，SauceNAO 几乎是刚需。写爬虫或图站管理脚本的开发者也离不开它的 JSON API——一个 HTTP 请求就能拿到结构化的搜索结果，批量处理几千张图不在话下。

## 🔧 安装准备

SauceNAO 的使用形态分两种——网页端直接访问，或者通过 API / 第三方客户端接入。下面分别说。

### 网页端：零安装，开箱即用

这是最主流的用法——打开浏览器访问 SauceNAO 官网，就能直接上传图片或贴图片 URL 开始搜索。没有注册门槛，免费用户可以直接用，唯一限制是请求频率。

> [!NOTE]
> 国内网络访问 SauceNAO 服务器速度不稳定，尤其是晚高峰时段。如果打开页面慢、或搜索请求一直转圈，建议换 4G / 5G 网络试试，或者科学上网后使用。

### 第三方安卓客户端

虽然 SauceNAO 官方没有发布 App，但社区有几个质量不错的安卓封装客户端。它们本质上还是调 SauceNAO 的云端 API，速度和网页端差不多，但手机屏幕小、展示内容精简，主观感受上可能更快。

安装步骤：

1. 从对应渠道下载 APK 文件（注意来源安全性，只在知名应用市场或社区发布帖里找）。
2. 如果是首次安装非应用市场来源的 APK，需要在系统设置里允许「未知来源」应用安装。不同厂商 ROM 的路径略有差异，一般在 **设置 → 安全 → 安装未知应用** 里找到文件管理器或浏览器，把开关打开。
3. 安装完成后打开客户端，首次使用可能需要填一个 SauceNAO API Key（免费用户在官网注册后就能拿到，不需要付费）。

### JSON API 接入（开发者用）

如果你想把 SauceNAO 集成到自己的脚本里，只需要一个 HTTP 请求。Python `requests` 库的最简示例：

```python
import requests

with open("search.jpg", "rb") as f:
    resp = requests.post(
        "https://saucenao.com/search.php",
        params={"output_type": 2, "api_key": "YOUR_API_KEY"},
        files={"file": f},
    )

data = resp.json()
for item in data["results"]:
    print(f"{item['similarity']}% —— {item['title']} by {item['author']}")
```

> [!TIP]
> API 请求有两层限流：**短窗口 30 秒内**的请求次数（`short_remaining`）和**24 小时内**的总次数（`long_remaining`）。每次调用后务必检查响应 header 里的这两个值，0 就等窗口恢复，不要硬怼。免费账户的长窗口限额是每天 200 次。

## 📖 反向搜图使用入门

### 基本流程：上传 → 选数据库 → 看结果

打开官网后，页面中央就是一个上传区域。两种搜图方式：

- **本地上传**：把图片拖进去，或者点选择文件。支持 jpg / png / gif 等常见格式。
- **URL 搜图**：把网络图片地址贴进去，SauceNAO 服务器会去那个地址下载图片再比对。

> [!WARNING]
> URL 搜图有两个坑：一是源站响应慢的话 SauceNAO 下载也要等；二是部分源站有防盗链，直接拒绝 SauceNAO 的请求。遇到这两种情况，把图片下载到本地再上传搜是更稳的做法。

上传之后有一个关键设置——**选数据库**。默认的 ALL 模式会搜全部 60+ 个数据库，覆盖面最广但也最慢。如果只搜 3~5 个常用库，速度至少快一倍。根据图片来源来缩小范围：

| 图片类型 | 推荐勾选的数据库 |
| --- | --- |
| Pixiv 插画 | Pixiv Images + Danbooru + Twitter |
| 动画截图 | Anime + Madokami + MangaDex |
| 游戏 CG | Game CG + Danbooru + e621 |
| cos 照片 | Cosplay + Twitter + 图站 |

### 速度慢的排查方法

SauceNAO 正常 3~10 秒出结果，如果一直转圈或者 15 秒以上没动静，按下面的优先级排查：

**图片太大**是最常见原因，占了大约四成。SauceNAO 要先下载你的图片再算指纹、再和数十亿张图逐一比对——图片越大越慢。参考一下这个处理时间表：

| 图片大小 | 典型处理时间 |
| --- | --- |
| < 1MB | 3~5 秒 |
| 2~5MB | 5~10 秒 |
| 5~10MB | 10~20 秒 |
| > 10MB | 20 秒以上，可能超时 |

解决方法很简单：上传前用任何图片工具压缩一下，长边缩到 1920 像素、质量设 80% 就够了。SauceNAO 的指纹匹配对这种程度的压缩完全不敏感，准确率几乎不受影响。

第二常见的原因是**选了 ALL 所有数据库**（约占 25%）。回到上面那个数据库勾选表，只勾你真正需要的那几个。

其次是**服务器繁忙**（约占 15%）。SauceNAO 是个人维护的，服务器资源有限，周末、日本时间晚上的高峰期偶尔会排队。这种情况不用管，等几分钟就好，或者升级付费账户走优先队列。

剩下的是**网络环境**问题（约占 15%）和 URL 搜图源站慢（约占 5%）。排查方法：换 4G 试试，如果手机上明显快就是 Wi-Fi / 公司网络的出口限速；URL 搜图太慢就改成本地上传。

> [!NOTE]
> 90% 的慢问题都能通过「压缩图片 + 缩小数据库范围」这两步解决。

### 结果解读：相似度、缩略图和元信息

搜索返回的每条命中从上到下依次包含：相似度百分比、缩略图、来源数据库名、标题 / 作者、跳转链接。

**相似度是核心判断指标**。90% 以上基本就是你要找的原图；70%~90% 可能是同一张图的不同版本（加了水印、裁了一半、压缩过）；50%~70% 大概率不对，但偶尔在裁剪严重的场景下能命中；低于 50% 可以直接忽略。

> [!WARNING]
> 高相似度也不一定完全靠谱。有时候数据库里有两张非常相似的图（比如同一张插画的两个构图变体），SauceNAO 都给了 90%+ 相似度。还有同角色同画风的两张不同插画也可能互相混淆。不要只看数字，点进去看实际页面确认一下。

**来源数据库**也能帮你判断可信度。Pixiv、Danbooru、Twitter 这些主流数据库的命中质量普遍较高；如果显示 Unknown，大概率是 SauceNAO 在某个临时索引里命中了但没法确定来源，可以忽略。

**标题 / 作者 / 跳转链接**是你真正需要的信息。光看缩略图可能认错，文字信息更可靠。跳转链接会在新标签页打开原图在来源站的页面——通常就是你最终要找的东西。

### 相似度低于 70% 的救场方法

如果搜出来相似度都很低、看着完全不对，按这个顺序排查：

1. **图片是不是被处理过**？截图 → 压缩 → 加水印 → 再截图 → 再压缩，最终到你手里的时候已经和原图相差很大了。尽量从来源处重新下载、找更高分辨率版本、去掉水印再搜。
2. **是不是搜了"衍生物"**？比如有人用一张插画做了手机壁纸、改了色调、加了文字——这张改后图和原图的像素指纹差异很大，但视觉上还能看出是同一张。试试搜原始素材而不是衍生物。
3. **SauceNAO 没收录到这张图**。这是最无奈也最常见的原因——图太新、太小众、或来源平台没被 SauceNAO 索引。这时候换 ascii2d / TinEye / Google 图片搜索交叉验证。
4. **是不是选错了数据库**？搜动画截图只勾了 Pixiv——Pixiv 里不会有动画帧的索引，结果自然离谱。回到数据库勾选表重新选。

### 结果元信息的实际用途

如果你用 API 调用（`output_type=2`），每条结果返回的 JSON 字段比网页端丰富得多：

| 字段 | 含义 | 什么时候用 |
| --- | --- | --- |
| `similarity` | 相似度百分比 | 判断靠谱程度 |
| `index_name` | 数据库名称 | 决定要不要信这个结果 |
| `title` / `author` | 原站标题和作者 | 快速确认目标 |
| `url` | 原站页面 URL | 最终落点 |
| `pixiv_id` / `danbooru_id` | 作品 ID | 自己写脚本时可以直接用这个 ID 去对应 API 拉更多信息 |
| `character` / `characters` | 识别到的角色 | 快速识别角色名 |
| `thumbnail` | SauceNAO 缩略图 | 预览用 |

不是每个数据库都会返回所有字段——Twitter 命中可能只有 URL 和作者名，没有 title；Danbooru 命中可能有完整的 tag 列表。写脚本时要做好字段缺失的容错处理。

### 知道它的边界，用得更稳

SauceNAO 在以下场景下就是搜不准，接受这个局限就不会被困扰：

- 被截掉 80% 以上的图片
- AI 生成的插画（指纹特征和传统插画不同）
- 写实照片（SauceNAO 专注二次元，写实领域是 TinEye 和 Google 的地盘）
- 非常小的图标 / emoji / 贴纸

遇到这些情况换工具或接受溯源失败——不是你的问题，也不是 SauceNAO 的问题，是技术边界。
