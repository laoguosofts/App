## ✨ Luker 是什么

Luker 是一款专为 AI 角色扮演（RP）场景设计的聊天平台，从社区知名的 SillyTavern 分叉发展而来。它保留了酒馆上游成熟的角色卡、世界书、预设、聊天记录等全套功能，数据可以直接双向兼容——把酒馆的 `data` 目录复制过来就能跑，想回去原封不动拷回去也不会破坏。但 Luker 真正有价值的是在这个基础上叠加的能力：长期记忆图、多 Agent 编排、Skills 技能库、AI 改卡与调预设、安卓 APK 内嵌后端、局域网多设备同步，这些都是原版酒馆没有或做得不完整的地方。

简单说，如果你玩 AI 角色扮演只是跑几楼短剧本，原版酒馆够用；但一个车要跑几十上百楼、在意前后剧情的一致性、不想手动在系统提示词里堆写作规则，Luker 更合适。它适合长线 RP 玩家、已经有酒馆积累想升级记忆与编排能力的老用户、想在手机上跑完整 RP 后端的用户、以及希望自部署服务器实例并多设备同步的玩家。

下面这个表格可以快速帮你判断 Luker 解决了哪些经典痛点：

| 能力 | 解决的具体问题 |
| --- | --- |
| 记忆图 | 跑了几百楼后角色忘了早期剧情、忘了去过的地点 |
| 多 Agent 编排 | 单模型回复跳节奏、忘设定、出戏做总结，一件事拆给多个 Agent 分工干 |
| Skills 技能库 | 写作规则全堆在巨型系统提示词里，改一处怕崩全局 |
| AI 改卡与调预设 | 改角色卡、调预设参数全靠手搓，没有 AI 帮忙审 diff |
| 安卓 APK | 完整后端跑在手机里，不用 Termux、不用端口转发 |
| 局域网同步 | 电脑和手机的数据各改各的，没人管同步冲突 |

从版本演进来看，v1.0 到 v1.16 主要是补丁式保存、世界书激活追踪、编排器雏形、安卓应用、备份还原等基础能力；v2.0 是大版本，文档站上线、CardApp 与 Studio、统一生成层、请求检查器；v2.2 推出了导演模式（八 Agent 套件），是重度玩家的分水岭；v2.4 修了记忆图数据丢失这个关键问题，v2.3 用户务必跳过直接升 2.4+；v2.6 上线 Skill 子系统，技能体系成为编排生态的核心组件；v2.8 加入了鸿蒙原生应用、AI 改图工作台、多存储引擎（SQLite / MySQL / PostgreSQL）等重要能力。

## 🔧 怎么安装 Luker

Luker 支持三种常见部署形态：安卓 APK、电脑 Node.js 自部署、Docker 容器。不同形态的安装门槛和后续维护成本差异不小，这里分别说明。

### 安卓 APK——最省心的手机方案

安卓版把完整后端打包进了 APK，装好打开就能用，不需要 Termux，也不需要配置端口转发。这是手机党首选的方式。安装步骤比较简单：

1. 从官方下载页拿到最新版本的 APK 文件，核对文件大小和版本号，避免装到旧版
2. 如果系统弹出"未知来源应用"授权，进入设置允许安装外部来源应用
3. 安装完成后首次打开，应用会自动探测可用端口并初始化后端
4. 连接上你想用的 AI 模型 API（自己填 API 地址和密钥），就能开始创建角色卡开聊了

> [!WARNING]
> 升级前务必备份 `data` 目录，尤其是跨大版本升级时——v2.3 曾引入过记忆图数据丢失问题，老用户跳过 2.3 直接升 2.4+ 更安全。

### 电脑 Node.js 自部署——适合自部署玩家

PC 端部署需要先装好 Node.js 环境，然后拉取项目代码、安装依赖、启动服务。具体流程大致是：

1. 克隆官方仓库代码到本地，切换到对应的发布分支或 tag
2. 在项目目录下执行 `npm install` 或 `pnpm install` 装依赖
3. 启动服务后，浏览器访问本地端口（默认由应用自动探测可用端口）
4. 配置 API 连接、导入或新建角色卡、开始使用

数据目录 `data/` 存放所有角色卡、世界书、预设、聊天记录和记忆图，这个目录是整个实例的核心。把酒馆的 `data` 目录直接复制过来，Luker 能识别大部分上游格式。

### Docker 容器——服务器部署首选

Docker 方式适合想在服务器上跑实例、多设备通过内网或公网访问的用户。拉取镜像然后按容器编排文件启动，升级时只需拉新镜像重启容器，不用手动管依赖更新。同样记得挂载 `data` 目录到宿主机，避免容器重建时数据丢失。

### 鸿蒙原生应用

v2.8.0 新增了鸿蒙原生应用，安装形态和安卓类似，装好即跑，适合鸿蒙用户直接在手机上使用。

## 📖 Luker 核心功能使用入门

Luker 的核心体验围绕「角色扮演长线开车」这个场景展开，下面按实际使用中最常打交道的几个模块分别拆解。

### 角色卡与预设绑定——导入即用的卡

社区里换角色卡的经典麻烦是：卡作者说"这张卡要配某某预设才出效果"，用户得自己去翻预设、下载、导入、切换，一通操作还经常配错。Luker 提供了**卡作者绑定预设与人设**的机制，解决了这个痛点。

**卡作者的操作**：在角色头像旁的角色管理下拉里选「绑定当前对话补全预设」，当前选中的预设会被加入这张卡的内嵌集合并设为默认。一张卡可以绑定多份预设，通过「管理已绑定的对话补全预设」逐个管理，也可以一次性全部清除。推荐人设（用户扮演谁）用同样方式绑定。

**普通用户加载时的体验**：打开带内嵌预设的角色时，预设选择器顶部会出现「本卡内嵌」分组，列出卡携带的所有预设，并且自动选中卡上的默认预设；卡推荐的人设也会自动露出。关键一点是——**关闭角色聊天后，这些绑定不会污染你的全局列表**，本地预设原样保留，不会被卡的内嵌预设覆盖。另外在「本卡内嵌」槽位上直接改参数，改的是卡内嵌副本，不影响你本地的其他预设。

> [!NOTE]
> 分享安全性有保障：内嵌预设时连接字段自动剥离，API 地址和密钥永远不会被打进卡里。卡作者放心导出，用户导入后用自己的 API 连接跑卡上的预设，两边都安全。导出 PNG / JSON 时会带走绑定预设、人设、编排覆写、内嵌技能，不需要任何伴生文件。

配合编排配置与内嵌技能，还能打包出"导入就有一套专属写作纪律"的卡——相当于把一张卡连同它的写作规则、预设参数、Agent 编排一起分享，别人导入就能直接用。

### 记忆图——让角色跑几百楼还能记住剧情

记忆图是 Luker 最有辨识度的能力之一。它解决的是长线 RP 里最让人头疼的问题：跑了几百楼后，角色忘了早期剧情、忘了去过的地方、忘了之前的约定。

默认节点类型有四种：角色、地点、事件、剧情线。大多数场景这四种够用了。但特定世界观有特定的"值得记的东西"——奇幻卡要记魔法体系和派系关系，悬疑卡要记线索和证词，种田文要记资源和建筑。这些内容塞进"事件"类型也能跑，但召回精度会打折。Luker 提供了 Schema 编辑器，可以自定义节点类型。

在 Memory 面板点"打开 Schema 编辑器"就能进入编辑界面。每个节点类型可以配置的核心字段包括：类型名与说明（提取 AI 依此判断什么内容该建成这种节点）、提取频率（每 N 楼提取一次，控制低价值类型的膨胀速度）、提取指引（给提取 AI 的专项写作要求）、持久注入（打开后该类型节点永远进提示词，不等召回）。

**持久注入**是个很实用的功能。比如新建一个 `world_law`（世界法则）类型，把"这个世界魔法不能复活死者"之类的铁律记进去并标为持久——主模型从头到尾都忘不掉。但持久注入类型要克制，全开等于把提示词越堆越厚。

> [!TIP]
> Schema 改动影响的是"以后怎么提取和召回"，已有记忆不会丢。不想手填字段的话，Memory 面板里的"AI 迭代 Schema"入口可以直接用自然语言描述想要的类型结构，AI 出方案你审批。大改前记得用记忆库的 JSON 导出功能先备份一份。

### 多 Agent 编排与 Skill 子系统

当单模型干太多事容易跳节奏、忘设定、出戏做总结时，多 Agent 编排把一件事拆给多个 Agent 分工干。v2.2 推出的**导演模式**（八 Agent 套件）是重度玩家的分水岭，之前后体验差距很大。

v2.6 上线的 **Skill 子系统**让技能体系成为编排生态的核心组件。之前写作规则全堆在巨型系统提示词里，改一处怕崩全局——Skill 把规则拆成可独立调用的单元，编排器按需要组合调用，灵活且安全。

### 局域网多设备同步

电脑和手机各改各的数据、没人管同步冲突，这是 RP 玩家多设备使用时的真实痛点。Luker 内置了局域网同步能力，电脑端跑实例的同时，手机端可以连接同步端口，两端的数据变更会自动合并，不需要手动复制 `data` 目录。

### 升级注意事项

升级有多种方式：电脑 Git 部署拉取更新加装依赖，Docker 拉新镜像重启，安卓 APK 覆盖安装或应用内一键更新。跨大版本前记得备份 `data` 目录。特别提醒：v2.3 有记忆图数据丢失问题，老用户务必跳过直接升 2.4+。
