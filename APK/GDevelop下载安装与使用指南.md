## ✨ GDevelop 是什么：零代码游戏引擎的务实派

GDevelop 是一款面向独立开发者和初学者的可视化游戏引擎，核心定位是「不用写代码就能做出可发布的游戏」。它的编辑逻辑基于事件表（Event Sheets）——用「条件 → 动作」的方块串联替代传统编程的 if-else 和函数调用，让完全没接触过代码的人也能在短时间内跑通原型。

引擎的完整功能在免费档全部开放：平台跳跃、物理模拟、寻路、多人联机、排行榜、AI 辅助创作等高级能力都能用，没有功能阉割。真正的门槛集中在云端服务额度上——桌面和安卓打包每天各 1 次、云端项目最多 3 个、AI 点数每月 40 点，对于学习和原型验证来说够用，商用项目再考虑订阅升级。

GDevelop 的效率优势在于「行为机制」：给任意对象点几下就能挂上平台角色、物理、寻路、缓动等上百种预置能力，一个玩家角色通常同时挂着四五个行为各司其职，冲突时后挂的行为属性可以覆盖前面的。这种模块化设计让事件表保持清爽，复杂逻辑也能一眼看懂。

> [!NOTE]
> 官方 FAQ 明确口径：个人和小型业务（年收入 5 万美元以内）在任意档位都可以商用，超额才强制升级到 Pro。不登录也能离线使用编辑器，只是云服务不可用。

## 🔧 安装与环境准备

GDevelop 提供 Windows、macOS、Linux 三大桌面平台以及 Android、iOS 移动端编辑器，下面分别说明。

### 桌面版安装

1. 从下载页获取对应操作系统的安装包（Windows 为 `.exe` 安装器、macOS 为 `.dmg`、Linux 为 AppImage 或 Snap 包）；
2. Windows 用户双击安装器，选择安装路径后等待进度条走完即可；若被 Windows Defender 或第三方杀毒软件误报，可在设置中将 GDevelop 目录加入白名单——开源引擎代码可审计，无需担心；
3. macOS 用户将 `.app` 拖入应用程序文件夹后首次打开时可能触发 Gatekeeper 提示，在系统设置 → 隐私与安全中点击「仍要打开」即可；
4. Linux 用户直接运行 AppImage 文件（需先赋予可执行权限）或通过 Snap 商店安装。

### 移动端编辑器

Android 版可在 Google Play 下载，iOS 版需通过 TestFlight 获取。移动端编辑器功能完整，但触控操作对于复杂事件表编辑不如桌面版高效，适合轻量修改和原型预览。

> [!TIP]
> 安装完成后首次启动，建议在设置中将编辑器语言切换为中文（如果官方提供中文界面），并登录账号——登录后才能使用云服务（云项目、AI 辅助、排行榜等），不登录则只能本地编辑和手动导出。

### 版本核对与更新

启动后在「帮助 → 关于」中确认当前版本号。GDevelop 迭代频率较高，大版本更新会引入新行为和新导出平台，建议每 1-2 个月检查一次更新。桌面版内置自动更新检查，也可以从官网手动下载覆盖安装。

## 📖 使用入门：从事件表到第一个游戏

### 核心概念：事件表

GDevelop 的编程单位是「事件」——每条事件由**条件**和**动作**两部分组成，逻辑是「当条件全部满足时，依次执行所有动作」。多条事件按顺序排列构成事件表，GDevelop 会在每一帧从顶到底扫描一次整张表。

```
条件：玩家 按空格键 被按下
动作：玩家 平台角色 开始跳跃
```

事件之间可以嵌套**子事件**——只有父事件条件全部成立时才会检查子事件，常用于分层逻辑。例如玩家血量降到 0 后，子事件分别处理延迟切换场景和屏幕变暗特效，两层逻辑互不干扰。对于需要逐个处理的对象实例，用「对每个对象事件」让引擎把筛选出的实例一个一个拿出来跑完整段逻辑，适合逐个敌人独立 AI 或逐个宝箱随机掉落这类场景。

### 给对象挂行为

事件表之外，行为是另一层效率工具。选中场景中的任意对象，在属性面板的「行为」区点「+」就能浏览上百种预置行为，常用的包括：

| 行为 | 给对象的能力 |
| --- | --- |
| 平台角色 | 走、跳、重力、斜坡、爬梯 |
| 寻路 | 自动绕开障碍物走向目标 |
| 缓动 | 属性平滑过渡动画 |
| 屏幕外销毁 | 出屏即删（回收子弹用） |
| 可拖动 | 鼠标/触摸拖动对象 |

一个对象挂多个行为是常规操作，比如玩家角色同时挂着平台角色、缓动和可拖动（调试时用）。行为之间各管各的维度，想运行时调整跳跃力、加速减速手感，通过事件动作里的「行为名 + 属性」组合就能实时修改。

### 循环与批量处理

单次事件处理一个逻辑，批量逻辑交给循环类事件：

- **重复事件**：固定次数执行，配合 `Random()` 表达式是生成波次敌人、随机铺道具的常用组合；
- **While 事件**：条件成立期间反复执行，循环体里必须有机会让条件变假（比如每次减 1），否则游戏会卡死在无限循环里——新手尽量用重复事件替代；
- **对每个子变量事件**：遍历数组或结构变量的每个子项，读存档背包列表逐个生成物品、遍历排行榜分数逐行渲染都靠它；
- **事件组与链接事件**：事件组是折叠整理用的容器，不影响逻辑；链接事件则是跨场景复用逻辑的官方姿势——一处修改处处生效。

### 云服务：排行榜实战

GDevelop 把排行榜做成了内置云服务，不用自己搭后端。接入分三步：

1. 在编辑器的排行榜面板为当前游戏创建榜单；
2. 游戏结束处加动作「保存玩家分数」，把成绩连同玩家昵称提交；
3. 用「请求排行榜条目」拉取前 N 名，在回调事件里把每行渲染到文本或列表对象上。

> [!WARNING]
> 免费档每游戏只能建 1 张榜单，超出额度会静默失败。设计时把最核心的指标（比如最高分）放在这唯一一张榜里。防刷方面官方只有基础校验，客户端提交型榜单天然防不住有心人，竞技强度高的游戏建议只把榜单当留存工具而非权威排名。

记分身份支持两种：匿名玩家只需提交时带一个昵称，门槛最低；登录玩家接了账号体系后成绩自动挂账号，后续成就类功能也基于它扩展，是官方推荐的做法。

### 免费档的真实边界

免费档不是阉割版——引擎全部功能、全部行为、全部手动导出路径都开放，限制集中在云端额度上：

| 限制 | 具体数额 | 应对 |
| --- | --- | --- |
| 云端项目 | 3 个 | 做完及时归档删除，或纯本地项目（不占额度） |
| AI 点数 | 每月 40 | 方案先用纯聊天过一遍再动手，文档能答的别问 AI |
| 桌面/安卓打包 | 每天各 1 次 | 测试走本地预览与网页预览，正式包一次打包到位 |
| iOS 打包 | 无 | 发网页版顶上，或升级订阅 |
| 版本历史 | 2 天 | 重要节点手动下载项目备份 |
| 排行榜 | 每游戏 1 张 | 按「最高分」单榜设计 |

引擎功能、资产商店免费素材、手动导出（网页文件夹、Cordova、Electron 工程）、gd.games 发布次数全部不限。个人学习、小游戏和原型验证全程免费走得通，当你发现打包次数或 AI 额度每周都在卡你时，就是考虑升级订阅的时机。
