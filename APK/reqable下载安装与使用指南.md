## ✨ Reqable 是什么

Reqable 是一款跨平台的 HTTP/HTTPS 抓包与流量调试工具，桌面端覆盖 Windows、macOS、Linux，移动端同时支持 Android 和 iOS。它不是单纯的抓包查看器——除了把网络请求一览无余地展示出来，更重要的是提供了一整套"改流量"的能力：预设规则自动重写、实时断点手动改、Python 脚本灵活控制，加上弱网模拟，基本上把接口调试场景能遇到的各种需求都覆盖了。

典型使用场景包括：接口联调时把生产请求临时指到测试环境、Mock 后端还没上线的响应、改请求参数测试边界条件、模拟弱网看 App 表现、手机 App 抓包定位问题等等。无论你是客户端开发者、测试工程师，还是需要排查网络问题的开发者，Reqable 都能派上用场。

与不少同类工具不同的是，Reqable 的桌面端和移动端并不是各自独立的——手机端进入调试模式后，电脑端会自动协同，手机上发出的每一个请求都会实时出现在桌面端的调试列表里，这时候重写、断点、脚本这些深度调试能力就都能用上了。Android 端甚至能拿到流量所属的应用信息，配合过滤器可以快速只看某一个 App 的请求。

## 🔧 安装步骤

桌面端安装比较直接，下载安装包后双击运行即可。Windows 用户如果遇到杀毒软件误报，建议在官方渠道确认下载来源后加入白名单；macOS 用户首次打开可能需要在「系统设置 → 隐私与安全性」中允许应用运行。

> [!WARNING]
> 安装完成后建议先核对版本号——不同版本的功能入口可能有差异，本指南基于当前主流版本编写。

移动端安装：Android 从应用商店直接安装，如果从其他渠道下载 APK，安装时需要允许"未知来源"授权；iOS 同样从 App Store 获取，首次启动时需要授予 VPN 权限（Reqable 利用本地 VPN 来拦截流量）。

> [!TIP]
> 移动端正常使用前还需要安装根证书，否则 HTTPS 请求无法解密。桌面端首次启动时会引导证书安装，移动端在协同模式下可以自动同步电脑端证书，省去手动配置的麻烦。

装完之后可以做一个快速验证：打开 Reqable，随便访问一个网页，如果调试列表里出现了请求记录，说明抓包链路已经通了。

## 📖 使用入门

### 流量调试的四种核心手段

Reqable 的调试能力集中在四个功能上：**重写、断点、脚本、弱网模拟**。其中前三个都是改流量，区别在于自动化程度和灵活度不同。

**重写**是最常用的，通过预设规则自动修改请求或响应，开启快捷键 `Shift + Control + K`。它提供五种模式，分工明确：

| 模式 | 作用 | 典型场景 |
|---|---|---|
| 重定向 | 把请求 A 的响应替换为请求 B 的结果 | 接口环境切换、临时指向测试环境 |
| 替换请求 | 整体替换请求方法、路径、请求头、请求体 | 构造固定请求反复测试 |
| 替换响应 | 整体替换响应状态、响应头、响应体 | Mock 固定响应 |
| 修改请求 | 细粒度修改请求的某一部分（参数、头、体） | 只改某个参数值 |
| 修改响应 | 细粒度修改响应的某一部分 | 只改响应里的某个字段 |

优先级方面需要记住一条：**重定向 > 替换 > 修改**。同一个请求同时命中多类规则时按这个顺序执行，而且替换和修改规则匹配的是重定向后的新 URL，不是原始请求。

**断点**与重写的区别在于时机——重写按预设自动跑，断点则是在请求或响应经过时**暂停下来**，让你实时查看、手动修改后再放行，适合每次修改内容都不一样的场景。开启快捷键 `Shift + Control + B`，命中断点后会弹出执行器界面，改完提交即可。使用时有两个注意点：客户端或服务器断开连接后断点自动失效，所以命中断点后尽快处理；每个断点请求占用一个独立线程，大量并发场景请改用重写或脚本。

**脚本**是最灵活的方式，用 Python3 语法编写。它提供两个入口函数：`onRequest` 在请求发出前调用，`onResponse` 在响应回到客户端前调用。两个函数分别运行在不同进程中，不能直接共享外部变量，需要传递数据时通过 `context.shared` 实现。返回 `None` 可以中断请求或响应。脚本 API 提供了对请求/响应各部分的读写能力（URL、头部、体、状态等），规则匹配模式尽量写窄，避免误伤无关流量。

> [!NOTE]
> 移动端不提供重写和断点功能，需要在桌面端操作。脚本同样只能在桌面端运行。

### 手机电脑协同抓包

设备连好、证书就位之后，流量转发本身只要一个按钮。手机端点击右下角的**调试按钮**，允许通知和 VPN 服务，进入调试状态。此时电脑端 Reqable 会**自动**进入调试状态，手机上任何 App 发出的网络请求都会实时出现在电脑端的调试列表里。

流量到了电脑端，后续的操作就和调试电脑流量完全一致了：按域名浏览、用过滤器聚焦目标 App 的请求、用重写/断点/脚本改流量、用弱网模拟测 App 的弱网表现。

流量没出现时按这个检查清单过一遍：

1. 手机与电脑在**同一局域网**
2. 手机证书安装成功（协同模式会自动同步电脑端证书）
3. 电脑防火墙放行了 Reqable 端口
4. 移动端增强模式已启用

用完记得关闭调试按钮，恢复正常网络。
