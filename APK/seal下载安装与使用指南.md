## ✨ Seal 是什么

Seal 是一款开源的安卓视频下载工具，底层基于 yt-dlp 引擎，把命令行里强大的媒体抓取能力搬到了手机端。它的核心思路很简单：粘贴一个视频链接，选好格式和画质，Seal 帮你把文件存到本地，还能自动写入元数据标签和封面图。

从版本演进看，v1.10 系列奠定了格式选择、字幕、Cookie、自定义命令、代理等基础能力，v1.11 起又陆续补上了 SponsorBlock 跳过赞助商片段、自定义输出模板命名、下载归档去重、多音轨合并等进阶功能，v1.12 之后这些能力被保留并持续打磨。当前版本已经覆盖了从 YouTube、Bilibili 到各类中小型视频站的主流场景。

Seal 面向的用户画像比较明确：不想在电脑前开浏览器找下载工具、希望在手机上直接完成视频抓取和离线观看的人；需要保存音频并自动带上标题、艺术家、封面等标签的音乐爱好者；习惯了 yt-dlp 但嫌命令行麻烦的轻量玩家。它不追求全平台覆盖（目前只有安卓端），但在单平台上的功能密度和可定制程度已经相当高。

## 🔧 安装步骤

### 安装前的准备工作

Seal 对设备的要求很低：Android 5.0（API 21）及以上版本即可运行，应用本体约 45MB，再加上你下载的视频文件预留存储空间就够了。安装方式是标准的 APK 侧载，需要允许安装来自文件管理器或网盘客户端的未知应用。

### 分发渠道与签名注意

Seal 有两个主要分发渠道，这点必须提前说清楚：

| 渠道 | 签名者 | 构建方式 | 更新频率 |
|---|---|---|---|
| F-Droid | F-Droid 官方 | 公开源码在 CI 里重新构建并签名 | 略慢，通常比 GitHub 晚几周 |
| GitHub Release | JunkFood02（开发者本人） | 用开发者自己的签名密钥构建 | 版本最新，Release 说明详细 |

> [!WARNING]
> **两个渠道签名不同，不能互相覆盖安装。** 如果手机里已经装了 F-Droid 版，想用 GitHub 版必须先卸载旧版。卸载前务必打开 Seal 的下载记录页面，使用"导出历史"功能把记录存成 JSON 文件备份——卸载会清除应用数据目录，里面有你的下载历史、Cookie 数据库、自定义命令模板等。

### 四步安装流程

1. **下载 APK**：拿到安装包后用文件管理器找到它，APK 文件名以 `.apk` 结尾。普通现代手机推荐选 `arm64-v8a` 架构，老款 32 位手机选 `armeabi-v7a`，模拟器用户选 `x86_64`。F-Droid 客户端会自动匹配架构，不用手动选。

2. **允许未知应用**：点击安装时系统会弹出禁止安装未知应用的提示，弹窗里通常有"设置"入口，进入后勾选允许"来自此来源的应用"（指你当前打开 APK 的应用，比如文件管理器或网盘客户端）。装完后建议把这个授权关闭，保持系统默认安全习惯。

3. **完成安装**：系统验证签名后自动解压，几秒钟就完成。如果突然提示"解析包错误"或"安装包损坏"，通常是下载不完整——删掉手机上的残缺 APK，重新从源下载一份再试。

4. **首次打开授权**：第一次打开 Seal 时会请求两个关键权限：

| 权限 | 用途 | 建议 |
|---|---|---|
| 存储访问（MANAGE_EXTERNAL_STORAGE） | 下载的文件要写入手机存储 | 必须允许，否则下载后文件找不到 |
| 通知（POST_NOTIFICATIONS） | 下载进度和完成时发通知 | 建议允许，方便后台下载时及时知晓完成状态 |

### 安装问题排查

| 问题 | 解法 |
|---|---|
| 签名冲突提示「应用未安装」 | 卸载旧版本再装新来源的版本，卸载前记得导出下载历史 |
| 解析包错误 / 安装包损坏 | 检查文件大小是否完整，删除残缺 APK 后重新下载 |
| 存储权限不生效 | 到系统设置 → 应用 → Seal → 权限里手动打开存储访问 |
| 安装完打不开 | 可能是 arm64 设备误选了 armeabi 的包，换正确架构重下 |

## 📖 使用入门

### 基础下载流程

第一次打开 Seal 看到的就是主界面——一个链接输入框加上格式选择区域。把视频页面的 URL 粘进去，Seal 会自动调用 yt-dlp 引擎解析，返回可用的画质和音轨供你选择。点击下载按钮后，文件会写入你授权的存储目录，同时 Seal 在通知栏显示下载进度。

下载完成后系统会发通知提示，同时 Seal 自动做两件事：一是 ffmpeg 合并视频流和音频流，二是 mutagen 库写入元数据标签。你在手机自带播放器或音乐 App 里打开刚下载的文件，应该能看到视频标题、上传者名字、封面图这些信息已经自动填好了。

### 格式选择与字幕处理

Seal 的格式选择界面会列出解析到的所有可用流，分辨率从 360p 到 8K 不等，编码格式涵盖 H.264、H.265、VP9 等。如果你知道设备的解码能力，可以直接选对应编码——比如硬件不支持 AV1 的设备，Seal v1.11.2 起会自动偏好 VP9 编码的流。

字幕方面，Seal v1.11.0 开始把字幕选择独立成对话框，每条字幕同时显示语言名称和语言代码（中文 / zh-Hans、English / en、日本語 / ja），自动翻译生成的字幕也会出现在列表里。你可以多选，Seal 会把多条字幕轨嵌入同一个视频文件。

### 元数据自动写入的工作原理

下载完成后，Seal 调用 mutagen 库依次写入四项元数据：

| 元数据字段 | 来源 | 写入时机 |
|---|---|---|
| Title（标题） | 视频标题 | 下载完成后立即写入 |
| Artist（艺术家） | 上传者或频道名 | 同上 |
| Album（专辑） | 播放列表标题（v1.12.0 起） | 下载的是播放列表视频时才写入 |
| AlbumArt（封面） | 视频缩略图 | 默认开启，可在设置里关闭 |

mutagen 是 Python 生态里最成熟的音频元数据库，Seal 继承了 yt-dlp 对它的集成，不需要额外引入其他库。它支持 MP3 的 ID3v2.4、AAC/M4A 的 MP4 原子标签、FLAC 的 Vorbis Comment、Opus 的 Ogg Vorbis 等几乎所有主流格式。少数播放器不显示封面、或者中文标题乱码，通常是播放器本身对 Unicode 标签的支持问题，不是 Seal 的写入问题。

### 进阶功能速览

**自定义输出模板**：v1.11.0 起引入了 yt-dlp 的 `-o` 输出模板选项，默认模板是 `%(title)s.%(ext)s`。你可以用 yt-dlp 的占位符语法自定义文件命名，比如 `%(uploader)s - %(title)s [%(resolution)s].%(ext)s` 会生成"频道名 - 视频标题 [1080p].mp4"这样的文件名。v1.11.1 又补充了 `%(playlist_title)s`（播放列表标题）和 `--restrict-filenames`（跨平台文件名安全化）两个增强项。

**下载归档去重**：同样在 v1.11.0 加入，Seal 会把已下载文件记录到一个本地归档里，下次解析同一视频时自动跳过，避免重复下载。这个功能底层依赖 yt-dlp 的 `--download-archive` 选项。

**SponsorBlock 集成**：Seal 自己不实现 SponsorBlock 的逻辑，而是在格式选择界面加上可勾选的类别 chips（跳过赞助商片段、自我宣传、互动提示等），勾选后把参数透传给 yt-dlp 执行。下载的视频会自动去掉你勾选的那几类片段。

**Cookie 导入导出**：如果你需要下载需要登录才能看的内容，Seal 支持从文本文件导入 Cookie（Netscape 格式）。v1.11.0 起还能反向导出——把 Seal 里积累的 Cookie 导出给其他 yt-dlp GUI 或命令行工具复用。

**多音轨合并**：v1.11.3 新增的功能。如果视频本身有多个音轨（比如主音轨 + 旁白音轨），Seal 可以把它们合并成一个音轨文件，适合下载纪录片、教程这类有多语言配音的内容。

**蜂窝临时下载**：Seal 默认只在 Wi-Fi 下下载以避免超流量，v1.11.3 起允许临时开启蜂窝下载，适合在路上急需下一段视频的场景。

### 常见问题处理

**Cookie 数据库损坏**：如果 Seal 突然报 Cookie 相关错误，可以在应用设置里找到清除 Cookie 的选项，清掉后重新导入或重新登录对应平台。

**IPv6 连接问题**：某些设备的 IPv6 网络不稳定，v1.11.2 起提供了 IPv4 强制选项，开启后所有网络连接走 IPv4。

**系统语言独立设置**：Android 13+ 设备上，Seal 可以在应用内单独设置语言，不跟随系统语言切换。这个选项同样在 v1.11.2 引入。
