## ✨ PingTools 是什么

PingTools 是一款专为 Android 打造的网络诊断工具箱，把 Ping、Traceroute、端口扫描、iPerf 测速、Wi-Fi 分析、流量统计、DNS 查询这些日常排查网络问题需要用到的工具，全部塞进了一个几十 MB 的轻量应用里。

它的定位很明确——不是给专业网络工程师用的重型装备，而是给普通用户和轻度技术爱好者准备的「口袋里的网络诊断台」。家里 Wi-Fi 忽然卡了、怀疑被蹭网、想测一下蜂窝网络的真实带宽、Ping 某个域名看是不是自己的问题……这些场景不用再开电脑、不用跑命令行，掏出手机打开 PingTools 就能搞定。

核心能力可以粗略分成几组：基础连通性（Ping、Traceroute）、带宽测量（Speed Test、iPerf 客户端和服务端）、局域网分析（Wi-Fi Scanner、局域网设备扫描、端口扫描）、流量监控（Network usage 按应用统计上传下载）、DNS 诊断（DNS 查询、反向 DNS）。每组工具都是独立的 Tab，点开即用，配置项不多。

和同类应用比起来，PingTools 有两个明显优势：一是**完整的 iPerf3 支持**——既能当客户端连远端服务器，也能自己起 Server 让别人来测，这在 Android 上并不常见；二是**界面直白**，参数默认值就够用，不需要先读一晚上文档才能上手。

## 🔧 安装步骤

PingTools 是 Android 专属应用，APK 安装流程和大多数第三方应用没有区别，但有几个注意点值得提前了解。

### 版本核对

安装前先确认两件事：**一是当前设备架构**（arm64-v8a 还是 armeabi-v7a），二是**Android 版本**。PingTools 对系统版本有最低要求，老版本 Android 可能会在安装时提示「解析包时出现问题」。下载页上一般会标注每个 APK 对应的架构和最低系统版本，对照自己的设备选就行。

> [!TIP]
> 如果你手头只有通用 APK，装完后可以进应用的 **About** 页面核对版本号是否和下载页一致。某些第三方下载站会把旧版 APK 标记成最新版。

### 未知来源授权

从应用商店以外的渠道安装，Android 会拦截一次。不同版本 Android 授权路径略有差异：

1. **Android 8.0 及以上**：在浏览器或文件管理器里点 APK，系统会弹出「允许此应用安装未知来源应用」的跳转页，找到 PingTools 并打开开关即可。
2. **Android 7.0 及以下**：设置 → 安全 → 未知来源，把开关打开后再回到安装包点击安装。

### 首次启动后的权限授予

PingTools 首次启动后，会在你**第一次点开对应功能时**才请求权限，而不是一上来就把所有权限弹窗糊你脸上——这点做得比较克制。你需要留意以下几个功能对应的权限：

| 功能 | 需要的权限 | 什么时候要给 |
|---|---|---|
| Wi-Fi Scanner | 位置信息 | 打开 Wi-Fi 扫描 Tab 时 |
| Network usage | 使用情况访问 | 打开流量统计 Tab 时，需跳到系统设置手动开 |
| iPerf Server | 后台运行 | 首次启动 Server 时，建议允许自启动防被系统杀 |

> [!WARNING]
> **使用情况访问权限**（Usage Access）不会在应用内弹窗授予——点了开关后会跳转到 Android 系统设置的「特殊应用权限 → 使用情况访问」页面，找到 PingTools 手动打开。某些手机的省电模式会周期性收回这个权限，发现流量统计突然不刷新了，先回这个设置页确认开关还在不在。

### 装完核对

全部装完后，建议先打开 Wi-Fi Scanner 和 Ping 各跑一次，确认核心功能正常：

- Wi-Fi Scanner 能看到周围的 SSID 列表和信号强度
- Ping 任意公共 DNS（比如 114.114.114.114）能返回延迟数据

## 📖 功能拆解与使用技巧

PingTools 的功能多，但并不是每个都需要深入研究。下面挑几个日常用得最多、也最容易踩坑的功能展开说。

### Network usage：谁在偷偷跑流量

Info 面板底部的 Network usage 区域，是按应用维度的流量统计——这一点比 Android 自带的流量统计有用得多。系统自带的只能看本月累计、只区分 Wi-Fi / 蜂窝，而 PingTools 会把每个应用的上传和下载量拆开展示，还能随时刷新看到最新值，不用等月底。

看数据有两种视图：条形图模式把下载量放左边、上传量放右边，横轴是数据量大小；列表模式每个应用一行，直接显示「下载 X MB / 上传 Y MB」。点某个应用还能跳转到详情页。

典型场景：蜂窝流量快用完了，打开看一眼哪个应用在后台偷偷同步大文件，直接关掉它的后台数据权限；怀疑路由器被蹭网，Wi-Fi Scanner 能帮你找到陌生设备，Network usage 可以间接佐证——突然出现大量不明下载，大概率有问题；做流量管控测试，给自己限速前后看对比，验证限制规则是否生效。

### iPerf 连接失败排查：区分两种报错

iPerf 是客户端-服务器模型，两端都要有进程。最常见的新手错误就是只开了客户端、忘了开服务端。PingTools 的 iPerf 功能既能当客户端（Client Tab），也能当服务端（Server Tab），Server 页点 START 就能起一个监听在默认 5201 端口的服务。

连不上服务器时报错分两类，**排查方向完全不同**：

- **Connection refused**：TCP 握手成功但目标端口没人监听——主机可达、服务没开。常见原因：服务器根本没跑 iPerf Server、服务器改了端口但客户端没同步、同一台服务器上开了多个 iPerf 实例互相冲突。
- **Connection timed out**：TCP 连接尝试超时——根本到不了目标主机。常见原因：防火墙或安全组拦了 5201 端口、服务器在内网没做端口转发、服务器只监听了 IPv6 或回环地址。

排查时可以和 Ping、Traceroute 结合：iPerf 超时但 Ping 通，说明 ICMP 可达但 TCP 5201 被防火墙拦了；iPerf 超时且 Ping 也不通，那就是网络层问题——目标主机不可达、运营商封锁、NAT 没转发。

> [!NOTE]
> iPerf Server 默认监听 5201 端口，启动前确保防火墙放通了这个端口的入站 TCP。如果是在家里 NAS 上跑，公网测带宽需要路由器做端口转发，把外部 5201 映射到 NAS 的 5201。

### Wi-Fi 信道选择：找一个不拥挤的频段

2.4 GHz 频段有 14 个信道，常用 1–11，每个信道占约 22 MHz 带宽。只有 **1、6、11** 三个信道是完全不重叠的（间隔 5 个信道），其他相邻信道之间都会产生干扰。5 GHz 信道更多（约 25 个），间距更大，基本不存在拥挤问题。

PingTools 的 Wi-Fi Scanner 有三个 Tab：LIST 展示附近所有 SSID 的详细信息，GRAPH 2.4 GHz 和 GRAPH 5 GHz 分别用柱状图展示每个信道上有多少个 AP、信号强度如何。

选信道的三步法：

1. **看 GRAPH 2.4 GHz**，在 1、6、11 三个位置找山峰最少、最低的那个。
2. 如果首选都被占满了，选和最强邻居相差 ≥4 信道的那个。
3. 如果路由器支持双频，**优先让设备连 5 GHz**——GRAPH 5 GHz 里几乎不会看到拥挤，随便挑一个都行。

改完路由器信道后，手机断开 Wi-Fi 重连，回到 Wi-Fi Scanner 确认自己的 AP 已经移动到了新信道位置，再用 Speed Test 或 iPerf 测一下实际带宽有没有提升。

| 策略 | 2.4 GHz | 5 GHz |
|---|---|---|
| 首选 | 1、6、11 中最空的 | 36、40、44、149、153、157、161、165 中任意 |
| 次选 | 若首选都满，选和最强邻居相差 ≥4 信道 | 5 GHz 信道间距够大，基本不存在拥挤 |
| 不推荐 | 2、3、4、5、7、8、9、10 | 100–144（DFS 信道，路由器可能自动跳频） |

### 结果分享：三种方式按需选

排查完网络问题，经常需要把结果发给别人看——帮朋友看 Wi-Fi 问题、提交工单给运营商、汇报给领导。PingTools 内置了 Share 和 Export 两个功能，前者是即时发送、后者是保存文件，两者的适用场景不同。

三种分享方式：

1. **分享文本**：结果页右上角菜单 → Share text，触发 Android 系统分享面板。分享出去的是格式化好的纯文本，包含目标主机、测试模式、汇总统计（平均延迟、丢包率、总时长）和逐条详细记录。接收方**不需要装任何应用**，直接看文本就能理解。
2. **分享截图**：适合视觉效果比文字好的时候——Traceroute 的路由地图、iPerf 的进度条，截成 PNG 发出去一目了然。
3. **分享 CSV**：如果对方也是技术人员且需要做数据分析，直接把 CSV 文件分享过去，方便导入 Excel 或其他工具处理。

### 隐私注意

PingTools 分享的文本和截图里可能包含敏感信息：公网 IP 地址、局域网 IP 段、设备 MAC 地址、域名和 DNS 记录。在公开发送（工单、公开论坛）前，考虑要不要打码这些信息。
