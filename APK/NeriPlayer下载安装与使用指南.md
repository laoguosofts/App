## ✨ NeriPlayer 是什么

NeriPlayer 是一款面向 Android 平台的开源音乐播放器，主打多平台音源聚合、本地管理与离线缓存。它的核心定位很明确——一个应用搞定 YouTube、Bilibili、网易云等平台的在线播放与下载，同时提供完整的本地音乐库管理能力。

不同于市面上大多数播放器要么偏在线流媒体、要么偏本地文件管理，NeriPlayer 的设计思路是**两者并重**：在线音源可以直接搜索、播放、一键下载到本地，下载完成后自动进入本地曲库，和自己导入的 MP3/FLAC 文件放在一起统一管理。对于经常在多个音乐平台之间切换的用户来说，这一点尤其实用——收藏一次，离线永久可用。

功能层面上，NeriPlayer 覆盖了几个常见场景：歌单管理、搜索、歌词显示、下载恢复、车载播放、统计同步。它还内置了一个开发者模式，供高级用户排查问题或调试网络环境。

## 🔧 安装步骤

NeriPlayer 目前主要面向 Android 平台，安装流程和大多数第三方 APK 类似，但有几个细节值得注意。

### 从 APK 安装

1. **获取安装包**：从官方下载页面下载最新版 APK 文件到手机或电脑
2. **传输到手机**：如果下载到电脑，用数据线或云盘把 APK 传到手机
3. **允许未知来源**：Android 8.0+ 需要对浏览器或文件管理器单独授权「安装未知应用」权限，旧版本则在系统设置的安全项里开启未知来源安装
4. **点击安装**：在文件管理器里找到 APK，点击确认安装即可

> [!WARNING] **安装来源要靠谱**
> 尽量从官方渠道下载 APK。第三方应用市场可能存在版本滞后或签名不一致的情况，安装前建议核对应用签名和开发者信息。

### 安装完成后的初次启动

首次打开应用会进入引导流程，需要你做几件事：

- **同意隐私协议**：确认数据收集范围
- **授予存储权限**：这是本地音乐管理和下载功能的基础
- **选择默认下载目录**：应用会提示你是否使用内部管理目录还是自定义目录，这个选择影响后期下载文件的存储位置

> [!NOTE] **不要跳过引导**
> 引导流程里授权不完整会导致后续功能异常，比如下载完成后文件找不到、本地曲库扫描为空等。如果跳过了，去系统设置的应用权限里手动补齐也可以。

### DEBUG 构建说明

NeriPlayer 提供 DEBUG 和 Release 两种构建：

| 构建类型 | 图标特征 | 应用名 | 数据隔离 |
| --- | --- | --- | --- |
| Release | 标准图标 | NeriPlayer | 正常使用 |
| DEBUG | 橙色图标 | NeriPlayer DEBUG | 与 Release 数据完全独立 |

如果两个版本共存，它们的应用数据互不影响，甚至「一起听」的深链也用不同的 scheme 来区分，避免误打开。普通用户直接用 Release 版本即可。

## 📖 使用入门

### 本地音乐管理与下载目录迁移

NeriPlayer 的下载文件默认保存在应用的内部管理目录——这个目录不需要额外权限，由 Android 系统自动管理，卸载应用时会一并清理。但如果你希望下载的歌曲能被其他播放器访问，或者需要在文件管理器里直接操作，就可以切换到自定义目录。

切换目录的方式是通过 SAF（Storage Access Framework）：应用调用系统的目录选择器，你选好目标文件夹后，系统会授予持久读写权限，之后所有下载都会落到新目录。

> [!TIP] **切换目录 = 整批迁移，不是改路径**
> 很多用户以为切换目录只是把新文件存到新位置，旧文件还留在原地。实际上 NeriPlayer 会**自动迁移已有的全部下载文件**——包括音频、歌词、封面和元数据索引——全部搬到新目录，然后清空旧目录。所以切换前要确认存储空间够用。

自定义目录下还支持**文件名模板**，比如 `{artist} - {title}` 会生成「周杰伦 - 稻香」这样的文件名，`{album}/{artist} - {title}` 则自动按专辑分目录。模板只对新下载的歌曲生效，已经下载的文件不会被重命名。

出于性能考虑，**不建议频繁切换 SAF 目录**。每次切换都触发整批文件复制，如果只是想临时测试，用内部管理目录更轻便。

### 流量统计：四维记录帮你看清消费

在线播放和下载都在消耗流量，NeriPlayer 的 TrafficStatsRepository 把这个问题拆成了两个维度：

**流量类型轴**区分了**播放流量**和**下载流量**——你在线听一首歌用了多少、下载到本地花了多少，分开记账。

**网络类型轴**区分了 **Wi-Fi / 移动网络 / 漫游** 三种场景。把这两个轴交叉起来看，统计页能告诉你「在移动网络上用了多少播放流量」、「在漫游状态下下载了多少 MB」这类精确信息。

统计里还有一个有意思的指标：**缓存命中次数**。从本地缓存读取音频时，这部分不计入播放流量，但缓存命中率会被单独展示出来。命中率越高，说明你的缓存策略越有效，在线流量越省。

#### 高风险下载提示

这是一个很多用户都没注意到但很实用的细节：在**移动网络**或**漫游**状态下下载时，应用会主动弹出确认提示，需要你确认后才真正开始下载。批量下载和单曲下载都同样触发。这个提示不是硬性阻止，而是在用户没注意自己正在用移动网络时给出知情权——毕竟漫游下载几十 MB 的流量费可能比一首歌的价值还高。

### 车载播放：三种场景的能力边界

开车听歌的需求越来越普遍，NeriPlayer 在车载场景上做了三个层面的适配：

| 场景 | 控制能力 | 浏览能力 |
| --- | --- | --- |
| 普通蓝牙 | 播放/暂停/上下曲 | 仅当前队列 |
| 支持浏览的 AVRCP 车机 | 完整控制 | 本地歌单、最近播放、离线歌曲、已有曲库搜索 |
| Android Auto | Android Auto 自己渲染界面 | 由 Android Auto 平台决定 |

连接方式很简单——用蓝牙把手机和车机配对，手机上打开 NeriPlayer 播放音乐，车机会自动识别并显示媒体信息。

#### 蓝牙媒体会话发布

NeriPlayer 向蓝牙媒体会话发布以下信息：歌名、歌手、专辑、时长、曲序、封面。每次切歌时这些信息会实时更新，车机的媒体界面会同步刷新。

#### 歌词传输的小技巧

AVRCP 协议本身没有独立的歌词字段，但 NeriPlayer 巧妙地**借用标题区域传输歌词**——每次歌词行更新时，把当前歌词行写入 AVRCP 的标题字段。车机如果支持动态标题显示，就能看到滚动的歌词；不支持的话，标题区域正常显示歌名和歌手。

在设置的「歌词设置」里可以调整蓝牙车载显示模式：

- **歌曲信息优先**：只传歌名/歌手/专辑，不传输歌词
- **歌曲与歌词**：同时显示，默认选项
- **原有歌词兼容模式**：旧版兼容模式，适配一些老车机

### 开发者模式：连续点击版本号 7 次

在设置页底部连续点击**版本号 7 次**，底栏会出现一个独立的 Debug 页面。这是一个完整的调试工具箱，包含：

| 探针 | 能看到什么 |
| --- | --- |
| YouTube 探针 | 当前 Cookie、PoToken、player.js 状态、会话信息 |
| Bili 探针 | Cookie、鉴权状态、WBI 签名信息 |
| Netease 探针 | 登录状态、会话 Cookie、最近 API 响应 |
| Search 探针 | 搜索管理器当前状态、缓存命中、队列 |
| Listen Together 探针 | 一起听房间状态、WebSocket 连接、成员信息 |

还有实时**普通日志**和**崩溃日志**查看器，方便排查 JVM 或 Native 层面的问题。

> [!NOTE] **普通使用不需要开发者模式**
> 这个功能是给开发者和高级用户排查网络环境、登录异常、播放故障用的。如果你遇到某个平台突然无法播放，可以先进开发者模式看一下对应探针的状态，确认是不是 Cookie 过期或鉴权失效。

除了实时日志查看器，应用还支持**持久文件日志**——在开发者模式外也可以开启，日志写入应用内部文件，便于复现疑难问题后统一导出分析。
