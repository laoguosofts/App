## ✨ Miracast 是什么

Miracast 是 Android 系统内置的无线投屏协议，核心思路是通过 Wi-Fi Direct 在手机与电视之间建立点对点链路，把手机屏幕上的任何内容——视频、游戏、文档演示、浏览器——实时镜像到大屏上。与传统的 DLNA 只支持推送视频文件不同，Miracast 是完整的屏幕镜像，手机上看到什么，电视上就显示什么。

这个协议从 Android 4.2 开始成为系统原生能力，大多数中高端安卓手机和智能电视都自带接收端，不需要在电视上额外安装任何 App，零门槛就能用。日常场景比如手机里的本地视频投去客厅电视看、开会时把手机上的 PDF 文档镜像到会议室大屏演示、躺在床上刷视频嫌手机屏幕太小想开大屏，都是 Miracast 的典型用武之地。

它的优势在于通用性：只要两端硬件支持 Wi-Fi Direct，同网络下就能互相发现；缺点是受 WiFi 环境影响大，链路质量直接决定了画质与流畅度。对不想折腾专用投屏器、又偶尔需要大屏显示的用户来说，Miracast 是成本最低的方案。

## 🔧 安装与权限检查

从应用商店或下载页拿到安装包后，安装过程与普通安卓应用一致。但有两个值得注意的地方。

**一是权限确认**。这款应用申请的核心权限全部围绕 WiFi 与投屏保活，逐条看下来：

| 权限 | 用途 | 是否投屏必需 |
| --- | --- | --- |
| 查看 WiFi 状态 | 判断网络可用、发现同网设备 | ✅ 是 |
| 修改 WiFi 状态 | 建立 Wi-Fi Direct 点对点连接 | ✅ 是 |
| 前台服务 | 投屏长时间运行不被系统杀掉 | ✅ 是 |
| 保持唤醒 | 防止屏幕熄灭导致镜像中断 | ✅ 是 |
| 网络访问 | 商店统计与在线能力 | 常规权限 |
| 广告标识 | 广告投放归因（免费版） | 可通过内购去掉 |

> [!NOTE]
> 对照这份清单可以判断应用的「本分程度」——如果安装时看到索要联系人、短信、存储批量扫描这类与投屏无关的敏感权限，应当提高警惕并核验安装包来源是否可信。

**二是版本核对**。下载完成后可以在应用内关于页面查看当前版本号，去下载页比对一下是否为最新版本。个别老版本在部分电视型号上握手有兼容性问题，保持最新通常能减少这类故障。

装好之后先别急着用，确保手机已连接到和电视相同的 WiFi 网络，这是后续一切步骤的前提。

## 📖 连接、画质与卡顿优化实战

### 电视端先进入接收状态

多数电视的投屏接收不是常开服务——你不进到那个页面，电视就不广播，谁也搜不到它。这也是很多人第一次投屏搜不到设备的最常见原因。

各品牌电视的开启路径速查：

| 品牌/系统 | 操作路径 |
| --- | --- |
| 小米电视/盒子 | 设置 → 无线投屏（老型号遥控器信号源键选 Miracast） |
| 索尼电视 | 设置 → 网络 → 屏幕镜像，或遥控器输入源选 Screen mirroring |
| 三星电视 | 设置 → 连接 → 屏幕镜像（Smart View 相关设置） |
| LG 电视 | 设置 → 网络 → Screen Share / Miracast |
| 海信/康佳等 | 设置里找「多屏互动」，部分机型需同时开启 DLNA 服务 |
| Android TV | 设置 → 设备偏好设置 → Cast；个别机型另有无「无线显示」入口 |

> [!WARNING]
> 进对页面后，电视屏幕会显示「等待设备连接…」之类的待机画面，设备名也会显示在上面。普通桌面或视频播放状态下，电视并不监听投屏请求——这一点特别容易被忽略。

部分电视有超时机制，几分钟无连接自动退出待机页，长时间操作手机端时记得回头确认电视还在等待状态。

### 第一次连接操作流程

1. 打开手机上的投屏应用，会自动扫描同网络下支持 Miracast 的设备；
2. 列表里找到与电视待机页上显示的**同一设备名**，点击即可发起连接；
3. 电视端会弹出配对请求，用遥控器确认允许；
4. 握手成功后手机屏幕立即开始镜像，右上角通常会出现一个投屏状态图标。

如果这是这台手机与这台电视的第一次连接，后续会自动记住配对，下次直接连上。

### 画质发虚的现实与对策

「连是连上了，画面怎么糊糊的？」——镜像清晰度不是单一参数，而是三个环节共同决定的下限：

1. **源分辨率协商**：连接建立时两端自动协商出镜像分辨率，上限受标准（Miracast 支持 1080p 级 H.264 传输）与两端能力约束，协商结果以较低一端为准；
2. **码率随链路浮动**：WiFi 带宽紧张时编码器主动降码率保流畅，画质就让路了——这也是为什么信号差的房间「糊」、路由器旁边「清」；
3. **接收端缩放**：低分辨率画面被电视拉伸到 4K 面板显示，放大算法再损失一轮。

应用本身**没有手动画质设置项**，协商全自动。能做的优化集中在链路与源端：

- 先稳链路再谈画质：切到 5GHz WiFi、物理靠近路由器；
- 源端尽量选高清晰度档位，手机播放器里本身就在输出低分辨率的话，镜像不可能清；
- 电视端关闭动态对比度、降噪、运动补偿这类后处理算法，切回标准图像模式对比一下；
- 文字界面（文档、网页）比视频对码率敏感得多，演示场景建议提前用真实内容试投一次。

> [!TIP]
> 想要恒定 4K 高码率？镜像链路给不了——那是电视端 App 直拉流或 HDMI 线的工作范围。无线镜像的三角关系里，「稳、清、流畅」三者最多占两样，保流畅是实时传输的第一优先级。

### 卡顿延迟的三端优化

镜像卡顿的本质是**流水线来不及**：屏幕编码 → 无线传输 → 电视解码，任何一段慢了都堆帧。优化也按这三段来，经验命中率：切 5GHz > 清后台 > 关运动补偿。

**发送端（手机）：把编码资源腾出来**

- 聊天、下载、自动更新的应用全关，编码器抢不到 CPU 就是掉帧源头；
- 关闭省电模式，省电策略降频会让编码器跑不满；
- 能播 1080p 别硬播 4K，手机屏幕本身分辨率决定了镜像源帧率上限；
- 别边充边玩重负载游戏，发热降频与充电发热叠加会让帧率雪崩。

**链路端（WiFi）：带宽与干扰是两个抓手**

- 切 5GHz，带宽翻倍、干扰少一个量级，效果立竿见影；
- 手机与路由器同屋、少隔墙，信号两格以下先解决信号问题；
- 家里有人在下载、另一台设备在放 4K，镜像带宽会被挤占，建议限速或错峰；
- 微波炉、蓝牙音箱、无线鼠标与路由器保持距离，这些都会造成 2.4GHz 干扰。

**接收端（电视）：解码与显示后处理**

- 关画质后处理，运动补偿、动态对比度这类算法好看但加延迟，投屏时全关；
- 电视后台装太多应用、常驻多的话解码资源吃紧，重启一次电视清后台；
- 个别老机型的 Miracast 接收模块有性能修复，保持固件最新。

一次只改一项、投屏观察对比，才能定位到真正的瓶颈。三项做完多数卡顿场景已经有肉眼可见的改善。
