## ✨ NoActive 是什么——Android 后台进程冻结工具

NoActive 是一款面向 Android 设备的后台进程冻结工具，运行在 LSPosed 框架之上，通过内核模块实现对应用进程的主动挂起（freeze）。当你切换离开某个应用后，NoActive 可以把这个应用的所有进程推入挂起态，让它不再消耗 CPU、不再后台自启、不再偷偷联网，直到你再次打开它。

对有 Root 的 Android 用户来说，后台管理一直是个痛点——国产 ROM 的冻结方案各有差异、黑域绿色守护这类老工具停更已久、原生 Android 的后台限制又不够彻底。NoActive 走的是内核级冻结路线：通过控制 Cgroup 的 freezer 子系统或者向进程发送 SIGSTOP 信号，让被冻结的进程完全暂停执行，CPU 占用归零，同时保留内存中的现场，唤醒时无缝恢复。

核心特性包括：

- 多种冻结方式适配不同内核——V2（5.10+ 推荐）、V1（4.19 厂商定制内核）、Kill（兜底方案）、API
- 内核模块通信，冻结与唤醒的响应延迟低
- 运行列表实时监控每个应用的进程冻结状态和内存占用
- 白名单、免冻结条件配置（后台播放、常驻通知、网络传输、定位等特殊状态自动跳过）
- 一机一码付费激活，刷机后可重新审核绑定

适合有 Root 权限、追求极致后台控制能力的进阶用户。如果你只是想偶尔清理一下最近任务，那 NoActive 可能过重了——但如果你已经在折腾 LSPosed、KernelSU、Magisk 这套组合，并且被某些应用反复后台自启、偷偷唤醒困扰，NoActive 值得尝试。

## 🔧 安装步骤——从 Root 到激活

NoActive 的安装链路比普通 APK 复杂一些，因为它依赖 LSPosed 框架和内核模块两层组件。整个流程建议按以下顺序走：

### 前置条件

- **已获取 Root 权限**（Magisk / KernelSU 均可）
- **已安装 LSPosed 框架**（LSPosed 是 NoActive 运行的宿主，没有它 NoActive 无法挂载到系统进程）
- **Android 版本**：参考官方说明确认自己的系统版本兼容性

### 第一步：刷入内核模块

从下载页获取当前内核版本对应的内核模块 zip，通过 Magisk 或 KernelSU 的模块管理器刷入，重启设备。

> [!WARNING]
> 内核模块版本必须与当前内核版本匹配。如果刷入后 NoActive 主页的「内核模块」卡片长期显示问号，说明模块没有正确加载，需要检查版本是否对应、是否被其他模块冲突拦截。

### 第二步：安装 NoActive 主应用

安装 NoActive 的 APK 文件，然后打开 LSPosed 管理器，在模块列表中找到 NoActive，**勾选「系统框架」作用域**——这一步不能漏，漏了 NoActive 完全无法生效。勾选后重启设备。

### 第三步：验证模块生效

重启后打开 NoActive，主页应该能看到内核模块状态正常（不是问号）。进入运行列表，如果能看到一些应用显示「已冻结」状态，说明链路打通了。

### 第四步：激活付费版

NoActive 采用一机一码的付费模式。在激活页面输入购买时获取的激活码，激活会联网提交设备信息并完成绑定。刷机后如果设备信息识别发生变化，激活时会自动提交审核，由后台人工确认后重新激活。

> [!NOTE]
> 激活码与设备绑定，一个激活码只能在一台设备上使用。如需更换设备，需要重新购买。如果忘记激活码，可以通过官网的找回功能用购买邮箱找回。

## 📖 使用入门——从运行列表到故障排查

NoActive 的功能入口主要集中在三个地方：**运行列表**、**应用列表**、**设置页**。上手最快的路径是先盯住运行列表，确认冻结生效了，再去配置白名单和排查问题。

### 运行列表：最直观的效果验证

打开 NoActive 后首先进入的就是运行列表，它实时展示当前所有活跃应用的进程状态。每个应用条目包含：

| 字段 | 含义 |
| --- | --- |
| 进程数 | 该应用的所有活跃进程（主进程、子进程、Service 进程等）总数 |
| 冻结数 | 已成功冻结的进程数——**冻结数 > 0 才说明真正生效了** |
| 冻结方式 | 当前使用的冻结模式（V2 / V1 / Kill / API） |
| 实际内存 | RSS 物理内存占用——冻结后应该保持稳定不再增长 |

一个常用的验证动作：打开某个应用（比如浏览器）浏览几秒，然后返回桌面等 3 秒，刷新运行列表。如果浏览器的冻结数从 0 变成了一个正数，说明 NoActive 在正常工作。冻结后的应用，内存占用曲线应该是平的——如果发现某个应用冻结后内存还在涨，那说明冻结不彻底，可能有进程没被覆盖到。

### 冻结方式的选择

NoActive 支持四种冻结方式，按内核版本推荐：

| 冻结方式 | 适用场景 |
| --- | --- |
| V2 | Linux 内核 5.10+，最干净的方案，优先使用 |
| V1 | Linux 内核 4.19 厂商定制版（部分国产 ROM） |
| Kill | 兜底方案，兼容性最强但效果不如前两种彻底 |
| API | 系统 API 级别，需要特定系统版本支持 |

如果运行列表里一直没有应用显示冻结状态，或者日志里持续出现 Freeze Error，第一件事就是去设置页切换冻结方式试试看。

### 白名单与免冻结条件

不是所有应用都适合被冻结。NoActive 内置了多层豁免机制：

- **白名单**：在应用列表中给某个应用开启白名单后，它永远不会被冻结（适合通话、闹钟、输入法这类不能挂的应用）
- **后台播放**：应用正在播放音频或视频时自动跳过
- **常驻通知**：有常驻通知栏通知的应用不冻结
- **网速识别**：应用正在进行网络上传或下载时跳过
- **网络解冻**：某些应用在网络恢复时会被自动解冻

点击运行列表中的任意应用可以进入详情页，看到它当前的前台状态、后台服务、特殊标记（定位、录音、相机、VPN、备份等）。如果某个应用始终不被冻结，进详情页扫一眼就能定位是哪个豁免条件在起作用。

### 日志查看

NoActive 的日志可以输出到两个位置：

| 输出位置 | 配置值 | 查看方法 |
| --- | --- | --- |
| LSPosed 框架日志 | xposed | 打开 LSPosed 管理器，搜索 `NoActive-Log` |
| 文件日志 | file | 通过 Root 文件管理器查看 `/data/system/NoActive_*/log/current.log` |

日常使用推荐「信息」级别，反馈 BUG 或排查深度问题时切到「调试」级别。常见错误日志含义：

- **Freeze Error（偶发）**：冻结请求发出时目标进程刚好已经死亡，属于正常竞态，不用管
- **Freeze Error（持续）**：当前冻结方式不被设备内核支持，需要切换方式
- **内核模块通信超时**：内核模块没有正常加载或版本不匹配，重新刷入
- **配置解析失败**：BaseConfig.json 的 JSON 格式有误，注意不要写注释和多余逗号

### 常见故障排查

**运行列表整体无冻结状态**，按这个顺序查：

1. LSPosed 作用域有没有勾选「系统框架」——没勾的话勾上并重启
2. 内核模块卡片是不是问号——是的话重新刷入对应内核版本的模块
3. KernelSU / Magisk 模块列表里 NoActive 附加模块有没有启用
4. 切换冻结方式试试，从 V2 开始逐个试
5. 打开 LSPosed 日志搜 NoActive-Log，看有没有持续的 Freeze Error

**单个特定应用始终不被冻结**，查这几项：

1. 这个应用是不是开了白名单（绿色盾牌图标）
2. 进详情页看有没有命中后台播放、常驻通知、网速传输等豁免条件
3. 它是不是系统应用——系统应用默认在全局白名单里，需要通过 MasterConfig 的 userAppSet 强制归类为用户应用

> [!TIP]
> 如果所有冻结方式都报 Freeze Error，最后可以尝试 Kill 方式加 magiskpolicy 绕过：`magiskpolicy --live "allow system_server * process {sigstop}"`，每次开机后执行一次。这是兼容性最强的兜底方案。
