## ✨ Shield 是什么

Shield 是一款面向 Android 平台的轻量级脚本开发工具，核心思路是用 Lua 语言驱动安卓界面——原生 XML 布局在这里换成了更顺手的 Lua 表，脚本写好直接在设备上跑，界面用 `setContentView(loadlayout(...))` 一键渲染。它主打快速原型验证和小工具开发：不需要 Java/Kotlin 编译链，写 Lua 就能出 APK 级别的界面效果，对想在手机上做点什么的脚本爱好者来说门槛很低。

工具箱里自带 DEX 查看、指定类分析等模块，研究第三方应用内部结构是正当用途。但 Shield 的定位很明确——**学习用途、本地自用**，「研究」与「改编分发」之间的边界需要自己守好，别人作品的使用条款和社区规矩不能破。

## 🔧 Shield 怎么装

Shield 是 Android 平台的应用，安装前需要做两件事：确认来源可信、给文件管理器授权「安装未知应用」。

### 第一步：核对安装包

下载完成后先看文件大小和版本号，跟下载页标注的对得上再装。官方渠道的包一般会提供 MD5 校验值——如果有，下载完成后跑一遍校验，避免文件损坏或被替换。

> [!WARNING]
> 市场上流通的第三方 APK 和 Shield 自身的安装包性质完全不同：前者来源是任何上传者，完整性无保证；后者来源经过确认。不要把两者混为一谈。

### 第二步：开启未知来源

Android 8.0 之后默认禁止未知来源安装，需要手动给你用的文件管理器（比如系统自带的文件应用）授权：

1. 打开「设置」→「安全」或「应用与通知」
2. 找到「安装未知应用」或类似选项
3. 选中你正在用的那个文件管理器，开启允许

> [!TIP]
> 这个授权**只给你正在用的那一个文件管理器**，不要全局放开——全局授权等于把手机的大门敞开。

### 第三步：安装与验证

双击 APK 按提示点「安装」，完成后打开 Shield，能正常进入主界面就是装好了。如果系统弹出安全警告，回到第二步检查授权是否正确开启。

## 📖 从零开始：写第一个 Shield 脚本

装好打开 Shield，你会看到一个默认工程——`main.lua` 里已经写好了基础骨架。**最值得做的第一件事：什么都不改，直接点顶栏的三角运行按钮**。能原样跑通的骨架证明环境没问题、工程没问题，之后每次出错范围一下子缩小到你自己的代码。

### 第一次运行会发生什么

按下运行后背后依次做三件事：

1. Lua 解释器读 `main.lua`，从头执行
2. 开头几行 `import` 把安卓界面类搬进来（`LinearLayout`、`TextView` 这些）
3. 最后一行把布局表渲染成界面

正确预期是：屏幕上出现一个几乎空白的页面。别失望，这就是你的第一个程序——它跑通了完整的「脚本 → 安卓界面」链路。

### 界面布局为什么用表来写

安卓原生界面用 XML，Shield 换成了 Lua 表：**表嵌表就是控件套控件，键值对就是属性**。基本形状长这样：

```lua
layout = {
    LinearLayout,              -- 第一项：容器类型
    orientation = "vertical",  -- 属性 = 值
    layout_width = "fill",
    {
        TextView,              -- 子控件
        text = "标题",
        id = "tv",
    },
    {
        Button,
        text = "确定",
        id = "btn",
        onClick = "click",     -- 值可以写函数名、函数变量或接口对象
    },
}
```

三条核心规则：

- **第一项是控件类型**：`LinearLayout`、`TextView`、`Button` 这些名字来自 import 的安卓类
- **其余键值对是属性**：支持绝大部分安卓控件属性
- **嵌套的表是子控件**：容器里塞几个表就有几个子项

两个省事简写：`fill` / `wrap` 代替 `layout_width` 和 `layout_height` 的原始常量名；`id` 就是 Lua 变量名——`id = "tv"` 之后代码里 `tv` 直接就是那个控件，不是 XML 里的数字 id。

写完布局跑起来位置不对？先把 `orientation` 换个方向（`vertical` ↔ `horizontal`）、给控件加 `padding` 试试——多数排版问题出在容器选错。

### 运行起来后怎么退出

界面被脚本接管，回到编辑器用系统返回键或从最近任务切回。如果手滑写了死循环导致脚本卡死，从最近应用里把它划掉重开，编辑内容不会丢。

### 常见报错场景速查

跑不通的时候按症状对号入座，比盯着报错文字猜快得多：

| 症状 | 最可能原因 | 怎么查 |
| --- | --- | --- |
| 点运行毫无反应 | 停在非 `main.lua` 的文件标签上 | 切回 `main.lua` 再跑 |
| 界面出来一片空白 | 布局容器没塞子控件 / 控件色跟背景同色 | 对照补子控件；给控件加 `textColor` 或背景色 |
| `attempt to call a nil value` | 方法名拼错 / 函数定义在调用之后 | 逐字母核对拼写；Lua 顺序执行，函数放前面 |
| 按钮点了没反应 | `onClick` 没写 / 函数没定义 / 挂接失败 | 三层检查见下文 |
| 加了网络请求后卡死 | `http.get` 同步执行冻住界面 | 把请求挪进 `task` 异步线程 |

按钮点击无反应的三层检查，从外到内：

1. `onClick` 属性写了没？属性名拼写对吗？
2. 指向的函数真定义了吗？函数名一字不差吗？
3. 函数体第一行加个 `print("进来了")` 跑一次——打印出来说明事件通、问题在函数内部；没打印说明挂接失败，回第 1 层

### 排查万能套路

三板斧用完基本都能定位：

1. **撤销回退**到上一个能跑的版本
2. **逐步重做**，每步一跑
3. **拆到最小**——把出问题的代码抄进独立工程，砍到只剩问题段落单独跑

三斧用完还没定位，把完整报错文字拿去搜索——Lua 报错在社区里的覆盖率很高。

### 装第三方 APK 的三条自查清单

Shield 的市场里有第三方上传的 APK 文件，和工具自身的安装包性质完全不同。装之前想三件事：

1. **文件是不是你想要的**：文件名跟说明对得上吗？名字含糊、说明缺失的条目直接跳过。真要研究应用内部结构，用 Shield 的 DEX 查看模块就够了，不必装成品。
2. **授权范围最小了吗**：安装未知应用的授权只给你正在用的文件管理器，不全局放开。安装过程中应用要的权限逐条看——一个计算器要通讯录权限，直接取消。
3. **装完行为正常吗**：装完观察几天，频繁弹窗、后台耗电异常、莫名发短信流量——出现任何一条立刻卸载，并在主页确认包名避免再装到同一家。
