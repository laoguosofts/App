## ✨ Hamibot 是什么

Hamibot 是一款运行在 Android 设备上的自动化脚本执行工具，采用 JavaScript 作为脚本语言，通过无障碍服务和系统注入 API 实现对手机界面的模拟操作。它的核心思路是把手机当作一个可编程的"机器人"——开发者写好脚本上传到云端，手机端保持长连接随时接收指令，就能自动完成点击、滑动、查找控件等一系列操作。

适合哪些场景？大致可以分成三类：**重复操作自动化**（比如每天定时打卡、批量领取积分、自动签到）、**游戏辅助开发**（坐标触摸模拟点击、固定路径滑动、游戏内挂机流程）、**设备集群管理**（多台设备统一下发脚本、远程查看日志、批量执行任务）。不管你是想让手机替你省力气，还是想自己写个脚本练手，Hamibot 都提供了一套相对完整的基础设施。

它的架构比较清晰：手机上装 Hamibot App 负责执行，网页控制台负责管理设备和脚本分发。你写好脚本后发布到控制台，所有已配对的设备就能收到并自动运行。整个流程不需要 root 权限——Android 7.0 及以上的系统 API 已经足够支撑大部分触摸和控件操作。

## 🔧 Hamibot 安装与设备配对完整流程

安装 Hamibot 不复杂，但有几个关键步骤容易踩坑。最核心的两件事：**先把手机端 App 装起来**，**再把手机和控制台配对**。

### 第一步：手机端安装 Hamibot App

1. 通过上面的下载入口获取最新 APK，或从应用商店直接安装
2. 如果走 APK 安装包，首次安装需要在系统设置里开启「允许安装未知来源应用」
3. 安装完成后不要急着打开，先进入系统设置把 Hamibot 加到「后台白名单」——否则很容易被系统杀掉进程导致设备离线

### 第二步：注册控制台账号

Hamibot 采用"手机为被控端、网页控制台为控制端"的设计。打开 Hamibot 控制台，用邮箱或手机号注册账号并登录。控制台是后续管理设备、上传脚本、查看日志的地方。

### 第三步：在控制台生成配对码

进入控制台的「设备」页面，点击「添加设备」，页面会显示一个短字符串作为配对码。配对码是一次性的，有有效期倒计时——过期了就重新点一次生成即可。

### 第四步：手机 App 输入配对码

打开手机上的 Hamibot App，主界面上有显眼的「配对」按钮。点击后输入刚才记下的配对码，确认即可。配对过程通常几秒内完成。

### 第五步：验证配对成功

成功的标志很明确：控制台的设备列表里多出一台在线设备，同时手机 App 界面也会显示已配对的设备名称。一个账号可以配对多台设备，各自独立生成配对码、独立管理。

> [!WARNING] 配对成功但设备不在线怎么办？
> - 检查手机网络（Wi-Fi 或流量均可，只要能上网）
> - 确认 Hamibot App 没有被系统后台清理，建议把它锁定在最近任务列表中
> - 尝试关闭 App 重新打开，长连接会自动恢复

### 权限设置——容易被忽略的必做项

配对完成后，还需要在手机系统里为 Hamibot 开启以下权限：

| 权限类型 | 用途 | 没开的后果 |
| --- | --- | --- |
| 无障碍服务 | 模拟点击、查找控件 | 脚本报错立即退出 |
| 后台弹窗 | 运行时显示日志和提示 | 日志窗口看不到、调试困难 |
| 屏幕截图 | 图像识别类脚本需要 | 脚本执行到截图逻辑时报权限异常 |

> [!TIP] 建议在手机设置里搜索"无障碍"，找到 Hamibot 的入口把服务开关打开。很多脚本运行后立即退出，排查半天最后发现就是无障碍服务没开或者被系统自动关闭了。

## 📖 脚本开发与使用入门

Hamibot 上手的核心就是"看懂脚本配置 + 掌握常用 API"。下面从几个实际开发场景出发，把最常用的功能点串起来。

### 脚本参数配置——不同场景的灵活适配

很多脚本首次运行前需要填写配置项，这是脚本作者预留的"自定义入口"。比如：脚本运行速度（快速/中速/慢速）、目标小程序地址、是否开启自动退款、刷新间隔等等。

配置界面由脚本作者定义，每个脚本的配置项可能完全不同。常见类型有：

- **文本输入框**——填写小程序 AppID、商品链接、激活码等字符串
- **数字输入框**——刷新间隔（毫秒）、重试次数、设备数量等数值
- **下拉选择框**——运行速度档位、操作模式（到店取/送到家）等固定选项
- **开关按钮**——布尔功能，比如开启到货通知、启用调试模式

建议的配置流程：先看脚本介绍页的配置说明 → 按说明填写必要参数 → 试运行一次观察输出 → 根据实际效果微调。配错了可以点「重置配置」恢复默认值。

### 坐标触摸——游戏画面和非标准控件的万能方案

标准安卓界面可以用控件选择器，但遇到两种情况会失效：**游戏引擎绘制的画面**（纯像素、没有控件树）、**APP 自绘控件**（为了性能或外观自己画的按钮）。这时候就要用基于坐标的触摸操作。

#### 获取坐标的方法

在手机「开发者选项」里打开「指针位置」或「显示触摸操作」，屏幕上就会实时显示手指位置的坐标值 (x, y)。

#### 分辨率自动适配——脚本换设备也能跑

直接写死坐标的脚本换一台分辨率不同的手机，点的位置就完全错了。解决方案是 `setScreenMetrics()`——设定脚本设计时的基准分辨率，Hamibot 在实际运行时会自动按比例放缩所有坐标：

```javascript
// 基准分辨率 1080x1920
setScreenMetrics(1080, 1920);
// 下面的所有坐标都会按比例放缩
click(540, 1000);  // 在 1080x1920 上点屏幕中央
```

#### 核心触摸函数一览

| 函数 | 作用 | 典型用途 |
| --- | --- | --- |
| `click(x, y)` | 模拟点击指定坐标 | 常规点击操作，过程约 150ms |
| `longClick(x, y)` | 长按 600 毫秒 | 长按触发菜单、拖拽起始 |
| `press(x, y, duration)` | 按住指定时长（毫秒） | 快速连点、精确控制按压时间 |
| `swipe(x1, y1, x2, y2, duration)` | 从起点滑到终点 | 页面上滑、游戏内划屏 |
| `gesture(duration, ...paths)` | 单手指多路径手势 | 模拟圆弧轨迹、复杂滑动 |
| `gestures(...gestureSets)` | 多手指同时操作 | 双指捏合、多指手势 |

#### 系统版本要求

坐标触摸函数依赖 Android 7.0 及以上的系统 API 来注入事件。7.0 以下需要 root 权限（旧版 Hamibot 曾提供 RootAutomator，现已弃用）。

> [!NOTE] 状态栏 / 导航栏偏移问题
> 部分 APP 的布局会受到状态栏和导航栏的影响，取坐标时需要考虑这个偏移。如果发现点击总是差一点点，大概率是坐标基准没对齐。

#### 坐标 + 控件结合技巧

有时候控件存在但 `clickable` 属性为 false，无法直接点击。可以取它的中心点坐标用 `click()` 强行点击：

```javascript
const widget = id("some_control").findOne();
const rect = widget.bounds();
click(rect.centerX(), rect.centerY());
```

### 脚本异常排查——按步骤定位问题

脚本跑不起来是常态。遇到异常时不要盲猜，最快的方法是**打开 Hamibot App 右上角的日志图标**，查看实时输出——日志里通常有明确的错误信息。

#### 常见异常与解法

**异常 1：运行后很快提示"运行结束"**

最可能的原因是权限没开。重点检查无障碍服务是否正常、后台弹窗权限是否授予。无障碍服务经常被系统在后台杀掉，跑完记得确认一下是否还在。

**异常 2：运行后没反应也没报错**

可能的情况有三种：

| 现象 | 排查方向 |
| --- | --- |
| 完全不动 | 脚本在 `findOne()` 等待一个永远不会出现的控件，或网络请求超时 |
| 慢慢变卡 | 手机内存不足，其他 App 在抢占资源 |
| 随机卡住 | 目标 APP 本身在加载，脚本执行太快需要加 `sleep()` 等待 |

快速处理方式：控制台手动停止 → 重新运行。如果反复卡住，需要修改脚本逻辑。

**异常 3：控件找不到**

```
Error: NoSuchElementException: 找不到匹配的控件
```

APP 版本升级、界面结构调整、脚本作者写死了某个版本的控件属性，都会导致选择器匹配失败。解决步骤：远程调试打开控件树确认真实属性 → 优先用 `id()` 匹配（最稳定），其次 `text()`，最后才是 `className()` → 或联系脚本作者看有没有新版本。

**异常 4：权限异常**

```
Error: 需要屏幕截图权限
Error: 需要无障碍服务
```

建议在脚本开头加上权限检查，没权限时主动提示：

```javascript
auto.waitFor();  // 等待无障碍
if (!requestScreenCapture()) {
    toastLog('请授予屏幕截图权限');
    hamibot.exit();
}
```

#### 日志的正确用法

Hamibot 有两类日志：

- **实时日志**：App 右上角图标，实时滚动输出，调试时盯着它看
- **历史日志**：控制台设备详情页，可回溯过去的运行记录

在日志里重点找这几类信息：`Error / Exception` 开头的错误行、脚本主动或被动退出的 `Exit` 标记、权限相关提示、以及找不到控件时日志里打印的尝试匹配的选择器。

#### 跨设备批量任务——集群管理的优势

当你有多台设备时，Hamibot 的集群管理能力就体现出来了：控制台可以看到所有在线设备、同时下发脚本、分别查看每台的运行日志。这比手动一台一台操作高效得多，尤其适合需要长时间运行的自动化流程。
