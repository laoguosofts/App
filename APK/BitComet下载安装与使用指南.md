## ✨ BitComet 是什么 — 20 年老牌 BT 客户端的全能定位

BitComet，中文圈内普遍叫它"比特彗星"，是一款使用 C++ 编写的免费下载客户端，同时支持 BitTorrent、HTTP、FTP 三种主流协议。它由国内开发团队 BitComet Team 于 2004 年 8 月首次发布，至今已经持续迭代超过 20 年——在 BT 客户端这个领域里算是资历最老、迭代最稳定的几款之一。

在 BitComet 出现之前，BT 客户端主要由国外产品主导——BitTorrent 原版、Azureus（后改名 Vuze）、uTorrent 等。BitComet 作为少数几个由国内团队开发、面向全球市场的 BT 客户端，从一开始就切入了几个竞品普遍没有解决好的痛点。

最核心的几个差异化特性：

- **长效种子技术**：老种子断种、下载卡 99% 完不成？BitComet 能从已完成用户的缓存节点继续拉数据，救回了无数在其他客户端里已经被判死刑的冷门资源。
- **智能磁盘缓存**：数据暂存内存再批量写入，下载时硬盘狂转、寿命损耗大的问题被大幅缓解。
- **跨协议下载**：不仅管 BT，内嵌 HTTP/FTP 下载，甚至给 HTTP 下载也加上 P2P 加速，一个客户端覆盖多个场景。
- **内置 DHT 网络**：没有 tracker 也能发现对等节点，种子发现能力更强。
- **边下边播**：视频下载到一半就能看，优先下载头部尾部关键帧。

截至 2026 年 9 月，BitComet 最新正式版为 v2.22，官方同时维护 Windows、macOS、Linux、Android 四个平台的版本。Windows 端功能最完整，Linux 端默认是轻量的命令行守护进程，macOS 和 Android 则侧重各自平台的原生体验。版本更新节奏大约每两到三个月一个小版本，半年到一年一个大版本。

在 BT 客户端阵营里，BitComet 的位置比较特殊。和 qBittorrent 比——qBittorrent 开源、界面现代、社区口碑更好，但没有长效种子和跨协议下载；和 uTorrent 比——uTorrent 后来被收购后广告捆绑问题严重，BitComet 虽然也有捆绑但相对克制，且功能更贴合国内网络环境；和迅雷比——迅雷有商业服务器加速但现在限制多、非会员速度慢，BitComet 是纯 P2P 客户端，没有服务器端的速度限制。简单说：**需要长效种子救老资源、需要同时下 HTTP/FTP 的，选 BitComet；看重纯开源、界面简洁的，选 qBittorrent**。

BitComet 这个名字是 "Bit Torrent Comet" 的缩写——BT 彗星，意思是"像彗星一样划过互联网的下载工具"。中文社区给它起的绰号"比特彗星"是对英文原名的直译，早期版本界面也确实有一个彗星划过的 logo。值得一提的是彗星通行证（BitComet Passport）——2006 年推出的积分系统，鼓励用户下载后继续做种以获得积分解锁额外功能，在中文用户群里曾经非常流行，但近年已经不是主流使用方式了。

## 🔧 BitComet 各平台安装步骤

BitComet 官方站点提供全平台安装包，建议直接从官网下载，避免第三方站点二次打包版本可能嵌入的额外广告或捆绑软件。

### Windows 用户

Windows 端是 BitComet 功能最完整的平台，提供两种安装方式：

- **标准安装包（.exe）**：带图形界面，适合绝大多数用户。安装过程中会让你选择安装路径、是否创建桌面快捷方式、是否开机自启、是否设为默认 BT 客户端等。
- **便携版（.zip）**：解压即用，不写注册表。适合绿色安装或多版本并行测试的需求。Windows 端同时提供 32 位和 64 位版本，64 位系统建议选 64 位版本，内存寻址更高效。

> [!WARNING]
> Windows 安装向导中会出现可选的第三方组件推荐（浏览器插件、桌面工具等），这些都是可选的，不需要请直接取消勾选。BitComet 本身免费，但厂商收入一部分来自捆绑推广，不要一路"下一步"过去。

安装完成后首次启动会弹出欢迎向导：选择默认下载保存目录（建议放到非系统盘、剩余空间充足的分区）、是否开机自启、是否在系统托盘区显示图标、确认防火墙放行（BitComet 会自动请求 Windows 防火墙添加规则）。向导完成后就能看到主界面——左侧任务分类栏、中间任务列表、底部任务详情面板、顶部工具栏，默认是中文界面。

### macOS 用户

macOS 端提供 `.dmg` 安装镜像，打开后把 BitComet.app 拖进 Applications 文件夹即可。因为 BitComet 不在 Mac App Store 上架，首次运行时系统可能提示"无法验证开发者"，这是正常的。解决方法：**右键点击应用图标 → 选择"打开" → 在弹出的对话框中点"打开"**，之后就可以正常双击运行了。

首次运行时 macOS 可能要求授予"完全磁盘访问权限"——BitComet 需要在用户目录下读写下载文件。前往"系统设置 → 隐私与安全性 → 完全磁盘访问权限"，添加 BitComet.app 即可。

macOS 端功能比 Windows 端略少，没有 Internet Explorer 集成插件和一些 Windows 专属的系统级集成功能，但核心的 BT 下载、长效种子、WebUI、跨协议下载都完整可用。

### Linux 用户

Linux 端默认是命令行守护进程，不提供图形界面。官方提供 `.deb`（Debian/Ubuntu）和 `.rpm`（CentOS/RHEL）两种包管理格式。Ubuntu/Debian 用户安装方式：

```
sudo dpkg -i bitcomet_版本号_amd64.deb
```

安装完成后 BitComet 以后台服务方式运行，控制命令：

```
bitcomet start      # 启动服务
bitcomet stop       # 停止服务
bitcomet status     # 查看状态
```

WebUI 默认地址是 `http://localhost:8080`，首次访问需要设置管理员密码。Linux 端的优势是轻量、可长期后台运行，适合家庭 NAS 或 VPS 场景。

### 升级与卸载

| 平台 | 升级方式 | 卸载方式 |
| --- | --- | --- |
| Windows | 下载新版本安装包覆盖安装，配置文件和进度保留，升级前先关闭 BitComet | 控制面板 → 程序和功能 → 卸载，可选是否保留用户数据 |
| macOS | 下载新 `.dmg`，替换 Applications 中的旧版本 | 从 Applications 拖到废纸篓，`~/Library/Application Support/BitComet/` 配置需手动删除 |
| Linux | `apt upgrade bitcomet` 或 `yum update bitcomet` | `sudo dpkg -r bitcomet`，配置在 `/etc/bitcomet/` |

> [!TIP]
> 卸载前如果之后还想保留配置，BitComet 里选 **选项 → 导出配置** 可以导出成一个文件保存，下次重装后导入即可恢复。

## 📖 BitComet 使用入门 — 从基础下载到 WebUI 远程控制

### 基础下载流程

BitComet 的主界面默认左侧是任务分类栏，中间是任务列表，底部是任务详情面板。添加下载任务有几种方式：

1. **粘贴磁链或 HTTP/FTP URL**：工具栏点"新建任务"，粘贴链接确定即可。
2. **导入 torrent 文件**：工具栏点"打开 torrent 文件"，选择本地种子。
3. **浏览器关联**：如果 BitComet 已设为默认下载器，在浏览器里点击磁链或下载链接会自动弹出来。

> [!NOTE]
> 如果浏览器点击链接没反应，大概率是 BitComet 的协议关联没生效。进 **选项 → 协议关联**，手动勾选 magnet、http、https、ftp 等协议即可。浏览器插件也需要在扩展管理里确认已启用。

下载目录建议放在非系统盘、剩余空间充足的分区——BT 智能磁盘分配会在下载开始前预分配完整大小的文件，磁盘剩 10GB 但任务要下 20GB 会直接报错。如果下载目录在 FAT32 分区上，FAT32 不支持单个文件超过 4GB，需要换到 NTFS 分区。

### 长效种子救冷门资源

这是 BitComet 最有代表性的功能。很多老种子在 qBittorrent、uTorrent 里已经下到 99% 就卡住再也不动了，但用 BitComet 打开同一个种子，等一会儿就能拉到完整数据。原理是 BitComet 维护了一个长效种子节点网络——已经完成下载的用户可选继续做种，数据被缓存在这些节点上，即使原始种子服务器断了也能从缓存节点继续拉。

开启长效种子很简单：**选项 → BT → 勾选"启用长效种子"**。默认是开启的，绝大多数情况下不需要额外配置。长效种子的代价是多占一点上行带宽，但对冷门资源来说是最实用的兜底手段。

### WebUI 远程管理

WebUI 是 BitComet 内置的轻量级 Web 服务器——开启后可以在任何设备的浏览器里访问管理家里 BitComet 的所有下载任务。想象一下这个场景：你在公司用手机或电脑，突然想起家里正在下载一个大文件——想看看进度、想加一个新任务、想暂停某个太吃带宽的做种任务，用 WebUI 都能搞定，不需要远程桌面。

#### 开启步骤

**第一步：打开高级设置**

BitComet 主界面 → **选项 → 高级设置**，在搜索框输入 `webui`，按以下建议值修改配置项：

| 键名 | 默认值 | 建议值 | 说明 |
| --- | --- | --- | --- |
| `webui.enable` | false | true | 总开关 |
| `webui.port` | 18080 | 自定义（如 28080） | 监听端口，**不要用默认值** |
| `webui.username` | admin | 自定义用户名 | **不要用 admin** |
| `webui.password` | 空 | 强密码 | **必须设置**，空密码等于把下载面板给全世界看 |
| `webui.allow_remote` | false | true | 允许外网访问（只局域网用可以保持 false） |
| `webui.language` | 跟随主程序 | `zh_CN` | 显示中文界面 |

修改完成后保存，BitComet 会自动重启 WebUI 服务，不需要重启整个程序。

**第二步：防火墙与端口映射**

如果希望外网能访问 WebUI：

1. Windows 防火墙：BitComet 开启 WebUI 时会自动请求添加防火墙入站规则。如果没自动添加，手动加：新建入站规则 → TCP → 允许特定端口 → 允许 → 所有配置文件 → 命名为"BitComet WebUI"。
2. 路由器端口映射：把路由器 WAN 口的一个端口转发到电脑内网 IP 的 WebUI 端口。
3. DDNS：家用宽带 IP 通常是动态变化的，建议装一个 DDNS 服务（花生壳、阿里云 DDNS、Cloudflare Tunnel 等）给家里分配一个固定域名。

> [!TIP]
> 只在局域网用就简单多了——打开防火墙放行即可，不需要路由器端口映射和 DDNS。局域网内直接用电脑内网 IP（如 `192.168.1.105:28080`）访问。如果家用宽带是 CGNAT（运营商级 NAT），直接从公网打过来的连接会被挡住，这时用 Cloudflare Tunnel 或 VPN 绕过比端口映射靠谱得多。

**第三步：HTTPS 加密**

如果在外网访问 WebUI，**强烈建议开启 HTTPS**。明文 HTTP 意味着你的密码、控制指令、任务名都会在公网上裸奔。BitComet 自带自签名证书功能——高级设置里找到 `webui.https.enable` 设为 true，浏览器访问时会提示"证书不受信任"，这是正常的，点"高级 → 继续访问"即可。更现代的做法是用 Cloudflare Tunnel 或 frp 等工具把本地 WebUI 暴露到 HTTPS 域名下，完全免费、自带 HTTPS、不需要路由器端口映射。

**第四步：测试**

按顺序测三层连通性：

1. 本机浏览器访问 `http://127.0.0.1:端口` → 能看到登录页面 = WebUI 服务正常。
2. 局域网另一台设备访问 `http://内网IP:端口` → 能打开 = 防火墙已放行。
3. 手机关 Wi-Fi 用 4G/5G 访问 `http://公网IP:端口` → 能打开 = 端口映射和防火墙都对了。

#### WebUI 能做什么、不能做什么

WebUI 的设计目标是**轻量远程控制**，不是完整 GUI 的一比一复刻：

- ✅ 查看所有任务的实时状态（进度、速度、对等者数量）
- ✅ 添加新任务（粘贴磁链、URL、上传 torrent 文件）
- ✅ 暂停/继续/删除/重排任务优先级
- ✅ 修改单个任务的限速值
- ✅ 预览/播放正在下载的视频（调用浏览器内置播放器）
- ❌ 修改全局选项（限速、缓存、连接数等）
- ❌ 创建/管理标签
- ❌ 制作 torrent 文件
- ❌ 登录通行证或查看积分

#### WebUI 安全注意事项

- **必须设置强密码**，不要用默认的 admin/admin。
- **换默认端口**，改成随机高位端口（如 31808）。
- **外网访问一定开 HTTPS**。
- 定期检查访问日志，如果有人在暴力破解你的 WebUI，日志里会出现大量失败登录尝试。
- 如果只自己用，优先通过 VPN（WireGuard / OpenVPN）回家时顺便访问 WebUI，比直接暴露在公网安全得多。

### 常见问题排查

#### 启动闪退 / 崩溃

最常见的原因有四个，按排查顺序来：

1. **配置文件损坏**：打开配置目录（Windows 安装版在 `%APPDATA%\BitComet\`，便携版在 BitComet.exe 所在目录，macOS 在 `~/Library/Application Support/BitComet/`），把 `config.xml` 重命名为 `config.xml.bak`，启动 BitComet 让它生成新配置。能正常启动 = 旧配置损坏。
2. **后台有僵死进程**：打开任务管理器找 `BitComet.exe` 结束任务再重启。
3. **DHT 数据损坏**：在配置目录里找到 `dht.dat` 删除，启动后 DHT 会重新初始化（首次可能稍慢）。
4. **Windows 账户权限不够**：右键 BitComet.exe → 属性 → 兼容性 → 勾选"以管理员身份运行此程序"。

#### 界面空白 / 显示异常

- **显卡驱动或硬件加速问题**：**选项 → 界面外观** → 关闭硬件加速重启，正常的话就是显卡驱动和 BitComet 渲染组件不兼容，更新显卡驱动。
- **DPI/HiDPI 缩放问题**：临时把显示缩放调回 100% 看是否正常，最新版 BitComet 已支持 HiDPI，旧版本升级即可。
- **主题/语言文件损坏**：切换语言或主题试试，不行就覆盖安装。

#### 进程假死 / 无响应

主界面完全卡住、CPU 可能 0%（线程死锁）或 100%（无限循环）：

- 临时解法：Windows 任务管理器立即结束任务、macOS 用 Command+Option+Esc 强制退出、Linux 执行 `kill -9 $(pgrep bitcomet)`。
- 预防：**不要同时开太多任务**（建议同时运行 ≤ 5 个下载任务）、**降低全局连接数上限**（调到 100~150，默认 200）、**定期重启**（每周一次，避免积累内部状态异常）。

#### 写入失败 / 无法创建文件

- 磁盘空间不够（BT 会预分配完整大小）。
- 目标目录在 C:\Program Files 等系统保留目录 → 换到 D 盘。
- 文件被杀毒软件扫描或其他 BT 客户端锁定。
- FAT32 分区单文件 4GB 限制 → 换到 NTFS。

#### 终极解法：重装

如果以上都没解决，重装是最靠谱的办法——快且干净。步骤：

1. **备份配置**：**选项 → 导出配置**。
2. **正常卸载**：控制面板卸载 BitComet。
3. **清理残留**：手动删除配置目录。**如果是配置损坏导致的问题，重装时不要恢复旧配置**。
4. **重新安装**：官网下最新版、管理员身份运行、装到干净目录。

重装不会影响磁盘上已经下载好的文件——那些都在 BitComet 配置目录之外，安全。
