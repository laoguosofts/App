## ✨ HopToDesk 是什么

HopToDesk 是一款跨平台的开源远程桌面与远程支持工具，覆盖 Windows、macOS（Intel 与 Apple Silicon）、Linux、Android、FreeBSD 等主流系统。它同时提供客户端模式（主动去连接别人）和主机模式（被别人远程控制），配合内置的设备管理面板，个人用户可以快速搭建自己的远程协助链路，小团队和运维场景则可以利用面板的团队成员体系、角色权限和安全加固能力做统一管理。

HopToDesk 的定位比较清晰：它不是另一款 TeamViewer 替代品的简单复制品，而是把远程桌面、文件传输、端口转发、终端会话、屏幕查看五种常见远程操作集成在同一个连接入口里——Connect 按钮旁的下拉框一切换，这次会话是要完整控画面、传几个文件、穿透内网、开命令行还是只看不动，一次说清，不用换软件。

适合谁用呢？个人用户想远程帮家里人处理电脑问题；SOHO 或十几人小团队需要一套自己的远程支持工具，不想把设备控制权交第三方 SaaS；运维同事需要临时穿透 RDP 或数据库做调试，又懒得专门配跳板机；这些都是 HopToDesk 比较典型的使用场景。

## 🔧 各平台安装注意点

HopToDesk 的多平台支持做得比较全，但每个平台的安装方式差异不小，尤其是 macOS 和 Linux 的权限环节、安卓的两条安装渠道功能并不相同，这里集中梳理一遍。

### macOS

macOS 下载页会同时提供 **Intel 芯片**和 **Apple Silicon（M1/M2/M3）** 两种 dmg 包，装之前先确认自己机器属于哪一档。打开 dmg 后把 HopToDesk 拖进「应用程序」文件夹即可，没有便携版概念，装好就是常规应用，后台常驻由系统的 LaunchAgent 负责管理。

> [!TIP] 首次启动的权限弹窗
> macOS 首次启动 HopToDesk 会自动弹出权限引导页，列出屏幕录制和辅助功能两项必给权限——不给这两项，就既抓不了被控端的屏也发不了键鼠输入。路径是「系统设置 → 隐私与安全性 → 对应权限类别 → 打开 HopToDesk 的开关」，完成后建议重启一次应用让权限生效。

### Linux

Linux 端按发行版有几种包格式可选：

| 发行版 | 包格式 | 安装命令 |
| --- | --- | --- |
| Debian / Ubuntu 及衍生 | deb | `sudo dpkg -i hoptodesk.deb` |
| Fedora / openSUSE | rpm | `sudo rpm -i hoptodesk.rpm` |
| Manjaro / Arch 系 | zst | `pacman -U hoptodesk.pkg.tar.zst` |
| 通用（任何发行版） | AppImage / Flatpak | 直接双击或 flatpak 安装 |

安装完成后会注册一个 systemd 服务，让设备在后台持续接受连接。

> [!WARNING] Wayland 用户的无人值守设置
> Wayland 桌面下首次被连接时会弹出系统级安全询问选共享哪块屏幕，勾选「记住此选择」可以免重复询问。但如果你需要**无人值守访问**（包含登录界面、锁屏界面也能直接连），必须去被控端的「设置 → 安全」里手动打开「Unattended Wayland Access」开关，否则每次都会弹确认框。

### 安卓

安卓端有两条安装渠道，**功能并不相同**，这一点是最容易踩的坑：

| 渠道 | 主控（主动连别人） | 被控（被电脑连） |
| --- | --- | --- |
| 官方 APK 直装版 | 有 | 有（完整主机模式） |
| Google Play 商店版 | 有 | **无**（仅客户端） |

如果你的需求是「电脑远程控制手机」，必须走 APK 直装渠道——商店版因为包体限制只保留了客户端功能，装完发现手机被控不了就是这个原因。

APK 直装的步骤和大多数安卓应用一样：下载到手机 → 点开安装 → 系统提示「未知来源应用」时按品牌引导放行这一次安装（一般在安装弹窗或系统设置的安装权限里）。装完打开，主界面四个标签：连接、聊天、共享屏幕、设置。设备 ID 和一次性密码在「共享屏幕」页面就能看到。

> [!NOTE] 安卓被控必须授予无障碍服务
> 想让电脑反过来控制这台手机，需要单独授予 HopToDesk「无障碍服务」权限：系统设置 → 无障碍 → 找到 HopToDesk 并打开。第一次接受连接时系统还会依次询问屏幕录制、输入控制等授权，逐项允许即可。

系统要求方面，安卓端需要 Android 5.0 及以上。

### FreeBSD

FreeBSD 13+ 同样提供 amd64 和 aarch64 两个架构的 pkg 包，用 `pkg install ./包名.pkg` 安装，与 Windows、macOS、Linux 版本完全互通。

## 📖 五种连接类型与进阶用法

装好之后，最核心的操作就是发起或接受一次连接。HopToDesk 的连接设计比较简洁：Connect 按钮旁边有个下拉框，切换的是「这次会话要干什么」，选对模式能省不少带宽和时间。

### 五种连接类型对比

| 类型 | 用途 | 典型场景 |
| --- | --- | --- |
| **远程桌面** | 完整控制：看画面、控键鼠、剪贴板同步 | 日常远控主力，默认选项 |
| **文件传输** | 直接打开文件面板，不共享屏幕 | 只想拷几个文件，没必要看对方桌面 |
| **端口转发** | 建立 TCP 隧道穿透到远程内网 | 访问远程内网的 RDP、数据库、内部网站 |
| **终端** | 开启远程命令行会话，不传输画面 | 改配置、看日志、跑脚本，低带宽下也流畅 |
| **仅查看 / 摄像头** | 只看不发键鼠输入 | 观察对方是否在用机器、演示时不干扰 |

前两种是日常最高频的组合，端口转发和终端更偏运维场景。比如运维同事临时需要访问远程机房里一台服务器上的 RDP 服务，但服务器没有公网 IP，这时开 HopToDesk 的端口转发模式，在被控端设备上建一条 TCP 隧道，本机就能像在同一内网一样连过去，不用专门配跳板机或 VPN。

### 快速连接与通讯录

连过的设备可以存进通讯录并打上标签——办公室、服务器、家里、客户 A……随你分。双击通讯录里的设备就能快速发起连接，不用每次手动输入 ID 和密码。面板用户还能把设备加入收藏列表，主窗口顶部的搜索框可以直接按设备名过滤。

### Web Connect：浏览器里的远程桌面

管理面板的设备列表里还有一个 Web 入口——浏览器直接开会话，**本机什么都不用装**。这个模式特别实用，三种情况最典型：用别人的电脑临时救急、ChromeOS 或平板等装不了客户端的设备、手机浏览器里点开就用。触屏上的交互也做了适配：点按即点击、长按即右键、按住拖动即拖拽。

### 团队安全体系

HopToDesk 的面板账号安全是一套组合拳，从个人级的两步验证到企业级的单点登录都覆盖了：

- **团队成员与角色**：任意档位都可以邀请成员，免费档支持 2 人，Pro 起席位不限。角色决定权限边界——所有者和管理员可以改设置、看账单，普通成员按分配的角色使用设备和工单。成员还可以按设备标签限定可见范围，外包技术员只看到分配给他的客户设备，不会误触其他机器。
- **两步验证**：设置里开启 TOTP 两步验证后，面板会发放 10 个一次性恢复码，验证器丢失时用这 10 个码兜底——恢复码和验证器最好分开存放。所有者和管理员可以**强制全员开启两步验证**，未设置的成员登录后会被要求先补齐，用通行密钥登录的成员和走 SSO 的成员自动豁免。
- **通行密钥（Passkey）**：用指纹、面容或设备锁屏密码登录面板，避免密码被钓鱼。一台电脑可以注册多个通行密钥，随时增删。通行密钥本身已经是多因素形态，开启后不再额外要求动态验证码。
- **单点登录（SSO）**：支持 OIDC 和 SAML 2.0 两种主流协议，可以对接微软 Entra、Okta 等现有身份提供方。员工用公司统一的账号体系登录面板，不再另记一套密码。配置 SSO 后还可以生成 SSO 邀请码——设备装完客户端、员工用 SSO 登录一次即自动入列，不需要手动添加。
