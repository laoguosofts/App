## ✨ SafeW 是什么

SafeW 是一款面向隐私敏感人群的端到端加密通讯工具。它的核心设计理念很清晰——**让消息只有收发双方能看到，连服务器都不知道你们聊了什么**。在主流通讯工具普遍采集元数据、推送个性化广告的大环境下，SafeW 选择了一条更纯粹的路。

它的主要能力包括：加密即时通讯、零日志匿名注册、多设备同时在线同步、大文件端到端加密传输，以及企业级私有化部署支持。SafeW 覆盖 Windows、macOS、Android、iOS、Linux 五大平台，同一个身份可以在多台设备上同时登录，消息和文件自动同步到每一台已授权的设备。

SafeW 最与众不同的地方在于它的零日志策略——服务器不采集通讯录、不追踪聊天行为、不记录可关联的元数据，连注册都不需要手机号或邮箱。这意味着即使服务器被攻破，攻击者能拿到的也只是一堆密文和不指向任何具体个人的技术数据。

> [!NOTE]
> 零日志不是"完全不记录任何东西"。为了转发消息、维持连接，服务器必须知道"这条密文要送到哪个 SafeW ID"。但这些技术数据不与真实身份关联、不用于商业目的、且定期自动清理——这才是隐私社区公认的标准。

SafeW 适合以下几类用户：对通讯隐私有较高要求的个人用户、需要安全协作的小团队、希望私有化部署的企业。如果你只是想找一个简单的聊天软件，SafeW 的零日志设计意味着你用不到一些便利功能——比如自动匹配通讯录好友、在线状态推送、已读回执推送——这些都是它为了隐私主动放弃的。

## 🔧 安装注意事项与步骤

SafeW 的安装过程本身不复杂，但有几个点值得提前注意，尤其是在国内网络环境下。

### 第一步：下载与校验

从官方下载页获取对应平台的安装包后，**务必做 SHA256 校验**。官方下载页会公示每个平台安装包的哈希值，下载完成后计算本地文件的 SHA256，与公示值比对。

| 情况 | 处理方式 |
|------|----------|
| 哈希值一致 | 继续安装流程 |
| 哈希值不一致 | 删除文件重新下载，或更换下载网络 |

> [!WARNING]
> SHA256 不一致意味着文件可能已被篡改。多次重试仍对不上时，**不要强行安装**，警惕仿冒站点。

### 第二步：处理杀毒软件误报

SafeW 作为加密通讯软件，可能被部分杀毒软件误报。这是因为加密软件使用的 API 行为会被启发式检测规则误判，尤其是国内部分杀毒软件对"不常见的加密客户端"检测过严。**只要 SHA256 校验通过，就可以安全安装**——将 SafeW 加入杀毒软件的信任列表或白名单即可。

### 第三步：各平台安装要点

**Windows**：
- 双击安装包，如果 SmartScreen 弹出警告，点击"更多信息" → "仍要运行"；
- 建议安装到默认路径，避免自定义路径导致权限问题；
- 首次启动时防火墙可能询问网络权限，选择允许。

**macOS**：
- 打开 .dmg 时如提示"无法验证开发者"，前往「系统设置 → 隐私与安全性」，在页面底部找到 SafeW 的提示并点击"仍要打开"；
- 如果提示"已损坏"，大概率是下载过程中文件损坏，重新下载即可；
- 高级用户可在终端执行 `xattr -d com.apple.quarantine /Applications/SafeW.app` 移除隔离属性（仅在 SHA256 确认通过后使用）。

**Android**：
- 安装 APK 时如提示"未知来源"，前往「设置 → 安全」，允许本次安装；
- "解析包时出现问题"通常是 APK 文件损坏，需要重新下载；
- 注意下载的 APK 要与你的 CPU 架构匹配（arm64 / armv7）。

**Linux**：
- deb 包如提示依赖缺失，执行 `sudo apt-get install -f` 自动补全；
- AppImage 格式需要先赋予执行权限：`chmod +x SafeW-xxx.AppImage`，然后直接运行。

### 安装完成后

首次启动可能遇到几个小问题：
- **崩溃**：尝试重启设备，确认系统版本满足最低要求；
- **通知不弹出**：检查系统通知权限和 SafeW 设置中的通知选项；
- **网络不通**：确认防火墙已放行 SafeW。

## 📖 从零开始用 SafeW

安装完成后打开 SafeW，你会发现它和用过的其他聊天软件不太一样——**没有手机号登录，没有通讯录匹配，甚至不需要填任何注册信息**。这正是它零日志设计的体现。

### 创建匿名身份

启动应用后，SafeW 会自动为你生成一个唯一的 SafeW ID，这就是你的身份标识。你可以选择是否创建恢复密钥——建议创建，写下来妥善保管，否则换设备或重装后身份就找不回来了。

> [!TIP]
> 恢复密钥不要存在云端笔记或聊天工具里。最好的方式是写在纸上，或者用密码管理器保存。

### 多设备同步

如果你有多台设备需要用同一个 SafeW 身份同步，操作很简单：在新设备上安装 SafeW，选择"加入已有身份"，然后用已授权的设备扫码或通过生物验证确认。**每台新设备的加入都必须经过已有设备的授权确认**，不能只凭密码加入——这是为了防止账号被静默劫持。

同步的内容包括：

| 同步项目 | 是否同步 |
|----------|----------|
| 聊天消息 | ✅ 自动同步到所有设备 |
| 文件 | ✅ 加密元数据同步，实际文件按需下载 |
| 联系人 | ✅ 所有设备上一致 |
| 群组 | ✅ 所有群在所有设备上可见 |
| 设置项 | ⚠️ 部分设置需单独在每台设备配置 |

多设备同步的安全机制不是简单的"存云端然后各端下载"。SafeW 的做法是：发送方设备为每个会话参与者加密一份消息密文，服务器只转发密文不存储明文，接收方的每台设备各自独立解密。这意味着即使服务器被攻击，攻击者拿到的也只是密文。

> [!WARNING]
> 多一台设备 = 多一个安全攻击面。不要在公共电脑或不可信设备上登录 SafeW。每台登录的设备都应该开启生物识别解锁或 PIN 码保护。如果某台设备丢失，立即在其他已授权设备上远程下线它。

### 大文件加密传输

SafeW 对单个文件大小不设硬性上限，但它的加密传输机制和普通网盘或聊天工具不同。了解这些特性能帮你正确处理大文件：

发送一个大文件时，SafeW 会将文件切成若干小块，每块独立加密，然后多个加密块并发上传到就近的边缘节点。对方拉取时也是从多个节点并发下载加密块，全部下载完成后在本地合并解密成原始文件。

这个流程的好处是**网络波动的影响是块级的**——一块失败只需要重传那一块，而不是整个文件。而且 SafeW 支持断点续传：中途断网或退出后，已上传的加密块会保留，下次发送同一个文件时会自动跳过已完成的部分。

| 问题 | 原因 | 解决方式 |
|------|------|----------|
| 传输很慢 | 上行带宽不足 / 加密计算开销大 | 在网络好的地方发送，或用桌面端 |
| 中途断开 | 网络波动 | 直接重新发送同一个文件，自动续传 |
| 对方没找到 | 文件还在传输中 / 被阅后即焚销毁 | 让对方稍等，检查阅后即焚设置 |
| 完成但打不开 | 加密块未全部下载 / 文件损坏 | 等待下载完成，或让对方重新发送 |

大文件传输完成后，对方可以在 SafeW 中查看文件的哈希值（MD5 或 SHA256），用于确认文件完整性。需要注意的是，SafeW 不会自动清理存储在本地的文件，大容量传输后记得手动管理磁盘空间。

### 零日志模式进阶

在设置中可以开启"零日志模式"，这会做一些额外限制：更严格的元数据清理策略、关闭任何可能泄露元数据的辅助功能、定期本地数据清理。对隐私需求极高的用户建议开启。

开启零日志模式后，你会发现一些便利功能被关闭了——比如在线状态、已读回执等。这是有意的设计取舍：**用便利性换隐私**。对大多数普通用户来说这些缺失是可以接受的，但如果你需要依赖这些功能，可能要权衡一下。

### 企业级使用

SafeW 支持私有化部署。在企业环境中，文件可以存储在企业自己的存储系统中，管理员可以配置最大文件大小、存储空间配额和文件保留期限。即使是私有化部署，端到端加密机制依然保持——服务器只能转发加密块，无法解密内容。
