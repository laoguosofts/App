## ✨ TaskManager 是什么

TaskManager 是一款面向 Android 设备的轻量级系统资源监控工具，主打六类核心资源的实时可视化——CPU、内存、磁盘 IO、网络、电池、温度，配上可交互的进程列表和进程管理功能，让用户能够直观看到手机此刻"谁在忙、忙什么、吃了多少资源"。

它的定位不是杀毒软件或清理工具，而是一台"体检仪"：当手机发烫卡顿、待机掉电异常、磁盘被悄悄读写时，打开 TaskManager 挂两分钟，基本就能定位到问题源头。对于喜欢折腾 ROM、玩大型游戏、或者对手机后台行为有洁癖的用户来说，这类工具的价值在于"看见"——很多系统层面的异常行为，普通用户是感知不到的。

TaskManager 采用 Material Design 3 设计语言，支持三套主题（浅色、深色、Dynamic 取色），界面简洁，没有广告。版本从最早的 v1.0.8 到最新的 v1.5.2，功能迭代集中在设置便利度（刷新频率滑块、进程项内嵌指标、单位切换）和进程管理的权限扩展上，核心的六类资源面板从一开始就具备。

## 🔧 安装步骤

TaskManager 以 APK 形式分发，安装过程和大多数第三方 Android 应用一致，但有几个注意点值得提前知道。

### 前置条件

- Android 7.0（API 24）及以上系统版本
- 设备允许安装未知来源应用（首次安装需在系统设置里授权）

### 安装流程

1. 从下载页获取最新 APK 文件，建议核对文件大小（v1.5.2 约 8MB 左右）和版本号，避免下载到旧版
2. 通过文件管理器找到 APK 文件，点击安装
3. 如果系统弹出"未知来源应用"提示，跳转到系统设置 → 安全 → 开启对应渠道的安装权限，返回继续
4. 安装完成后在桌面找到 TaskManager 图标启动

### 首次启动的权限请求

TaskManager 首次启动会请求以下权限：

| 权限 | 用途 | 是否必须 |
|---|---|---|
| 后台服务 | 保持监控持续运行 | 是（不授权则退出后台后监控停止） |
| 通知权限 | Android 13+ 要求 | 否（但后台常驻通知栏方便快速访问） |
| Shizuku 绑定 | 进程管理的核心权限 | 否（不绑定则只能看不能杀进程） |

> [!TIP]
> **关于 Shizuku**：TaskManager 的进程结束功能依赖 Shizuku 框架。普通 Android 应用无法直接调用 `am force-stop`，Shizuku 通过无线调试或 root 方式授权后才能执行系统级命令。如果你只看资源曲线不杀进程，可以跳过 Shizuku 设置，但进程面板里的 Force Stop 按钮会变灰。

### 版本差异提醒

v1.0.8 是早期版本，没有刷新频率滑块、过滤规则、进程项内嵌指标等便利功能，但核心的六类资源面板和进程管理入口已经具备。v1.3.2 加入了进程项内嵌 CPU+内存双指标，v1.5.x 加入了英制单位切换。如果追求完整体验，建议使用 GitHub 上的最新版本。

## 📖 使用入门

TaskManager 的日常使用可以围绕六个资源面板和进程列表展开，下面按实际场景组织内容，帮助你快速上手。

### CPU 监控：找持续霸榜的进程

切到 CPU 面板，默认视图就是一个滚动的实时占用曲线 + 下方按 CPU 占用降序排列的进程列表。这意味着列表顶部那条就是此刻最忙的进程。

**识别真凶的三条经验：**

- 看持续时间，不是看瞬时值。Top 1 瞬间冲到 40% 然后掉回 3%，可能只是应用冷启动加载。真正有问题的进程会在 Top 1~3 位置持续停留，占用率长期维持在 15% 以上。建议把 TaskManager 放后台挂 2~3 分钟，回来看进程列表前几条的位置有没有明显变化。
- 区分系统进程和第三方。进程名的包名前缀能快速判断归属：`com.android.*` 是安卓系统核心，`com.google.*` 是 Google 服务，`com.miui.*` / `com.huawei.*` 等是厂商定制，其他才是第三方应用。系统进程不要随便杀——非 root 模式下 TaskManager 也结束不了它们。
- 线程数异常高。正常单应用线程数一般在 10~50 之间。如果看到某个第三方应用有几百个线程，点开详情确认——可能是线程泄漏或广告 SDK 在偷偷跑后台服务。

点开进程列表里的任意一条，进详情页可以看到 PID、包名、当前 CPU 与内存占用、优先级（Nice 值，-20 到 19，数字越小优先级越高）、线程数、启动时间、可执行路径等信息，底部有 Force Stop 和 App Info 两个操作按钮。

### 磁盘 IO：排查后台偷偷读写存储

切到 DISK 标签，左上角两个数字分别是读取速率和写入速率（单位 MB/s），右侧是两条滚动的实时曲线。

**日常 DISK 面板的正常数值范围：**

| 场景 | 读速率 | 写速率 |
|---|---|---|
| 待机 | 0~2 MB/s | 0~1 MB/s |
| 刷微信 / 网页 | 1~10 MB/s | 0~2 MB/s |
| 玩游戏加载 | 10~80 MB/s | 0~5 MB/s |
| 安装 / 更新应用 | 20~100 MB/s | 10~50 MB/s |

UFS 3.x / 4.x 存储的手机极限读取可以到 2000+ MB/s，但正常使用中很少触及。

> [!WARNING]
> **值得关注的异常行为**：手机放着不动、屏幕关闭时，DISK 面板却有持续的 10~50 MB/s 写入——这肯定是有东西在后台读写存储。常见嫌疑包括云同步应用（Google Photos、百度网盘上传照片）、垃圾清理工具（定期全盘扫描）、加密挖矿木马、以及系统后台维护（Google Play Services 的应用验证、媒体扫描器重建数据库）。

写入速率长期高位也需要注意——可能是某个应用在录制日志（调试模式没关）、缓存机制异常反复写临时文件、或者病毒/挖矿程序。TaskManager 能帮你看到"磁盘确实很忙"，但要精确到"谁在写"需要 root 权限（类似 Linux 的 iotop），目前 TaskManager 不提供按进程查看磁盘 IO 的功能。

### 设置面板：让监控更顺手

v1.0.9 及以上版本的设置面板提供了几项实用的偏好调整：

**刷新频率滑块**：默认约 1 秒刷新一次曲线和进程列表，三档可选——300ms（最快，适合捕捉瞬时尖峰、测试游戏帧率抖动）、1s（日常使用）、3~5s（省电，后台挂着观察用）。刷新越快，TaskManager 自己的 CPU 占用会稍微升高一点，日常用 1s 足够。

**过滤与搜索**：勾选"排除系统进程"后会把 `com.android.*`、`com.google.*`、厂商定制进程（如 `com.miui.*`、`com.huawei.*`）全部从列表里隐藏，只显示第三方应用——对排查流氓应用特别好用。搜索框支持实时过滤，输入包名关键词或应用名都行。

**进程项内嵌指标**（v1.3.2+）：进程列表的每条直接内嵌 CPU 和内存（PSS）两条趋势，不用切面板也能同时看到两种指标。

**主题与单位制**：三套主题（浅色 / 深色 / Dynamic 跟随壁纸取色，Android 12+ 默认启用 Dynamic），单位制支持公制/英制切换（温度 °C↔°F），国内用户保持公制即可。

### 进程管理：权限矩阵和结束操作

TaskManager 的进程管理能力分三档，对应的权限要求不同：

| 操作 | 需要的权限 | 实际条件 |
|---|---|---|
| 结束普通安卓应用 | Shizuku 运行中并已授权 | Shizuku 由无线调试或普通方式启动即可 |
| 结束 Linux 进程 | Shizuku 需由 root 方式启动 | 手机已 root + Shizuku 以 root 方式启动 |
| 调整进程优先级（Nice） | Shizuku 需由 root 方式启动 | 同上 |

普通应用的 Force Stop 是最常用的操作：点进进程详情 → Force Stop 按钮，会发送 `am force-stop <包名>` 命令，应用的所有进程、前台服务、后台任务、定时任务都会被终止，通知消失，但**不会清除应用数据**（卸载才会清数据）。Force Stop 之后应用不会自动重启，除非有 BOOT_COMPLETED 接收器（只在重启时触发）、推送渠道（FCM、厂商通道）把它拉起来、或者系统定时任务把它拉起来。

> [!WARNING]
> **Root 模式下的能力边界**：当 Shizuku 以 root 方式启动时，TaskManager 可以结束任何 Linux 进程（包括 system_server、media.codec 等系统级进程），也可以调整进程优先级（Nice 值 -20 到 19，-20 最高优先级，19 最低）。**强烈建议不要用这些能力去结束系统进程**——system_server 被杀等于软重启，轻则重启 UI，重则重启整个系统。

Nice 值调整的实际价值很有限——Android 自己的调度器已经做得很好，手动调 Nice 不会让游戏帧率明显提升，反而可能导致后台服务不稳定。

### 一个完整的排查流程示例

假设手机待机时掉电异常，TaskManager 的典型使用流程是：

1. 打开 TaskManager，放后台挂 2~3 分钟，保持屏幕关闭
2. 回到 TaskManager，先看 DISK 面板——有没有持续的读写？如果有，说明有应用在后台扫描存储
3. 切到 CPU 面板，看进程列表前 3 条是不是和 2 分钟前一样？如果某条一直钉在 Top 1，就是方向
4. 点开那个进程的详情，看线程数是不是异常高？包名前缀是不是系统级的？
5. 如果是第三方应用且有 Shizuku 权限，点 Force Stop 结束它；如果只是想确认，点 App Info 跳转到系统设置看详细信息
6. 切回 DISK 和 CPU 面板，确认数值是否回落——如果回落了，问题定位完成
