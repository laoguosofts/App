## ✨ MateClaw 是什么

MateClaw 是一款面向个人和小团队的 LLM Agent 框架。跟市面上多数 AI 聊天工具不同，它的核心不是对话界面，而是**LLM Wiki**——把零散的原始材料（PDF、文档、网页、笔记文件夹）消化成结构化的知识页面，带双向链接、摘要、实体图谱，让 Agent 真正「读懂」你的资料，而不是只在向量库里捞几段相似文本。

框架本身是自托管的，你可以跑在本地机器、内网服务器或者 Docker 容器里。控制台提供完整的可视化界面：知识库浏览、知识图谱、消化流水线进度、渠道配置、Doctor 自诊断都集中在一个 Web UI 里。支持多种 IM 渠道接入（Slack、Telegram、飞书、企业微信等），Agent 可以在你常用的沟通工具里直接调用知识库回答问题。

底层支持 PostgreSQL、MySQL、H2 三种数据库，模型供应商可自由切换（OpenAI、Anthropic、本地 Ollama 都能配）。如果你手上有一堆资料想让 AI 真正用上，而不是只会「检索增强生成」那点套路，MateClaw 值得试试。

## 🔧 安装与部署

### 方式一：Docker 部署（推荐）

Docker 是 MateClaw 最省心的部署方式，官方提供了预构建镜像，数据库（PostgreSQL）和搜索引擎（SearXNG）都在同一个 docker-compose 文件里编排好了。

1. 确保机器上已安装 Docker 和 Docker Compose
2. 从下载页获取 docker-compose.yml，直接 `docker-compose up -d` 拉起来
3. 容器全部 healthy 后访问控制台（默认端口 8080），用 admin / admin 登录

> [!WARNING]
> 首次部署后**务必立刻改掉默认 admin 密码**——Doctor 自诊断会把这个作为安全检查项，检测到默认密码会标红 FAIL。

### 方式二：本地运行（开发者或内网环境）

不想用 Docker 也可以直接跑：

1. 安装 JDK 17+ 和 PostgreSQL 14+
2. 下载 ZIP 包解压，修改 `application.yml` 里的数据库连接信息
3. 执行 Flyway 迁移初始化数据库表结构
4. 运行 `java -jar mateclaw.jar`，浏览器访问本地 8080 端口

### 安装后自检

装完别急着用，先跑一次 Doctor 自诊断：

- 进控制台 → System → Doctor
- 点按钮，等几秒出结果
- 重点看数据库连接、Flyway 迁移状态、模型供应商连通性这三项是不是都 🟢 PASS
- 有 🔴 FAIL 就对着修复建议逐条解决，比如数据库连不上就检查 PostgreSQL 是不是启动了、端口对不对

Doctor 还会提醒磁盘剩余空间（低于 10% 警告）和 JVM 堆内存（高于 80% 警告），这些是上线后容易被忽略但出问题就很麻烦的点。

## 📖 核心功能上手

### LLM Wiki：不是向量库，是一本能翻的书

MateClaw 最核心的设计是它的 LLM Wiki 三层模型。传统 RAG 的思路是：扔一个 PDF → 切成固定长度的 chunk → 存 embedding → 查询时捞几段相似文本。Agent 拿到的是零散的文本块，知道「相关」但说不清「到底是什么」。

MateClaw 走了另一条路——它把原始材料**消化**成结构化的知识页面：

| 层级 | 是什么 | 作用 |
|---|---|---|
| 原始材料层 | 你扔进来的 PDF / 文件夹 / Markdown | 唯一真相源，随时可以重新消化 |
| 知识页面层 | LLM 生成的结构化页面，带双向链接、摘要、标签 | Agent 读写的主战场 |
| 实体图谱层 | 从材料里提取的人名、公司名、技术名词和关系 | 支持实体级检索和关联发现 |

三种入库模式可选：

- **自动写页面**：材料进来立刻消化生成页面，要快速可用就选这个
- **手动入库**：先存原始材料，等你准备好了再手动触发消化
- **持续加工**：1.5.0 之后支持 Transformation 规则，给消化管线加自定义逻辑——比如给所有页面自动打标签、合并相似度超过阈值的页面、对特定格式做预处理

### 消化管线里发生了什么

一份 PDF 丢进去后，MateClaw 在后台跑一条完整管线：

1. **格式识别与提取**——自动识别文件类型，图片里的文字走视觉管线
2. **语义分段**——不是按 token 数量硬切，而是按语义段落切分，保证每个 chunk 自包含
3. **页面生成**——LLM 读每个分段，判断是已有页面的补充还是要新建页面
4. **摘要与元数据**——每个页面自动生成摘要、关键词、标签
5. **实体提取**——识别人名、公司名、产品名、技术名词
6. **WikiLink 建立**——检查页面引用的概念，建立双向链接
7. **来源追溯**——每个页面保留原始材料的引用位置

整个过程在 UI 里是可见的——每个原始材料行上有进度条，你能看到走到了哪一步。每个知识库还自动生成两页系统页：**overview**（覆盖什么主题、多少页面、主要实体）和 **log**（管线执行日志），Agent 可以自动读 overview 快速了解知识库全貌。

### Wiki 浏览与编辑

Wiki 浏览页是 MateClaw 信息密度最高的界面。一屏里能看到：

- 所有知识库列表，每个库的页面数、状态、最近更新时间
- 某个知识库的知识图谱可视化（可缩放、可点击实体）
- 消化流水线实时状态
- WikiLink 死链列表

点进知识库后，页面按 WikiLink 关联组织而不是平铺，每个页面可以展开看摘要、双向链接、修改历史。Agent 生成的页面和你手动写的页面视觉上有区分，多一个来源标记。编辑用 Markdown 编辑器，实时预览，保存后自动触发 WikiLink 扫描，被链接的另一端会收到更新通知。

Wiki 搜索也不是简单全文搜索，三路并行：**标题精确匹配** + **内容向量检索**（语义搜索）+ **实体图谱检索**（比如搜「所有提到 Spring Boot 的公司」），结果按相关性排序，命中位置高亮。

### WikiLink 死链治理

知识页面之间通过 WikiLink 互相引用（类似 Obsidian 的双链）。MateClaw 会自动检测死链——某个 WikiLink 指向的页面不存在时：

- 页面上这个链接直接标红
- 知识库主页的死链区列出所有死链和建议创建的页面
- Agent 在运行过程中会自动发起缺失页面的创建建议，等人审核确认

这让 Wiki 可以自组织：Agent 发现需要一个概念页面但还不存在，自己提创建请求，知识库越用越完整。

### Doctor 自诊断：一键体检

升级之后、定期巡检、或者客户求助时，跑一次 Doctor 最省事。它检查的项目包括数据库连接、Flyway 迁移状态、模型供应商连通性、IM 渠道状态、磁盘空间、JVM 堆内存、Docker 容器健康和安全配置（JWT secret 长度、默认密码是否已改）。

每项结果三种状态：🟢 PASS、🟡 WARN（能跑但有风险）、🔴 FAIL（影响正常使用）。FAIL 项下面直接给具体修复建议——比如「数据库连接失败：Connection refused at localhost:5432 → 检查 PostgreSQL 是否启动」，省掉远程排查的来回沟通。
