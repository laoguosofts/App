## ✨ Shizuku 是什么：让 Android 应用拥有 adb 级权限的中间人

Shizuku 是一个在 Android 设备上运行的服务框架，它的核心作用是把 adb（Android Debug Bridge）的权限以安全方式暴露给其他应用。正常情况下 adb 调试授权是给电脑用的，手机上的应用拿不到这份权限；Shizuku 把这条通道搬到了手机内部——应用只需向 Shizuku 申请授权，就能执行原本只有 adb shell 才能完成的系统级操作，比如移除预装应用、修改系统参数、读写受限区域等。

这件事的意义在于，很多实用工具不需要再要求 root 权限就能工作了。过去想删厂商预装软件必须解锁 Bootloader、刷 Magisk，现在借助 Shizuku + 精简工具 App，在无线调试或一次 adb 授权的基础上就能完成。当然，Shizuku 自己不做任何功能——它是权限代理层，真正干活的是接入了 Shizuku 的生态应用。

Shizuku 提供三种启动方式：root 模式（最稳定、支持开机自启）、无线调试模式（Android 11+ 免 root、一次配对后长期可用）、以及经典的 USB 连电脑模式。对多数免 root 用户来说，无线调试已经是日常主力，Android 13+ 上配合可信 WLAN 自动启动，体验基本追平 root。

适合谁用？折腾党、想精简系统的用户、喜欢自动化的极客、需要 adb 级权限但不想 root 的人。对普通用户来说，Shizuku 本身没有直接可见的功能，装了 Shizuku 之后还需要搭配具体的工具应用才能发挥作用。

## 🔧 Shizuku 安装与启动

Shizuku 的安装本身是标准的 Android APK 安装流程，真正需要注意的是**启动方式**——不同方式的门槛和权限时效差异很大，选对启动方式是后续所有功能的前提。

### 安装前置条件

- Android 系统版本：无线调试需要 Android 11 及以上；root 模式无版本限制；
- 手机已开启开发者选项（设置 → 关于手机 → 连续点击版本号 7 次）；
- 从可信渠道下载 APK 文件，安装时允许「未知来源应用」安装权限。

### 三种启动方式对比

| 启动方式 | 是否需要 root | 重启后是否失效 | 开机自启 | 推荐人群 |
| --- | --- | --- | --- | --- |
| root 模式 | 是 | 不失效 | 原生支持 | 已有 root 的用户 |
| 无线调试 | 否 | 失效（需重启后手动启动） | Android 13+ 可信 WLAN 可自动启动 | 绝大多数免 root 用户 |
| USB 连电脑 | 否 | 失效 | 不支持 | 临时使用、首次配对 |

### 无线调试模式（免 root，推荐大多数人）

这是目前最主流的方案，核心思路是用 Android 系统内置的无线调试能力给 Shizuku 授权：

1. **开启无线调试**：开发者选项里找到「无线调试」并开启，选择「使用配对码配对设备」；
2. **获取授权**：在 Shizuku 应用内选择无线调试启动，按屏幕提示输入配对码和端口号；
3. **服务启动**：配对成功后 Shizuku 服务会开始运行，状态显示为绿色即表示授权生效。

> [!TIP]
> **配对只需一次**。配对完成后，下次启动 Shizuku 不需要再次输入配对码，直接在应用内点「启动」即可。Android 13+ 用户还可以在应用设置里把常用的 Wi-Fi 标记为可信网络，连上该网络时服务会自动拉起。

### root 模式（最省心的长期方案）

如果你已经通过 Magisk 等方案获得了 root，只需在 Shizuku 应用内选择 root 启动，弹出 root 授权请求时给予永久允许即可。root 模式的优势是**服务进程不依附 adb 授权**，重启手机后不会失效，并且原生支持开机自启——真正做到「激活一次，长期有效」。

> [!WARNING]
> **root 用户需额外注意自启动设置**。root 模式下 Shizuku 开机自启的前提是：系统自启动白名单允许 Shizuku、电池优化已豁免、root 管理器对 Shizuku 的授权是「永久允许」。MIUI、EMUI 等国产系统默认会屏蔽所有应用的自启动权限，必须手动放行。

## 📖 核心玩法与生态应用

Shizuku 本身是框架，真正的能力来自接入它的生态应用。下面介绍几个最常见的使用场景，帮你理解 Shizuku 能做什么、怎么用。

### 精简系统：用 Canta 卸载预装应用

厂商预装的应用分两类：普通应用可以直接卸载；**系统预置应用**在常规界面连「卸载」按钮都没有。这类应用要移除，本质是执行系统级的包管理操作——过去必须 root，如今借助 Shizuku 的 adb 权限就能完成。Canta 是这一场景里最常被提起的工具：它依赖运行中的 Shizuku 服务工作，不需要解锁 Bootloader、不需要刷机，把「给手机减肥」变成了点几下按钮的事。

**操作流程**很简单：

1. Shizuku 已启动，从可信渠道安装 Canta；
2. 打开 Canta，按提示授权 Shizuku；
3. 列表会列出全部应用，包括平时看不见的系统组件，底部导航可按类别过滤；
4. 对目标应用选择「为当前用户移除」（**不要选彻底删除**）。

**动手前必读风险分级**。Canta 的列表里混着「删了没事」「删了要小心」「删了会出事」三种东西，社区通行做法是借助 Universal Android Debloater 的数据来判断——它按移除风险、用途、厂商给包名分了级。动手原则：先从明显安全的目标练手（运营商定制应用、厂商商城、第三方推广应用）；看不懂的包名一律不动；一次只删一两个，出问题容易定位。

> [!NOTE]
> **删错了能恢复**。选「为当前用户移除」时，预置应用的安装包仍在系统分区里，通常可以随时恢复——在 Canta 里对已移除应用执行恢复操作即可。真正无法恢复的是把系统分区里的包本体删掉，所以永远选保守的那一档操作。

### 授权管理：哪些应用值得拿到 adb 级权限

应用拿到 Shizuku 授权后，可以借助它执行**系统级操作**——移除应用、改动参数、读写受限区域。对可信应用，这是功能；对恶意应用，这是破坏力。弹窗出现时，快速过四个问题：

1. **它是谁**：有没有公开的项目主页或开发团队？在主流商店有没有正常的更新记录与评价？来路不明的一票否决；
2. **它为什么要**：支持 Shizuku 的应用类型是有限的——权限管理、系统精简、冻结、终端、自动化。一个手电筒应用要 Shizuku 授权，本身就是危险信号；
3. **授权范围合理吗**：好的工具会在文档里说明它用 Shizuku 干什么；说不出用途的，默认不该给；
4. **不用了收得回吗**：授权随时可在 Shizuku 应用内撤销，但要养成习惯——闲置即收回，别让钥匙插在门上。

| 信任级别 | 典型对象 | 建议 |
| --- | --- | --- |
| 高 | 知名开源项目、开发者本人可查 | 可授权，保持更新 |
| 中 | 商店正常上架、评价尚可的付费/免费工具 | 授权前查一眼项目背景 |
| 低 | 论坛群组流传的 APK、改名仿冒 | 拒绝 |
| 不明 | 要求关闭安全设置才能用的 | 立即放弃 |

还有两个容易忽略的细节：root 模式授权更要谨慎——服务以 root 特权运行时，授权应用的实际能力上限更高，对中级信任的对象也应从严；另外 Shizuku 自己的包名是 `moe.shizuku.privileged.api`，来源只认官方渠道，谨防假冒。如果误授权了疑似恶意应用，最干脆的补救方式是在系统设置里撤销 USB 调试授权——这会一次性清空全部调试信任。

### 保活与自启：让 Shizuku 长期在线

无线调试模式最大的痛点是**重启手机后 Shizuku 服务会失效**，因为 adb 授权本身随重启清零。解决思路有两条：要么在重启后自动把服务拉起来，要么降低手动启动的成本。

**Android 13+ 免 root 用户**可以利用 v13.6.0 引入的可信 WLAN 自动启动——在应用设置里把家庭/办公 Wi-Fi 标记为可信网络，手机连上的瞬间服务自动拉起。这个功能的边界是：离开可信网络（连公共 Wi-Fi 或用流量）就恢复原样，它是「自动点启动」而非「永久授权」，底层机制仍是无线调试，系统限制没有被绕过，只是把手动那一下点击自动化了。

**root 用户**的自启是原生支持的——root 模式的服务进程由 root 权限直接拉起，不依附 adb 授权，配合系统开机广播就能在启动完成后自动把服务带起来。自启不生效时按这个清单排查：

1. 系统应用管理里允许 Shizuku 自启动（MIUI、EMUI 等默认禁止全部自启，必须手动放行）；
2. 把 Shizuku 从电池优化/省电限制中排除；
3. 确认 root 管理器对 Shizuku 的授权是「永久允许」；
4. 开机后稍等半分钟——服务进程排在系统启动队列后段，刚开机时状态异常属正常现象。

对多数人来说，如果没有 root 需求，先把后台保活做扎实 + 记住重启后点一下启动，这两下点击的实际成本远低于折腾 root 的总成本。
