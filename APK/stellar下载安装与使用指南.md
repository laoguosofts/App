## ✨ Stellar 是什么：一句话说清它能干嘛

Stellar 是一款面向 Android 的高权限服务工具，核心思路与 Shizuku 一脉相承——通过 ADB 无线调试或 Root 在后台拉起一个高权限服务进程，让普通应用经由它调用系统 API。它不是简单的壳或配置器，而是 Shizuku 的深度定制分支，保留了原版的核心架构，同时重写了服务层，叠加了细分权限、降权激活、TCP 预热等多项改进。

对于日常玩机场景，Stellar 能解决的典型问题包括：需要系统权限的自动化脚本、跨应用的权限授予、开机自启的稳定保障，以及一些 Shizuku 官方弃用但实际仍有用的 API 能力（比如直接创建特权进程、运行时权限授予/撤销）。

相比原版 Shizuku，Stellar 最大的增量在于细分权限系统——不再是单一的"全有或全无"授权，而是让应用按需申请具体能力；配合降权激活机制，Root 启动的服务可以自动降到 shell 身份运行，主动收窄自己的权限边界。此外还重新启用了 Shizuku 新版标记为弃用的两项能力，并修复了联发科设备的兼容性问题。

Stellar 内置 Shizuku 兼容层，已经基于 Shizuku API 开发的应用无需改代码即可直接运行，授权页会单独列出"Shizuku 兼容应用"。原始 Shizuku 代码保留 Apache-2.0 许可证，Stellar 自身的修改部分则以 MPL-2.0 发布，作为开源项目它的安全机制在代码中可见可审计。

## 🔧 安装与激活：四步自查后再动手

无线调试激活的失败，十有八九出在环境没备好。按下表逐项核对，再回应用里点启动，成功率会高得多。

### 激活前四项自查

| 检查项 | 要求 | 不满足怎么办 |
| --- | --- | --- |
| 系统版本 | 无线调试激活需 Android 11 及以上 | 更低版本走电脑 ADB 启动 |
| 开发者模式 | 已开启 | 在系统设置中连点"关于手机"的版本号触发 |
| 无线调试 | 已在开发者选项中开启 | 开关位于开发者选项的"无线调试"子页面 |
| 网络环境 | 手机与无线调试处于同一 WLAN | 连上 WiFi 再试；无网场景参考后文 TCP 预热 |

> [!TIP] 配对只需要一次
> 很多用户以为每次启动都要配对，实际上配对成功后无需重复。配对入口在开发者选项的"无线调试"子页面里，而不是开发者选项首页。

### 无线调试启动流程

准备工作就绪后，在 Stellar 应用主页选择无线调试通道，按界面提示完成配对与授权。首次启动时应用会请求通知权限与后台运行权限，建议全部允许——配对过程会弹出通知，后台运行权限则关乎服务能否稳定驻留。

> [!NOTE] 管理器版本也要跟上
> 老版本对新系统的兼容性可能有缺口，遇到奇怪问题时先检查管理器是否为最新版，升级往往能直接解决。

### Root 用户的捷径

设备已 Root 的话，可以跳过无线调试整套流程，直接在主页用 Root 通道启动。Root 启动后服务可自动降到 shell（uid=2000）身份运行，主动收窄权限——这是 Stellar 默认开启的降权激活机制，能在方便的同时守住安全边界。

## 📖 使用入门：从日常操作到进阶玩法

### 服务驻留与开机预热

Stellar 的服务启动依赖网络——设备重启后如果 WLAN 还没连上（比如开机密码还没输、或干脆在无网环境），常规拉起就会失败。TCP 预热功能专门解决这个死角。

在连接 WLAN 的环境下启动或预热 Stellar 时，服务会经由 TCP/IP 端口建立连接。v1.0.18 加入的"开机预热模式"提供了一个中间状态：预热 ≠ 真启动，它只把连接信息提前铺好，等真正需要服务时再拉起——即使设备处于无 WiFi 环境也能走 TCP 通道连上。

> [!WARNING] 预热的前提条件
> 预热依赖此前在联网环境完成过一次完整启动；改过端口后连不上时，先检查端口是否被其他应用占用。另外 TCP 预热的信息在设备重启后需要重新铺垫，配合开机自启使用效果最好。

### 权限管理：分级授权与降权

Stellar 相比 Shizuku 的核心升级之一是细分权限系统。不再只有一种权限，而是让应用按需申请具体能力。授权分为自动降权、分级授权、一次性授权三重把关，权限随时可撤销。

一次性授权感知是另一个细节改进——客户端能精准知道自己拿到的是永久还是一次性授权，这在授权管理场景下很有用。

### 安全性三问

提权类工具天然招人警惕，这是合理的。把安全性拆成三个具体问题来看：

**不 Root 会不会缺功能？** 核心能力——特权 API 调用、授权管理、命令执行——都不依赖 Root；Root 只是换来开机自启更稳这类便利。普通用户建议先用免 Root 的无线调试通道，够用就不必碰 Root。

**它会不会动系统？** 安全机制有三道防线：不改系统分区、不解锁引导，卸载应用即完全移除；Root 启动的服务可自动降到 shell 身份运行，主动收窄权限；分级授权与一次性授权三重把关，权限随时可撤销。

**命令执行风险多大？** 风险与能力同源：服务身份能改的，误操作也能改坏。自保习惯三条——读不懂的不跑、新命令先手动执行验证、敏感工具给一次性授权。

| 人群 | 推荐方案 |
| --- | --- |
| 普通玩机用户 | 免 Root 通道 + 按需授权 |
| 重度折腾用户 | Root 通道务必开降权激活 |
| 给家里长辈用 | 不建议——授权与命令的判断成本不适合 |

### 与 Shizuku 的关系

一句话：**Stellar 是 Shizuku 的深度定制分支**。继承了 ADB 拉起服务进程的核心思路、客户端接入范式和 Apache-2.0 开源属性；新增了跟随启动机制、细分权限系统、一次性授权感知、降权激活、联发科支持、应用内更新与 TCP 预热等能力；移除了原版内置的 rish shell 工具和 Sui API 支持；重新启用了 `newProcess()` 和运行时权限授予/撤销这两项 Shizuku 官方弃用但实际仍有价值的 API。

如果你之前就在用 Shizuku，内置的兼容层会让过渡非常平滑——无需改代码即可直接运行基于 Shizuku API 的应用。
