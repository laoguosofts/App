## ✨ Agora 是什么：一款以离线为核心的 AI 对话应用

Agora 是一款面向移动平台的 AI 对话应用，核心定位是让用户在手机上同时接入本地离线模型与云端模型提供商，把「断网也能跑 AI」作为设计的一等公民。与那些只依赖云端 API 的对话应用不同，Agora 从底层就支持 GGUF 格式本地模型的导入与推理——装好一个模型文件之后，通勤、飞行、地下室等弱网甚至无网场景下，翻译、总结、写作这类任务照样能跑。

应用采用 BYOK（Bring Your Own Key）模式——API 密钥由用户自己提供，不锁定任何单一提供商。主流云端模型都能接入，同时还支持自托管的 Ollama 服务作为中间层。设置页把提供商密钥、记忆系统、上下文预算、网络代理等入口集中在一张地图里，对话抽屉负责跨对话的组织与管理，底栏模型选择器则在发消息前给出当前模型、上下文占用与生成状态的即时反馈。

Agora 适合两类人群：一类是需要在移动场景下持续使用 AI、对离线可用性有刚需的用户；另一类是希望把多提供商、多模型统一在一个界面下管理、同时重视数据本地控制权的高级玩家。

## 🔧 安装与首次启动注意事项

Agora 主要面向 Android 平台，安装过程本身不复杂，但有几个细节值得提前留意：

1. **安装包来源**：从下载页获取 APK 文件后，需要在系统设置里允许「未知来源应用安装」。不同品牌手机的入口略有差异——小米在「安全设置」里，华为在「隐私」分组下，原生 Android 则在「应用与通知 → 特殊应用访问权限」。
2. **文件大小核对**：基础安装包体积不大，但首次启动后如果需要导入本地 GGUF 模型，模型文件本身可能在数 GB 量级，建议在 Wi-Fi 环境下完成下载。
3. **存储权限**：导入本地模型、导出归档等操作都需要文件访问权限，首次启动时系统会弹窗请求，建议全部授权，避免后续手动到设置里逐个开启。

> [!WARNING]
> 不要从第三方应用市场下载经过二次打包的版本。Agora 的 BYOK 模式意味着密钥由用户自己填写，二次打包版本可能在网络请求环节植入额外逻辑，导致密钥泄漏或数据上传。

首次启动时应用会引导完成模型提供商的配置——可以选择先填一个云端 API 密钥快速体验，也可以跳过配置直接进入主界面，后续再从设置页补加。本地 GGUF 模型的导入可以在设置页的「提供商与模型」分区完成，也可以直接把文件放到应用指定的目录下让它自动扫描。

## 📖 上手到进阶：四个高频模块的使用思路

Agora 的界面逻辑可以概括为「抽屉管全局、底栏管当前」——主界面左上角的菜单按钮打开左侧对话抽屉，负责跨对话的组织与管理；对话界面底栏那条聚合区域则是每次发消息前必须扫一眼的「驾驶舱」。

### 对话抽屉：管理你的对话矩阵

抽屉从左侧滑出后最显眼的三样东西是顶部搜索框、新对话按钮和底部设置入口。搜索框支持按关键词定位历史对话，索引范围（是否连附件文本一起搜）可以在设置页的「对话搜索」分区调整。新对话按钮点一下立刻开一条互不干扰的新对话，不影响当前正在聊的那条。

抽屉打开后，每条对话支持重命名、置顶、归档、删除四种操作。默认标题可以自动生成（基于对话内容），也可以手动改；常用对话置顶固定在列表顶部；不常用但不想删的收进归档让列表立刻清爽；删除后不可恢复——重要对话建议先导出归档再删。

> [!TIP]
> 实践里比较好用的组织思路是：同一个任务的探索过程放在一条对话里，靠应用内的树状分支功能对比不同走向；不同的任务、项目、话题各开一条独立对话，用置顶与归档控制列表长度。这样既能保证单条对话的上下文连续性，又不会让抽屉列表变成一锅粥。

### 设置页地图：九个分区各管什么

抽屉底部的设置入口通向应用的中枢。设置页从对话抽屉底部进入后，所有功能分区一屏可见，大致可以按下面这张表来记：

| 分区 | 核心职责 | 典型场景 |
| --- | --- | --- |
| 提供商与模型 | 填 API 密钥、配自定义端点、同步与启用模型 | 首次接入云端服务、切换多提供商 |
| 对话搜索 | 历史对话的索引范围与匹配方式 | 搜索不到某段对话时调整索引策略 |
| 上下文 | 预算预设与 Compact（上下文压缩）行为 | 长对话走到上下文上限时的压缩策略 |
| 终端 | 远程 Shell 命令执行的 SSH 设备管理 | 从手机远程控制服务器执行命令 |
| 网络 | HTTP 或 SOCKS 代理转发配置 | 公司网络或需要科学上网环境 |
| 记忆 | 活跃记忆与保存文件的编辑 | 管理 AI 的长期记忆条目 |
| 数据控制 | 导出或导入全部数据的归档操作 | 换机迁移或备份 |
| 外观 | 主题、配色方案与动态颜色 | 个性化界面风格 |
| 语言 | 应用显示语言切换 | 多语言环境使用 |
| 关于 | 版本信息、检查更新 | 确认当前版本与更新开关 |

有两个容易混淆的点：一是**生成参数**（温度、Top P、最大输出）不在设置主页，而是在模型与对话相关界面里调整；二是 SSH 直连与本地模型推理不经过网络代理，断网跑本地模型时不需要动代理设置。

### 底栏模型选择器：发消息前扫一眼

对话界面最下方那条区域聚合了发消息前需要确认的全部信息，是全应用的「驾驶舱」：

- **模型选择条**：点开即列出所有已启用的模型，云端与本地混列。当前模型名字直接显示在条上，发消息前扫一眼是最省事的防错习惯——已发出的消息记录的是发送那一刻的模型，事后换模型不会追溯修改。
- **上下文占用估算**：选择条同时显示当前对话相对预算的估算占用。它是本地估算值，与提供商账单口径可能有出入，但足够用于判断「离上限还有多远」。点开它还能手动触发压缩操作。
- **生成状态与发送按钮**：按钮状态有一套固定规则——空闲无草稿时灰态不可点；有草稿或附件时可点击发送或入队；正在生成时按钮变为「停止」用于中断；正在生成但同时有新草稿时，点击发送会让新内容排队，等上一条回复完自动发出。

> [!TIP]
> 「生成中可排队」是容易被忽略的贴心设计——不用守着进度条等上一条回复完，提前打好下一条点发送即可。做多模型对比时，把两三个候选模型都保持启用，同一问题用底栏换模型重新生成，配合树状分支功能，不同模型的回答会并排保留在分支里随时回看。

### 离线边界：哪些功能断网还能用

这是 Agora 区别于纯云端应用的核心价值所在。装好本地 GGUF 模型之后，断网可用的功能覆盖了日常使用的大头：

| 功能 | 断网状态 |
| --- | --- |
| 本地 GGUF 模型对话 | 完全可用——推理在手机上完成 |
| 浏览、搜索、编辑历史对话 | 完全可用，全在本地 |
| 活跃记忆与保存记忆的编辑 | 完全可用 |
| 云端提供商对话 | 不可用（请求发不出） |
| 网页搜索、MCP、远程 Shell | 不可用 |
| 模型同步、检查更新 | 不可用 |
| 自动备份 | 本地目的地可用，云端目的地需网络 |

离线路线的完整配置逻辑很清晰：先在联网状态下把 GGUF 模型文件下载到手机（文件以 GB 计，必须联网），之后记忆、提示词、设置全在本地随便改。建议提前开启自动备份到本地目录，避免手机丢失或损坏导致数据无法找回。

> [!NOTE]
> 两个容易误解的边界需要特别记住：第一，「离线可用」不等于「首次下载离线」——GGUF 文件必须联网下载；第二，本地推理与 SSH 直连本来就不走网络代理，断网时无需动任何网络设置。飞行模式下用本地模型处理翻译、总结、写作类任务足够顺手，重要的长对话提前做好 Compact 压缩，小模型也能在有限预算里抓住要点。
