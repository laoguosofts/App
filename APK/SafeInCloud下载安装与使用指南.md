## ✨ SafeInCloud 是什么——跨平台的本地优先密码保险库

SafeInCloud 是一款主打**端到端加密 + 本地存储**的密码管理器，支持 Windows、macOS、Android、iOS 四大平台，同时提供 Chrome、Firefox、Edge、Safari 等主流浏览器的自动填充扩展。它的核心理念很简单：你的所有密码、银行卡号、证件扫描件都以 AES-256 加密后存储在本地，云端只做同步不做解密。

与 Bitwarden、1Password 等同行相比，SafeInCloud 有几个鲜明的定位差异：

- **保险库文件全归用户**：数据可以存在本地，也可以加密后手动上传到 Google Drive、Dropbox、OneDrive 等任意云盘，厂商本身不托管你的保险库文件
- **加密实现开放审计**：虽然不是开源产品，但 SafeInCloud 允许安全研究员提交代码审查请求，这在闭源密码管理器中属于少见的透明做法
- **免费版不限制存储量**：免费账户可以创建无限张卡片，付费版主要解锁附件容量、密码生成器高级选项、跨设备同步等增强功能

适合哪些人用？如果你之前只靠浏览器自带的密码保存、或者把密码记在 Excel/便签里，SafeInCloud 是一个门槛很低的升级选择——导入现有密码很快，日常自动填充几乎无感，丢手机时也不用慌。

## 🔧 安装步骤——四平台各有讲究

SafeInCloud 的安装在各平台上有差异，主要体现在权限授予和未知来源授权两个环节。

### Windows 桌面版

1. 从下载页获取安装包后双击运行，安装向导默认走系统盘 Program Files，也可以自定义路径（建议保留默认，方便浏览器扩展自动定位）
2. 首次启动时会弹出"创建主密码"界面——**这是最关键的一步**，主密码一旦丢失无法恢复，务必设置为至少 12 位、包含大小写+数字+特殊字符的强密码，并在纸上或安全位置备份
3. 设置完成后进入主界面，勾选"开启 Windows Hello 生物识别解锁"可以在锁屏后用指纹或 PIN 快速解锁

> [!WARNING]
> 安装过程中如果 Windows SmartScreen 弹出"未识别的应用"提示，点击"更多信息"→"仍要运行"即可。这是因为 SafeInCloud 是小众软件，没有积累足够多的 SmartScreen 声誉分数，不代表安装包有问题。

### macOS 版

1. 从下载页下载 dmg 文件，打开后将 Safe 图标拖入 Applications 文件夹
2. 首次运行时系统可能拦截，前往"系统设置 → 隐私与安全性"，在底部点击"仍要打开"
3. 主密码设置完成后，在"系统设置 → 密码 → 自动填充密码"中勾选 Safe，否则浏览器和 App 的自动填充不会触发

### Android 版

1. 优先从 Google Play 安装，确保下载的是正版
2. 首次启动创建主密码后，系统会引导你前往"设置 → 系统 → 语言和输入法 → 自动填充服务"，将 SafeInCloud 设为首选自动填充服务
3. 开启"生物识别解锁"选项，之后每次打开 App 用指纹就能跳过输入主密码

> [!TIP]
> 如果从第三方渠道下载 APK 安装包，安装前需要前往"设置 → 安全 → 未知来源"允许浏览器或文件管理器的安装权限。安装完成后建议关闭，避免其他来源的 APK 误装。

### iOS 版

1. 从 App Store 搜索安装即可
2. 首次启动后，前往"设置 → 密码 → 自动填充密码"，确认开关打开且 SafeInCloud 已勾选
3. iOS 上 Safe 会复用系统 Keychain 存储加密密钥，整体安全度比 Android 更高，但代价是跨设备同步需要依赖 iCloud 或手动导出导入保险库文件

## 📖 使用入门——从零到日常的完整路径

### 第一步：把已有的密码全部导进来

绝大多数人开始用 Safe 的场景是：浏览器里已经存了几十上百个密码，不想手动一条条录。这时用浏览器导出再导入 Safe 是最高效的起点。

**Chrome 导出操作**：桌面版 Chrome → 设置 → 自动填充和密码 → 密码管理器 → 右上角三个点 → "导出密码" → 输入系统账户密码确认 → 保存为 CSV 文件。

**Firefox 导出操作**：桌面版 Firefox → 右键菜单 → 密码（或访问 `about:logins`）→ 右上角三个点 → "导出登录信息"。

**Safari (iOS) 导出操作**：iOS 设置 → 密码 → 点击左下角导出按钮，将密码导出为 CSV，通过"文件"App 选择保存位置。

导出 CSV 后回到 Safe，路径是：**设置 → 导入密码 → 选择对应浏览器来源 → 选中刚才的 CSV 文件 → 确认导入**。

> [!WARNING]
> 浏览器导出的 CSV 文件包含**明文密码**。Safe 导入成功后**立即删除本地 CSV 文件**，不要把它发到云端或聊天软件。如果曾经发给过任何人，那些密码应视为已泄露，需要全部替换。

导入完成后建议手动抽查几个重要账户的密码是否正确、Safe 是否自动关联了正确的网站 URL——URL 匹配直接影响后续自动填充能否识别。

### 第二步：认识密码卡片——Safe 的核心数据单元

Safe 中所有存储的内容（登录凭证、银行卡、证件、笔记）都以"卡片"为单位。一张卡片可以包含多种字段：

| 字段 | 说明 | 必填 |
| --- | --- | --- |
| 标题 | 卡片名称，如 "Gmail"、"招商银行信用卡" | ✓ |
| 网址 | 关联的网站 URL，自动填充匹配依据 | 登录类卡片建议填写 |
| 用户名 | 登录用的用户名 / 邮箱 / 手机号 | 登录类卡片建议填写 |
| 密码 | 登录密码 | 登录类卡片建议填写 |

除了这些基础字段，每张卡片还能附加：

- **自定义字段**：任意数量，类型可选文本 / 隐藏文本（密码类，不直接显示）/ 邮箱 / URL / 日期 / 电话——适合存 PIN 码、安全问题答案、第二因素验证码
- **富文本备注**：支持换行、加粗、列表格式，记录账户开通时间、与客服的沟通记录、特殊使用注意事项
- **文件附件**：图片（JPG/PNG）、PDF、DOC 等常见格式，附件也会随卡片一起被 AES-256 加密，单张建议不超过 5MB
- **标签与文件夹**：标签适合给一张卡打多个标记（`工作`、`金融`、`2FA已开启`），文件夹则是逻辑分组（`社交 / 论坛`、`金融 / 网银`），一个卡片只能属于一个文件夹但可以有多个标签

Safe 还提供了几种预设卡片模板，创建新卡片时可以直接选择：**登录**（最常用，带网址+用户名+密码+2FA 字段）、**书签**（只存网址）、**银行卡**（卡号/持卡人/CVC/有效期/PIN）、**证件**（护照/身份证/驾照扫描件）、**软件授权**（许可证号/购买日期/到期时间）、**笔记**（富文本）。

### 第三步：让自动填充跑起来

自动填充要正常工作，需要同时满足四个条件：

1. Safe 处于解锁状态（主密码或生物识别已验证）
2. 系统级 / 浏览器自动填充设置正确
3. Safe 中已保存该网站的密码卡片
4. 当前页面的 URL 与卡片中保存的 URL 匹配

**Android 专项设置**：设置 → 系统 → 语言和输入法 → 自动填充服务（不同版本路径略有差异）→ 确认 Safe 是首选服务。Chrome 内还要额外设一步：设置 → 自动填充和密码 → 自动填充 → 选"使用其他服务自动填充"。

**iOS 专项设置**：设置 → 密码 → 自动填充密码 → 打开开关且勾选 Safe。Safari 内置了 Safe 的自动填充（不是通过扩展），如果 Safari 也不触发，先确认系统级设置，再强制退出 Safari 重开。

**浏览器扩展**：安装 Safe 的浏览器扩展后，Chrome/Firefox 需要确认两件事——扩展已启用、Safe 桌面端正在运行（扩展需要与本地 Safe 通信）。Chrome 131+ 还需注意新的自动填充服务选择机制：Chrome 设置 → 自动填充服务 → 选"使用其他服务自动填充"，否则 Chrome 会优先自己的密码管理器。

### 自动填充不生效怎么办——快速排查清单

如果某个页面 Safe 没弹出填充建议，按这个顺序排查：

1. **Safe 是否解锁**——很多时候只是忘了解锁保险库
2. **是否存了对应的密码卡片**——在 Safe 里搜索当前网站，没存过自然没法填
3. **URL 是否匹配**——卡片里存的是 `example.com` 但实际访问的是 `www.example.com` 或 `login.example.com`，可能匹配不上。编辑卡片，把网站 URL 改成与实际页面一致
4. **App 是否支持标准 API**——某些第三方 App 的开发者没有使用 Android AutoFill Framework 或 iOS Password AutoFill API，这些 App 中自动填充无法触发，只能手动打开 Safe 复制密码

### 安全机制：用户自己能做的五件事

密码管理器再安全，用户侧的操作习惯同样重要。以下五个动作是无论用哪款密码管理器都强烈建议执行的：

1. **开启设备的生物识别解锁 + 锁屏超时**：降低设备丢失后的暴露时间窗口
2. **云服务账户开启 2FA**：Google Drive、OneDrive、Dropbox 等账户本身就是重要防线
3. **定期备份保险库文件**：Safe 支持手动备份到本地文件，建议每季度做一次
4. **使用泄露监测功能**：Safe 的泄露监测通过 Have I Been Pwned 运行，匿名检查邮箱和密码是否出现在公开泄露库中
5. **定期更换高危账户密码**：邮箱、银行、支付账户的密码建议每年更换一次

SafeInCloud 的加密实现开放审计——任何安全研究员都可以提交代码审查请求，检查加密算法的实际实现是否正确。这与完全开源的 Bitwarden 各有优势：开源密码管理器的"林纳斯法则"保证了足够多的眼睛盯着代码，而 SafeInCloud 在闭源前提下通过审计证明加密核心没有问题，同时可以更灵活地迭代功能。
