## ✨ Cherry Studio 是什么

Cherry Studio 是一个面向桌面端的 AI 客户端整合平台。它的核心思路很直接——把你手上的各种大模型服务商、各类 AI 功能（对话、绘画、知识库、Agent 自动化、小程序）、以及日常用的网页服务入口，统一收进一个桌面应用里，账号配一次，全程复用。

它适合谁？大概是这样几类人：已经在用多家大模型服务商（硅基流动、智谱、PPIO 派欧云、OpenAI 等）的，懒得在不同聊天窗口之间来回切的；想把 AI 能力嵌进自己日常工作流的，比如让 AI 每天早上自动生成摘要、派驻到飞书群当值班专家的；还有想轻量体验 AI 绘画但不想单独去 Midjourney 或 DALL·E 官网另起账号的。

从功能版图上看，Cherry Studio 把 AI 桌面端的几个核心环节都铺到了：多助手多对话管理、文生图绘画页面、知识库沉淀、MCP 工具调用、Agent 工作流、频道派驻和定时任务自动化、还有小程序生态。这些模块之间是打通的——Agent 可以挂知识库、调 MCP 工具，生成式小程序可以直接调用你配好的 AI 模型，对话历史可以导出归档或送进知识库做向量化索引。

## 🔧 安装步骤

Cherry Studio 支持 Windows、macOS、Linux 三大桌面平台，各平台安装略有差异但整体流程一致。

### Windows

1. 下载 `.exe` 安装包，双击运行
2. 选择安装路径，默认装到 `C:\Program Files\Cherry Studio`，也可以改到自己常用的软件盘
3. 如果 Windows Defender 弹出杀毒提示，通常是误报——数字签名校验通过即可放行
4. 安装完成后桌面和开始菜单都会生成快捷方式

### macOS

1. 下载 `.dmg` 文件，双击打开
2. 把 Cherry Studio 图标拖进 `Applications` 文件夹
3. 首次启动时如果被 Gatekeeper 拦截，去「系统设置 → 隐私与安全性」里点「仍要打开」

### Linux

各发行版提供 AppImage、deb、rpm 三种格式。AppImage 最省事，下载后加执行权限直接运行，不用安装到系统目录。

> [!TIP]
> **务必核对版本号**：安装前对照下载页确认是最新稳定版。旧版本可能有已知的对话导出 bug 和模型兼容性问题。

装完第一次启动，应用会提示你去「设置 → 模型管理」里配置服务商的 API Key。配好之后才能正常使用对话、绘画等功能——这是樱桃工作室所有功能的前置条件，没配模型等于空壳。

## 📖 使用入门

### 模型配好之后先干什么

第一次打开 Cherry Studio，左边是助手列表，中间是对话界面，右边是启动台快捷入口。建议从这几件事开始：

**先建几个助手**。助手是 Cherry Studio 的核心工作单元——每个助手有自己的人设提示词、挂载的模型、可用的 MCP 工具和知识库。你可以建一个「产品经理」助手、一个「代码助理」助手、一个「写作润色」助手，各自独立管理。同一个助手下可以开多个独立对话，比如在「产品经理」助手里分别开「App 改版讨论」和「新功能评审」两个对话，上下文互不串场。

> [!NOTE]
> 对话历史自动按助手分组归档。切换回某个助手时，它的所有对话列表都在，不用从几千条历史里翻。全局搜索支持跨所有助手的所有对话搜关键词，命中结果直接跳到对应位置。

### 对话管理和导出

对话多了之后 Cherry Studio 提供三层搜索：助手内搜索（只匹配该助手的对话）、全局搜索（跨所有助手）、对话内搜索（打开后搜上下文）。搜索结果显示对话标题加命中文本片段，点进去直接跳。

导出功能支持三种格式：Markdown（适合放 GitHub、Obsidian、Notion 再加工）、Word（适合发邮件、做报告）、PDF（适合归档和打印）。操作在对话右上角「⋯」菜单里，选「导出」，可以导全部也可以只导选中的片段。

> [!WARNING]
> 正常卸载 Cherry Studio 会清除应用数据目录，对话历史会丢失。重要对话请先导出，或者定期手动备份整个 Cherry Studio 数据目录到外部位置。桌面端和移动端的对话历史默认不自动合并，要同步的话靠知识库或导出文件。

### 文生图：复用已配服务商的零门槛入口

Cherry Studio 的绘画页面是个轻量入口——你在模型管理里配的服务商如果包含图像模型（比如硅基流动的 `qwen-image`、智谱的 `cogview-3`），它们会自动出现在绘画页面的模型下拉里，按服务商分组显示。一个账号配一次，对话、绘画、翻译全都能用。

进入绘画页面的路径：启动台 → 绘画，或者顶部标签栏右侧 `+` 打开启动台点绘画图标。页面结构很简单——左侧画板列表、中间画布、底部输入区加服务商和模型选择。

开始画一张图的基本流程：

1. 底部选一个文生图模型
2. 输入提示词，中文英文都行，越具体越好，比如「一只戴着圆眼镜的橘猫坐在书堆上，复古油画风格，温暖的黄昏光线」
3. 调整尺寸（默认 1024×1024 够用）、步数、CFG、随机种子等参数
4. 点击「生成」，等几秒到几十秒
5. 生成的图可以下载、收藏、或者一键再画一张

如果不想每次手动选模型，可以去「设置 → 默认模型 → 绘画模型」里指定一个，以后打开绘画页面自动用它。Gemini 图片生成比较特殊——它是多模态交互式的，不支持 Cherry Studio 绘画页面的参数调节，想用 Gemini 画图的话去对话界面开个 Gemini 模型的对话直接说就行。

和其他绘画工具的对比：

| 维度 | Cherry Studio | Midjourney | DALL·E 3 |
| --- | --- | --- | --- |
| 接入方式 | 复用已配服务商 | Discord 命令行 | 官网 / API |
| 上手门槛 | 已有服务商 → 零门槛 | 需 Discord | 低 |
| 和对话联动 | 可以让对话助手帮你想提示词 | 不联动 | 不联动 |

Cherry Studio 不打算取代这些专业绘画工具，它提供的是一个**轻量入口**——已经在 Cherry Studio 里了、已经有模型账号了，想画一张图直接画，不用切平台。

### 小程序生态：网页服务和本地 AI 小程序一锅端

启动台里的「小程序」入口打开后是网格视图，分两类小程序：

| 类型 | 添加方式 | 能否调用 Cherry AI | 沙盒 |
| --- | --- | --- | --- |
| 网站型 | 填名称 + URL + Logo | 不能 | Cookie 和系统浏览器隔离 |
| 本地生成式 | 安装 `.miniapp` 包或开发者地址 | 可以（安装时授权） | 独立沙盒，不能读本机任意文件 |

网站型小程序就是把常用网页固定进 Cherry Studio，预置了 GitHub、GitLab、Gitee、Notion、飞书文档、掘金、阿里云、OpenAI Playground 等数十家常用服务。Cookie 独立保存在 Cherry Studio 里，和系统浏览器完全隔离——在 Cherry Studio 里登飞书不影响浏览器里的飞书登录。常用小程序可以右键固定到左侧导航栏，一键直达。

本地生成式小程序是特色——开发者写的小程序安装时可以申请调用 Cherry Studio 已配置的 AI 模型。比如一个自定义写作小程序，输入文章标题后直接调你配的 DeepSeek 帮你写初稿。这类小程序运行在独立沙盒里，不能读电脑上的任意文件，安装时会弹窗列出它要申请的权限。

三者的分工：助手是一次对话一次回答，Agent 是自主执行多步骤任务，小程序是固定工作流加用户交互界面。实际工作流里可以配合——比如生成式写作小程序里内嵌一个对话界面，这个对话背后绑定一个助手，助手又挂了知识库。

### Agent 自动化：频道派驻和定时任务

Cherry Studio 提供两种让 Agent 在后台自主运行的方式：

| 方式 | 运行触发 | 典型场景 |
| --- | --- | --- |
| 频道派驻 | 群成员发言时自动触发 | 技术支持值班、销售 FAQ、新员工培训、开源项目维护 |
| 定时任务 | 到点自动触发 | 每日摘要、周报生成、系统状态巡检、数据同步、会议纪要归档 |

频道派驻的配置流程：接入飞书 Bot 或 Discord Bot 凭证 → 选一个配好的 Agent（建议挂载知识库和常用 MCP 工具）→ 派驻到指定群。群里有人 @机器人或直接提问时，Agent 自动接手处理，结果发回群里。推荐用「智能批准」或「完全访问」权限模式，因为无人值守运行需要自动执行。

定时任务用 cron 表达式描述触发时间，常见的几个：

| cron 表达式 | 含义 |
| --- | --- |
| `0 9 * * *` | 每天早上 9 点 |
| `0 17 * * 5` | 每周五下午 5 点 |
| `0 */1 * * *` | 每小时整点 |
| `0 3 * * *` | 每天凌晨 3 点 |

定时任务可以把结果发送到指定飞书群、写入文件、或者展示在 Cherry Studio 里。

> [!WARNING]
> 频道派驻和定时任务都需要 Cherry Studio 在后台运行——桌面端最小化到系统托盘就行。如果想 7×24 无人值守跑，建议部署到一台常驻的服务器或 NUC 上。Cherry Studio 没在运行的话，定时任务和频道响应都不会触发。
