## ✨ itch 是什么

itch 是 itch.io 平台的官方桌面客户端——itch.io 本身是一个主打独立游戏分发的数字商店，开发者可以直接上传作品，玩家可以付费购买或免费下载。itch 客户端把网页端的浏览、下载、库管理搬到了桌面上，对于经常光顾 itch.io 的玩家来说，它比每次打开浏览器要顺手得多。

客户端的核心价值不在于"能下载游戏"，而在于**统一管理**。通过客户端下载的游戏会自动归档到库里，支持启动配置、自动更新、卸载清理等完整生命周期操作；甚至你从网页端手动下载的游戏目录，也能通过"链接已有文件夹"功能纳入客户端管理，不需要重新下载一遍。

它支持 Windows、macOS 和 Linux 三大桌面平台，界面风格朴素直接，没有花里胡哨的商店包装，重点放在游戏库的检索和组织上——对于喜欢独立游戏、对 Epic 或 Steam 的商店界面感到疲劳的玩家来说，itch 提供了一个更轻量的选择。

## 🔧 安装步骤

itch 的安装在三大平台上走的都是标准路线，但每个平台有几个值得注意的细节。

### macOS 安装

macOS 用户下载 dmg 安装器后打开，把 itch.app 拖进 Applications 文件夹即可。安装完成后应用会自动启动。

> [!NOTE] 首次双击没反应？
> 官方文档自己承认了一个偶发现象：**双击 dmg 里的安装器如果没反应，再试一次就行**。这是安装器本身的小毛病，不影响后续使用，也不是你电脑的问题。

如果你对应用的来源有顾虑，可以在终端跑一条命令验证签名：

```bash
spctl -a -vvvv ~/Applications/itch.app
```

签名正确时会输出 `accepted` 和 itch corp 的 Developer ID 标识，看到这两项就可以放心用了。

### Windows 与 Linux

Windows 走标准的安装包流程，下载后双击安装器、选择安装路径、一路下一步即可。Linux 用户可以选择 AppImage（免安装，双击直接跑）或者系统包管理器安装，两种方式都能正常使用全部功能。

> [!TIP] 安装目录的选择
> 默认安装路径就够用，但如果你的磁盘空间紧张，想把游戏库放到其他盘符，这一步之后在应用内就能调整——安装目录和游戏存储位置是分开的两个设置项，互不影响。

安装完成后打开应用，它会自动检查更新，版本号和你下载的安装器一致就可以继续下一步。

## 📖 使用入门

安装好了，但这才刚开始。itch 客户端的使用有几个关键节点：首次登录、把已有游戏纳入管理、以及让客户端自动帮你盯更新。

### 首次登录：浏览器授权流程

itch 客户端**必须登录才能使用**——网页端虽然支持匿名浏览和匿名下载，但客户端不提供匿名模式。游戏库、购买记录、集合这些功能全部锚定在你的 itch.io 账号上。

登录走的是 OAuth 浏览器授权路线，而不是在应用窗口里直接填密码。整个流程是这样的：

1. 打开应用后会弹出登录提示，点击进入下一步
2. 应用自动调起系统默认浏览器，跳到 itch.io 的登录页
3. 在浏览器里正常输入账号密码，如果开了两步验证就照常完成两步验证
4. 登录成功后浏览器会弹出授权确认页，点击同意
5. 控制权自动交回应用，登录完成——全程不需要手动粘贴任何授权码

> [!WARNING] 旧通道即将退役
> 应用里还残留了一个传统的用户名密码登录入口，但官方已明确它会在未来版本中移除。遇到登录问题时，**优先走浏览器授权路线**，不要在旧通道上浪费时间。

登录成功后你会看到应用主界面，左侧是游戏库，右侧是推荐和分类入口。

### 链接已有文件夹：把手动下载的游戏纳入管理

不是所有游戏都经过 itch 客户端下载。你可能从朋友那里拷了整个游戏目录，或者早年在网页端下载过 zip 自己解压的——这些目录缺少客户端的登记特征，它的"扫描安装位置"功能认不出来。这时候就要用到**链接已有文件夹**。

链接和扫描的分工很清晰：

| 功能 | 适用对象 | 原理 |
| --- | --- | --- |
| 扫描安装位置 | 客户端自己下载安装的游戏 | 遍历目录，按登记特征认领 |
| 链接已有文件夹 | 手动下载/拷贝的游戏目录 | 手动指定目录，与应用内的库条目挂钩 |

两者的目标一致：让客户端重新获得对这个游戏目录的管理权——包括启动配置、更新跟踪和卸载。

操作也不复杂：在游戏库中找到对应游戏的条目（你账号拥有它就会有条目），从游戏的管理入口选择"链接已有文件夹"，然后指向磁盘上的游戏目录即可。应用会记住这个路径作为该游戏的安装位置之一。

> [!NOTE] 链接后的更新行为
> 手动来源的游戏目录，文件结构可能和客户端的预期不完全一致，后续更新跟踪可能出现偏差。如果更新后游戏启动出问题，最干净的解决方案是删掉手动版本，让客户端重新下载安装。

### 游戏自动更新：它在后台帮你盯着

独立游戏的更新节奏很碎——jam 作品赛后连修三个补丁是常事。itch 客户端把更新做成了**完全自动的后台事务**，你通常只需要知道它什么时候发生。

更新检查有两个时机：

- **应用启动时**：打开应用就会先查一轮所有游戏的最新版本
- **运行期间每 30 分钟轮询一次**：不用你手动刷新

下载什么版本由游戏本身决定。如果游戏只有一个可用版本，客户端直接静默下载安装，不打扰你；如果游戏挂了多个候选版本（比如多平台、多构建），会弹出列表让你挑——当初怎么选的，更新时还怎么问。

开发者使用 butler 工具推送构建时，客户端还支持**增量补丁**：只下载与旧版本有差异的部分。几百 MB 的更新可能只传几 MB，体验上几乎无感。

更新过程对存档是安全的。客户端采用对账式更新：新版本里有、旧版本里也有的文件被替换；新版本里删掉的文件从安装目录移除；而**游戏运行时自己生成的文件**（存档、配置、用户数据）原样保留——这是它的设计承诺，大多数情况下存档都能安然无恙。

> [!TIP] 需要手动干预的场景
> 通过 Steam 快捷方式直连启动的游戏不会自己更新——它们绕过了 itch 客户端的启动流程。偶尔打开一次应用让它检查更新即可。另外，手动解压然后链接的游戏目录，更新跟踪可能不准，发现异常时手动触发一下检查。
