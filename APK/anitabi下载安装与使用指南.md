## ✨ Anitabi 是什么：圣地巡礼人的协作地图

Anitabi 是一个专为动漫圣地巡礼爱好者打造的协作式地标地图平台。它以 Bangumi（番组计划）的作品条目为索引，把社区贡献者标注的动画/漫画取景地坐标、对应截图、出现集数和时间戳全部汇集到一张可交互的地图上——从《吹响吧！上低音号》的京都宇治到《鬼灭之刃》的云取山，你能在这里找到几乎所有热门番的实景参照点。

与 Google Maps 或高德地图不同，Anitabi 不做通用导航，它的一切设计围绕「巡礼」这个场景：地标详情页直接嵌入对应的动画帧截图，点开就能对照街景；作品页聚合该作品的全部取景地，支持按 EP 顺序浏览；社区审核机制保证地标精度——十几米以内误差算正常，几十米以上可能打回。

平台核心数据来自社区贡献，同时开放 API 供个人项目和开源项目接入。它适合三类用户：计划实地巡礼的动漫粉丝、希望给现有地标补全截图或修正坐标的贡献者、以及想用 Anitabi 数据做二次开发的独立开发者。

## 🔧 开始之前：注册登录与基础配置

Anitabi 本质上是一个 Web 应用，不需要安装任何客户端。打开浏览器访问主站即可进入地图界面，但注册登录能解锁更多功能：地标编辑、投稿提交、历史记录同步。

### 注册与登录

1. 打开 Anitabi 主站，点击右上角登录按钮
2. 目前支持 Bangumi 账号直接跳转授权登录——这对巡礼人来说是最方便的方式，作品列表和偏好设置会自动关联
3. 首次登录后建议先进入个人资料页，设置一个贡献者昵称，方便其他巡礼人在你提交的地标上看到署名

### 底图切换与坐标系

底图的选择直接影响地标定位的视觉准确度，这点经常被忽略：

| 底图 | 坐标系 | 适用场景 |
| --- | --- | --- |
| Google Maps | WGS-84 | 日本、台湾、海外地区最准 |
| 百度地图 | GCJ-02（火星坐标） | 中国大陆境内有加密偏移 |
| 必应地图 | WGS-84 | 卫星视图精度好 |
| 卫星视图 | 原始卫星影像 | 核对地物轮廓、避开底图偏移干扰 |

> [!NOTE]
> 如果你发现多个地标整体往同一个方向偏了差不多的距离，大概率不是地标本身标错了，而是底图坐标系不匹配。这时候切换到底图为「卫星视图」或「必应地图」再看一遍，往往能解决。

### 配套工具链

资深巡礼人通常配合两个工具使用 Anitabi：

- **PotPlayer**：本地播放器，截取动画帧时文件名会自动带上 EP 和时间戳，上传到 Anitabi 时能直接填入
- **trace.moe**：反向图片检索服务，用来确认某一帧具体属于哪部作品的哪一集哪一秒——截好图后先过一遍 trace.moe 抓准时间，提交审核时通过率会高很多

## 📖 使用入门：从搜作品到贡献地标的完整链路

### 搜不到作品怎么办

Anitabi 里有两种「搜不到」，解决路径完全不同：

**情况 A：搜作品名没任何结果**

这意味着 Bangumi 上也没有该作品的 Subject 条目。你需要先到 Bangumi 社区创建条目——登录后点右上角头像 → 编辑数据 → 新建条目，填写原名、中文译名、类型、开播日期和封面图，提交后等待社区审核。审核通过拿到 Subject ID（bangumi.tv/subject/{subjectID} 里那串数字），回到 Anitabi 地图搜索框直接粘贴 Bangumi Subject 链接，Anitabi 会自动创建作品。

> [!WARNING]
> Bangumi 编辑社区非常严格，不要随便乱建条目。条目需要有足够的权威来源支撑（IMDB、维基百科、官方网站等），太冷门或信息不全的条目会被删除。

**情况 B：能搜到作品但地标数为 0**

作品在 Bangumi 上存在但还没人贡献地标——这时候轮到你出手了。搜 Bangumi Subject ID 有时比搜作品名更精准；地图飞到作品位置后点空白坐标，选择「添加地标到当前作品」，上传 PotPlayer 截好的帧，填入 EP 和秒数，提交审核即可。

搜索本身也有技巧：搜不到可以换关键词试试——中文名换原名（日文/英文），全称换简称，反过来也试试。部分作品有后台设置的缩写名（比如 SHN 对应《吹响吧！上低音号》），全名搜不到就试试缩写。

### 地标坐标偏了怎么排查

巡礼到现场发现地标对不上街景？先判断偏差范围再决定修不修：

| 偏差范围 | 可能原因 | 严重程度 |
| --- | --- | --- |
| < 20 米 | 正常误差（GPS / 手动标记精度） | 忽略 |
| 20 - 100 米 | 贡献者标不准 | 可以修正 |
| 100 - 500 米 | 标错了整条路 / 相邻建筑 | 需要修正 |
| > 500 米 | 完全标错地点 | 必须修正 |

自己核对坐标有三种常用方法：

1. **Google Street View 对比**：地标详情页点「使用谷歌导航」拿坐标，在 Google Maps 里打开 Street View，对比动画截图和实景是否对得上
2. **经纬度直接比**：地标详情左上角显示经纬度，复制粘到 Google Maps 搜索框，看红色大头针扎在哪
3. **现场 GPS 定位**：如果你人在现场，用手机 GPS 定位自己当前位置，看 Anitabi 地标与你实际位置的偏差

确认偏了之后，进地标编辑器（需要登录）在地图上重新点正确位置，坐标自动更新，检查截图对应关系后提交即可。Anitabi 的社区审核标准是十几米以内误差可以接受，几十米以上可能打回要求重新定位。

> [!TIP]
> 有些场景不必纠结精确到米：学校、图书馆、政府机关大体位置对就行；室内取景（餐厅、商场、博物馆）只能标建筑物外轮廓；海上、野外、特殊地形本来就难精确。巡礼的本质是找到对的区域，不是厘米级的 GPS 定位。

### 截图上传后加载不出来的排查

截图上传成功但地图上看不到，先看时间线判断是哪种情况：

| 时间线 | 原因 | 解决 |
| --- | --- | --- |
| 上传完立刻不显示 | 审核中（社区志愿者还没审到） | 等几天 |
| 等了一周还不显示 | 可能没通过审核 | 查通知，改后重提 |
| 自己看不到但别人能看到 | 浏览器缓存 | Ctrl+Shift+Delete 清缓存 |
| 提交时报错 | 格式或尺寸问题 | 按规范调整后重传 |

最常见的原因就是审核中。热门番（如鬼灭、海贼王）审核量大会比较慢，3-7 天正常；冷门番可能更快也可能超慢（没人看）；KML 批量导入走批量审核通道稍快。

审核没通过的常见触发点：上传了手机截屏、上传了动画+实景对比图、非 16:9 比例、截图带播放器 UI（进度条/弹幕/水印）、EP/时间戳填错、来源未填写。PotPlayer 截的帧一般没问题（文件名自动带时间），手动填或 trace.moe 抓错作品的概率更高。

网络问题也可能导致加载异常：Anitabi 图片走 image.anitabi.cn、数据走 api.anitabi.cn，主域 anitabi.cn 挂了不影响图片。主域正常但图片加载慢时，可以换备用地址 w.anitabi.cn/map，或清浏览器缓存、换浏览器试试。

### 开放 API 与二次开发

Anitabi 提供免费开放 API，允许非商业非盈利项目调用地标坐标、截图等信息。两个基础地址要记清楚：

- **数据 API**：`api.anitabi.cn`——所有地标、作品、统计数据
- **图片 API**：`image.anitabi.cn`——缩略图和原图

> [!WARNING]
> 不要在任何场景下请求主域 anitabi.cn 来拿数据，主域不确保资源地址和数据结构的稳定。

常用端点只有两个：

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/bangumi/${subjectID}/lite` | GET | 某作品的轻量版巡礼信息：城市、主色、前 10 个地标、地标总数 |
| `/bangumi/${subjectID}/points/detail` | GET | 某作品的完整地标详情：全部地标的截图、EP、秒数、来源 |

API 明确禁止商业项目调用（含 App 内广告、付费功能）和爬虫大批量抓取。展示时建议用缩略图参数（`plan=h160` 或 `plan=h360`），完整尺寸截图会给服务器造成压力。批量调用建议加每秒 1 个请求的延迟。
