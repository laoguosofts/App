## ✨ Skit 是什么：一款轻量的 Android 应用管理工具

Skit 是一款面向 Android 设备的应用信息查询与管理工具，核心定位是让用户对手机里装了什么、占了多少、多久没用过这些问题有一个清晰的视图。它不做应用商店，不做卸载器，而是专注于把每款已安装应用的元数据、存储占用、使用频率这些信息以结构化的方式呈现出来——从个人开发者到做逆向排查的技术人员，都能找到自己需要的那一层深度。

从功能覆盖面看，Skit 大致可以分成三块：**信息查询**（应用详情、证书、组件、活动等一切能拿到的字段）、**日常管理**（排序筛选、体积统计、使用报告）、**清单导出与迁移**（应用清单 JSON、分包安装器）。界面支持深色模式跟随系统自动切换，3.6 版本之后做了 edge-to-edge 的全面适配，状态栏和导航栏区域与内容背景融为一体，没有白条割裂感。

> [!TIP]
> 如果你只是想卸载应用或清理缓存，系统自带的应用管理就够用；Skit 真正发挥价值的场景是：排查仿冒应用时需要核对包名和签名证书、换机时想精确导出装过的应用清单而不是整机备份、或者单纯想搞清楚哪款应用在后台偷偷占流量。

功能上比较值得关注的几个点：3.4 版本给所有排序维度补上了倒序开关，体积从大到小、时间从新到旧都不用翻到底部；3.5 版本加了详情页长按复制，包名、版本号、证书字段随手就能贴到笔记或排查表里；应用清单从自定义 TXT 升级为带体积、安装时间、SDK 版本等附加信息的 JSON 格式，既方便换机迁移，也能直接当存储盘点工具用。

## 🔧 安装步骤

Skit 目前主打 Android 平台，安装流程对有过安装第三方 APK 经验的用户来说没有障碍，核心就是两步：**允许未知来源** + **核对包名和签名**。

### 允许未知来源安装

系统设置路径因厂商而异，常见入口：

1. **原生 Android**：设置 → 应用和通知 → 特殊应用权限 → 安装未知应用 → 选择你用来下载 APK 的浏览器或文件管理器 → 允许
2. **MIUI / HyperOS**：设置 → 隐私保护 → 特殊权限设置 → 安装未知应用
3. **ColorOS / OneUI**：设置 → 安全 → 安装未知应用（或通过应用管理里的具体应用权限页进入）

> [!WARNING]
> 允许未知来源是一次性授权，装完可以在同一菜单下关掉。如果是从非官方渠道下载的安装包，务必核对下面的包名和签名，避免装到被二次打包的仿冒版本。

### 核对包名与版本

正式发布的 Skit 安装包，包名为 `com.piyushpatel2005.skit`。你可以用 Skit 自身或任意 APK 分析工具打开安装包，确认包名一致后再安装。版本号可以在下载页和安装后的应用详情里交叉核对。

### 安装完成后的首次运行

第一次打开时会申请「查询已安装应用列表」的权限，这是 Skit 的核心能力来源——不给这个权限，应用列表就是空的。部分系统还会额外申请通知权限和使用情况统计权限，后者用于生成使用报告（哪些应用最近在活跃、哪些长期闲置）。

## 📖 使用入门

下面是几个高频场景的操作思路，从参考文档的实际用法整理而来，覆盖日常查询、清理、换机三条主线。

### 应用详情查询：从基础到证书

点开任意应用卡片进入详情页，能看到的信息分三层：**基础信息**（包名、版本号、安装日期、应用体积、更新时间）、**证书信息**（签名者、证书有效期）、**组件列表**（活动 Activity、服务 Service、广播接收器、内容提供者）。

> [!NOTE]
> 3.5 版本起，详情页、证书页、组件页的所有文本字段都支持**长按复制**——查仿冒应用时把可疑包名长按复制出来，与官方渠道的包名逐字符比对；跨设备核对版本号也不用截图发 OCR 了。这个细节改进虽然小，但高频使用场景下能省不少事。

### 日常管理：排序 + 筛选的组合拳

列表顶部搜索框旁的两个小图标——排序和筛选——是最高频的管理杠杆。排序维度覆盖**名称、体积、安装时间、最后使用时间、数据用量**五个维度，3.4 版本之后每个维度都支持倒序切换（体积从大到小、时间从新到旧）。

筛选管「只看哪一类」，排序管「按什么顺序看」。实战组合举例：

- 筛选系统应用 → 体积倒序 → 预装大块头一眼可见，排查存储占用的首选组合
- 筛选用户应用 → 安装时间正序 → 就是一部装机编年史，最早装的应用顶在最前
- 筛选「未使用超过 30 天」→ 最后使用时间正序 → 清理候选清单直接到手

3.4 版本同一轮重构还解决了排序在部分场景下失灵的老问题，现在切换排序或视图是即时生效的，没有重新加载等待。

### 换机迁移：用 JSON 清单「按图索骥」

换机时最烦的是「装过哪些应用想不全」。Skit 提供了一条极简路径：把整机应用导出成一份 JSON 清单，新手机上照单恢复。

操作步骤：

1. **老手机**：工具页 → Apps list（应用列表）→ 点创建按钮 → 选择要记录的应用范围 → 生成清单文件
2. **传输**：清单文件本身只有几十 KB，聊天工具、网盘、数据线随意
3. **新手机**：打开清单逐个装回，清单里的应用条目可以跳转到商店对应页面

清单迁移和整机备份的边界需要搞清楚：

| | 应用清单 | 整机备份迁移 |
| --- | --- | --- |
| 迁什么 | 「装过什么」的记录 | 应用 + 数据 + 设置 |
| 体积 | 几十 KB | 数 GB 起 |
| 恢复方式 | 照单手动装 | 一键还原 |
| 适用场景 | 换品牌、跨生态、干净装机 | 同品牌换机 |

清单不止服务于换机——导出的 JSON 里自带每款应用的体积、最后更新时间、SDK 版本和安装时间，用来盘点存储占用、检查哪些应用久未更新都很好用。3.5 版本还在生成清单时补记了安装时间字段，这份清单同时就是一份完整的应用档案。

### 深色模式：跟随系统的默认体验

3.1 版本起深色模式的默认值改为「跟随系统」——系统在日落到夜间自动切深色的机型上，Skit 的界面会同步切换，不用任何手动干预。主题设置里保留了三档可选：**跟随系统 / 浅色 / 深色**，随时可以手动锁定。

深色下的实际观感：应用列表、详情页、统计图表完整适配，进度条与环形图的颜色方案随主题联动；3.6 版本的 edge-to-edge 改进同样作用于深色，状态栏和导航栏区域与内容背景一体，没有突兀的白条。跟随系统的好处是与全局一致——省电模式自动切深色、按日程切换等系统级策略，Skit 无须重复实现，也不会出现「系统深色、这个应用还亮着」的割裂感。

搭配高级版的界面定制能力（专属主题与外观微调），浅深两套形态都能调出顺手的样式。
