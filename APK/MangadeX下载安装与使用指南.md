## ✨ MangadeX 是什么

MangadeX 是一款开源的漫画聚合阅读应用，核心价值在于把分散在网络各处的漫画源整合到同一个界面里。它本身不托管任何漫画资源，而是通过扩展系统接入第三方内容源，让用户在一个应用内完成发现、追更、下载、离线阅读的完整流程。

应用的目标用户非常明确——有稳定追更习惯的漫画读者。如果你每天要刷几部连载、偶尔还想发现点新书，MangadeX 的书架管理、批量下载、多源对比这些功能会比在浏览器里挨个翻站高效得多。扩展市场里的源数量不少，常用的几家更新速度和完整度都能跟上主流平台，基本能覆盖日常阅读需求。

**核心功能速览：**

- **多源聚合**：一个应用接入数十家内容源，跨源搜索和对比都在本地完成
- **书架追更**：把在追的作品收进书架，更新自动推送提醒，不用手动巡站
- **离线下载**：支持单章、整卷、批量下载，没网也能继续看
- **阅读器定制**：翻页方向、显示模式、色彩滤镜等阅读体验参数全部可调

> [!NOTE] MangadeX 是开源项目，社区持续维护。应用内的内容源来自第三方，源的可用性和更新时效取决于上游站点，官方不保证所有源始终可用。

## 🔧 安装步骤

### Android 平台

从下载页拿到 APK 安装包后，安装流程分两种情况：

1. **首次安装未知来源应用**：系统会弹出「禁止安装」提示，需要先进入系统设置，找到「安全」或「隐私」相关条目，开启「允许安装未知来源应用」权限。不同品牌手机的设置路径略有差异，一般在设置 → 应用管理 → 特殊权限中能找到。
2. **已有旧版本覆盖安装**：直接点击 APK 文件即可，系统会保留已有书架和设置数据。

> [!WARNING] 安装前建议核对文件大小和版本号。如果下载的 APK 体积明显偏小（低于正常版本的 70%），很可能是下载不完整，删掉重下。部分国产 ROM 自带的安全中心会对第三方 APK 进行病毒扫描拦截，属于正常机制，放行即可。

### 文件大小与版本核对

应用体积通常在 20-40MB 之间，取决于版本和 CPU 架构。如果从非官方渠道获取安装包，务必确认包名以 `eu.kanade.tachiyomi` 开头，这是 MangadeX 的标准应用标识，改包名的第三方构建可能存在安全风险。

### 装完怎么核对

打开应用后，首页会展示默认扩展市场的内容源列表。如果能正常看到源并点开其中的「浏览」或「最近更新」，说明安装成功、网络权限也没问题。首次启动应用会请求存储权限，用于离线下载的章节存放，全部授权即可。

## 📖 使用入门

### 发现页：两种逛法选哪种

进入应用后的默认界面是发现页，每个已启用的内容源右侧都挂着「最近更新」和「浏览」两个按钮。这两个按钮虽然都通向同一个源，但页面内容和适合的场景完全不同：

「最近更新」展示的是该源最新放出的章节列表，按发布时间倒序排列，新的在上。日常巡逻追更时，把常用源的最新章节各扫一遍，比挨个点进作品页快得多。如果你想快速判断某个源「活没活着」，看一眼更新列表的时效性就知道——列表停在几天前的源基本可以考虑换掉。

「浏览」则进入该源的封面墙模式，按站内目录顺序铺开所有作品的封面。刚装好应用、还不清楚各源都收什么内容时，进封面墙快速建立整体印象最有效。追的作品都更新完了想开个新书，也适合在这里闲逛，配合源内的筛选功能按题材缩小范围。

一个省时间的日常组合动作：先扫一遍常用源的「最近更新」处理追更，有剩余时间再挑一个没逛过的源点「浏览」开新坑。追更与开坑两不误，书架也会慢慢长出健康的梯队。

### 下载队列：离线任务的总控制台

所有下载任务都汇入侧栏的下载队列，批量下载几部作品的章节时，队列是判断「到底下到哪了」的唯一权威。

队列里能看到三类信息：正在进行的任务显示当前章节的下载进度与速度；排队的任务按加入顺序等待，前一个完成自动接续；已经下载好的章节留在本机，随时离线可读。

常用的队列管理动作包括：网络切换到流量时暂停队列，回 Wi-Fi 再恢复；下错章节或不想下的书直接取消释放空间；个别章节反复失败时点开任务详情看错误提示，多数是源站临时故障，稍后重试即可。

队列的运行逻辑有两个值得注意的设计：一是**串行推进**，任务按顺序逐个下载而不是并发全开，这是对源站友好的设计，也降低了整体失败率；二是**与书架联动**，下完的章节自动反映到书架的「已下载」筛选里，不用手动登记。

> [!TIP] 队列长时间停在同一个进度、速度恒为零时，先看是不是整网断了；网络正常但就是不动的，取消该任务重新加入比干等有效。

### 下载常见问题排查

离线下载环节的问题集中在上游源、存储和网络三处，以下按排查优先级列出：

**队列卡住不动**：先确认整网是否正常——其他应用能上网的话，多半是单个任务的源临时故障，取消后重新加入即可。队列状态机偶尔也会卡住，重启应用能自动恢复。另外手机空间见底时下载会悄悄失败，记得留足存储空间。

**章节反复下载失败**：如果同一个源上多部作品都下不动，是源的图床或接口故障，等恢复或换源；只有单部作品失败的话，可能是特定章节文件异常，跳过失败章节先下后面的；弱网下大图容易中断，换稳定 Wi-Fi 再批量下载。高峰时段源站拥堵，错峰下载成功率明显更高。

**下载完找不到文件**：离线章节不出现在系统文件管理器的常规目录里，它们存在应用私有存储中。从作品详情页或书架的「已下载」筛选进入阅读即可。就算通过特殊手段看到了私有目录里的文件，也别手工移动或改名，会破坏应用对章节的索引。

### 离线章节突然看不了

这种情况一般有三个原因：应用数据被「清除数据」操作连带着清掉了，只能重新下载；换了设备，离线库存存在本机不跟随，新机上重新下载即可；误删了章节——删除操作不可撤销，批量删之前多看两眼。

### 内容源质量判断

书架的追更体验上限由主力源决定。挑源不该凭第一印象，可以从三个维度做体检，观察一两周就能得出结论：

**更新时效**：看源上「最近更新」列表的新鲜度，以及你收藏作品的章节上架速度。记录某部周更作品「原文更新 → 该源可读」的时间差，译文上架稳定在更新后一两天内为优，长期滞后或更新列表停在几天前为差。

**访问速度**：三个具体动作的响应——点「浏览」出封面墙的速度、点章节出正文图的速度、搜索出结果的速度。偶发慢不算差，时快时慢、随机超时才是危险信号。多数时候两三秒内响应为优，十秒级等待成为常态为差。

**内容完整度**：章节是否缺页、图片是否裂图、热门作品的收录是否完整、章节排列是否乱序。拿一部熟悉的书对照阅读，缺页裂图率心里就有数了。

| 体检结果 | 处置建议 |
| --- | --- |
| 三维全优 | 转正主力源，放心收藏 |
| 更新优、速度一般 | 保留做追更用，阅读换别的源 |
| 完整度差 | 无论其他多好都降级，缺页毁阅读体验 |
| 长期停更 | 移除或禁用该源 |

> [!NOTE] 源体检结论只说明「这家站整体如何」，具体到某本书，同源不同书的翻译质量也可能天差地别。换源重收一部书之前，先试读确认译文质量再做决定。
