## ✨ Sophclaw 是什么

Sophclaw 是一款以**跨会话记忆**和**多 Agent 隔离**为核心特色的 AI 智能体运行平台。与常规的对话式 AI 助手不同，Sophclaw 允许你为每个独立的使用场景配置专属的"龙虾"——它会把对话中产生的重要信息持久化存储在本地工作区，下次会话自动加载恢复上下文，就像一只真的记得你的个人助理。

平台覆盖手机端和 PC 客户端两条产品线。PC 端又细分为常规版和 **SophCode Desktop**（开发者增强版），后者专为代码编写场景设计，提供 diff 审阅与写入前确认机制，确保 AI 不会悄悄修改你的代码基线。无论是日常自动化任务、团队协作机器人，还是需要严格安全边界的开发工作，Sophclaw 都能通过灵活的工作空间隔离和工具权限配置，让多个 Agent 各司其职、互不串扰。

> [!NOTE]
> 如果你需要一只"懂自己"的龙虾，可以在初始化完成后逐步修改 Agent 的身份文件来设定它的行为边界——这是 Sophclaw 个性化能力的核心设计。

## 🔧 安装指南

### 手机端安装

手机端的安装流程和普通 App 无异——在应用商店搜索 Sophclaw 下载安装，首次启动后用 Sophnet 账号完成验证码登录即可。登录后回到首页点击"即刻体验"或"创建 Sophclaw"按钮，服务端会在几秒到几十秒内拉起智能体实例，初始化完成后对话框变成可输入状态。

### PC 常规版安装

常规 PC 客户端适合非代码类的通用任务（文档整理、数据处理、自动化脚本等）。安装包体量不大，双击运行后按向导选择安装路径即可。安装完成后用 Sophnet 账号登录，在控制台或 Web 控制台里执行创建命令，首次创建时会自动拉取依赖和初始化工作空间。

### SophCode Desktop（开发者版）安装

如果你是开发者、主要用 AI 来写代码，SophCode Desktop 是更好的选择。它自带完整的 Node.js 运行时，不需要你自己装依赖，首次安装时间可能在 5~10 分钟。安装完成后打开客户端，登录 Sophnet 账号，在控制台里执行创建命令或通过 Web 控制台创建智能体实例，等待状态变为"就绪"即可开始对话。

> [!TIP]
> SophCode Desktop 和常规 PC 客户端不是替代关系——非开发任务用常规版，开发任务切到 SophCode Desktop，两个客户端可以在同一台机器上共存。

### 安装后核对

创建完成后，服务端已经自动帮你做了这些事：拉取 Agent 运行时环境、初始化工作空间目录结构、加载默认的基础配置（身份、记忆、工具权限）、连接你选定的大模型后端。建议先派一件小而完整的事来验证整条链路是否通畅，比如让它写一份按重要程度排序的待办事项清单——这样能同时确认模型后端连接、指令理解和执行都正常。

## 📖 使用入门

### 认识你的龙虾：四个身份文件

每只 Sophclaw 都有四份核心身份文件，这是它个性化能力的来源。你可以在控制台或 PC 客户端里随时查看和编辑：

| 文件 | 作用 | 什么时候改 |
| --- | --- | --- |
| SOUL.md | Agent 的核心身份定义（名称、定位、风格、角色说明） | 想要调整龙虾的人设时 |
| MEMORY.md | 长期记忆存储空间 | 自动维护，也可以手动追加重要信息 |
| AGENTS.md | 工作规则（允许做什么、禁止做什么、产品知识库等） | 需要划定权限边界或补充领域知识时 |
| TOOLS.md | 可用的工具清单 | 安装新工具或回收不需要的工具时 |

这些文件都存放在 Agent 各自的 workspace 目录里，和其他 Agent 完全物理隔离。

### 多 Agent 隔离配置

当你需要让多只龙虾同时干活时（比如一个主助手、一个飞书专属助手、一个钉钉专属助手），**必须为每个 Agent 配置独立的 workspace**。共用 workspace 会导致记忆串扰、文件互相覆盖、权限边界模糊——这是 Sophclaw 使用中最常见的踩坑点。

配置方法是在 Sophclaw 的配置文件中，为每个 Agent 在 `agents.list` 里指定独立的 workspace 路径，然后在各 channel 的配置里通过 `agentId` 把消息路由到对应的 Agent。这样飞书消息自动进飞书专属 Agent 的 workspace，钉钉消息进钉钉专属 Agent 的 workspace，各自的记忆和文件完全独立。

> [!WARNING]
> 如果你的客服 Agent 会收到外部用户的消息，务必给它单独分配一个只读权限的 workspace，不要让它能访问到主 Agent 的正式工作目录——否则一条恶意指令可能直接删掉你的重要文件。

每个 workspace 里的内容大同小异，都包含 SOUL.md、MEMORY.md、AGENTS.md、TOOLS.md 这几份身份文件，以及该 Agent 执行指令时生成的所有产物（文档、表格、代码等）。隔离做好了，每个 Agent 就像独立的"员工"——有自己的工位、自己的岗位职责、自己的记忆，不会串岗也不会越权。

### 开发者专属：diff 审阅与写入前确认

这是 SophCode Desktop 最核心的差异点。在常规 PC 客户端里，AI 对文件的修改是直接写入的——在大型代码库里动错一个文件，除非你主动去看 git diff，否则可能悄悄进入你的代码基线。而在 SophCode Desktop 中，AI 不会直接写文件，而是先生成类似 git diff 格式的修改预览，由你审阅后再决定是否应用。

你有三个选择：**接受**（AI 写入修改）、**拒绝**（AI 放弃这处修改，可能换一种方案重试）、**修改后接受**（你手动调整 diff 内容再让 AI 写入）。这条路径确保每一处变更你都看到、每一处变更都经过你确认——AI 不会悄悄改你的代码。

除了 diff 审阅，SophCode Desktop 的本地安全执行也比常规版更严格：每个 workspace 对应一个开发项目或独立工作目录，workspace 外的文件 AI 完全看不到，项目依赖的第三方库（node_modules、venv 等）默认只读。对于已经在用 Git 做版本管理的开发者来说，diff 审阅和 Git 的配合非常自然。

### 远程协同：本地 Agent + 云端 Agent

很多开发任务需要本地和云端同时出力——本地代码需要云端 GPU 做模型训练，或者需要云端大模型做大规模重构。这时候 SophCode Desktop 会自动调度**远程协同**模式。

协同架构分三层：本地 Agent 跑在你的电脑上，负责文件读写、终端命令执行和 diff 审阅交互；云端 Agent 跑在 Sophclaw 服务器上，负责大模型推理、GPU 算力和云端 API 调用；两者之间通过 TLS 1.3 加密的 WebSocket 安全通道通信。

触发方式很简单——你下发指令时 SophCode Desktop 会自动判断是否需要云端能力：

> "帮我用本地的 train.py 脚本训练模型，需要用到 GPU 算力"

Sophclaw 的处理流程是：先在 diff 里生成修改 train.py 的改动（如果需要调整参数适配云端环境），你确认后写入本地，然后把训练脚本推送到云端 Agent 用 GPU 跑训练，训练结果和日志实时回传到本地，本地 Agent 把结果整理后告诉你。整个过程你只需要看进度、审阅 diff，不需要手动管理本地和云端的文件传输。

> [!NOTE]
> 如果你完全不涉及需要云端算力的任务（纯本地文件操作、轻量脚本、纯文本处理），远程协同这个功能对你暂时用不上，先把 diff 审阅和本地沙箱用好就行。本地 Agent 会优先在本地执行——只有确实需要云端时才会调度。

### 进阶玩法：Agent Teams 协同开发

SophCode Desktop 原生支持多 Agent 协同做一个开发任务——一个 Agent 负责写代码、一个负责写测试、一个负责代码 review、一个负责文档更新。每个 Agent 有独立 workspace 和独立权限，最后汇总到主 workspace 供你统一审阅。这个能力适合需要并行推进多个子任务的团队开发场景。
