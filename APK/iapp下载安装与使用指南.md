## ✨ iApp 是什么

iApp 是一款在安卓设备上运行的低代码开发工具——简单说，不用电脑、不用复杂的编译环境，拿一部手机就能做出安卓应用甚至小游戏。它的核心卖点是内置了自研的"裕语言"脚本体系，配合可视化的界面编辑器，让没有编程经验的用户也能从零搭出有实际功能的 App。

从最早的单语言版本到现在支持跨平台打包的 V7，iApp 走过了十年时间，积累了大量社区源码、教程和第三方资源。无论是想做一个简单的工具类应用（比如文件管理器、数据查询面板），还是想在手机上快速原型一个界面、甚至用它内置的 iGame 模块做 2D 小游戏，它都能覆盖。对于学习编程的新手来说，iApp 也是一个不错的入门载体——边做边学，即时看到效果。

> [!NOTE]
> iApp 的社区生态比较活跃，网上流传的源码案例以裕语言 V3 和 V7 为主，入手前先了解一下版本谱系会省不少事。

## 🔧 安装步骤

iApp 是安卓平台上的独立安装包，安装过程与普通 APK 应用类似，但有几个注意点需要留意。

1. **下载来源核对**：建议从下载页或官方渠道获取安装包，第三方下载站的版本可能存在差异。文件大小通常在几十到百多 MB 之间，下载完成后可以做一下 MD5 校验。
2. **未知来源授权**：安卓系统默认禁止安装非应用商店的应用，首次安装时需要手动打开"允许安装未知来源应用"的开关。不同手机品牌的设置路径略有差异，一般在「设置 → 安全 → 安装未知应用」里找到你的文件管理器或浏览器，允许它安装应用即可。
3. **安装过程**：正常点击安装包、选择安装位置（建议内部存储，能获得最佳读取速度），等待几秒完成。安装包可以在应用首次启动后删除，不影响运行。
4. **首次启动验证**：打开 iApp，进入"关于"或"设置"页面确认版本号是否与下载说明一致。新版 iApp 首次启动还会请求存储权限，允许后才能正常读写项目文件。

> [!WARNING]
> 部分国产 ROM（MIUI、ColorOS、OneUI 等）对未知来源应用的权限管控更严格，安装时可能弹出病毒提醒或要求特殊授权，这属于系统安全策略，不是 iApp 本身的问题。

## 📖 使用入门

安装好 iApp 之后，创建项目、搭界面、写代码、打包发布——整个流程都可以在手机上完成。下面按实际上手的顺序把几个关键环节过一遍。

### 创建项目与选择语言

打开 iApp，新建项目时首先要选的就是"语言类型"。目前可以看到五个选项：裕 V7、裕 V6、裕 V5、游戏（iGame）、裕 V3。

| 语言版本 | 语法风格 | 推荐场景 |
|---------|---------|---------|
| 裕 V7 | 类 C 风格，`s a = 1` 直接赋值、`if`/`for` 结构清晰 | **新项目首选**，唯一支持跨平台打包（exe/ipa/html/鸿蒙） |
| 裕 V3 | 单字母指令 + 中文助记，如 `s` 赋值、`f` 判断 | 看老教程、读社区源码时必须会读 |
| 裕 V5/V6 | V3 的扩展版和中间迭代版 | 存量项目维护 |
| iGame | 场景 + 精灵 + 帧循环 | 做小游戏（贪吃蛇、打砖块等 2D 项目） |

如果是完全新手、目标是做普通应用，直接选裕 V7 就行。它的语法最接近主流编程语言的直觉，而且跨平台能力是其他版本没有的。

### 界面搭建与常用控件

项目建好后进入界面编辑器。iApp 的组件面板里有不少控件，按用途分四类来选会清晰很多：

**展示类**：文本（段落/行内）、图像、视图容器——标题、说明、卡片式布局都靠它们。视图容器本身不显示内容，用来圈一块区域装其他控件，做底部导航栏、卡片分组时必须先用容器分区。

**输入类**：输入框（单行，账号/搜索词）、文本域（多行，留言/日记）、下拉列表（固定选项让用户挑，比手输规范）。

**操作类**：按钮——几乎每个应用都离不开，配合"点击事件"绑定代码逻辑。

**数据展示类**：列表——展示消息列表、商品列表这类重复结构数据。注意列表控件不能直接拖子组件进去，需要先设计好列表项样式再动态加载。

**媒体类**：音频 / 视频播放器控件，做播放器界面或视频列表页用。

> [!TIP]
> 控件选型的通用原则：能选窄的不选宽的，能少一层容器就少一层——控件树越简单，后面写事件、调位置越省事。

### 裕语言 V7 的变量与类模块

在 V7 里，变量分四种：普通变量、响应式变量、全局变量、固定变量。响应式变量是界面绑定的核心——它的值变了，界面上引用它的控件文本会自动刷新，不需要手动更新。这和前端框架的数据绑定思路类似，也是 V7 比 V3 用起来顺手的一个原因。

项目变大之后，类模块是必须掌握的组织手段。假设"判断密码是否合法"这段逻辑在登录、注册、改密码三个地方都要用到，没有类模块就得复制三份，改规则要改三处。把它抽成一个模块 `mk1`，三处都写 `mk1.abc()` 调用就行，维护成本一下降下来。

V7 还有个方便的设定：**界面本身就是类**。每个界面自带载入、更新、销毁等事件方法，你在界面里写的事件代码本质上就是往这个类里填方法。理解这一点之后，"导入界面传数据""提供与注入数据"这些功能就好懂了——都是在界面类之间传递数据或调用方法。

### iGame 游戏开发

如果选了"游戏"类型创建项目，iApp 会切换到游戏开发体系：界面组织变成"场景 + 精灵 + 帧循环"，关心的是画面刷新、碰撞检测、计分这些游戏逻辑，而不是普通应用的"界面 + 控件 + 事件"骨架。官方为 iGame 录制了独立的视频教程系列，还做过《我的江湖》这种完整游戏的开发实录，跟着走一遍比啃零散知识点效率高得多。

> [!NOTE]
> 游戏逻辑比普通应用更吃性能，定时器的停用纪律和线程意识在这里更重要。建议第一个游戏目标定小一点（贪吃蛇、记忆翻牌这个量级），先玩透"帧刷新 + 触屏控制 + 计分"三件套再往上加复杂度。
