## ✨ Qoder CN 是什么

Qoder CN 是一款面向开发者的 AI 编程助手，以 IDE 插件和桌面端两种形态交付，核心能力涵盖代码补全、行间会话、自主任务委派（Quest）和数字员工（QoderWake）四个模块。它不是简单的代码补全器——Quest 可以让 AI Agent 像初级工程师一样自主规划、编码、跑测试、交付改动，QoderWake 则把 Agent 升级成 7×24 值守的数字员工，支持定时、事件、API 三种触发方式。

从定位上看，Qoder CN 瞄准的是「开发全流程 AI 化」：写代码时它在编辑器里给你行间补全和就地问答；跨文件重构、功能实现这类重活可以丢给 Quest 自主委派；每日巡检、PR 自动审查这种无人值守的事情交给 QoderWake。四者串起来，覆盖了从单次编码到批量自动化的完整链条。

界面分两个主要区域：左侧是代码编辑器，内置行间会话（Inline Chat）入口；右侧是 Ask/Agent 面板和 Quest 任务看板。行间会话绑定当前代码上下文，适合单文件、局部修改；Agent 面板可以跨文件、跑命令、调 MCP 工具；Quest 则把 Agent 升级成任务管理系统，支持多任务并行、状态追踪、审批流。

> [!TIP]
> 第一次上手建议先花 10 分钟走一遍「行间会话 → Agent 面板 → Quest 任务」的基本流程，感受三个层级的边界——行间会话轻量、Agent 面板灵活、Quest 重管理，选对入口能省不少来回切换的时间。

## 🔧 安装步骤

### 桌面端安装

Qoder CN 以桌面应用形式分发，安装包体积适中，整个过程不依赖额外运行时。

1. 从下载入口获取对应平台的安装包（Windows 为 `.exe`，macOS 为 `.dmg`）。
2. **核对版本号**：安装前确认下载页标注的最新版本号与安装包文件名一致，避免拿到旧版本。
3. 运行安装程序：
   - **Windows**：双击 `.exe`，默认安装到 `C:\Program Files\Qoder CN`，可自定义路径；如果杀毒软件弹窗提示，选择「允许」——Qoder CN 需要与本地 IDE 通信属于正常行为。
   - **macOS**：双击 `.dmg`，将 Qoder CN 拖入 Applications 文件夹；首次打开如果被系统拦截，在「系统设置 → 隐私与安全」里点「仍要打开」。
4. 首次启动后，IDE 插件会自动加载——在 VS Code 或 JetBrains IDE 里可以看到 Qoder 的侧边栏图标。

> [!WARNING]
> 如果安装后 IDE 里找不到 Qoder 插件，先确认桌面端是否已登录（右上角头像是否亮起），再检查 IDE 的扩展市场里 Qoder CN 插件是否启用。某些安全策略严格的企业环境可能需要手动放行插件加载。

### IDE 插件单独安装（可选）

如果只想要插件不需要桌面端，也可以在 IDE 扩展市场里搜索「Qoder CN」直接安装——不过桌面端提供了 Quest 任务看板和 QoderWake 管理界面，功能完整度更高，建议还是装全。

### 安装后核对

启动桌面端后，依次检查：

1. **右下角状态指示灯**是否为绿色（表示已连接 AI 服务）。
2. **IDE 内联补全**是否生效（在编辑器里输入代码，是否出现灰色建议行）。
3. **右侧会话面板**能否正常打开（快捷键通常是 `Ctrl/Cmd + Shift + I`）。

三项都正常，安装就没问题了。

## 📖 使用入门

### 第一层：行间会话——就地问、就地改

行间会话（Inline Chat）是 Qoder CN 最常用的入口。它绑定当前代码上下文——你选中哪段代码，或者光标停在哪个函数里，Qoder 自动把那段代码作为对话的前提，不需要你手动粘贴。

| 操作 | Windows | macOS |
|---|---|---|
| 打开行间会话 | `Ctrl + I` | `⌘ + I` |
| 发送请求 | `Enter` | `Enter` |
| 应用生成的代码 | `Ctrl + Enter` | `⌘ + Enter` |
| 关闭 | `Esc` | `Esc` |

基本流程是：**选中代码 → 按快捷键 → 提请求 → 看 diff → 应用**。请求可以很灵活——问概念、要修改、要生成都行。比如选中一个函数，问「这个并发实现会有 race condition 吗？」，或者直接说「给这个函数加参数校验和异常处理」。

生成的代码会以 diff 形式展示，新增行高亮绿色、删除行高亮红色，你清楚知道会改什么。不满意可以继续追问，不用重新打开一次会话——改完参数校验还能接着说「顺便补一下 docstring」，上下文会保持住。

> [!TIP]
> 想要更准确的回答，**多选几行再打开行间会话**——上下文越丰富，AI 理解越到位。另一个小技巧是先写一行注释再打开会话，比如在目标位置上方写「这里需要一个静态工厂方法」，AI 会精准命中你的意图。

和右侧 Ask/Agent 面板的区别简单记：**当前文件、当前位置的问题 → 行间会话；跨文件、需要工具调用 → 右侧面板**。

### 第二层：Agent 面板——跨文件、多步骤

当任务超出单文件范围时（比如「把这个模块从 Callback 改造成 Promise」涉及 5 个文件），就要用右侧的 Agent 面板了。Agent 模式下，Qoder 可以自己 Grep 搜索、Glob 找文件、批量编辑、跑终端命令，相当于把一个初级工程师的工具链搬到了 AI 手里。

Agent 执行过程中你能看到它的每一步：读了哪个文件、改了什么、跑了什么命令、遇到了什么错误。它不会盲目一条路走到黑——遇到需要澄清的问题会停下来问你，遇到测试失败会尝试修复后重跑。

### 第三层：Quest 自主委派——把任务当项目管

Quest 是 Qoder CN 最有分量的功能。它把 Agent 升级成一个**任务管理系统**——你给一个目标，Quest 自动拆解成子任务、分配给多个 Agent 并行执行、追踪每个子任务的状态、汇总交付物让你审批。

任务看板是 Quest 的核心界面，每个任务有明确的状态流转：

| 状态 | 含义 |
|---|---|
| 待处理 | 刚创建、还没开始执行 |
| 进行中 | Agent 正在执行 |
| 需要你 | 高风险操作等确认 / Agent 需要澄清 |
| 评审中 | Agent 完成执行，等你审批 |
| 已完成 | 审批通过 |
| 失败 | 执行出错或被手动停止 |

Quest 支持**多任务并行**：一个长重构任务在后台跑，同时发起一个小 bug 修复；工作区多个项目各开一个 Quest；规划专家分配的子任务自动并行。每个任务可以加标签备注方便区分，需要你审批的会高亮提示。

点击任意「进行中」的任务能看到实时执行细节：当前阶段（规划中 / 编码中 / 测试中）、最近动作、工具调用记录、进度估计。这一切都是透明的——你看到的不只是最终答案，而是 Agent 怎么得到这个答案的。

### 产物审查——Agent 交付的代码怎么验收

Quest 任务完成后会交付产物（Artifacts），包括文件改动列表（带逐行 diff）、测试结果（跑了哪些、过了哪些、失败原因）、文档输出和任务总结。审查流程推荐四步走：

1. **先看任务总结**——高层概览：改了多少文件、增删多少行、主要做了什么、有什么假设或注意事项。判断方向对不对，再深入细节。
2. **看文件改动列表**——每个文件有操作类型和行数变化，点击看逐行 diff。重点检查：有没有不该改的文件被改了、有没有顺手改了无关代码、风格是否和项目一致、边界处理有没有覆盖异常和空值。
3. **看测试结果**——Agent 跑了哪些命令、通过率多少、失败的有没有自动修复。
4. **决定接受还是迭代**——全部 OK 直接接受；有小问题就在同一 Quest 对话里追加修正（比如「UserExportDTO 的 createTime 改成 createdAt，其他 OK」），Agent 会在已接受的改动基础上继续改，不用从头来。

> [!NOTE]
> Agent 不会自动 commit Git 操作——接受改动后，改动以未提交状态存在于工作区，你可以 `git diff` 再检查一遍，自己写 commit message 或让 Agent 帮你写，然后正常 push、开 PR。保持 Git 操作的完全可控。

### 第四层：QoderWake——让 AI 当数字员工

QoderWake 把 Agent 升级成 **7×24 值守的数字员工**，支持三种触发方式：

| 触发方式 | 说明 | 典型场景 |
|---|---|---|
| 定时（Schedule） | 按日历计划自动运行 | 每日日报、每周巡检、每小时数据同步 |
| 事件（Event） | 外部事件驱动 | GitHub PR 提交 → 自动审查；Webhook 通知 → 自动处理 |
| API 调用 | 通过 API 主动发起 | 内部系统需要 AI 能力时调用 |

**创建自主工作之前必须先走稳定化流程**——不要一开始就把没验证的任务放进无人值守：

```
对话验证 → 流程固化 → 自动触发
```

先在 QoderWake 里手动发起 Waker 任务，确认输入输出和失败处理都正确；稳定后创建自主工作，配置触发规则；连续运行几次无异常后再放心放全自动。

定时触发的配置很直观：选定时、设 Cron 或日历规则、绑定 Waker、写自然语言任务描述、设最大运行次数和截止日期防止无限循环。事件触发需要在外部系统（GitHub、GitLab、飞书等）配置 Webhook，QoderWake 收到事件后自动路由到对应 Waker。API 触发适合多系统串联——比如订单系统在订单关闭时调 API 让 Waker 发邮件。

自主工作的状态在任务看板里一目了然：待运行、运行中、成功、失败、已暂停、已停止。失败的可以手动重跑或配自动重试。

> [!WARNING]
> 自主工作放全自动之前，务必设置超时时间和最大运行次数——防止卡住的 Waker 一直占资源，或者出 bug 后无限循环跑崩。建议先在低峰期跑几次观察，没问题再切高峰期。
