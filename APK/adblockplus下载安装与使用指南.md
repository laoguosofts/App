## ✨ Adblock Plus 是什么

Adblock Plus（简称 ABP）是目前全球用户量最大的广告拦截工具，最早作为 Firefox 扩展诞生于 2006 年，如今已覆盖 Chrome、Firefox、Edge、Safari、Android、iOS 等几乎所有主流平台。它的核心定位很简单：在你浏览网页时自动拦截广告和跟踪请求，让页面加载更快、更干净，同时减少被广告联盟跟踪的风险。

ABP 的工作原理并不复杂——它本身不内置任何过滤规则，而是依赖外部社区维护的"订阅列表"。安装时根据浏览器语言自动推荐一份合适的订阅（中文浏览器默认是 EasyList China），之后定时从订阅的 URL 下载最新规则并缓存到本地。过滤引擎收到页面请求后，先对照规则库决定哪些请求直接掐断，再对剩余的 HTML 内容应用元素隐藏规则，把页面内嵌的广告 div 用 CSS 隐藏掉。

这个设计的好处是规则和软件解耦——广告形态千变万化，订阅维护者可以独立更新规则而不需要等 ABP 发版。坏处也很明显：ABP 的拦截能力几乎完全等于你装了哪些订阅，新手最容易犯的错就是只装一份 EasyList 就嫌拦得不够，不知道 EasyPrivacy、Fanboy Social 这些增强订阅需要单独添加。

除了广告拦截，ABP 还提供反跟踪（切断第三方域名的 cookie 和像素请求）、恶意域名拦截、可接受广告白名单（默认开启，只放过符合特定标准的非侵入式广告）等附加能力。移动端版本则进一步优化了电池消耗和页面加载性能。

适合谁用？如果你已经受够了网站里无处不在的横幅弹窗、视频前贴片、页面跳转广告，或者担心自己的浏览行为被广告联盟静默跟踪，ABP 是上手门槛最低、社区生态最成熟的选择。即便是对技术不太熟悉的普通用户，装好默认订阅后立刻就能感受到页面清爽了不少。

## 🔧 安装步骤与注意事项

ABP 的安装过程非常简单，不同平台各有一些小细节需要注意。

### 浏览器扩展（Chrome / Firefox / Edge / Safari）

1. 打开对应浏览器的扩展市场，搜索 "Adblock Plus"
2. 找到开发者为 "eyeo GmbH" 的官方扩展，确认下载量在千万级以上
3. 点击"添加到浏览器"，等待扩展安装完成
4. 安装完成后浏览器右上角会出现 ABP 图标，点击可以随时查看和调整设置

> [!TIP]
> 扩展安装后不要急着关掉安装向导——向导会根据你的浏览器语言自动推荐最合适的订阅列表变体（中文浏览器默认 EasyList China），点确认就好，不需要手动折腾订阅配置。

### Android 端

1. 从应用商店搜索 "Adblock Plus" 安装
2. 首次启动时会引导你开启 VPN 模式（ABP 在 Android 上通过本地 VPN 路由实现全局流量过滤，不会真的把你的数据传到任何远程服务器）
3. 授权 VPN 连接请求后，ABP 就开始工作了

> [!WARNING]
> Android 端的 VPN 模式是系统级的，如果你同时装了其他 VPN 应用，两者会冲突——系统只允许一个 VPN 活跃。这时要么关掉其他 VPN，要么改用浏览器扩展版本（Firefox for Android 支持 ABP 扩展）。

### iOS 端

iOS 不允许任何应用直接拦截 Safari 的网络请求，所以 ABP 在 iOS 上走的是 Safari 内容拦截扩展的路线：

1. 从 App Store 安装 Adblock Plus
2. 打开 iOS 设置 → Safari → 内容拦截器
3. 在列表中勾选 "Adblock Plus" 并开启
4. 回到 ABP 应用本身，选择你想启用的订阅列表

### 安装后的核对

装好之后打开 ABP 设置面板，快速确认三件事：

- **已启用的订阅列表**：至少应该有一份 EasyList 变体和 Acceptable Ads 列表
- **过滤状态**：访问一个广告多的网站，点击 ABP 图标看拦截计数是否在增长
- **Acceptable Ads 开关**：默认开启，如果你希望零广告可以关掉

## 📖 使用入门：订阅体系、拦截策略与白名单

ABP 的核心竞争力不在软件本身，而在它背后的订阅生态和社区规则维护。理解了这一层，你就能自己搭配出最适合的拦截方案，而不是被默认设置牵着走。

### 订阅列表：ABP 的"大脑"

订阅列表本质上就是一份纯文本文件，每行一条过滤规则。EasyList 作为全球使用最广泛的主力订阅，包含约两万条规则，覆盖横幅、弹窗、弹出式视频广告、YouTube 前贴片等欧美主流网站的广告形态。它还衍生出多种语言变体，安装向导会根据浏览器语言自动推荐。

| 订阅 | 定位 | 是否广告拦截 |
| --- | --- | --- |
| EasyList（含各语言变体） | 基础广告拦截主力 | ✅ |
| Fanboy's List | 英文广告拦截（与 EasyList 重叠约 80%） | ✅ |
| EasyPrivacy | 反跟踪专用 | ❌ |
| Fanboy Anti-3rd Party | 第三方域名跟踪拦截 | ❌ |
| Fanboy Social | 社交媒体按钮移除 | ❌ |
| Acceptable Ads | 可接受广告例外规则（默认开启） | ❌ |

一个新手容易忽略的点：ABP 首次安装时只启用 EasyList 变体 + Acceptable Ads 两份，EasyPrivacy 反跟踪列表需要你主动点"添加"才会启用。所以你可能以为自己在"反跟踪"，实际上默认配置只拦了广告，没拦跟踪。

> [!NOTE]
> 不要同时开 EasyList 和 Fanboy's List——两者规则重叠度太高，不仅浪费过滤引擎算力，误伤概率还会叠加。同理 EasyPrivacy 和 Fanboy Anti-3rd Party 二选一就好。推荐的实用组合：EasyList（广告主力）+ EasyPrivacy（反跟踪）+ Fanboy Social（社交按钮移除），Acceptable Ads 留着或者关掉看你自己的偏好。

### ABP 怎么对付不同类型的广告

ABP 的过滤引擎分两层工作，不同广告形态走不同的拦截通道：

**横幅广告**有两种来源。一种是从广告联盟域名（如 doubleclick.net、googlesyndication.com）独立加载的，ABP 在第一层网络请求拦截时直接掐断；另一种是内嵌在页面源码里的 div，靠 CSS 类名标识（常见类名有 `ad`、`banner`、`sponsor`），ABP 在第二层用元素隐藏规则把它从页面上抹掉。好的订阅列表两条规则一起写，差的列表只做一层，结果就是页面上留个空白框。

**弹窗广告**是最典型的网络请求拦截场景。传统的 window.open() 弹窗浏览器本身就会拦，但新标签页弹窗（`target="_blank"`）和弹出式视频广告（用户点内容先弹一个视频广告，看完才能进）浏览器不一定管，ABP 能识别这类请求特征直接掐掉。弹出式视频广告特别好处理——视频从广告域名加载，ABP 一把切断，广告就放不出来了。

**原生广告**最棘手。它长得和正文几乎一模一样，从网站自己的域名加载，URL 和域名都看不出广告特征。对付原生广告必须靠元素隐藏——订阅维护者需要人肉分析页面结构，找到原生广告的 HTML 模式（比如 class 里有 `promo`、`recommended`、`related`），写成 CSS 选择器来隐藏。所以原生广告的拦截准确率和订阅质量高度相关，需要持续投入人肉维护。

**为什么有些弹窗就是拦不住？** 近年来网站开始用"反拦截"策略：用户点关闭按钮后弹一个确认框"你确定要关闭本站的广告吗？"、弹窗加载完后用 JS 动态改写 DOM 让 CSS 选择器失效、广告直接注入和主域名相同的 iframe。遇到这种情况要么在 ABP 里手动写规则，要么找专门针对该网站的社区规则。

### 白名单与智能允许

白名单（Allowlist）的作用是让 ABP 对你信任的网站跳过过滤——比如你希望支持某个独立创作者，或者某个网站被 ABP 误伤了需要放行。ABP 在弹窗上就可以快速操作：点 ABP 图标 → "在该网站上禁用" 就能把整个域名加进白名单。

ABP 默认启用"智能白名单"机制，让白名单变成一种"租约"而非永久许可：

- 你添加一个网站到白名单 → 租 7 天
- 7 天内访问该站 → 租约自动续到下一个 7 天
- 7 天没访问 → 租约到期，ABP 自动把它从白名单移除

这个设计解决了一个常见问题：很多人白名单用着用着就忘了，某些网站加进去后再也没访问过，白名单越积越长，不仅没用还会误伤排查时难以定位问题。智能白名单自动清理过期条目，保持列表干净。

| | 开启智能白名单（默认） | 关闭智能白名单 |
| --- | --- | --- |
| 白名单清理 | 自动 | 手动 |
| 白名单膨胀风险 | 低 | 需要自己维护 |
| 误伤排查 | 条目少，好排查 | 条目可能很多 |
| 适合场景 | 偶尔支持，之后可能忘了 | 长期固定支持某些网站 |

如果你希望白名单里的网站永远留在里面，可以到 ABP 设置面板 → 常规设置 → 取消勾选"智能白名单"。关掉之后需要手动删除才能移除条目。

> [!TIP]
> 白名单只影响 ABP 的过滤——浏览器自己的安全机制（Chrome 内置安全浏览、HTTPS-only 模式等）仍然生效。把一个网站加进白名单 ≠ 放开浏览器的安全防线，这个边界要记住。

### 自定义规则 vs 订阅列表

一个实用的组合策略是：订阅列表负责大范围拦截（覆盖几万条规则），你自己写几条自定义规则来处理误伤或者补充拦截。两者的本质区别是——订阅列表由社区维护、自动更新，你不直接编辑；自定义规则（通常以 `@@` 开头表示例外）永远不会被自动覆盖，ABP 会一直保留它们。

比如某个网站的评论区被 EasyList 某次更新误伤了，你不需要等社区修，直接在 ABP 的自定义规则里写一条 `@@||example.com/comments` 的例外规则就能放行。这种"订阅兜底 + 自定义补漏"的模式是大多数老用户的用法。

### 排查拦截问题的思路

遇到"某个网站被拦坏了"或者"广告没被拦住"的问题时，不要先急着骂 ABP。正确的排查顺序是：

1. 先看拦截计数：点 ABP 图标，看这个页面的拦截数是 0 还是在增长
2. 如果拦截数在增长但广告还在 → 大概率是元素隐藏没覆盖到，需要检查订阅是否更新到最新
3. 如果拦截数为 0 但应该有广告 → 可能订阅列表里根本没这条规则，考虑换更合适的订阅
4. 如果是误伤（正常内容被拦） → 先试着临时禁用 ABP 确认问题，再决定是加白名单还是写例外规则

理解了订阅体系，排查问题时就能从正确的方向入手，而不是盲目反复重装。
