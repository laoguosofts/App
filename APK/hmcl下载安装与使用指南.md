## ✨ HMCL：Minecraft Java 版的一站式启动管理

HMCL（Hello Minecraft Launcher）是一款专门面向 Minecraft Java 版的启动器，把版本下载、加载器安装、模组管理、光影配置、账户切换这些原本分散在各个工具里的事，集中到一个界面里完成。安卓 64 位设备用户是它的主要使用群体——装一个启动器，就能跑纯净原版，也能装 Forge/Fabric 加载器玩整合包，光影、模组、存档全都在手机存储里统一管理。

它的核心功能可以概括为几条：自动匹配 Java 运行时（内置 Java 8 和 Java 17，不用自己找）、一键安装游戏任意版本、支持 Forge 和 Fabric 两大加载器的图形化安装、模组与光影文件的导入管理、多账户登录切换。启动器会按所选游戏版本自动挑对 Java——1.16 及更早用 Java 8，1.17 及更新用 Java 17，这是新手最该记住的一条分工，社区里大量"点启动就闪退"的求助最后都是拿错 Java 版本导致的。

设备门槛方面，官方建议 64 位安卓 8.0 及以上系统、至少 4 GB 运行内存、512 MB 可用存储。实际体验中内存是最敏感的项：3 GB 及以下只能轻量玩纯净版，4~6 GB 可以带轻量模组，8 GB 以上才有余力跑中小型整合包和光影。存储 512 MB 只是底线，装模组和光影后游戏运行时占用会明显上涨，建议按 2 GB 起步预留。

## 🔧 从零装好启动器

APK 安装本身和其他安卓应用没有区别，容易卡住的是权限环节，这里按顺序走一遍。

**1. 安装 APK**

在文件管理器里点开下载好的 APK 文件，系统会弹出安装确认，点确认即可。如果系统提示"禁止安装未知来源应用"，按提示跳转到设置页允许对应来源，再返回继续安装流程。安装完成后点"打开"，或者回桌面找到启动器图标手动点开。

**2. 首次启动必须给存储权限**

第一次打开启动器时，系统会申请存储（文件）访问权限，务必选择允许。这不是多余的索取——游戏本体、版本文件、模组、光影、存档全部落在手机存储的游戏目录里，没有存储权限启动器既写不进游戏文件，也读不到你放进来的模组包，后续每一步都会失败。部分系统的权限弹窗只给"仅本次"选项，建议选"允许"而非"仅本次"，避免每次启动都重复询问。

> [!WARNING]
> 存储权限是硬性要求，不给的话启动器能打开但什么都做不了，卡在这一步直接重开检查权限设置即可。

**3. Java 运行时通常不用手动装**

好消息是启动器内置了 Java 8 和 Java 17 两种运行时，正常情况下启动游戏时会按所选游戏版本自动匹配，不需要手动干预。只有两种场景需要手动管：启动器提示找不到合适运行时时按提示下载对应版本；或者你想用自己准备好的 Java 压缩包，可以解压后在启动器设置里指定路径。

> [!TIP]
> 版本匹配记一张表就够：1.16 及更早 → Java 8，1.17 及更新 → Java 17。拿 Java 8 去跑 1.17+ 的游戏，或者反过来，游戏启动即退、日志里会出现版本不支持的报错。

**4. 打开后的界面长什么样**

权限给到位后进入主界面：左侧从上到下是账户分组、游戏分组与通用分组，右下角是启动按钮。此时还没有任何游戏版本，属于正常状态——下一步要么直接点启动按钮让启动器自动装最新正式版，要么在游戏版本管理里自己挑版本。

## 📖 启动器使用全解

装好启动器只是开始，下面把日常用得最多的几块功能拆开讲。

### 内存分配：决定体验上限

内存是影响游戏体验最敏感的因素，启动器的全局游戏设置里可以手动调内存分配。原则很简单：**不超过手机可用运行内存的一半**。分配太少游戏会卡顿甚至闪退，分配太多系统会杀掉游戏进程。

| 设备运行内存 | 大致体验预期 |
|---|---|
| 3 GB 及以下 | 仅建议轻量版本纯净游玩，少开后台 |
| 4 GB 至 6 GB | 纯净版流畅，轻量模组可行 |
| 8 GB 及以上 | 中小型整合包与光影有得玩 |

### 游戏版本与设备匹配

游戏版本越新，对设备压力越大。老设备建议从较老的正式版本玩起（比如 1.12 时代），新版本留给性能充裕的机器。低配设备硬上最新版，是闪退求助里最常见的情形。选版本时先掂量一下自己手机的内存和存储，再决定上哪个时代的版本。

### 模组与加载器：Forge 和 Fabric 怎么选

想要装模组，第一步不是下模组文件，而是先给游戏实例装上加载器。两大主流加载器各有侧重：Forge 生态成熟、支持的模组数量最多；Fabric 轻量、版本更新速度快，新游戏版本出来后 Fabric 加载器通常先跟上。启动器里提供了加载器的图形化安装功能，选好游戏版本后一键就能装上，不用手动跑安装器。

装加载器前先确认 Java 版本：Fabric 安装器需要 Java 17 或 21，拿 Java 8 跑 Fabric 安装器会进不去；Forge 安装器的兼容范围更宽一些，Java 8/17/21 通常都能工作。

### OptiFine 想和 Fabric 同装怎么办

OptiFine 走的不是 Forge/Fabric 的模组体系，默认装不上 Fabric 环境——但社区有通行的桥接方案。先想清楚你装 OptiFine 是为了什么：如果只是提性能，Fabric 体系有钠系一类专门的渲染优化模组；如果是想开光影，Fabric 有 Iris 光影模组；缩放、动态亮度这些功能也都有对应的单功能 Fabric 模组。**能走替代路线就不走桥接**，单功能模组各自独立维护，兼容性比桥接方案稳得多。

确实要用 OptiFine 本体时，桥接件 OptiFabric 是标准答案。操作步骤是：先给实例装好 Fabric，装上 Fabric API 前置，然后从发布站或启动器模组搜索里获取 OptiFabric 模组装进实例，再下载对应游戏版本的 OptiFine jar，最后在实例的模组管理里把 OptiFabric 和 OptiFine 两个文件都添加进去。桥接方案对版本极其敏感，OptiFabric 只支持特定区间的 OptiFine 与 Fabric 版本，游戏版本越新适配越紧，装不上或游戏崩时第一反应是核对三者版本是否在互相支持的区间内。

Forge 与 OptiFine 的情况简单些，多数版本能直接共存，但也有不兼容的组合，装前查一眼 OptiFine 发布页标注的兼容情况。

> [!NOTE]
> 桥接方案是"实在需要才用"的备选，不是常规路线。日常玩 Fabric 整合包用 Iris + Fabric 优化模组的组合，体验比硬塞 OptiFine 更稳。

### 模组文件的导入与管理

模组文件（一般是 jar 格式）下载好后，在启动器的实例模组管理里直接添加即可。启动器会把文件复制到对应游戏实例的 mods 目录下，卸载时从列表里删除就会自动清理。光影包同理，放到实例的 shaderpacks 目录，或者在启动器的光影管理里导入。

### 账户与多人游戏

启动器支持多个账户同时登录，切换账户直接在主界面的账户分组里点选。正版账户可以直接登录官方认证，离线账户用于非正式服务器。多人游戏时注意服务器的加载器版本和游戏版本要与本地实例匹配，版本对不上会被服务器拒绝连接。
